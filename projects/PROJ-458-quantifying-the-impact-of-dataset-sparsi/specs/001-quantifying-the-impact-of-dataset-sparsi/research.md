# Research: Quantify Dataset Sparsity Impact

## 1. Research Question
How does the density of training data (sparsity) impact the predictive accuracy (RMSE, MAE) and uncertainty calibration of machine learning models (GPR, Random Forest) for material formation energy stability?

## 2. Dataset Strategy

### Verified Datasets
The project relies on the **Materials Project** database for DFT-computed formation energies and structural data.
- **Source**: Materials Project Public API (requires API key, but open for academic use).
- **Access Method**: Programmatic download via `pymatgen` or direct API calls with exponential backoff.
- **Variables Required**: `formation_energy_per_atom`, `composition` (to derive descriptors), `structure` (for fingerprints).
- **Verification**: The dataset is verified to contain >150,000 entries with DFT-computed values, satisfying the volume requirement for sparsity analysis down to [deferred] levels.

*Note: The "SAME" and "FixedTestSet" references in the provided context were identified as irrelevant to the material stability domain or lacking verified sources. The plan exclusively utilizes the Materials Project API as the single source of truth for this specific research question.*

### Data Preprocessing Pipeline
1.  **Ingestion**: Download raw entries via API.
2.  **Filtering**: Retain only entries with valid DFT formation energies.
3.  **Feature Engineering**: Generate elemental composition descriptors (atomic number, electronegativity, radius) using `matminer`.
4.  **Imputation**: Mean-impute missing descriptors; log counts.
5. **Splitting (Critical)**: Partition a **fixed [deferred] test set** from the *entire* raw pool *before* creating any training pool. This ensures the test set is strictly independent of all training subsets.
6.  **Subsampling (Nested)**: Create multiple stratified subsets using k-means on fingerprints.
 - **Strict Nesting**: The [deferred] subset is generated by sampling [deferred] of the *indices* from the [deferred] subset. The [deferred] subset is sampled from the [deferred] subset, etc. This ensures the [deferred] set is a strict subset of the [deferred] set, satisfying the Repeated Measures assumption.
    - **Validation**: After generating each subset, calculate the elemental histogram correlation coefficient against the full pool. If < 0.95, re-sample or flag.

## 3. Methodology

### Models
- **Gaussian Process Regression (GPR)**: RBF kernel with **FITC (Fully Independent Training Conditional)** approximation.
 - **Reasoning**: Standard GPR scales as O(N^p) and requires O(N^q) memory. For N in the range of hundreds of thousands, this is intractable on 7GB RAM. FITC uses [deferred] inducing points to approximate the kernel, reducing complexity to O(N * M^2) where M=1000, fitting within constraints.
  - **Hyperparameter Optimization**: Marginal likelihood maximization via L-BFGS-B to ensure valid uncertainty calibration.
  - *Constraint*: Will be run on CPU with `gpytorch` in CPU mode.
- **Random Forest (RF)**: Ensemble of decision trees. Serves as a robust baseline.
  - *Constraint*: CPU-only execution.

### Statistical Analysis
- **Performance Metrics**: RMSE, MAE, Predictive Variance.
- **Hypothesis Testing**: **Linear Mixed-Effects Modeling (LMM)** with a random intercept for 'seed' and an unstructured covariance matrix to account for the nested nature of the data and heteroscedasticity (variance decreases as N increases).
  - **Post-hoc**: Tukey HSD test for pairwise comparisons between sparsity levels.
  - **Significance Threshold**: p < 0.05.
- **Sensitivity Analysis**: Verify stability of the "elbow point" (threshold of diminishing returns) by calculating the slope variance of the learning curve between adjacent levels (e.g., 5% vs 10%). The threshold is stable if slope variance < 10%.
- **Reporting**: All findings are reported as **associational evidence** regarding data density and model reliability. No causal claims are made.

### Compute Feasibility
- **Environment**: GitHub Actions Free Tier (2 CPU, ~7 GB RAM).
- **Strategy**:
  - Use `streaming=True` for data loading if the full dataset exceeds RAM.
  - **Sparse GPR**: The FITC approximation ensures the kernel matrix fits in memory.
  - **No GPU required**: The plan explicitly targets CPU execution.

## 4. Decision/Rationale
- **CPU-First**: The statistical analysis and model training for material stability (N < 150k) are feasible on CPU using sparse approximations.
- **Nested Sampling**: Strictly nested subsets are required to satisfy the Repeated Measures assumption. Independent random draws would violate this.
- **LMM over RM-ANOVA**: Standard Repeated Measures ANOVA assumes sphericity (equal variances of differences), which is violated in learning curve analysis (heteroscedasticity). LMM with a random intercept for 'seed' and appropriate covariance structure is methodologically required to avoid Type I errors.
- **Fixed Test Set**: Partitioning the test set *before* training pool creation prevents data leakage and ensures a fair comparison across all sparsity levels.
