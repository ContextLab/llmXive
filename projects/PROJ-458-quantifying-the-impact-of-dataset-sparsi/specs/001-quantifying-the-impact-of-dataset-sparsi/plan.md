## Summary

This feature implements a computational pipeline to quantify how dataset sparsity affects the predictive performance of machine learning models (Gaussian Process Regression and Random Forest) trained on material stability data (formation energies). 

**Key Methodological Constraints & Fixes**:
1. **Nested Subsampling**: We generate strictly nested subsets ([deferred] is a subset of [deferred], etc.) by first generating the [deferred] set, then sampling [deferred] of that for the [deferred] level, etc., to satisfy the Repeated Measures assumption.
2. **Sparse GPR**: To handle the O(N^3) scaling of GPR on ~120k points within 7GB RAM, we use the **FITC (Fully Independent Training Conditional)** approximation with [deferred] inducing points.
3.  **Statistical Rigor**: We use **Linear Mixed-Effects Modeling (LMM)** with a random intercept for 'seed' and an unstructured covariance matrix to handle heteroscedasticity (violated sphericity), rather than standard Repeated Measures ANOVA.
4. **Fixed Test Set**: A [deferred] test set is partitioned from the *entire* raw pool *before* any training pool creation to ensure strict independence.
5.  **Associational Reporting**: All findings are reported as associational evidence regarding data density and model reliability, avoiding causal claims.

The approach involves ingesting data from the Materials Project API, engineering elemental composition descriptors, creating stratified subsamples at multiple defined levels ([deferred], [deferred], [deferred], [deferred], [deferred], [deferred], [deferred]), training models on CPU, and performing statistical analysis (LMM with Tukey post-hoc) to identify performance degradation thresholds.

**Structure Decision**: Selected Option 1 (Single project) with a clear separation of `code/`, `data/`, and `tests/`. This structure supports the linear data flow required for the sparsity analysis and ensures all artifacts are versioned and checksummed as per the Constitution.

**Orchestration Details**:
- **Seed Management**: The `sparsity_sampling.py` script iterates over 3 seeds (42, 123, 456) for each of the 7 levels.
- **Nested Logic**: For a given seed, the [deferred] subset is generated first. The [deferred] subset is generated by sampling [deferred] of the *indices* from the [deferred] subset, ensuring strict nesting. This continues down to [deferred].
- **Metadata**: Each run generates a `sparsity_<level>_<seed>.json` file in `data/metadata/` containing the seed, percentage, and a checksum of the subset indices.
- **Contract Conformance**: The `data/results/metrics.csv` and `data/results/statistics.json` files are generated to strictly conform to the `contracts/metrics.schema.yaml`.
