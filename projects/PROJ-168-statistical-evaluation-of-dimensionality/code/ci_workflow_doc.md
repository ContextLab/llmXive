# CI Limits Checker Documentation

The CI limits checker is implemented in `code/ci_limits.py`. It is a lightweight script that enforces the resource constraints defined by the project's success criteria:

- **SC‑003**: Peak RAM usage must not exceed **7 GB** (7 000 000 000 bytes).
- **SC‑004**: Total wall‑clock time must not exceed **6 hours** (21 600 seconds).

## How It Works

1. The script reads `results/monitoring.csv`, which is generated by the pipeline's resource‑monitoring instrumentation.
2. It sums the `wall_time_s` column to obtain the total runtime and takes the maximum of the `peak_ram_bytes` column to obtain the highest memory consumption observed across all steps.
3. If either metric exceeds its respective limit, the script prints a clear error message to **stderr** and exits with status code **1**. Otherwise it exits with status code **0**.

## Usage

The script can be invoked directly from the command line (e.g., within a GitHub Actions job) as follows:

```bash
python code/ci_limits.py
```

The exit code can be used to fail the CI job automatically:

```yaml
- name: Check CI resource limits
 run: python code/ci_limits.py
```

## Implementation Details

- **File:** `code/ci_limits.py`
- **Key constants:**
 - `RAM_LIMIT_BYTES = 7_000_000_000`
 - `TIME_LIMIT_SECONDS = 21_600`
- **Functions:**
 - `_load_monitoring_csv(csv_path)`: Loads and validates the CSV.
 - `main()`: Performs the limit checks and handles exit codes.

The script uses the `llmxive_toolkit.paths` helper to locate `results/monitoring.csv` and the `llmxive_toolkit.get_logger` utility for consistent logging.

For more information, see the source code and the surrounding documentation in the repository.
