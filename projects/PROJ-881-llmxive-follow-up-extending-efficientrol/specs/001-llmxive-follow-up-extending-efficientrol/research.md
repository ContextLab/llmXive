# Research: llmXive Follow-up: Entropy-Guided Token Validity Prediction in RL Rollouts

## Research Question

Does intermediate-layer Shannon entropy in transformer models predict token validity (ground-truth match) during autoregressive generation on GSM8K and MiniGrid tasks? Specifically, can an entropy threshold be identified that maximizes the ratio of skipped computation to accuracy loss?

## Dataset Strategy

The study utilizes two verified, open-source datasets. All downloads are performed programmatically via the Hugging Face `datasets` library to ensure reproducibility and automated fetching on CI.

| Dataset | Source URL | Programmatic Loader | Notes |
| :--- | :--- | :--- | :--- |
| **GSM8K** | https://huggingface.co/datasets/openai/gsm8k | `load_dataset("openai/gsm8k", "main", split="test")` | Math reasoning. Contains `question` and `answer`. Ground truth is the exact solution string. |
| **MiniGrid (Minari)** | https://huggingface.co/datasets/minari/babyai-nav | `load_dataset("minari/babyai-nav")` | Navigation. Contains `observations` and `actions`. Ground truth is the pre-computed action sequence. |

**Dataset Constraints & Handling**:
- **Access**: Both datasets are open and directly downloadable. No credentials or data-use agreements are required.
- **Size**: The plan limits the subset to a manageable number of examples per task to fit within the available CI window and RAM constraints.
- **Streaming**: To prevent OOM errors, data is streamed (`streaming=True`) and processed in batches of 500 examples (rows) for dataset loading, and A limited token budget for model inference.
- **Ambiguity**: For MiniGrid, the ground truth is defined as the *canonical* path generated by a deterministic solver (A*) if not pre-computed. A token is labeled "valid" only if it matches this canonical path exactly. If the dataset does not provide the `actions` field, the plan will use the `minigrid` environment with a deterministic A* solver to generate the ground truth on-the-fly.

**Ground Truth Generation for MiniGrid**:
If the `minari/babyai-nav` dataset does not provide the specific `actions` field, the plan will use the `minigrid` environment with a deterministic A* solver to generate the ground truth on-the-fly, ensuring the validity labeling step is possible.

## Methodological Rigor

### Statistical Approach
The core analysis employs **Mixed-Effects Logistic Regression (GLMM)** to model the binary outcome (Validity: 0/1) as a function of intermediate-layer entropy.
- **Fixed Effects**: Entropy value, sequence length, task type (GSM8K vs. MiniGrid), token type (numeric vs. alphabetic), `path_type` (canonical vs. alternative).
- **Random Effects**: Random intercepts for `sequence_id` and `layer_id` to account for the nested structure of tokens within sequences and layers.
- **Justification**: Standard logistic regression (ignoring sequence ID) would violate the independence assumption, inflating Type I error rates. GLMM is the standard for hierarchical data in this context.

### Power & Sample Size
- **Sample**: 1000 examples (500 per task) is a feasibility-driven limit.
- **MDES**: Assuming an Odds Ratio (OR) of 1.3 for the entropy-validity relationship (based on pilot studies of confidence calibration), and a baseline validity rate of a substantial majority, a sample of 1000 examples provides >80% power to detect the effect at alpha=0.05.
- **Limitation**: If the true effect size is smaller (e.g., OR < 1.15), the study may be underpowered. The analysis will explicitly report confidence intervals and acknowledge power limitations.
- **Sequence Length**: SC-004 requires measuring decay across sequence lengths. The dataset will be stratified into "short" (< 32 tokens) and "long" (> 64 tokens) subsets for comparative analysis.

### Measurement Validity
- **Entropy**: Calculated as $-\sum p_i \log p_i$ from the softmax output of intermediate layers.
- **Validity**: Binary match against ground truth. For GSM8K, exact string match. For MiniGrid, exact match to the canonical solver path.
- **Instruments**: GSM8K and Minari are standard benchmarks in NLP and RL, respectively, with established validity for reasoning and navigation tasks.

### Tautology Risk Mitigation
The plan explicitly distinguishes between the *model-generated token* and the *independent ground truth*.
- **Validity** is not the model's own prediction, but the match to an *external* ground truth (dataset answer or solver path).
- The analysis tests if *internal* entropy predicts *external* correctness, breaking the circularity of "model confidence vs. model output".

### Causal Assumption
The analysis is correlational. It does not claim that intermediate entropy *causes* validity, but that it is a *predictor* of the outcome. The plan acknowledges that intermediate entropy is part of the causal chain to the final token, but the study tests if it carries predictive signal beyond the final layer's output. The study does NOT control for final-layer entropy (which would cause collinearity). Instead, it tests if *intermediate* entropy predicts validity *conditional* on the final layer's output being the selected token. The 'validity' is an external binary outcome (match to ground truth). The intermediate entropy is a *predictor* of this external outcome, not a component of the final decision in the regression model. The analysis isolates the signal by treating the final layer's selection as the mechanism that produced the token, while the intermediate entropy serves as an early warning signal for that outcome.

### Nested Structure Control
The GLMM includes random intercepts for `sequence_id` and `layer_id` to account for the nested structure of 'tokens within layers' and 'tokens within sequences'. This ensures that the independence of observations within layer groups is verified and that residual confounding from layer-specific autocorrelation is modeled.

### Modality Control
The GLMM includes a fixed effect for `token_type` (numeric vs. alphabetic) and `task_type` (GSM8K vs. MiniGrid) to account for the potential confound of modality. This ensures that the entropy-validity correlation is not driven by the dataset type rather than the general phenomenon of intermediate-layer prediction.

### Path Variance Control
The GLMM includes a fixed effect for `path_type` (canonical vs. alternative) to account for the variance introduced by alternative valid paths. The validity label is defined strictly against the *canonical* path for consistency, but the model accounts for the fact that 'invalid' labels may include valid alternative paths by including a `path_type` covariate in the sensitivity analysis. This ensures the entropy-validity correlation is not biased by the strict labeling of alternative valid paths as 'invalid'.

### Multiple Comparison Correction
To address the testing of multiple layers and tasks, the plan implements:
1.  **Benjamini-Hochberg (BH)**: Applied to the **Family of Tests** defined as "all layer groups across both tasks" to control the False Discovery Rate (FDR).
2.  **Bonferroni**: Implemented as a conservative sensitivity check (reported but not primary) to ensure robustness.
The choice between BH and Bonferroni is determined by the hypothesis family definition, as per FR-006.

## Compute Feasibility

### CPU-First Strategy
- **Model**: A medium-scale parameter model (e.g., TinyLlama) is selected for CPU execution.
- **Optimization**: `torch.backends.cudnn.benchmark = False`, `torch.set_float32_matmul_precision('medium')`.
- **Memory**: Intermediate states are discarded immediately after entropy calculation. Batching (50 tokens for inference, 500 examples for dataset streaming) ensures RAM usage stays < 7GB.

### GPU Escape Hatch (Kaggle)
- **Trigger**: If the 1.5B model fails to generate valid sequences or if a 7B quantized model is required for higher fidelity.
- **Implementation**: The code detects `CUDA_VISIBLE_DEVICES`. If present, it loads a quantized large language model (8-bit) on the GPU.
- **Scaling**: The GPU run is scaled to a representative sample size per task to fit within the 9-hour Kaggle kernel limit, ensuring the full pipeline completes.

## Decision/Rationale

| Decision | Rationale |
| :--- | :--- |
| **GLMM over Standard Regression** | Required by the nested nature of token data (tokens within sequences). Standard regression violates independence assumptions. |
| **Streaming/Batching (50 tokens for inference, 500 rows for dataset)** | Essential to fit within 7GB RAM. Loading full sequences for 1000 examples with intermediate states would exceed memory. |
| **GSM8K + Minari (babyai-nav)** | Provides diversity in reasoning (math) vs. spatial (navigation) tasks. Minari provides pre-computed action sequences, ensuring valid ground truth. |
| **BH + Bonferroni** | FR-006 requires handling multiple comparisons. BH is more powerful for exploratory analysis; Bonferroni is conservative. Both are implemented (BH primary, Bonferroni sensitivity). |
| **Canonical Solver for MiniGrid** | Resolves non-deterministic ground truth. The solver generates a single canonical path; any deviation is "invalid". The model accounts for alternative valid paths via a `path_type` covariate. |
