# Implementation Plan: llmXive Follow-up: Extending WBench with Sequence Complexity Analysis

**Branch**: `001-llmxive-wbench-entropy` | **Date**: 2026-07-21 | **Spec**: [link]

## Summary

This feature extends the WBench benchmark by conducting a **Controlled Experiment** to quantify the relationship between input sequence entropy and visual fidelity degradation. The plan involves: (1) programmatically generating Low/Medium/High entropy variants of WBench interaction logs using **Token Substitution and Truncation** (preserving the original action chain) to ensure semantic validity, verified by a **Task Validity Validator**; (2) executing CPU-optimized inference (or proxy metrics) on a statistically powered stratified sample of sequences; and (3) performing statistical analysis (ANOVA with Bonferroni correction) to determine if higher entropy levels cause significant fidelity drops, controlling for the underlying task complexity (dependency depth).

**Note on Scope**: Due to GitHub Actions free-tier constraints (limited CPU, constrained RAM, time limit), the full dataset (multiple cases × 3 variants × N models) cannot be fully processed. The plan adopts a **Stratified Sub-sampling** strategy (N=50 cases per model) to ensure feasibility while maintaining statistical power for the pilot study.

**Causal Inference Note**: This is a **Controlled Experiment** where the independent variable (Entropy Level) is actively manipulated. Randomization of variant order and the use of a semantic plausibility check allow us to frame results as causal effects of entropy level on fidelity, provided the proxy metric (if used) is valid.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| **Task Validity Validator** | Required for FR-001 to ensure 'Low Entropy' variants are valid instruction sequences (action chains), not just high-similarity text. | Simple text similarity checks fail to detect broken action chains (e.g., loops). |
| **Token Substitution & Truncation** | Required to vary entropy without destroying the causal structure of the task. | Reordering commands destroys the temporal logic of multi-turn interactions. |
| **Dependency Depth from Original Intent** | Required for FR-002 to ensure the covariate reflects task structure, not the manipulation. | Calculating depth on manipulated text creates a circular correlation. |
| **Stratified Sub-sampling** | Required to fit 6-hour runtime on 2 CPUs. | Full dataset (large-scale runs) is physically impossible in the time budget. |
| **Bonferroni Correction** | Required for FR-006 to control family-wise error rate across N models. | Uncorrected p-values would inflate Type I error rates, violating statistical rigor (SC-003). |
| **ANOVA over Pearson** | Required because the independent variable (Entropy Level) is discrete (Low/Med/High). | Pearson correlation assumes continuous variation and is inappropriate for stratified groups. |

## Success Criteria

### Measurable Outcomes

- **SC-001**: The **ANOVA F-statistic** and **Bonferroni-corrected p-value** between Entropy Level and Fidelity Score are measured against the null hypothesis of no difference (F=0, p=1.0), requiring a p-value < 0.05 (after correction) to confirm a significant relationship. **Condition**: If `execution_mode == 'video'`, the hypothesis is "Entropy degrades Video Fidelity"; if `execution_mode == 'proxy'`, the hypothesis is "Entropy degrades Proxy Fidelity Metrics". (See FR-005, US-3).
- **SC-002**: The identified trend or significant difference is measured against the distribution of complexity scores to ensure it falls within the observed range, confirming the non-linear degradation pattern. **Condition**: The trend analysis must explicitly state the `execution_mode` used (Video vs Proxy). (See FR-005, US-3).
- **SC-003**: The family-wise error rate for the set of N model analyses is measured against the standard alpha level (0.05) after applying Bonferroni correction, ensuring statistical validity (See FR-006, US-3).
- **SC-004**: The total inference runtime for the **stratified sub-sample** (50 cases × 3 variants × N models, where 3 ≤ N ≤ 5) is measured against the 6-hour GitHub Actions limit, ensuring the analysis is feasible on free-tier CPU (See FR-003, US-2).
- **SC-005**: The variance of the "Entropy Score" across the generated variants is measured against a minimum threshold of variance > 0.05 to ensure the predictor variable is sufficiently distinct for correlation (See FR-001, US-1).
