## Unresolved concerns

- FR-003 mandates that 'Studies employing Homomorphic Encryption or Hybrid mechanisms may be categorized for **exploratory descriptive summaries** but are **NOT** required for the primary hypothesis testing.' However, no user story explicitly requests exploratory summaries for HE or Hybrid. US-3 focuses on DP and SA interaction analysis. FR-012 states inclusion of HE and Hybrid is 'optional' for exploratory summaries, but no story articulates the value or acceptance criteria for these exploratory outputs. Orphaned FR: FR-012 (and the exploratory pathway in FR-003) lack a corresponding user story or acceptance scenario.
- The `transformation_log` column is defined as 'string (JSON list)' with a whitelist of allowed operations, but no FR explicitly requires logging transformations. FR-010 states 'Any proxy values (e.g., cohort median) used for normalization MUST be explicitly flagged and documented as such,' which implies transformation logging, but does not mandate the `transformation_log` column structure or the whitelist. The data schema introduces a requirement (transformation logging) that is not backed by an explicit FR. Either add an FR requiring transformation logging with the specified schema, or move the transformation_log column to an optional/exploratory section.
- FR-003 states DP and SA are 'mandatory' for primary analysis; FR-012 says HE/Hybrid inclusion is 'optional' for exploratory summaries. But FR-006 applies multiple-comparison correction to 'DP and SA metrics only' (k=4), implying HE/Hybrid are excluded from correction. If HE/Hybrid data ARE extracted and analyzed (per FR-012), they must either be included in the correction family or explicitly forbidden from hypothesis testing. Current text is ambiguous about whether exploratory HE/Hybrid results undergo correction.
- FR-004 says 'If variance data (SD/SE) is missing for >50% of studies within a specific mechanism-skew group, fall back to descriptive aggregation.' FR-007 says 'If the exclusion rate within a group exceeds a majority threshold, switch to descriptive review.' These two thresholds (>50% missing vs. 'majority threshold') are stated differently and may conflict. Define a single, consistent threshold for when to switch from inferential to descriptive mode.
- FR-002 states: 'If a metric is reported as a range "X–Y", extract midpoint (X+Y)/2 ONLY if both X and Y are numeric and bounded; otherwise, flag as invalid_format.' But what if a paper reports '40–60%' (clearly bounded) but also says 'approximately 50%' in the same sentence? Does the 'Ambiguous Text Rule' (flag as invalid_format) override the 'Range Rule' (extract midpoint)? Specify precedence.
- The whitelist includes 'scale_by_median' but FR-008 and FR-009 discuss 'valid_baseline' and 'proxy_baseline' for computational cost normalization. If a computational cost is normalized using a cohort median baseline, should the transformation_log entry be 'scale_by_median' or should there be a separate 'baseline_type' column? Current schema does not clarify how proxy baselines are recorded.
- SC-002 requires manual spot-check validation of extracted data with error rate <1% for N>100. SC-005 requires a validation script to confirm 'every numerical value in the final report matches a value present in extracted_metrics.csv.' These are different validation targets: SC-002 validates extraction accuracy (source PDF → CSV), while SC-005 validates report generation (CSV → report). Clarify whether SC-005's validation script is a separate automated check or part of the SC-002 manual review.
- FR-011 states studies with 'skew_unknown' MUST be excluded from primary interaction analysis but included in descriptive summary. The Assumptions section states 'The dataset contains the necessary variables (privacy mechanism type, accuracy loss, privacy budget, data skew parameters) for all included studies; if a study lacks a specific metric or skew parameter, that study will be excluded from the primary analysis.' This contradicts FR-011: does a skew_unknown study get excluded entirely, or included in descriptive summaries? Clarify the scope of 'excluded from primary analysis.'
- The Methodology Details section defines search strings for DP, SA, HE, and Hybrid mechanisms. However, FR-001 states the system 'MUST query arXiv and Semantic Scholar APIs using the exact search strings defined in the Methodology Details section' but does not explicitly state that HE and Hybrid searches are optional/exploratory. Add a note clarifying that HE and Hybrid searches are performed only if exploratory analysis is enabled (per FR-012).
- FR-013 requires 'a formal interaction test using meta-regression with Data Skew as a moderator.' FR-004 states that if variance data is missing for >50% of studies in a mechanism-skew group, fall back to descriptive aggregation and use non-parametric tests. Can meta-regression be performed in the fallback mode (descriptive aggregation)? If not, FR-013 must explicitly state it applies only when sufficient variance data exists.
- The Metric entity definition includes 'raw_value: Single float OR List of floats if per-client values are reported' and 'value_type: Enum [aggregate, per_client_list].' However, the Data Schema table does not include a 'raw_value' or 'value_type' column—only 'accuracy_loss' and 'privacy_budget' as floats. Reconcile the Key Entities definition with the Data Schema table: either add these columns to the schema or remove them from the entity definition.
- FR-010 states 'The system MUST NOT introduce any simulated, placeholder, or hardcoded values into the statistical analysis.' Constitution Principle IV states 'Every figure, statistic, or interpretation in the paper MUST trace back to exactly one row in this project's data/ and one block in this project's code/.' These are compatible but FR-010 does not mention the traceability requirement. Add explicit reference to the constitution's traceability mandate.
- If a metric is reported as 'approx. X' or 'about X', the system MUST flag the value as `invalid_format` and exclude it from the primary analysis." — This is stated but SC-002 requires 0 errors for N≤100 on 'raw_value' field. How is 'raw_value' populated when the source says 'approx.'? Must clarify: does the system extract the numeric X anyway (and flag separately), or does it leave raw_value empty/null?
- Pass criterion is '0 errors for N ≤ 100' on fields 'raw_value', 'mechanism_type', and 'skew_parameter'. But 'raw_value' is not defined in the Data Schema table. The schema lists 'accuracy_loss' and 'privacy_budget' as separate float columns. Which column(s) constitute 'raw_value' for the spot-check? Must clarify the mapping.
- Requires 'A validation script MUST confirm that every numerical value in the final report matches a value present in `extracted_metrics.csv`.' But the script itself is not a deliverable FR. Must add an FR requiring the validation script to be generated and its output logged, or clarify that SC-005 is aspirational rather than testable.

- Requires `transformation_log` to be 'a subset of' a whitelist. But the schema does not specify the JSON structure: is it `[\"op1\", \"op2\"]` or `[{\"op\": \"op1\", \"input\": X, \"output\": Y}]`? Must clarify the exact JSON schema for this column to make extraction and validation testable.
- States 'Studies with `skew_unknown` MUST be excluded from the primary interaction analysis (FR‑004) but included in a general descriptive summary.' But no FR or SC defines what 'general descriptive summary' means or where it appears in the output. Must add an FR specifying the content and location of this summary.
- Requires 'The pipeline passes if the file contains at least 10 records.' But US-1 does not mention a minimum of 10 records; it only says 'output CSV contains ≥10 records with valid metadata fields.' These are consistent, but SC-006 does not specify what happens if the pipeline retrieves <10 records. Must clarify: does the pipeline fail, or does it succeed with a warning?
- FR-010 and SC-005 explicitly prohibit 'simulated, placeholder, or hardcoded values' and mandate that 'every numerical value in the final report matches a value present in extracted_metrics.csv'. However, FR-005 requires 'forest plots for effect sizes (when computable)' and 'scatter plot for Accuracy Loss vs. Privacy Budget'. - FR-004 specifies meta-analysis with 'Hedges' g' effect sizes and 'random-effects models', while FR-013 adds 'meta-regression with Data Skew as a moderator'. These are methodologically distinct approaches (fixed-effects vs. random-effects vs. meta-regression). The spec must clarify: (1) which is PRIMARY (Hedges' g with random-effects or meta-regression)? (2) if both, what is the decision rule for when to apply each? (3) how does the fallback to 'descriptive statistics' in FR-004 interact with the mandatory interaction test in FR-013? If N or variance is insufficient for FR-013, does the interaction test still run (and report 'insufficient data') or is it skipped entirely?
- SC-002 requires 'manual spot-check of the entire dataset if N ≤ 100, or a random sample if N > 100' with '0 errors for N ≤ 100' or '<1% error rate for N > 100'. This is a RESEARCH OUTCOME (the accuracy of the extraction pipeline), not a SPECIFICATION of what the system must do. The spec should state: 'System MUST support manual validation workflows' or 'System MUST log extraction confidence scores', not prescribe the acceptance threshold for research results. Move SC-002's validation procedure to the plan/tasks stage where it belongs.

- The interaction test (FR-013) proposes meta-regression with 'Data Skew as a moderator' to assess whether privacy mechanism effects differ across skew levels. However, the spec does not define what constitutes a 'skew level' operationally. FR-004 mentions stratification by 'Low, Medium, High, or continuous α' but never specifies the binning thresholds or justification. Without explicit cutpoints, the interaction test is not reproducible and the choice of bins could drive the result.
- FR-004 states the system 'MUST fall back to descriptive aggregation (median, IQR) and MUST NOT use fixed-effects models' if variance data is missing for >50% of studies within a mechanism-skew group. This threshold (50%) is arbitrary and not justified. A group with 51% missing variance is treated identically to one with 99% missing—both trigger fallback. The spec should justify this threshold or make it data-adaptive (e.g., based on effective sample size after exclusion).
- FR-006 applies Benjamini-Hochberg correction to k=4 comparisons (two metrics × two mechanisms). However, the spec does not state what the 'family' of tests actually comprises. Are these four separate hypothesis tests, or are they nested within a single omnibus test? If the four comparisons are not independent (e.g., if accuracy loss and privacy budget are correlated outcomes from the same studies), the correction method may be inappropriate. The spec should clarify the test structure and justify the choice of correction method given the dependence structure.
- FR-004 and FR-007 both address missing variance data but use different decision rules: FR-004 uses a >50% threshold within a group to trigger fallback; FR-007 says 'exclude them from random-effects models' and 'if exclusion rate exceeds a majority threshold, switch to descriptive review.' These two rules are not clearly reconciled. Does FR-007's 'majority threshold' refer to the same 50% cutoff? If not, which rule takes precedence when both apply?
- FR-013 proposes a meta-regression interaction test but does not specify the regression model form, link function, or weighting scheme. For example: is this a fixed-effects or random-effects meta-regression? Are studies weighted by inverse variance, sample size, or equally? Are there covariates beyond the skew moderator? Without these details, the test is not reproducible and different analysts could implement it differently.
- FR-002 specifies extraction of 'Accuracy Loss (%), Privacy Budget (ε), and Data Skew parameters' but the Data Schema table lists `accuracy_loss` as 'float (percent)' and `privacy_budget` as 'float (ε)'. However, FR-002's 'Range Rule' says 'extract the midpoint (X+Y)/2 ONLY if both X and Y are numeric and bounded.' This rule is ambiguous: does 'bounded' mean the range is explicitly stated as 'X-Y', or does it include open-ended ranges like 'at least X'? The spec should clarify with examples.
- FR-011 requires extraction of `skew_parameter` (e.g., Dirichlet alpha) and flagging studies as `skew_unknown` if missing. However, the spec does not define what counts as a 'reported skew parameter.' For example: if a paper states 'we use non-IID data' but does not report a numeric α value, is that `skew_unknown`? If a paper reports only a qualitative description ('highly skewed'), should it be flagged or excluded? The spec should provide concrete decision rules.
- The Assumptions section states 'The remaining [deferred] will be flagged for manual review' (referring to PDFs that cannot be parsed by tabula-py/pdfplumber). This uses the `[deferred]` marker incorrectly—per the spec template, `[deferred]` is for empirical values (counts, percentages) that will be measured during implementation, not for qualitative outcomes like 'flagged for manual review.' Replace with a concrete statement: e.g., 'PDFs that cannot be parsed will be logged in `parsing_failures.log` and excluded from the primary analysis.'
