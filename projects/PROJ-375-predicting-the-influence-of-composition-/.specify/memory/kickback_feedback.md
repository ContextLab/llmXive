## Unresolved concerns

- The plan queries Materials Project with 'spacegroup=amorphous'. This is methodologically invalid because amorphous materials (metallic glasses) do not have a crystallographic space group. The API filter will likely return zero results or incorrect crystalline data, failing to construct the required dataset.
- The permutation test shuffles the target CTE values but refits the model on the *training* split. This is incorrect for a null hypothesis test of the *observed* relationship. The null distribution should be generated by shuffling the target relative to the *features* (X) to break the X-Y link, or by shuffling the residuals. Shuffling Y and retraining on X tests if the model can learn noise, but the implementation described (shuffling Y, then refitting) is ambiguous and risks calculating a p-value against a distribution that doesn't properly represent the null hypothesis of 'no relationship between composition and CTE'.
- The plan drops features with VIF > 5.0. While this addresses multicollinearity, the plan does not specify how to handle the scenario where *all* four descriptors are dropped due to high inter-correlation (common in compositional data). The methodology lacks a fallback strategy (e.g., PCA, ridge regression, or a lower VIF threshold) to ensure a model can still be trained, risking a 'no predictors' failure state.
- Stratified splitting by 'primary element' may result in data leakage if the primary element is the dominant driver of CTE. If the test set contains only Zr-based alloys and the model learns Zr-specific patterns, the R² will be inflated. The methodology should consider splitting by 'alloy family' (e.g., Zr-Cu-Al vs. Pd-Ni-P) if distinct families exist, or explicitly acknowledge that the test set evaluates interpolation within families rather than generalization across families.
- FR-001 requires retrieving data from 'Materials Project and AFLOWlib'. The plan (Phase 0) explicitly states 'AFLOWlib: not used' and proceeds with Materials Project only. There is no task in the plan to attempt AFLOWlib ingestion or handle its specific failure mode as required by the spec's 'and' condition. This leaves FR-001 partially unbacked.
- FR-009 requires recording 'thermal history metadata' and flagging entries with inconsistent metadata for 'sensitivity analysis'. The plan (Phase 0) extracts 'thermal_history' but Phase 1-5 contain no task to 'flag' these entries or perform the required 'sensitivity analysis'. The plan only logs counts or drops rows, missing the specific sensitivity analysis requirement.
- SC-004 requires measuring computational efficiency against GitHub Actions limits. While Phase 6 logs runtime/memory, the plan lacks a specific task to 'measure' the result against the limit and report the outcome (pass/fail) as a success criterion. It only aborts if exceeded, which is a constraint enforcement, not a measurement/reporting task for the success criterion.
- The plan queries Materials Project with `spacegroup=amorphous`. This is an invalid filter for the MP API; MP does not store 'amorphous' as a space group (space groups are integer indices for crystalline lattices). Metallic glasses are non-crystalline and lack a space group. Relying on this filter will return zero results or crash the API call, making the dataset acquisition impossible as described.
- The plan assumes the existence of an `elasticity.cte` field and an `amorphous` boolean flag in the raw MP JSON response. The Materials Project API primarily provides DFT-calculated elastic constants (Cij) and bulk/shear moduli, not a direct 'CTE' (Coefficient of Thermal Expansion) field, nor a standard 'amorphous' flag. The plan fails to cite a specific endpoint or calculation method to derive CTE from elastic constants or to identify amorphous structures, rendering the data ingestion strategy factually incorrect for the cited source.
- The plan explicitly excludes AFLOWlib because 'no verified open endpoint' exists. However, AFLOWlib provides a public REST API (AFLOW-REST) and a downloadable database. While it may require an API key, dismissing it entirely as 'not used' without attempting the standard public access method or citing a specific blockage (e.g., 'requires paid tier for metallic glass subset') risks missing a critical data source if MP lacks sufficient amorphous entries. The plan should verify the specific access constraints of AFLOWlib's public tier before discarding it.
- Plan Step 1 queries Materials Project with `spacegroup=amorphous`. The Constitution (Principle VI) and Spec (FR-001) require filtering for 'amorphous or metallic glass' entries, but the Materials Project API does not use a 'spacegroup' field for amorphous materials (which lack long-range order). This query will likely return zero results or incorrect crystalline data, violating the data ingestion requirement and the constitutional mandate for valid data sources.
- Plan Step 5 drops descriptors with VIF > 5.0. The Spec (FR-008) mandates this, but the Plan does not specify the fallback behavior if *all* descriptors are dropped (leaving no features for the model). The Constitution (Principle VII) requires a valid validation process; a model with zero features cannot be trained or evaluated, creating a potential pipeline failure not addressed in the plan.
- Plan Phase 5 Step 3 computes 'Pearson correlation' between descriptors and CTE, then 'Spearman ρ' between rankings. The Spec (SC-003) and Data Model (FeatureImportance.spearman_rho) explicitly require the Spearman correlation between the *rankings* of importance and absolute correlation. The plan text is slightly ambiguous about whether it computes the correlation of values or ranks first, though it likely intends the correct logic. Clarification is needed to ensure strict alignment with SC-003.
- Plan Phase 4 defines a 'Baseline Comparison' using 'weighted-average elemental CTE'. However, the Spec (SC-001) requires measuring accuracy against a 'linear weighted average of elemental CTEs'. The Plan does not explicitly state that the *baseline model* will be trained/evaluated to produce an R² for comparison, but rather implies a simple calculation. If the baseline is not a trained model (e.g., a simple lookup), the comparison metric (R²) may be undefined or misleading. The plan must clarify if a baseline model is trained or if the comparison is purely statistical.
- The Plan's Constitution Check for Principle II states 'No external citation is introduced without a verified URL'. However, the Plan (Phase 0) relies on the 'mendeleev' package for elemental properties (atomic radius, etc.) without explicitly citing a source or verifying its data provenance in the plan text. While the package is pip-installable, the Constitution (Principle II) requires verified accuracy for *every* external citation/data source. The plan should explicitly mention the data source for 'mendeleev' or confirm its verification status.
- The plan computes 'Weighted mean atomic radius' (μ) and 'Atomic size mismatch' (σ) as predictors. Mathematically, σ = √[Σ fᵢ(rᵢ - μ)²]. These two features are functionally dependent (σ is a deterministic function of μ and the input radii). While VIF is proposed to drop one, the plan does not specify which one to drop if both are high, nor does it address that the 'independence' of the remaining features is still compromised by the shared underlying elemental data. This risks a circular interpretation of feature importance where the model selects the 'mismatch' feature simply because it captures the variance of the 'mean' feature, not because it is a distinct physical driver.
- The baseline is defined as a 'weighted-average elemental CTE'. However, the plan does not specify the source of these 'elemental CTE values'. If these values are derived from the same Materials Project dataset (by averaging CTEs of pure elements), the baseline is mathematically coupled to the target variable's distribution. If the target CTEs are DFT-computed for alloys, and the baseline uses DFT-computed pure elements, the comparison may be tautological (predicting alloy CTE from a linear mix of its parts' CTEs is a known physical approximation, not a null hypothesis). The validation target (alloy CTE) and the baseline predictor (linear mix of elemental CTEs) are not independent; the baseline is a trivial lower-bound estimator of the target, making the 'improvement' metric (R² gain) potentially trivial or definitionally constrained.
- The plan computes a Spearman ρ between 'feature importance' (derived from the model) and 'absolute descriptor-CTE correlations' (derived from the data). This is a circular diagnostic: feature importance in a linear model is directly proportional to the correlation with the target (scaled by variance). In a Random Forest, importance is also driven by correlation. Comparing a model's internal ranking to the ground-truth correlation ranking is a self-fulfilling prophecy, not an independent validation of the model's ability to find 'new' drivers. It validates that the model learned the correlation, which is the definition of the model's success, not an independent check of scientific validity.
- The plan filters for 'amorphous' entries using a flag from Materials Project. However, Materials Project primarily contains crystalline structures. The 'amorphous' flag in MP is often a metadata tag for 'glass' or 'amorphous' *if* the structure was explicitly submitted as such, but MP does not natively generate amorphous structures via DFT in the standard elasticity workflow. Relying on a boolean flag 'amorphous' from a database of mostly crystalline structures risks a data leakage or selection bias where the 'amorphous' entries are actually just specific crystalline phases mislabeled, or the dataset is too small to be statistically significant. The plan assumes the existence of a robust 'amorphous' dataset in MP without verifying the physical validity of the 'amorphous' flag in that specific API context.
