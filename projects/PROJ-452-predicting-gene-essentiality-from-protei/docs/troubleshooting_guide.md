# Troubleshooting Guide

This document lists common error codes and log messages generated by the pipeline,
specifically those introduced in tasks T073, T074, T075, and T076, along with
step-by-step resolution instructions.

## Data Fetching Errors (T073)

### Error: `DataFetchError: STRING API fetch failed for organism {organism_id}`
**Log Message:** `DataFetchError: Failed to fetch STRING network for organism {organism_id}. Error code: {code}. Skipping organism.`

**Possible Causes:**
1. Network connectivity issues.
2. STRING API rate limiting (HTTP 429).
3. Invalid organism ID in `code/config.py`.
4. STRING service outage.

**Resolution Steps:**
1. **Check Network Connectivity:** Run `ping api.string-db.org` or `curl -I.
2. **Verify Organism ID:** Ensure the organism ID (e.g., '9606', '559292') is correct in `code/config.py` under `ORGANISM_IDS`.
3. **Wait and Retry:** If rate-limited (HTTP 429), wait 60 seconds and re-run the pipeline. The pipeline includes exponential backoff for transient errors, but persistent 429s require manual delay.
4. **Check API Status:** Visit the STRING database status page or check their Twitter feed for service outages.
5. **Manual Fetch:** If the API is down, consider manually downloading the network data from the STRING FTP site and placing it in `data/raw/` (ensure the filename matches the expected pattern).

## ID Mapping Errors (T074)

### Error: `DataFetchError: ID mapping failed for organism {organism_id} after fallback`
**Log Message:** `DataFetchError: Primary BioMart and secondary Gene Symbol fallback both failed for {organism_id}. Coverage too low.`

**Possible Causes:**
1. Ensembl BioMart API is unreachable.
2. Gene symbols in the essentiality dataset do not match those in the PPI network.
3. The organism has very few mapped genes (< 10% coverage).

**Resolution Steps:**
1. **Check BioMart Connectivity:** Run `curl -I https://www.ensembl.org/biomart/martservice`.
2. **Verify Gene Symbols:** Inspect the essentiality data file (e.g., `data/raw/essentiality_{organism_id}.csv`) and ensure gene names are in the correct format (e.g., standard gene symbols, not Ensembl IDs if the fallback expects symbols).
3. **Review Fallback Logs:** Check the logs for the specific number of genes matched via the secondary strategy. If the number is very low, the essentiality dataset might be for a different organism or use a different naming convention.
4. **Manual Mapping:** If automated mapping fails, create a custom mapping file (CSV with columns `gene_id, symbol`) and place it in `data/mappings/`. The pipeline can be modified to load this file if needed (contact maintainers for modification details).

## Sensitivity Analysis Errors (T075)

### Error: `SensitivityAnalysisError: Threshold {threshold} failed for organism {organism_id}`
**Log Message:** `Warning: Threshold {threshold} failed for organism {organism_id} due to {error_reason}. Recording as 'skipped' in sensitivity summary.`

**Possible Causes:**
1. Data fetch failure for a specific threshold (e.g., high confidence threshold results in no data).
2. Network sparsity (too few edges) causing downstream analysis to fail.
3. Critical error in centrality calculation.

**Resolution Steps:**
1. **Check `results/sensitivity_summary.json`:** Look for the entry marked as `skipped` and read the `error_reason` field.
2. **Investigate Specific Threshold:** If the error is "network_too_sparse", try running the analysis with a lower confidence threshold (e.g., 500 instead of 900) to see if the network becomes usable.
3. **Review Logs:** Check the detailed logs for the specific threshold run to see the underlying exception.
4. **Manual Intervention:** If a specific threshold consistently fails due to data issues, it may be acceptable to exclude that threshold from the final report, but ensure the `sensitivity_summary.json` accurately reflects this.

## PGLS Model Errors (T076)

### Error: `PGLSConvergenceError: PGLS model failed to converge for {organism_list}`
**Log Message:** `Warning: PGLS model failed to converge for {organism_list}. Singular matrix or convergence error. Skipping PGLS result.`

**Possible Causes:**
1. Small sample size (effective n < 10).
2. High collinearity in the data.
3. Singular matrix in the phylogenetic tree or correlation data.
4. Numerical instability in `statsmodels`.

**Resolution Steps:**
1. **Check Sample Size:** Ensure that at least 10 organisms have valid correlation data and corresponding tips in the phylogenetic tree. If not, PGLS cannot be reliably performed.
2. **Review Phylogenetic Tree:** Check `data/phylogeny/tree.newick` for any malformed entries or missing tips for the organisms with data.
3. **Check Correlation Data:** Ensure that correlation coefficients are not all identical or extremely close to 1/-1, which can cause numerical issues.
4. **Increase Sample Size:** If possible, include more organisms in the analysis by fetching data for additional species.
5. **Manual Model Fitting:** If the pipeline fails to converge but you believe the data is valid, you can attempt to fit the PGLS model manually using `statsmodels` with different parameters (e.g., `method='REML'` instead of default).

## General Pipeline Errors

### Error: `ConfigError: Configuration file missing or invalid`
**Log Message:** `ConfigError: Failed to load config from {path}. Error: {error_msg}`

**Resolution Steps:**
1. **Verify Config File:** Ensure `code/config.yaml` (or the path specified in `quickstart.md`) exists and is valid YAML.
2. **Check Required Fields:** Verify that all required fields (e.g., `ORGANISM_IDS`, `CONFIDENCE_THRESHOLDS`, `random_seed`) are present.
3. **Validate YAML Syntax:** Use a YAML linter or validator to check for syntax errors.

### Error: `FileNotFoundError: Required output directory not found`
**Log Message:** `FileNotFoundError: Directory {path} does not exist.`

**Resolution Steps:**
1. **Run Initialization:** Ensure you have run the project initialization script (`scripts/init_project_structure.sh`) or manually created the required directories (`data/`, `results/`, `code/`, etc.).
2. **Check Permissions:** Ensure you have write permissions for the project directory.

## Reporting Issues

If you encounter an error not listed here, or if the resolution steps do not work, please:
1. Check the full log output in `logs/pipeline_run.log`.
2. Verify your environment meets the requirements listed in `quickstart.md`.
3. Open an issue on the project repository with the error message, log excerpt, and steps to reproduce.
