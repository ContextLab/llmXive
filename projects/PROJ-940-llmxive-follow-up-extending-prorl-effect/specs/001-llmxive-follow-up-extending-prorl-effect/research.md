# Research: llmXive Follow-up: Extending ProRL for Zero-Shot Proactive Recommendation

## 1. Problem Definition
The research investigates whether ProRL's bias-correction mechanisms (Stepwise Reward Centering and Position-Specific Advantage Estimation) can function as a zero-shot, post-hoc filter to improve proactive recommendations in cold-start scenarios. Unlike standard RL, which requires training a policy, this approach applies deterministic formulas to a diverse candidate pool of paths generated by Beam Search on a static content-similarity graph.

**Hypothesis**: Applying SRC and PSA to a beam of candidate paths will yield higher Precision@K and Diversity compared to raw greedy/beam scores, without requiring model training.

## 3. Methodology

### 3.1 Graph Construction (FR-001)
- **Nodes**: Items.
- **Edges**: Weighted by cosine similarity of content features (genre vectors).
- **Feature Vector**: One-hot encoding of genres (pipe-separated).
- **Similarity**: Cosine similarity.
- **Handling Sparsity**: Items with no genre overlap get score 0.0 (FR-009).

### 3.2 Path Generation (FR-003)
- **Algorithm**: **Beam Search** with width $B=50$. (Replaces single-path greedy to avoid local optima and provide a diverse candidate pool).
- **Input**: Seed item (cold-start).
- **Length**: Fixed $L=5$.
- **Baseline**: Raw scores of the top-K paths from the Beam Search.
- **Secondary Baseline**: Single-path Greedy (for comparison against naive methods only).

### 3.3 ProRL Rectification (FR-002)
- **Stepwise Reward Centering (SRC)**:
  $S_{rect} = S_{raw} - \mu_{batch}$
  Where $\mu_{batch}$ is the mean of raw scores of the **B=50 candidate paths** generated for the current seed. This ensures the centering is non-trivial.
- **Position-Specific Advantage (PSA)**:
  $S_{final} = S_{rect} \times (1 + \alpha \times pos)$
  Where $pos$ is the 0-indexed position in the path (0 to $L-1$) and $\alpha = 0.1$.
- **Control Condition**: A "PSA-Null" variant where $\alpha = 0$ is run to isolate the effect of the position term.
- **Constraint**: No gradient updates. Purely deterministic post-hoc calculation.

### 3.4 Evaluation Metrics (FR-004)
- **Precision@K**: Fraction of top-K items (from the **re-ranked** list) matching the ground-truth next item. $K=10$.
- **Recall@K**: Fraction of ground-truth items found in top-K.
- **Diversity**: $1 - \frac{1}{K(K-1)} \sum_{i \neq j} \cos(\vec{v}_i, \vec{v}_j)$.
- **Coverage**: $\frac{|\text{unique items in top-K}|}{|\text{unique items in candidate pool}|}$.

### 3.5 Statistical Analysis (FR-005, FR-006)
- **Normality Test**: Shapiro-Wilk on metric differences (per seed).
- **Significance Test**:
  - If $p_{Shapiro} < 0.05$: Wilcoxon signed-rank test.
  - Else: Paired t-test.
- **Sensitivity Analysis**: Sweep decision cutoffs (similarity thresholds) over {0.01, 0.05, 0.1} and report metric variance.

## 4. Compute Feasibility & Resource Plan

### CPU-First Strategy
- **Environment**: GitHub Actions free-tier (2 CPU, 7 GB RAM).
- **Method**:
  - Graph construction: Use sparse matrices (`scipy.sparse`) to minimize memory.
  - Path generation: Beam Search is iterative and memory efficient.
  - Scoring: Vectorized NumPy operations.
- **GPU Escape Hatch**: Not required. The method is purely algebraic.

### Feasibility Verification
- **RAM**: Target < 6 GB. The dataset is small; graph construction is efficient.
- **Disk**: Target < 10 GB. Parquet files and graphs are small.
- **Time**: Target < 6 hours. Beam Search on 50k nodes with B=50 is fast.

## 6. Decision Rationale

- **Why MovieLens?** Verified source, contains both item features and sequential user data required for "next item" ground truth.
- **Why Zero-Shot?** Aligns with Constitution Principle VI. Training a model would invalidate the hypothesis test of the *filter* mechanism.
- **Why CPU?** The operations are simple linear algebra and graph traversal, not deep learning. No CUDA needed.
- **Why SRC/PSA formulas?** Direct implementation of the ProRL paper's bias-correction terms, adapted for batch statistics (mean) instead of learned value functions.
- **Why Beam Search?** Provides a diverse candidate pool necessary for the SRC operation to be non-trivial and for the PSA re-ranking to have an effect on the top-K selection.
