## Phase 1 – Setup, utilities, and first end‑to‑end analysis  

**Goal**: Obtain real (or synthetic) solar‑wind composition and geomagnetic data, align them to a clean hourly grid, compute coupling functions, and verify that the pipeline runs on a small real subset before scaling to the full multi‑decadal interval.

- [ ] **T001** [P] Pin every project dependency in `requirements.txt` to the pattern `package==major.minor.*` and provide CI evidence that a clean `pip install -r requirements.txt` succeeds.  
  *File(s)*: `requirements.txt`, `ci/install_log.txt` (generated by CI).  
  *Verification*:  
   • CI step runs `pip install -r requirements.txt` on a fresh runner and stores stdout/stderr in `ci/install_log.txt`.  
   • A pytest test `tests/integration/test_requirements_install.py` asserts that the log contains the phrase `Successfully installed` for each package and exits with code 0.  

- [ ] **T002** [P] Refactor `code/utils/io.py` to provide `load_parquet(path)` and `save_parquet(df, path)` with a safe fallback from `pyarrow` to `fastparquet`.  
  *Verification*: `pytest tests/unit/test_io.py` passes on a runner lacking `pyarrow`; the saved parquet file’s SHA‑256 matches the checksum recorded in `data/raw/checksums.yaml`.

- [ ] **T003** [US1] Download the **real** solar‑wind bulk and geomagnetic archives from CDAWeb/NOAA, store the raw CDF files unchanged, and create a SHA‑256 manifest.  
  *File(s)*: `code/ingestion/download_real.py` → creates  
   `data/raw/ace_swics/` (ACE SWICS CDFs),  
   `data/raw/wind_sms/` (WIND composition CDFs),  
   `data/raw/omni/` (OMNI bulk parameters + Dst/Kp),  
   `data/raw/checksums.yaml` (manifest of all raw files).  
  *Verification*:  
   • Integration test `tests/integration/test_download_real.py` checks that each directory exists, contains at least one CDF file per year, and that the SHA‑256 recorded in `checksums.yaml` matches the file on disk.  
   • The script raises a `RuntimeError` on any HTTP failure; no synthetic fallback is invoked.  

- [ ] **T004** [US1] Align and merge the three streams, resample to a strict **1‑hour** grid using **hourly median** aggregation, and enforce the following rules:  
    • Maximum temporal offset ≤ 30 minutes.  
    • Exactly one row per hour for the entire study period (including leap‑year handling).  
    • Core columns (`dst_index`, `kp_index`, bulk parameters) **must be non‑null**; composition fields (`o_fe_ratio`, `he_h_ratio`, `c_o_ratio`) may be `null` when the 2‑hour cadence provides no measurement.  
    • Gaps > 6 hours are recorded in `data/artifacts/alignment_report.json`.  
    • Division‑by‑zero protection: any denominator < 1e‑6 is replaced by 1e‑6.  
  *File(s)*: `code/ingestion/align.py` → outputs  
   `data/processed/aligned_hourly.parquet` (conforms to `contracts/dataset.schema.yaml`),  
   `data/artifacts/alignment_report.json`.  
  *Verification*:  
   • Unit test `tests/unit/test_align.py` validates: (i) exactly one row per hour, (ii) monotonic timestamps, (iii) `max_offset_minutes ≤ 30`, (iv) core columns non‑null, (v) schema compliance via `jsonschema`, (vi) any > 6 h gaps listed in the report.  

- [ ] **T005** [US2] Compute the **Akasofu ε** and **Newell dΦ/dt** coupling functions from bulk parameters and append them to the aligned dataset.  
  *File(s)*: `code/analysis/coupling_functions.py` → reads `data/processed/aligned_hourly.parquet` and writes `data/processed/with_coupling.parquet`.  
  *Verification*:  
   • Unit test `tests/unit/test_coupling.py` feeds a handcrafted row and asserts that `epsilon` and `newell_flux` match analytically‑computed values within 1e‑6 relative tolerance.  
   • The script exits with code 0 and the output parquet file exists.  

- [ ] **T006** [US2] Fit **baseline** (coupling functions only) and **full** (coupling + composition) multivariate linear regression models for both targets (**Dst** and **Kp**). Compute **Variance Inflation Factor (VIF)** for every predictor and flag any with VIF ≥ 5.  
  *File(s)*: `code/analysis/regression.py` → produces  
   `data/artifacts/baseline_model.json`,  
   `data/artifacts/full_model.json` (generated **only if** real composition data are present and Principle VI has been amended),  
   `data/artifacts/vif_warnings.txt`.  
  *Verification*:  
   • Integration test `tests/integration/test_regression.py` checks that each JSON contains `coefficients`, `p_values`, `r_squared`, `adj_r_squared`, and `vif` dictionaries; that all p‑values lie in [0, 1]; and that `vif_warnings.txt` lists only predictors with VIF ≥ 5 (or is empty).  

- [ ] **T007** [US2] Compute the **incremental ΔR²** (`R²_full − R²_baseline`) and perform **5‑fold time‑series cross‑validation** (`TimeSeriesSplit`) for both models, reporting out‑of‑sample R² and the cross‑validated ΔR².  
  *File(s)*: `code/analysis/cross_validation.py` → writes  
   `data/artifacts/delta_r2.json`,  
   `data/artifacts/cv_metrics.json`.  
  *Verification*:  
   • Integration test `tests/integration/test_cross_validation.py` asserts that `delta_r2.json` contains `delta_r2` equal (within 1e‑8) to the difference of the two in‑sample R² values, and that `cv_metrics.json` includes keys `baseline_r2`, `full_r2`, `delta_r2_cv` for each target.  

- [ ] **T008** [US2] Compute a **95 % bootstrap confidence interval** for ΔR² using **10 000** resamples (fixed RNG seed).  
  *File(s)*: `code/analysis/bootstrap_ci.py` → outputs `data/artifacts/delta_r2_ci.json`.  
  *Verification*:  
   • Unit test `tests/unit/test_bootstrap_ci.py` confirms that the CI bounds enclose the observed ΔR² and that a provenance block (`source_file`, `script`, `git_commit`, `timestamp`) is present.  

- [ ] **T015** [P] Generate a deterministic synthetic solar‑wind & geomagnetic dataset (fallback when real composition is unavailable).  
  *File(s)*: `code/ingestion/generate_synthetic_data.py` → creates  
   `data/raw/synthetic.parquet` and `data/raw/synthetic_config.yaml`.  
  *Verification*:  
   • Unit test `tests/unit/test_synthetic.py` checks reproducibility (identical SHA‑256 across runs) and schema conformity to `contracts/dataset.schema.yaml`.  

- [ ] **T016** [P] Submit a **Principle VI amendment request** permitting the synthetic‑data fallback for workflow validation and defining the gating condition for downstream composition‑dependent analysis.  
  *File(s)*: `data/artifacts/amendment_request.md` (human‑written rationale, required approvals, and reference to the amendment policy).  
  *Verification*: Manual reviewer sign‑off; CI asserts the file exists before any real‑data download is attempted.

## Phase 2 – Complete the study and validate its evidence  

**Goal**: Validate that any improvement from composition ratios is statistically robust and not an artifact of multiple testing.

- [ ] **T009** [US3] Implement the **block permutation test**: shuffle each composition predictor in **24‑hour blocks**, run at least **1 000** iterations (early stop when the standard error of the p‑value < 0.001, hard cap = 10 000). Produce null distributions and two‑sided p‑values for each of the six hypotheses (three ratios × two indices).  
  *File(s)*: `code/analysis/permutation_test.py` → writes `data/artifacts/permutation_results.json`.  
  *Verification*:  
   • Unit test `tests/unit/test_permutation.py` checks that the stopping criterion is respected, that each entry contains `observed_coefficient`, `null_distribution` (list of floats), and `p_value` ∈ [0, 1].  

- [ ] **T010** [US3] Evaluate **percentile significance** (observed coefficient outside the 95 % percentile range of its null distribution) and apply the **Benjamini‑Hochberg FDR** correction across the six tests.  
  *File(s)*: `code/analysis/significance.py` → outputs  
   `data/artifacts/percentile_significance.json`,  
   `data/artifacts/fdr_results.csv`.  
  *Verification*:  
   • Unit test `tests/unit/test_significance.py` confirms that percentile flags match the 95 % rule and that `fdr_results.csv` contains columns `hypothesis, raw_p, fdr_p, significant` for all six tests.  

- [ ] **T011** [US3] Perform a **sensitivity sweep** over significance thresholds `{0.01, 0.05, 0.10}` using the FDR‑corrected p‑values from T010. Report for each threshold the number of significant predictors and the stability of ΔR².  
  *File(s)*: `code/analysis/sensitivity.py` → writes `data/artifacts/sensitivity.json` and `data/artifacts/threshold_stability.csv`.  
  *Verification*:  
   • Unit test `tests/unit/test_sensitivity.py` asserts three rows, non‑negative integer counts of significant predictors, and that ΔR² values are recorded for each threshold.
