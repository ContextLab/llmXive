# Data Schemas for Predictive Interval Calibration Pipeline

This document defines the data schemas used throughout the `PROJ-713` pipeline, including raw inputs, processed datasets, model outputs, and evaluation metrics. All schemas are designed to ensure compatibility with the `data_loader`, `models`, and `metrics` modules.

---

## 1. Raw Data Sources

### 1.1 M4 Hourly Dataset
- **Source**: M4 Competition (Hourly subset)
- **Format**: CSV
- **Location**: `data/raw/m4_hourly.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `series_id` | string | Unique identifier for the time series |
 | `timestamp` | datetime | Timestamp of the observation |
 | `value` | float64 | Observed value |

### 1.2 UCI Electricity Dataset
- **Source**: UCI Machine Learning Repository (Hourly)
- **Format**: CSV (Multivariate)
- **Location**: `data/raw/uci_electricity.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `timestamp` | datetime | Timestamp (hourly) |
 | `MT_1`... `MT_370` | float64 | Hourly consumption (MW) for each client |
 | *Note*: Each column represents a distinct time series. |

---

## 2. Processed Data

Processed data is stored in `data/processed/` after splitting, standardization, and validation.

### 2.1 Split Series Format
- **Location**: `data/processed/{dataset_name}/series_{id}_split.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `timestamp` | datetime | Timestamp |
 | `value` | float64 | Observed value |
 | `split` | string | Either `train` or `test` |
 | `std_value` | float64 | Standardized value (zero mean, unit variance) |

### 2.2 Standardized Statistics
- **Location**: `data/processed/{dataset_name}/stats_{id}.json`
- **Schema**:
 ```json
 {
 "series_id": "string",
 "train_mean": "float",
 "train_std": "float",
 "n_train": "int"
 }
 ```

---

## 3. Model Outputs

Model outputs are generated by `code/models/` modules and stored in `results/predictions/`.

### 3.1 Forecast Predictions
- **Location**: `results/predictions/{model_name}/{series_id}_forecast.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `timestamp` | datetime | Forecast timestamp |
 | `point_forecast` | float64 | Point estimate |
 | `lower_bound` | float64 | Lower bound of prediction interval |
 | `upper_bound` | float64 | Upper bound of prediction interval |
 | `nominal_level` | float | Confidence level (e.g., 0.80, 0.95) |

---

## 4. Evaluation Metrics

Metrics are aggregated by `code/evaluation/runner.py` and `code/metrics/` modules.

### 4.1 Coverage Results
- **Location**: `results/coverage.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `series_id` | string | Series identifier |
 | `model_name` | string | Model used (e.g., ARIMA, Prophet, LSTM) |
 | `nominal_level` | float | Target confidence level |
 | `empirical_coverage` | float | Actual coverage rate (0.0 to 1.0) |
 | `coverage_deviation` | float | Difference between empirical and nominal |
 | `status` | string | `pass` or `fail` based on deviation threshold |

### 4.2 Distributional Metrics (PIT & CRPS)
- **Location**: `results/distributional_metrics.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `series_id` | string | Series identifier |
 | `model_name` | string | Model used |
 | `crps_score` | float | Continuous Ranked Probability Score |
 | `pit_mean` | float | Mean of Probability Integral Transform |
 | `pit_std` | float | Standard deviation of PIT |
 | `ljung_box_pvalue` | float | P-value from Ljung-Box test for uniformity |
 | `uniformity_passed` | boolean | True if p-value > 0.05 |

### 4.3 Significance Test Results
- **Location**: `results/significance_test.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `model_a` | string | First model name |
 | `model_b` | string | Second model name |
 | `metric` | string | Metric compared (e.g., coverage_deviation) |
 | `p_value` | float | Bootstrap p-value |
 | `significant` | boolean | True if p-value < 0.05 |
 | `winner` | string | Model with better metric (lower deviation) |

### 4.4 Conformal Calibration Results
- **Location**: `results/conformal_results.csv`
- **Schema**:
 | Column | Type | Description |
 |:--- |:--- |:--- |
 | `series_id` | string | Series identifier |
 | `model_name` | string | Base model name |
 | `baseline_coverage` | float | Coverage before conformal wrapping |
 | `conformal_coverage` | float | Coverage after conformal wrapping |
 | `interval_width_change` | float | % change in average interval width |
 | `calibration_improved` | boolean | True if coverage closer to nominal |

---

## 5. Validation Rules

- **Data Types**: All numeric columns must be float64 or int64. Timestamps must be ISO 8601 compatible.
- **Missing Values**: No `NaN` or `Inf` allowed in final output files. Models must handle these internally or raise `DataValidationError`.
- **Range Constraints**:
 - `empirical_coverage`, `nominal_level`, `uniformity_passed`, `significant`, `calibration_improved` must be in [0.0, 1.0].
 - `crps_score` must be non-negative.
- **Uniqueness**: `series_id` + `model_name` + `timestamp` must be unique in prediction files.

---

## 6. API Integration

These schemas are consumed by:
- `code/data_loader.py`: Validates raw input and splits.
- `code/models/*`: Generates predictions matching Schema 3.1.
- `code/metrics/*`: Computes metrics matching Schema 4.1, 4.2.
- `code/evaluation/runner.py`: Aggregates results into Schema 4.1–4.4.
- `code/utils/exceptions.py`: Raises `DataValidationError` on schema mismatch.
