# Golden Set Creation Process

## Overview

This document describes the process for creating the **Golden Set**, a manually labeled dataset of student interactions used to train and validate the Cognitive Load Estimation Model.

**CRITICAL**: The Golden Set **cannot** be generated automatically. It requires expert human judgment to assign cognitive load scores based on interaction patterns. The pipeline will halt if this manual process is not completed.

## Why Manual Labeling is Required

Cognitive load is a complex psychological construct that cannot be reliably inferred from behavioral proxies alone without ground truth. While the model will eventually use features like latency, errors, and hint requests as predictors, these features must first be validated against **expert human judgments** to ensure the model learns the correct associations.

Automated generation of load scores would introduce circular reasoning and fail to capture the nuanced cognitive processes involved in learning.

## Process Overview

1. **Generate Template**: A script creates a template CSV file with interaction data but empty load scores.
2. **Expert Review**: Domain experts review each interaction and assign a load score (0-100).
3. **Validation**: The populated Golden Set is validated to ensure it meets minimum requirements (≥50 rows, valid scores).
4. **Model Training**: The validated Golden Set is used to train and validate the Cognitive Load Estimation Model.

## Step 1: Generate the Template

The template is generated by running the following command:

```bash
python code/generate_golden_set_template.py
```

This script produces:
- `data/processed/golden_set_template.csv`: A CSV file with columns:
 - `interaction_id`: Unique identifier for the interaction
 - `expert_load_score`: **Empty** column for experts to fill
- `data/processed/golden_set_README.txt`: Instructions for experts (this document)

**Do not manually edit the template.** Use the script to ensure proper formatting.

## Step 2: Expert Labeling Process

### Who Should Label?

Labeling should be performed by individuals with:
- Experience in educational psychology or cognitive science
- Familiarity with the subject matter (e.g., mathematics, reading comprehension)
- Understanding of cognitive load theory (intrinsic, extraneous, and germane load)

### Labeling Guidelines

For each interaction in `golden_set_template.csv`:

1. **Review the Interaction Data**: Examine the behavioral features provided (latency, error patterns, hint requests, etc.).
2. **Assess Cognitive Load**: Based on your expertise, estimate the total cognitive load experienced by the student during this interaction.
3. **Assign a Score**: Enter a value between 0 and 100 in the `expert_load_score` column:
 - **0-20**: Very low load (student is fluent, minimal effort required)
 - **21-40**: Low load (minor effort, mostly automatic processing)
 - **41-60**: Moderate load (balanced effort, some struggle but manageable)
 - **61-80**: High load (significant effort, potential for overload)
 - **81-100**: Very high load (likely cognitive overload, struggling significantly)

### Important Considerations

- **Avoid the "Illusion of Competence"**: Do not rely on self-reported ease or surface-level fluency. A student who answers quickly may still be experiencing high load if they are using inefficient strategies.
- **Consider Context**: Intrinsic load (task difficulty) and extraneous load (poor instruction) both contribute to total load.
- **Be Consistent**: Use a consistent rubric across all interactions. If possible, label a small batch, review, and calibrate before proceeding.
- **Minimum Sample Size**: At least **50 interactions** must be labeled for the model training to proceed.

## Step 3: Save the Populated Golden Set

Once labeling is complete:

1. Save the file as `data/processed/golden_set.csv` (replacing the template name).
2. Ensure the CSV format is preserved (comma-separated, UTF-8 encoding).
3. Verify that all `expert_load_score` values are numeric and within the 0-100 range.

**Do not submit the template file.** The pipeline requires the populated `golden_set.csv`.

## Step 4: Validation

After saving the populated Golden Set, the pipeline will automatically validate it by running:

```bash
python code/validate_and_load_golden_set.py
```

This script checks:
- File existence: `data/processed/golden_set.csv` must exist.
- Row count: At least 50 labeled interactions.
- Score validity: All `expert_load_score` values are numeric and between 0-100.

**If validation fails**, the pipeline will halt with a clear error message:
> "WAITING_FOR_HUMAN: Golden Set file (data/processed/golden_set.csv) is missing AND no public dataset with concurrent self-reports found. Please complete the manual labeling process described in `docs/golden_set_creation.md` to acquire the Golden Set. The pipeline cannot proceed without external expert labels."

## Troubleshooting

### "Golden Set file is missing"
- Ensure you saved the file as `golden_set.csv` (not `golden_set_template.csv`).
- Verify the file is in the `data/processed/` directory.

### "Validation failed: Less than 50 rows"
- Label at least 50 interactions. More is better for model robustness.

### "Invalid score values"
- Ensure all scores are numeric (no text, no empty cells).
- Ensure scores are between 0 and 100.

## Ethical Considerations

- **Privacy**: If using real student data, ensure all personally identifiable information (PII) has been removed or anonymized.
- **Bias**: Be aware of potential biases in your labeling. If possible, have multiple experts label a subset of interactions to assess inter-rater reliability.
- **Transparency**: Document any deviations from the standard process (e.g., if fewer than 50 interactions were available due to data constraints).
