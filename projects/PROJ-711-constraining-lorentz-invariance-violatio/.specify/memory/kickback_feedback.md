## Unresolved concerns

- The plan states '10,000 Monte Carlo simulations per burst' for null testing. However, the regression model (FR-005) requires a population of ~30 bursts to disentangle intrinsic lags from LIV. Running 10,000 null iterations *per burst* (300k total) to validate a *global* regression coefficient is statistically inefficient and computationally wasteful. The null distribution should be generated for the *global* statistic (the slope of the regression) by resampling the entire population of lags, not by generating independent nulls for each burst which does not capture the covariance structure of the population fit.
- The plan proposes 'weighted linear regression' to derive $E_{QG}$. However, the spec (US-2) and research context acknowledge that intrinsic source lags are a major confound. A simple linear regression of $\Delta t$ vs $D(z)$ assumes the intercept (intrinsic lag) is zero or constant, which is physically unlikely. The methodology lacks a mechanism to model the intrinsic lag as a nuisance parameter (e.g., hierarchical Bayesian model or random intercept) rather than just 'weighting' by uncertainty. Without this, the slope estimate ($E_{QG}$) will be biased by the correlation between intrinsic lag and redshift or energy.
- The research doc claims 'Causal Inference: The study is observational... Claims are framed as constraints... not causal proof'. However, the methodology relies on a linear regression to isolate the LIV term. If the intrinsic source lag is correlated with redshift (e.g., due to evolution of GRB progenitors) or energy, the regression slope will be confounded. The plan does not specify how to test for or control this confound (e.g., using a control sample of low-redshift bursts or a specific functional form for intrinsic lag), making the causal claim of the LIV constraint unsupported by the proposed design.
- The plan cites 'Fermi Science Support Center (FSSC)' and 'Fermi GBM Trigger Catalog' as the source for the 'top 30 brightest GRBs' but fails to provide a specific, programmatic URL or accession ID for the selection criteria. The research.md explicitly notes 'NO verified source found' for a direct URL. Without a canonical, programmatic link to the specific fluence-ranked list or the exact API endpoint used to derive the 'top 30', the dataset selection is non-reproducible and violates Constitution Principle I (Reproducibility) and Principle II (Verified Accuracy). The plan must cite the exact URL or API query string used to generate the list.
- The research strategy relies on 'standard public access pattern' (e.g., `https://heasarc.gsfc.nasa.gov/FTP/fermi/data/gbm/`) but admits the 'top 30' list is not a static file. The plan assumes the code will 'query the FSSC API or download the full catalog and filter locally' without defining the specific API endpoint or the exact fluence metric (e.g., peak flux vs. total fluence, energy range for fluence calculation) used for ranking. This ambiguity makes the dataset definition 'top 30 brightest' non-deterministic and unverified against the primary source.
- Constitution Principle VII mandates '10,000 synthetic light curves... that preserve the observed temporal structure but randomize photon energies.' The plan states: 'Generate 10,000 synthetic light curves per burst (time-shift null test) to generate null distribution.' Time-shifting one band relative to another preserves the internal temporal structure of each band but does not randomize photon energies within the light curves as required by the Constitution. This is a fundamental methodological contradiction that invalidates the null test's ability to rule out spurious detections caused by intrinsic source variability as intended by the Constitution.
- Constitution Principle VII requires the null distribution to be generated from synthetic light curves that 'randomize photon energies.' The plan's 'time-shift null test' (shifting one band by random amounts) is a standard lag-randomization test, not an energy-randomization test. The plan fails to implement the specific mechanism (energy randomization) mandated by the Constitution to ensure the 'lack of a systematic bias in simulated control analyses' is a mandatory gate.
- The plan lists 'scikit-learn' as a dependency for regression, but the spec (FR-006) requires 'hierarchical Bayesian meta-analysis or robust weighted mean' to account for non-Gaussian errors. While scikit-learn can do weighted regression, it does not natively support hierarchical Bayesian meta-analysis. The plan should clarify if a different library (e.g., PyMC, Stan) is needed or if the 'robust weighted mean' is the only implemented fallback, to ensure alignment with the spec's requirement for handling non-Gaussian errors.
- The plan lists `contracts/grb_event.schema.yaml` in the directory tree, but the `data-model.md` defines `GRBEvent` with `fluence_rank` and `sky_position` (nested). The `contracts/grb_event.schema.yaml` (provided in inputs) correctly defines these. However, the plan's `contracts/` section lists `grb_event.schema.yaml` but the `data-model.md` also references `light_curve.schema.yaml`, `spectral_lag.schema.yaml`, and `liv_constraint.schema.yaml`. The plan's `contracts/` list is consistent with the data model entities, but the `plan.md` text under 'Project Structure' should explicitly confirm that all four schema files listed in the `contracts/` block are generated in Phase 1 to avoid ambiguity.
- The null test methodology is circular. The plan states: 'Generate 10,000 synthetic light curves... (time-shift null test)... to generate null distribution.' However, the LIV signal is defined as an energy-dependent time delay ($\Delta t \propto E$). Randomly time-shifting one band relative to another destroys the *intrinsic* correlation but does not simulate the *null hypothesis* of 'no LIV' if the intrinsic source lag is non-zero. A proper null test for LIV requires simulating data where $\Delta t_{LIV} = 0$ but intrinsic lags ($\Delta t_{int}$) are preserved (e.g., by shuffling energy labels while keeping time structure, or using a model of intrinsic lag). Simply time-shifting bands creates a distribution of *total* lags, not a distribution of *LIV-only* lags, making the comparison to the observed $E_{QG}$ invalid.
- The regression model $\Delta t = eta \cdot D(z) + lpha$ assumes the intercept $lpha$ (intrinsic lag) is constant or negligible across the population. However, intrinsic spectral lags in GRBs are known to be highly variable and often scale with luminosity or energy, not just redshift. Treating $lpha$ as a single global constant or ignoring its variance introduces a massive systematic error that will bias the slope $eta$ (and thus $E_{QG}$). The plan lacks a mechanism to model or marginalize over the distribution of intrinsic lags, rendering the derived $E_{QG}$ bound scientifically unsound.
- The null test generation method described ('time-shifting one energy band by random amounts') is methodologically flawed for testing LIV. If the goal is to test if the observed lag is due to LIV, the null hypothesis is 'Lag = Intrinsic Lag'. Randomly shifting bands creates a distribution of 'Lag = Intrinsic Lag + Random Shift', which does not represent the null distribution of the LIV parameter. The correct approach is to generate synthetic data where the LIV term is explicitly zero (e.g., by using the observed light curves but removing the energy-dependent dispersion component if known, or by using a population of bursts with known zero LIV). The current plan validates the metric against a quantity that is not the true null, leading to a tautological or misleading consistency check.
