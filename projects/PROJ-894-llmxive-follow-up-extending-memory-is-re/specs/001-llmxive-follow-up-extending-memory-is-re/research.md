# Research: llmXive follow-up: extending "Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents"

## Research Question

Is reducing the depth of memory graph traversal (via "Lazy" or "Greedy" heuristics) **associated with a decrease** in reasoning accuracy compared to "Full" active reconstruction on the constructed graph, and can a threshold of `nodes_visited` be identified where performance drops below 95% of the baseline?

## Dataset Strategy

The study relies on the **LoCoMo** benchmark for multi-hop reasoning tasks. The synthetic noisy graph dataset will be generated programmatically from the LoCoMo graph structures.

### Dataset Fit & Feasibility

- **LoCoMo**: The dataset is a CSV file containing raw text context. It **does not** provide explicit graph structures. The plan constructs a directed graph where **Nodes = sentences** and **Edges = semantic similarity** using a **fixed embedding model (`all-MiniLM-L6-v2`)**.
    - **Graph Construction Model**: The "Full" strategy traverses the graph constructed by this fixed model. This construction is the definition of the "ground truth" graph for this study.
    - **Feasibility**: To ensure the 6-hour runtime constraint is met on CPU, the plan implements a **Sampling Strategy**: only the **top-K (e.g., 50)** most relevant sentences (by similarity to the question) are included in the graph. This reduces the O(N^2) construction complexity to O(N).
    - **Derived Proxy Limitation**: The "Full" baseline is defined as traversing **all nodes in the constructed (sampled) graph**, not the entire original text. The graph is a derived proxy from the text.
- **Compute Constraints**: The dataset size is small enough (CSV) to fit in memory. The LLM inference will be the bottleneck. The plan uses a quantized small model (e.g., Llama-8B-4bit or similar if available, or a smaller model like Phi-3-mini) to ensure CPU feasibility.
    - **LLM Usage**: The quantized LLM is used **ONLY** for final answer generation. Edge expansion decisions are made by Model B (embedding model) to ensure the timeout constraint is feasible.
- **Feasibility**: The dataset is directly downloadable. No authentication is required.

## Methodology

### 1. Data Preprocessing & Graph Construction
- Download `locomo.csv` from the verified URL.
- **Graph Construction (Model A)**:
    - Parse context into a directed graph: Nodes = sentences/facts; Edges = semantic similarity.
    - **Fixed Model**: Use `all-MiniLM-L6-v2` for **all** graph construction. This model is fixed for the entire study to ensure the "Full" strategy traverses a consistent graph structure.
    - **Sampling**: Limit graph construction to the **top-K (e.g., 50)** most relevant sentences per task to ensure computational feasibility.
    - **Immutability**: Save the resulting graph as an immutable JSON artifact. **All strategies (Full, Lazy, Greedy) MUST load and traverse this EXACT same graph instance.**
- **Graph Validation (Edge Coherence)**:
    - Calculate an "Edge Coherence" score (mean similarity of connected nodes).
    - **Exclusion**: If coherence < threshold, flag task as `invalid_graph` and **exclude from main analysis** (do not run strategies) to avoid biasing results with random noise.
- **Generate Noisy Graphs**: For each graph, **replace** a fixed density (e.g., [deferred]) of existing edges with random edges to simulate noise (FR-001 strict compliance).

### 2. Traversal Algorithms
- **Full (Baseline)**: Traverse all nodes in the **constructed (sampled) graph**.
- **Lazy**: Expand edges only if the evidence score (confidence from **Model B: `all-mpnet-base-v2`**) exceeds a threshold (e.g., 0.7). **Hard Cap**: Stop traversal if `nodes_visited` exceeds a fixed limit (e.g., 50).
- **Greedy**: Select only the top-k edges with highest confidence (Model B) at each step. **Hard Cap**: Stop traversal if `nodes_visited` exceeds a fixed limit.
- **Decoupling Strategy**: The "evidence score" is derived from a **distinct** frozen embedding model (Model B) than the one used for graph construction (Model A) to ensure the scoring metric is independent of the graph construction bias.
- **LLM Usage**: The quantized LLM is used **ONLY** for final answer generation. Edge expansion decisions are made by Model B.

### 3. Execution & Metrics
- Run each strategy on a fixed subset of tasks (or full set if feasible).
- **Sensitivity Sweep**: Iterate through a defined range of evidence thresholds (e.g., 0.5 to 0.9) for the Lazy strategy. Log the **exact threshold value** used for each run.
- **Metrics**: `accuracy` (match with ground truth), `nodes_visited`, `inference_time_seconds`, `token_count` (from LLM metadata).
- **Timeout**: Enforce a fixed time limit per task (30 mins). Log timeouts.

### 4. Statistical Analysis
- **Hypothesis Test**: Paired t-test (or Wilcoxon signed-rank if non-normal) comparing Accuracy(Baseline) vs. Accuracy(Heuristic). Apply Bonferroni correction for multiple comparisons.
- **Correlation**: Point-Biserial correlation between `nodes_visited` (hard-capped) and `success` (binary).
- **Threshold Detection**: Implement `bin_tasks_by_nodes()` in `code/analysis/stats.py`. Bin tasks by `nodes_visited` (min 3 tasks per bin). Identify the first bin where mean accuracy < 95% of baseline.
- **Robustness Check**: Perform a specific paired t-test comparing **Lazy (Noisy) vs. Baseline (Noisy)** as required by Constitution Principle VII.
    - **Hypothesis**: Test H0: Accuracy(Lazy, Noisy) == Accuracy(Baseline, Noisy) vs H1: Accuracy(Lazy, Noisy) != Accuracy(Baseline, Noisy).

## Statistical Rigor & Assumptions

- **Multiple Comparisons**: If testing both Lazy and Greedy against Baseline, apply Bonferroni correction (alpha = 0.05 / 2 = 0.025) to control family-wise error rate.
- **Power Limitation**: The sample size is fixed by the LoCoMo benchmark. A post-hoc power analysis will be included. If power is low, results will be framed as exploratory.
- **Causal Inference**: The study is **observational** regarding the dataset. The "experiment" is limited to the traversal strategy on a *specific embedding-model-derived graph representation* of the text. The graph structure is a derived proxy, not ground truth. Claims will be framed as associational ("Strategy X is associated with Y% accuracy") rather than causal. The strategy is an experimental manipulation only on the traversal path of the derived graph, not on the text itself.
- **Collinearity**: `nodes_visited` and `inference_time` are likely collinear. The analysis will report them separately but acknowledge the relationship.
- **Measurement Validity**: Accuracy is measured against the benchmark's ground truth. We assume the benchmark ground truth is valid for the purpose of this study (Assumption 5 in spec).
- **Independence of Variables**: By using **distinct embedding models** (Model A for construction, Model B for scoring) and enforcing a **hard cap** on `nodes_visited`, we ensure that the predictor (`nodes_visited`) is not a direct function of the outcome (`accuracy`) or the graph construction bias. The graph structure is **immutable** across strategies.
- **Derived Graph Limitation**: The "Full" strategy traverses all nodes in the *constructed* graph, not the original text. The results are specific to the embedding model used and the top-K sampling strategy.

## Decision / Rationale

- **CPU-First**: The plan uses CPU-only quantized models. No GPU escape hatch is needed as the task is algorithmic benchmarking, not training large models. The compute load is dominated by inference, which is feasible on a small quantized model on CPU within a reasonable time window for a subset of tasks.
- **Dataset**: LoCoMo is the only verified source for the reasoning task. No substitute is needed.
- **Noise Injection**: Programmatically generated via edge replacement to ensure reproducibility (Constitution Principle I).
- **Graph Validation**: Replaced circular validation with "Edge Coherence" to avoid bias.
- **Sampling Strategy**: Top-K sampling implemented to ensure O(N) complexity and fit within 6-hour runtime.
- **LLM Usage**: LLM restricted to final answer generation to ensure feasibility; edge scoring handled by lightweight embedding model.
