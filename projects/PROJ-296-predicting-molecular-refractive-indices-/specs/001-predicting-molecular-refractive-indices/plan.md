# Implementation Plan: Predicting Molecular Refractive Indices from Graph-Based Molecular Representations

**Branch**: `001-predict-molecular-refractive-indices` | **Date**: 2026-10-08 | **Spec**: `specs/001-predict-molecular-refractive-indices/spec.md`

## Summary

This project implements a CPU‑feasible Message Passing Neural Network (MPNN) to predict molecular refractive indices from SMILES strings, comparing performance against a traditional atomic‑contribution baseline. The pipeline enforces strict memory (7 GB) and time (6 h) constraints, utilizes scaffold‑based splitting to prevent data leakage, incorporates molecular weight as a global feature, and applies Integrated Gradients for structural interpretability. All steps are validated against JSON schemas and the project constitution.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: PyTorch (CPU‑only), PyTorch Geometric, RDKit, scikit‑learn, pandas, numpy, scipy, torchmetrics, tqdm  
**Storage**: Local CSV/Parquet files (streamed), GitHub Actions cache  
**Testing**: pytest (unit tests for parsers, integration tests for pipeline), paired t‑tests for metrics  
**Target Platform**: Linux (GitHub Actions Free Tier: 2 vCPU, 7 GB RAM)  
**Performance Goals**: < 6 h total runtime, < 7 GB peak RAM  
**Constraints**: No CUDA, no external API calls during training, strict memory limits  
**Scale/Scope**: Dataset ~10 k–50 k molecules (filtered for MW < 500 Da)

## Detailed Plan Phases

### 1. Dataset Download & Verification (FR‑001)

1. **Dataset**: `chemistry/ri_dataset` (Hugging Face) – verified to contain `smiles`, `refractive_index`, and optional `molecular_weight`.  
2. **Download** via `code/data/download.py` using `datasets.load_dataset("chemistry/ri_dataset", split="train")`.  
3. **Checksum** recorded in `state/` for reproducibility.  
4. **Column Verification**: script asserts presence of `smiles` and `refractive_index`; aborts with clear error if missing (addresses Concern [data_resources‑bd232ab5]).  
5. **Schema Validation**: raw CSV/Parquet validated against `contracts/dataset.schema.yaml` (see Contract Validation section).

### 2. Preprocessing & Filtering (FR‑001, Methodology‑21d64e78)

* **SMILES parsing** with RDKit; failures logged to `failed_parsing.log`.  
* **MW filter**: exclude molecules with molecular weight > 500 Da.  
* **Temperature Normalization**: apply Edlén equation when temperature data present; otherwise flag uncertainty.  
* **Feature Engineering**: node features (atomic number, degree, hybridization, aromaticity) and edge features (bond type, conjugation, stereochemistry).  
* **Global Feature**: normalized molecular weight added as a scalar concatenated to the graph readout (explicitly addresses the MW confound).  
* **Output**: `data/processed/train.csv`, `val.csv`, `test.csv`.

### 3. Scaffold Split Implementation (FR‑003)

* Compute Murcko scaffolds via `RDKit.Chem.Scaffolds.MurckoScaffold.GetScaffoldForMol`.  
* Perform an **80/10/10** split (train/validation/test) with **zero scaffold overlap** enforced by stratified sampling on scaffold IDs.  
* Save split CSVs under `data/processed/`.  

### 4. Baseline Implementation (FR‑004)

* **Molar Refractivity (MR)**: sum of atomic fragment contributions using literature tables (e.g., Meylan et al.).  
* **Lorentz‑Lorenz conversion**: `RI = sqrt((1 + 2*MR)/(1 - MR))`.  
* Baseline predictions saved to `baseline_predictions.csv`.  

### 5. MPNN Architecture (FR‑002)

* **Layers**: 3 message‑passing layers, hidden dimension **64**.  
* **Aggregation**: mean.  
* **Readout**: global average pooling → 2‑layer MLP (64 → 32 → 1) with ReLU.  
* **Device**: `torch.device("cpu")` enforced; `torch.backends.mkldnn.enabled = True` for speed.  
* **Batch size**: default 32, auto‑reduced on OOM.  

### 6. Training (FR‑002, Methodology‑c6f9c7eb)

* **Loss**: MSE.  
* **Optimizer**: Adam (lr = 1e‑3).  
* **Early stopping**: patience = 10 on validation loss.  
* **Power Analysis** (pre‑study):  
  * Detectable MAE reduction ΔMAE = 0.2.  
  * Estimated σ is moderate (based on pilot data).  
  * α = 0.05, power = 0.8 → required N ≈ 210 per condition.  
  * If usable N < 210, the report will note limited power and refrain from claiming statistical significance.  
* **Epoch cap**: 200 (typically stops < 100). Expected runtime on the order of a few hours on CPU.

### 7. Integrated Gradients Attribution (FR‑005, Methodology‑3c84bbdf)

* **Baseline**: zero‑vector (all‑zero node/edge features) – justified as a neutral reference for graph data.  
* **Integration steps**: 50.  
* **Sensitivity Analysis**: repeat IG with (a) average‑feature baseline, (b) random baseline; compute variance of top‑10 attribution scores across baselines.  
* **Output**: `attributions.csv` with columns `smiles`, `node_attributions`, `edge_attributions`, `top_features`.  

### 8. Evaluation Metrics & Statistical Tests (FR‑006, Methodology‑7a3467df)

* Compute **MAE** and **RMSE** for GNN and baseline on the test set.  
* **Paired error differences**: `|pred_gnn - true| - |pred_baseline - true|`.  
* **Assumption Check**: Shapiro‑Wilk test on paired differences (α=0.05).  
  * If normal → paired t‑test.  
  * If not normal → Wilcoxon signed‑rank test.  
* Report p‑value, effect size (Cohen’s d), 95 % CI.  

### 9. Plots Generation (FR‑007)

* **Parity Plot** (Predicted vs Actual) → `parity.png` (PNG < 5 MB).  
* **Feature‑Importance Bar Chart** (average node/edge attribution per feature type) → `importance.png` (PNG < 5 MB).  

### 10. Sensitivity & Robustness (User Story 3)

* Train with three seeds (42, 123, 999); compute MAE variance (target < 0.01).  
* Hyperparameter sweep on L2 weight decay (0, 1e‑4, 1e‑3); plot MAE vs. decay.  

### 11. Contract Validation (plan_consistency‑ed3eaf66)

* **Dataset validation**: `code/data/download.py` loads raw data and validates each record against `contracts/dataset.schema.yaml`.  
* **Output validation**: `code/training/evaluate.py` validates `results/metrics.csv` and `results/predictions.csv` against `contracts/output.schema.yaml`.  

### 12. Entity Usage (plan_consistency‑4ef8ed35)

All pipeline stages consume or produce the core entities defined in `data-model.md`:
* `MoleculeGraph` – created in preprocessing, input to MPNN and baseline.  
* `PredictionResult` – generated in evaluation, conforms to `output.schema.yaml`.  
* `FeatureAttribution` – produced by IG step, stored in `attributions.csv`.  

## Compute Feasibility

* **CPU‑First**: All steps run on CPU; PyTorch Geometric compiled for CPU.  
* **Memory**: Streaming dataset loading if > 1 GB; dynamic batch‑size reduction on OOM.  
* **Time**: Expected < 4 h training, < 30 min evaluation, total < 6 h on GitHub Actions.  

## Risks & Mitigations

| Risk | Impact | Mitigation |
| :--- | :--- | :--- |
| Dataset missing RI column | Fatal | Verification step aborts with clear error (addressed). |
| OOM on 7 GB RAM | High | Streaming, batch‑size tuning, optional H‑atom removal. |
| Overfitting | Medium | Early stopping, dropout 0.2, L2 regularization. |
| Scaffold split infeasible | Medium | Fall back to 80/20 split, note limitation. |
| Attribution baseline bias | Medium | Sensitivity analysis across multiple baselines. |
