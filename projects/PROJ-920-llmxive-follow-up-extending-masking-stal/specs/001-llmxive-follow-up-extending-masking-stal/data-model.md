# Data Model: llmXive follow-up: extending "Masking Stale Observations Helps Search Agents -- Until It Doesn't"

## Overview
Defines the JSON and CSV schemas for the synthetic trajectories and simulation logs used throughout the pipeline.

## Trajectory Schema (`contracts/trajectory.schema.yaml`)
Synthetic trajectories are generated in a balanced design:
- **Low density**: ~167 trajectories with entropy ≤ 2.0 bits/token
- **Medium density**: ~167 trajectories with 2.0 < entropy ≤ 4.0 bits/token
- **High density**: ~167 trajectories with entropy > 4.5 bits/token

Each trajectory contains:
- A sequence of turns (text blocks)
- Exactly one critical evidence turn (randomly selected)
- Calculated entropy and technical-token ratio for the evidence block
- Composite density = 0.6 * entropy + 0.4 * tech_ratio

## Simulation Log Schema (`contracts/simulation_log.schema.yaml`)
Each row represents one simulation trial (trajectory × retention horizon pair):
- `trajectory_id`: identifier for the source trajectory
- `density`: composite density of the critical evidence block
- `horizon`: retention horizon used (1 to T turns)
- `evidence_age`: age of the evidence relative to the current turn
- `success`: binary outcome (0 = failure, 1 = success)
- `retrieval_prob`: probability of retrieval under the solver (sigmoid-based)
- `clamped_entropy`: boolean flag indicating if entropy was clamped to a small positive value (for zero-entropy diagnostics)

## File Paths
- `data/raw/trajectories.json` – conforms to `trajectory.schema.yaml`.  
- `data/logs/simulation_results.csv` – each row must validate against `simulation_log.schema.yaml`.  
- `results/regime_map.png` – PNG image generated by `analyze_results.py`.  
- `results/regression_summary.json` – conforms to `contracts/regression_output.schema.yaml`.  

## Data Hygiene Practices
- **Checksums**: SHA‑256 hashes of `trajectories.json` and `simulation_results.csv` are recorded in `state/projects/PROJ-920-llmxive-follow-up-extending-masking-stal.yaml`.  
- **Immutability**: Raw trajectory file is never overwritten; analysis scripts read it read‑only and write derived artifacts to new files.  
- **No PII**: All data are synthetic; no personally identifying information can arise.
