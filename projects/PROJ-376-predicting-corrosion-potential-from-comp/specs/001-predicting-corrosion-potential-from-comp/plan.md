# Implementation Plan: Predicting Corrosion Potential from Composition and Environment

**Branch**: `001-predict-corrosion-potential` | **Date**: 2024-05-21 | **Spec**: [spec.md]
**Input**: Feature specification from `/specs/001-predict-corrosion-potential/spec.md`

## Summary

This project implements a reproducible machine learning pipeline to predict corrosion potential (mV vs SHE) from alloy composition (elemental weight fractions) and environmental conditions (pH, temperature). The system ingests data from public sources (NIST-IR-8200 primary, OpenCorrosion fallback), enforces strict schema validation (rejecting runs with < 500 records), and trains Random Forest and Gradient Boosting models using a "Leave-One-Specific-Alloy-Out" split (or GroupKFold fallback) to ensure generalization to unseen alloys. Statistical rigor is maintained via permutation tests with FDR correction for feature importance.

## Technical Context

**Project Type**: data-science-research-pipeline  
**Performance Goals**: Total execution ≤ 6 hours; Model training ≤ 30 minutes per model  
**Constraints**: No synthetic data fallback (unless primary and fallback sources fail); Halt on < 500 valid records; Strict CPU-first execution  
**Scale/Scope**: ~500-2000 records; ~10-50 alloy designations

## Constitution Check

*GATE: Must pass before Phase 0 research.*

| Principle | Verification Strategy |
| :--- | :--- |
| **I. Reproducibility** | All scripts in `code/` will use pinned random seeds (`config/seeds.yaml`). The seed configuration is explicitly linked to the versioning discipline: `state/projects/PROJ-376-predicting-corrosion-potential-from-comp.yaml` will be updated upon any artifact change. External data sources are defined by URL (if available) or specific loader names. The `data/` directory will contain checksums of all raw and derived files. |
| **II. Verified Accuracy** | Citations in `research.md` will be limited to the verified dataset block or standard literature (ASTM G59-16). The pipeline will attempt to access NIST-IR-8200, then OpenCorrosion, and halt if both fail or yield < 500 records; it will NOT invent URLs for unverified sources. |
| **III. Data Hygiene** | Raw data downloads will be stored in `data/raw/` with SHA256 checksums recorded in `state/`. No in-place modification; all preprocessing writes to `data/processed/`. |
| **IV. Single Source of Truth** | All metrics in `research.md` and the final report will be derived from the `data/` artifacts generated by `code/`. No hand-typed numbers. |
| **V. Versioning Discipline** | Every artifact change updates `state/projects/PROJ-376-predicting-corrosion-potential-from-comp.yaml`. Content hashes will be computed for all output schemas. |
| **VI. Composition-Environment Feature Integrity** | Feature engineering will strictly use Centred Log-Ratio (CLR) transformed elemental weight fractions and encoded environmental variables (pH, temp, category). No microstructural proxies will be introduced. |
| **VII. Leakage-Aware Validation** | The split strategy will be explicitly "Group Split" by `specific_alloy_designation` (Leave-One-Specific-Alloy-Out). If < 15 alloys, GroupKFold(k=5) is used. The code will assert zero overlap between train/test alloy IDs before training. Grouping by alloy family is prohibited. |
