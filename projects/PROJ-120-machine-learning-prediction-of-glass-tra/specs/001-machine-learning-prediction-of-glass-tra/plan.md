# Implementation Plan: Machine Learning Prediction of Glass Transition Temperature from Composition

## Summary

This feature implements a machine learning pipeline to predict the glass transition temperature ($T_g$) of oxide glasses using *only* compositional descriptors. The system ingests raw oxide glass composition data from a **verified open source** (Zenodo DOI: 10.17188/1271234), parses chemical formulas into atomic fractions using `pymatgen`, and generates a feature matrix including network-former ratios (Si, B, P), modifier content (Na, K, Ca), average electronegativity, and valence electron counts. It trains Random Forest and Gradient Boosting models, comparing their performance against a physics-based linear mixing rule baseline (using a strict stoichiometric conversion algorithm) to quantify the predictive ceiling of composition alone. The pipeline adheres to strict resource constraints (CPU-only, ≤7 GB RAM), ensures reproducibility via fixed random seeds and checksummed data, and employs SHAP values for interpretability to correctly handle compositional constraints.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| **Stoichiometric Conversion Algorithm** | Required by the Linear Mixing Baseline. | Elemental fractions (Si, O, Na) must be mapped to oxide mole fractions (SiO2, Na2O). A simple sum is insufficient; a prioritized algorithm is needed to handle excess oxygen and mixed cations. |
| **SHAP Interpretability** | Required to handle compositional constraints correctly. | Standard permutation importance breaks the sum-to-one constraint and introduces covariate shift. SHAP (TreeExplainer) correctly handles feature interactions and dependencies in tree models. |
| **Bootstrap Fallback (N < 50)** | Required for statistical validity with small samples. | 2-3 fold CV variance is unstable. Bootstrap resampling provides robust confidence intervals. for descriptive estimation when hypothesis testing is underpowered. |
| **Domain Validity Check** | Required to ensure dataset comparability. | If the fallback dataset has a different composition distribution (e.g., phosphate vs. silicate), the baseline comparison is invalid. The check ensures domain alignment before training. |


## Data Acquisition & Featurization Details

1.  **Source**: Zenodo DOI: 10.17188/1271234 (Verified Open Source).
2.  **Parsing**: `pymatgen` `Composition` class. Invalid formulas are excluded.
3.  **Featurization**:
    *   **Elemental Properties**: Calculated via `matminer` `ElementProperty` (Electronegativity, Atomic Mass, Valence).
    *   **Custom Ratios**: Network former (Si, B, P) and modifier (Na, K, Ca) fractions calculated as custom post-processing steps (not generated by `matminer`).
4.  **Domain Check**: Pipeline calculates mean SiO2 fraction. If outside the default valid range, execution halts with a domain mismatch error..

## Model Training & Evaluation Details

1.  **Baseline**: Linear Mixing Rule ($T_g = \sum x_i T_{g,i}$).
    *   **Stoichiometric Conversion**: Algorithm maps elemental fractions to oxides (Si->SiO2, Na->Na2O). Excess O is handled by prioritizing modifiers.
    *   **Missing $T_g$**: If a pure oxide $T_g$ is undefined, the sample falls back to the dataset mean $T_g$ for that baseline calculation.
2.  **ML Models**: Random Forest and Gradient Boosting.
3.  **Evaluation**:
    *   **Split**: -fold Cross-Validation (or Bootstrap if N < 50).
    *   **Paired Test**: Paired t-test on **residuals** (MAE) of ML vs. Baseline on the **same** folds.
    *   **Small N (< 50)**: Skip t-test. Use Bootstrap (sufficient iterations) to generate confidence intervals for R² and MAE.
4.  **Interpretability**: SHAP values (TreeExplainer) to rank feature importance.
