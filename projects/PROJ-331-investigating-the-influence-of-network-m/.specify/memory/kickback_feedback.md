## Unresolved concerns

- The research question is phrased as *‘Do specific 3‑node and 4‑node network motif configurations in structural brain connectomes **constrain** individual variation in resting‑state functional connectivity (rsFC) strength and global efficiency…’* This wording implies a causal influence, whereas the planned analysis is purely correlational (partial Pearson/Spearman with a disclaimer that findings are associational). The mismatch risks overstating the inferential scope of the study.
- Success Criterion SC‑006 (results.json generation and contract validation) is traced to task T018 in the FR/SC Traceability table, but task T018 does not appear in the concrete Task List. Consequently there is no implemented step that produces `results.json` and runs the contract tests, leaving SC‑006 unbacked.
- The plan states it will perform deterministic tractography from *raw diffusion volumes* streamed from the HuggingFace parquet datasets (e.g., `https://huggingface.co/datasets/7eu7d7/HCP-Diffusion-datas/...`). However, these HuggingFace datasets provide pre‑processed diffusion-derived features in parquet format, not the original DWI NIfTI volumes required for tractography. Using them for tractography would be impossible, making the dataset inappropriate for the core structural‑connectome step (FR‑002). Replace the cited source with a dataset that supplies the raw diffusion images (e.g., the HCP 1200‑Subject Release via ConnectomeDB) or adjust the pipeline to work from already‑tractographed streamlines.
- The plan never exercises the `contracts/analysis_results.schema.yaml` contract. No task creates or validates an artifact that conforms to this schema, leaving the contract untested.
- The data model defines a `StructuralConnectome` metadata JSON (see `contracts/structural_connectome.schema.yaml`), but the plan only creates `structural.npy` and never generates the required metadata file or validates it against the schema.
- The Constitution Principle V (Versioning Discipline) requires that every artifact’s content hash be recorded in the project’s state YAML. The plan mentions “content hashes recorded automatically” but does not specify where or how this is done, making the SSoT for versioning ambiguous.
- The plan states that Bonferroni correction is applied across **32 primary tests** (8 motifs × 2 metrics × 2 correlation types). However, the structural motif enumeration includes **13 distinct undirected motifs** (4 three‑node + 9 four‑node classes). The correct number of tests should be 13 × 2 × 2 = 52. Using an incorrect denominator inflates the family‑wise error rate, making any reported “significant” findings potentially false positives. This also propagates to the power‑analysis module, which uses α = 0.05/32 instead of the appropriate α = 0.05/52.
- Relatedly, the plan repeatedly refers to “8 motifs” (e.g., in the FR‑005 description and the correlation task list). This contradicts the motif enumeration step (FR‑004) that enumerates **all** 3‑node (4 classes) and 4‑node (9 classes) motifs. The inconsistency suggests a mis‑specification of the predictor set, which undermines the validity of the statistical inference.
- The plan includes structural global degree as a covariate while also using motif z‑scores derived from the same structural connectome as predictors. Controlling for a summary statistic of the same network may over‑adjust the model, potentially removing variance that motifs capture and reducing statistical power. A more principled approach would either (a) omit structural degree as a covariate or (b) include it only if theoretical justification exists, and report the impact of its inclusion.
