# Implementation Plan: llmXive follow-up: extending "PhysisForcing: Physics Reinforced World Simulator for Robotic Manipula"

## Summary

This project implements a "physics-first" data curation pipeline for robotic manipulation video generation. The core hypothesis is that applying a lightweight, post-generation physics-consistency filter (using PyBullet) to synthetic videos generated by the Wan2.1 model yields a dataset of sufficient quality that a distilled diffusion model trained *only* on this curated data achieves physical consistency comparable to models trained with expensive physics-informed joint optimization. The plan covers three phases: () Generation and CPU-based filtering to create a high-consistency dataset (with GPU offload for generation), () Training a distilled diffusion model of reduced parameter scale on CPU (frame-based), and (3) Evaluating the model against PhysisForcing and unfiltered baselines using R-Bench and PAI-Bench, including statistical equivalence testing (TOST).

**Spec Traceability**:
- **FR-003**: Discard bottom [deferred] (retain top [deferred]) based on physics score (Constitution Principle VI, source).
- **FR-009**: Data augmentation applied if curated count < 30, with non-parametric statistical fallback.
- **FR-006**: TOST equivalence test with a pre-defined equivalence margin, requiring n >= 30 unique samples or non-parametric alternative.
- **FR-008**: Dual engine (PyBullet/MuJoCo) used for metric diversity (continuity vs. pose error), not just engine independence.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Dual Physics Engine (PyBullet + MuJoCo) | FR-008 requires independence validation; PyBullet is for fast filtering (continuity), MuJoCo for robust validation (pose error). | Using only one engine risks circular correlation (Principle VII) and fails the orthogonality gate. |
| TOST Statistical Testing | SC-003 requires equivalence testing (≤15% margin), not just difference testing. | Standard t-tests cannot prove equivalence; TOST is the scientific standard for this hypothesis. |
| CPU-First with GPU Escape Hatch | Compute constraints (7GB RAM) prevent full-scale GPU training; however, video generation requires CUDA. | A fake CPU approximation of a GPU model would be fabrication. The plan uses CPU-tractable large-scale models (frame-based); if generation fails, the GPU escape hatch (Kaggle) is the only honest alternative. |
| Non-Parametric TOST | R-Bench/PAI-Bench may yield binary/proportional data. | Standard TOST assumes normality; non-parametric bootstrap ensures validity for small samples. |
