# Data Model: llmXive follow-up: extending "Trust Region Policy Distillation"

## Overview

This document defines the data structures, schemas, and storage formats used in the `001-llmxive-topd-extension` feature. The data model supports the generation of synthetic reasoning paths, the logging of training episodes, and the statistical analysis of reasoning collapse using a Two-Part Model.

## Core Entities

### 1. Reasoning Problem (Input)
Represents a single synthetic logic puzzle generated by the `ReasoningMDP`.

*   **Fields**:
    *   `problem_id`: Unique identifier (UUID).
    *   `depth`: Target solution depth (integer).
    *   `initial_state`: Serialized representation of the starting state.
    *   `ground_truth_path`: List of inference rule IDs (the optimal solution).
    *   `valid_rules`: List of all inference rules applicable in this domain.

### 2. Training Episode (Raw Log)
Records the trajectory of a single student policy execution.

*   **Fields**:
    *   `episode_id`: Unique identifier.
    *   `run_id`: Identifier for the specific experimental configuration (e.g., `alpha_0.5_horizon_4`).
    *   `alpha`: Interpolation coefficient used.
    *   `student_horizon`: Max steps allowed for this student.
    *   `teacher_depth`: Target depth of the problem.
    *   `steps_executed`: Number of steps the student took before stopping.
    *   `effective_depth`: Calculated depth of the solution found (capped at `student_horizon`).
    *   `is_solved`: Boolean (1 if solution found, 0 otherwise).
    *   `is_censored`: Boolean (1 if `effective_depth == student_horizon`, indicating mechanical truncation).
    *   `is_collapse`: Boolean (1 if `effective_depth <= 0.5 * teacher_depth` AND `is_solved`).
    *   `loss_trace`: List of loss values over the episode (for stability calculation).
    *   `final_loss`: The loss value at the end of the episode.

### 3. Experiment Configuration (Metadata)
Defines the parameters for a batch of runs.

*   **Fields**:
    *   `config_id`: Unique identifier.
    *   `alpha`: Float.
    *   `student_horizon`: Integer.
    *   `num_episodes`: Integer (target count, e.g., 200).
    *   `seed`: Integer (random seed for reproducibility).
    *   `timestamp`: ISO 8601 timestamp of creation.

### 4. Analysis Result (Aggregated)
The output of the Two-Part Model (Logistic + OLS) and sensitivity analysis.

*   **Fields**:
    *   `analysis_id`: Unique identifier.
    *   `config_id`: Reference to the experiment config.
    *   `collapse_interaction_p_value`: Float (from Logistic Regression).
    *   `collapse_interaction_coefficient`: Float.
    *   `depth_interaction_p_value`: Float (from OLS, uncensored subset).
    *   `collapse_rate`: Float (fraction of episodes collapsed).
    *   `mean_effective_depth`: Float (of uncensored, solved episodes).
    *   `stability_metric`: Float (variance of loss).
    *   `model_fit_logistic`: String (AIC/BIC for logistic model).
    *   `model_fit_ols`: String (AIC/BIC for OLS model).

## Storage Format

*   **Raw Logs**: Stored as **Parquet** files in `data/raw/` for efficient columnar access during analysis.
    *   Filename pattern: `episodes_{run_id}_{timestamp}.parquet`
*   **Configuration**: Stored as **JSON** in `data/configs/`.
    *   Filename pattern: `config_{config_id}.json`
*   **Results**: Stored as **CSV** in `data/processed/` for easy plotting.
    *   Filename pattern: `results_{analysis_id}.csv`

## Data Flow

1.  **Generation**: `ReasoningMDP` generates a problem $\rightarrow$ `TrainingRunner` executes student policy $\rightarrow$ `Episode` record created.
2.  **Filtering**: `AnalysisRunner` filters episodes for OLS (must be `is_solved == True` AND `is_censored == False`).
3.  **Aggregation**: `Episode` records are batched by `run_id` $\rightarrow$ `AnalysisRunner` runs Two-Part Model $\rightarrow$ `AnalysisResult` created.
4.  **Storage**: `AnalysisResult` written to `data/processed/`.

## Constraints & Validations

*   **Determinism**: All random seeds must be recorded in the `Experiment Configuration` and applied to the `ReasoningMDP` and `StudentPolicy`.
*   **Censoring Logic**: `is_censored` is strictly derived from `effective_depth == student_horizon`.
*   **Completeness**: `is_collapse` must be derived strictly from `effective_depth` and `teacher_depth` according to the spec (FR-006).
*   **OLS Filter**: OLS analysis must exclude any episode where `is_solved == False` or `is_censored == True` to prevent circularity.
