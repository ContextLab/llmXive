## Summary

This project investigates the association between structural connectivity (dMRI-derived) and functional synchrony (rs-fMRI-derived) in the human brain. Due to data availability constraints (verified source is a Parquet shard), the implementation **exclusively uses "Pre-computed Mode"**, loading available connectivity matrices rather than performing raw tractography. The pipeline downloads a subset of the **OpenNeuro ds000224** (HCP Young Adult) matrices for up to **10 subjects**, computes node-level centrality and synchrony metrics, and performs a **subject-level** correlation analysis.

**Critical Statistical Clarification**: The primary analysis correlates node-level metrics (400 nodes) **aggregated per subject** across the 10 subjects. The unit of analysis is the **subject** (N=10), not the node (N=400). 
- **Power Limitation**: With N=10, statistical power is limited to detecting only massive effect sizes (rho > 0.8). Results will be framed as "preliminary and associational."
- **Null Distribution Coarseness**: The permutation test (shuffling subject IDs) with N=10 yields a discrete null distribution. With a limited number of permutations, the p-value resolution is coarse. This limitation is explicitly acknowledged.
- **Spatial Autocorrelation**: To address node non-independence, the plan prioritizes a **Spatial Null Model** (e.g., BrainSMASH/spin tests). If unavailable, subject-level permutation is used with a warning about potential Type I error inflation.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| **Subject-Level Permutation (N=10)** | Required to avoid Type I error inflation from treating 400 nodes as independent. | Node-level shuffling is statistically invalid for connectomics due to spatial autocorrelation. |
| **Spatial Null Model (BrainSMASH)** | Required to preserve spatial autocorrelation in the null distribution. | Simple vector shuffling assumes node independence which does not exist in brain networks. |
| **Threshold Sensitivity Sweep** | Required by FR-007 to ensure robustness of graph topology assumptions. | A single threshold would introduce arbitrary bias; the sweep validates the stability of the structure-function relationship. |
| **Strict Storage Management** | Required by GitHub Actions 14 GB limit for 10 subjects. | A naive "download all then process" approach would exceed disk limits; streaming and immediate cleanup are mandatory. |
| **Power Limitation Acknowledgement** | Required by statistical reality of N=10. | Pretending N=10 has high power would be scientifically dishonest. The plan frames results as preliminary. |

## Sensitivity Analysis Protocol (FR-007)

To satisfy FR-007, the `analyze.py` script will:
1.  Sweep structural graph threshold density over a range of low values.
2.  For each threshold, compute the Spearman correlation (rho) between centrality and synchrony.
3.  Calculate the **Stability Index** (standard deviation of rho across thresholds) and the **Area Under the Curve (AUC)** of the rho-threshold plot.
4.  Report the correlation at each threshold, the Stability Index, and the AUC in `data/results/analysis_results.json`.
5.  Avoid "p-hacking" by pre-defining the thresholds and the aggregation metric (Stability Index + AUC) in the plan.

## Success Metric Logging (SC-001)

To satisfy SC-001, the pipeline will:
1.  Track the number of successfully processed subjects.
2.  Calculate the proportion: `processed / target` (e.g., 9/10).
3.  Write this to `data/results/processing_summary.json` with fields: `target`, `processed`, `skipped`, `proportion`.

## Statistical Power & Limitations

- **Sample Size**: N=10 subjects.
- **Power**: With N=10, the power to detect effects smaller than rho > 0.8 is negligible. The permutation test (shuffling a set of items) yields a discrete null distribution with only 10! possible permutations (sampled at 1000). The p-value resolution is coarse.
- **Framing**: Results will be explicitly framed as "preliminary and associational." A non-significant result is treated as a valid primary finding (Principle VII).
- **Unit of Analysis**: The correlation is performed across **subjects** (N=10), not nodes (N=400). A set of nodes is aggregated per subject to create the input vectors for the correlation. This avoids the spatial autocorrelation violation.

## Data Gap Protocol

If the verified dataset URL (Parquet) lacks pre-computed SC/FC matrices:
1.  **Attempt to load** the Parquet.
2.  **If Parquet contains pre-computed SC/FC matrices**: Proceed with analysis.
3.  **If Parquet lacks required data**: Halt with a "Data Gap" error. Do not fabricate data or invent a new URL.
4.  **Log**: The error is logged in `data/results/processing_summary.json` with reason "Data Gap: Pre-computed matrices missing".
