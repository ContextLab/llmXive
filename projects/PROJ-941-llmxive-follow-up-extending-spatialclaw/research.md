# Research Report: llmXive Follow-up – Extending SpatialClaw

## 1. Introduction

This research investigates the performance implications of restricting agentic spatial reasoning to a 2D action space, as defined by the "SpatialClaw" benchmark. The study compares a restricted 2D agent (using only `shapely` and `numpy`) against a full 3D baseline (using `trimesh`/`pytorch3d`) on a synthetic dataset designed to exhibit information loss during 2D projection.

## 2. Methodology

### 2.1 Experimental Design
The study employs a **paired experimental design** to isolate the effects of action space restriction.
- **Dataset**: "Synthetic SpatialClaw Proxy" (`data/raw/synthetic_spatialclaw_v1.json`), generated via `code/data/generator.py`.
- **Conditions**:
 1. **Baseline (3D)**: Full 3D geometric reasoning capabilities.
 2. **Restricted (2D)**: Action space limited to 2D projections; 3D libraries blocked at the kernel level.
- **Task Types**: Occlusion detection, Depth estimation, and Relative positioning.
- **Sample Size**: Determined by power analysis (see Section 2.2).

### 2.2 Power Analysis & Budget Validation
Prior to data generation, a power analysis was conducted to determine the minimum sample size ($N$) required to detect a medium effect size ($d = 0.5$) with 80% power ($\beta = 0.2$) at $\alpha = 0.05$.
- **Configuration**: Defined in `data/power_config.yaml`.
- **Result**: The analysis calculated a required sample size of $N_{req}$.
- **Budget Check**: The estimated runtime for $N_{req}$ was validated against the 6-hour compute budget in `code/utils/budget_check.py`. Execution aborted if the budget was exceeded.
- **Output**: `results/analysis/power_analysis_summary.json`.

### 2.3 Data Generation & Stochasticity Control
- **Generator**: `code/data/generator.py` creates task instances with randomized 3D primitives (cubes/spheres).
- **Stochasticity**: To ensure reproducibility and allow for variance analysis, a master seed is derived from `master_seed + run_id`.
- **Reproducibility**: The pipeline enforces fixed seeds (`numpy`, `random`, `torch`) and temperature=0 for all LLM calls via `code/utils/reproducibility.py`.
- **Runs**: Each task instance is executed $N_{runs} \ge 5$ times to capture variance.

### 2.4 Execution Kernel & Restrictions
The 2D agent operates within a **Restricted Kernel** (`code/kernel/restricted_kernel.py`) that:
- Intercepts imports and blocks libraries: `trimesh`, `pytorch3d`, `open3d`.
- Allows only 2D-safe libraries: `shapely`, `numpy`, `scipy`.
- Logs blocked operations and their latency overhead to `results/logs/execution.log`.

### 2.5 Metric Collection
Performance metrics are collected via `code/metrics/collector.py`:
- **Success Rate**: Binary outcome (1/0) per task.
- **Latency**: Wall-clock time per step, with **effective latency** calculated as `total_time - blocked_time_ms` to exclude kernel overhead.
- **Paired Comparison**: Results from both agents are matched by `task_id` and `seed` in `results/analysis/paired_comparison.csv`.

### 2.6 Statistical Analysis
Statistical significance is determined using `code/stats/tests.py`:
- **Binary Outcomes**: McNemar's test for paired proportions (success/failure).
- **Continuous Metrics**: Wilcoxon signed-rank test for latency and error differences.
- **Correction**: Bonferroni correction applied for multiple comparisons across task types (occlusion, depth, relative).

### 2.7 Sensitivity Analysis
A sensitivity analysis was performed on depth-estimation thresholds (`code/stats/sensitivity.py`):
- **Sweep**: Thresholds varied from low to high magnitudes.
- **Metrics**: False Positive Rate (FP) and False Negative Rate (FN) calculated against ground truth (`gt_3d_is_occluded`).
- **Flat Objects**: Specific handling for tasks with near-zero depth variance to identify projection loss failures.
- **Output**: `results/analysis/sensitivity_report.csv`.

### 2.8 Failure Attribution
Failures on the 2D agent are explicitly classified using `code/stats/sensitivity.py`:
- **Categories**: "projection_loss", "action_restriction", "other".
- **Logic**: Failures on flat objects where the 3D baseline succeeded are attributed to "projection_loss".
- **Log**: Detailed failure analysis recorded in `results/logs/failure_analysis.log`.

## 3. Results Summary

*Note: The following sections describe the structure of the results produced by the pipeline.*

### 3.1 Power Analysis
- **File**: `results/analysis/power_analysis_summary.json`
- **Content**: `n_required`, `estimated_runtime`, `budget_status`.

### 3.2 Paired Comparison
- **File**: `results/analysis/paired_comparison.csv`
- **Columns**: `task_id`, `task_type`, `success_flag`, `wall_clock_time_ms`, `agent_type`.
- **Aggregation**: Mean success rates calculated per task type for both 2D and 3D agents.

### 3.3 Statistical Significance
- **File**: `results/analysis/statistical_summary.json` (generated by `code/stats/tests.py`)
- **Content**: P-values for McNemar's and Wilcoxon tests, with Bonferroni-corrected significance flags.

### 3.4 Sensitivity Analysis
- **File**: `results/analysis/sensitivity_report.csv`
- **Columns**: `threshold_value`, `false_positive_rate`, `false_negative_rate`.
- **Insight**: Identifies the threshold range where 2D projection loss significantly degrades performance.

### 3.5 Failure Attribution
- **File**: `results/logs/failure_analysis.log`
- **Content**: JSON lines detailing specific `task_id` failures, their classification, and geometric context.

## 4. Conclusion

The methodology establishes a rigorous framework for evaluating the cost of 2D action space restriction in spatial reasoning agents. By enforcing strict kernel restrictions, controlling stochasticity, and utilizing paired statistical tests, the study isolates the performance degradation attributable solely to the loss of 3D geometric information. The sensitivity analysis further quantifies the specific conditions (e.g., flat objects, depth thresholds) under which the 2D agent fails, providing actionable insights for future agent design.
