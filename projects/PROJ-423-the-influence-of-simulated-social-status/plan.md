# Project Plan: The Influence of Simulated Social Status on Risk-Taking Behavior

## Overview
This project investigates how simulated social status (High vs. Low) influences risk-taking behavior, moderated by observed behavior (Risky vs. Conservative). We employ a mixed-methods approach combining simulation and meta-analysis to ensure robustness and reproducibility.

## Objectives
1. Generate synthetic data based on verified meta-analytic effect sizes.
2. Implement adaptive regression models (Mixed-Effects for within-subjects, Fixed-Effects for between-subjects).
3. Conduct sensitivity analyses and generate reproducible reports.

## User Stories
- **US1**: Data Synthesis and Preprocessing
- **US2**: Adaptive Regression Analysis
- **US3**: Sensitivity Analysis and Reporting

## Phase 0: Research & Data Strategy
- Verify effect size citations.
- Calculate sample size N using power analysis.
- Generate `research.md` with verified effect sizes and N.
- Generate `simulation_parameters.json` with verified parameters.

## Phase 1: Setup & Foundational
- Create directory structure (`data/`, `code/`, `tests/`, `docs/`).
- Create `requirements.txt` with pinned versions.
- Configure `.pre-commit-config.yaml` and `.gitignore`.
- Initialize `data/checksums.json`.
- Implement foundational modules (`logger.py`, `models.py`, `utils.py`).

## Phase 2: User Story 1 - Data Synthesis and Preprocessing
- Implement `simulate.py` for synthetic data generation.
- Implement `preprocess.py` for data cleaning and binning.
- Detect outcome variable type and save to `outcome_type.json`.
- Ensure deterministic output with fixed random seed.

## Phase 3: User Story 2 - Adaptive Regression Analysis
- Implement `analysis.py` with adaptive model selection logic.
- Generate `model_config.json` (single source of truth for design and family).
- Calculate VIF, parameter recovery, and CI width.
- Validate model output against schema.

## Phase 4: User Story 3 - Sensitivity Analysis and Reporting
- Implement sensitivity sweep over outlier thresholds {2.5, 3.0, 3.5}.
- Perform post-hoc pairwise comparisons with Bonferroni correction.
- Generate forest plot and final report (HTML/PDF).
- Validate report structure against schema.

## Contract Mapping
- **Model Configuration**: The file `data/processed/model_config.json` serves as the single source of truth for design type, family type, and number of subjects. This file is generated by T021b and consumed by T021a.
- **Alias Note**: The plan previously referenced `structure_config.json`. Per T021c, `structure_config.json` is generated as an alias (copy) of `model_config.json` to maintain backward compatibility with any legacy references in the plan or contracts. The primary configuration source is `model_config.json`.
- **Model Output**: `data/processed/model_output.json` contains coefficients, p-values, VIF, CI bounds, and parameter recovery.
- **Report Schema**: `contracts/report_schema.yaml` defines the structure of the final report.

## Complexity Tracking
- **Sensitivity Sweep**: Thresholds {2.5, 3.0, 3.5} (Corrected from {3.0, 3.5}).
- **Model Complexity**: Target max cyclomatic complexity < 10 for all functions.
- **Performance**: Full pipeline must complete within configured time limit.

## Assumptions
- Meta-analytic effect sizes are available and verified.
- Simulation parameters are derived from verified sources.
- Real data fetch fails loudly if source is unreachable.

## Risks & Mitigations
- **Risk**: Meta-analysis data unavailable.
 - **Mitigation**: Fall back to simulation path (T010c/T010d).
- **Risk**: Model convergence issues.
 - **Mitigation**: Use asymptotic standard errors as fallback (T024).
- **Risk**: High multicollinearity.
 - **Mitigation**: Flag VIF > 5.0 and report in output (T022).
