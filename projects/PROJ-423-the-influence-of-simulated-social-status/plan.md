# Project Plan: The Influence of Simulated Social Status on Risk-Taking Behavior

## Overview
This project investigates the relationship between simulated social status and risk-taking behavior using a "Simulation-First" approach. The pipeline generates synthetic data based on meta-analytic effect sizes, preprocesses it, fits adaptive regression models, and generates a comprehensive report.

## Core Philosophy: Simulation-First Approach
The project adopts a **Simulation-First** methodology. Instead of attempting to aggregate raw, heterogeneous real-world datasets which may suffer from inconsistent measurement protocols, we generate a synthetic dataset that strictly adheres to the validated effect sizes extracted from peer-reviewed literature. This ensures:
1. **Parameter Fidelity**: The injected interaction effects are known ground truth, allowing for rigorous validation of the statistical pipeline (Parameter Recovery).
2. **Design Control**: Experimental conditions (High/Low Status, Risky/Conservative Behavior) are perfectly balanced and variance-controlled.
3. **Reproducibility**: The entire dataset is deterministic given a random seed, enabling exact replication of results.

## Single Source of Truth
The file `code/simulation_parameters.json` serves as the **Single Source of Truth** for all simulation parameters. It is generated by the research phase (T000h) and contains:
- `injected_interaction_effect`: The hypothesized effect size (Cohen's d) derived from verified citations.
- `sample_size`: The calculated N required for 80% power.
- `random_seed`: The seed for deterministic generation.
- `ci_width_warning_threshold`: The threshold for CI width validation.
- `design_type`: The experimental design structure.
- `data_source`: Set to "simulation" for this pipeline.

All downstream scripts (`simulate.py`, `analysis.py`) must read parameters from this file rather than hardcoding values.

## Workflow Phases

### Phase 0: Research & Data Strategy
- Verify citations from `sources_list.md` using `crossref`.
- Extract effect sizes and calculate required sample size (Power Analysis).
- Generate `research.md` and `code/simulation_parameters.json`.

### Phase 1: Setup & Foundational
- Initialize directory structure (`data/`, `code/`, `tests/`).
- Pin dependencies and setup linting.
- Define data models and schemas.

### Phase 2: User Story 1 - Data Synthesis & Preprocessing
- **Simulation**: Generate `data/raw/simulated_data_effect.csv` and `data/raw/simulated_data_null.csv` using `code/simulate.py` and parameters from `code/simulation_parameters.json`.
- **Preprocessing**: Clean data, map categories, handle missing values, and detect outcome type.
- **Output**: `data/processed/cleaned_data_effect.csv`, `data/processed/cleaned_data_null.csv`, `data/processed/outcome_type.json`.

### Phase 3: User Story 2 - Adaptive Regression Analysis
- **Design Detection**: Automatically detect between-subjects vs. within-subjects design.
- **Model Fitting**: Fit Mixed-Effects or Fixed-Effects models based on detected design.
- **Validation**: Calculate VIF, Parameter Recovery, and CI Width.
- **Output**: `data/processed/model_output_effect.json`, `data/processed/model_output_null.json`.

### Phase 4: User Story 3 - Sensitivity Analysis & Reporting
- **Sensitivity**: Sweep outlier thresholds to test robustness.
- **Reporting**: Generate forest plots, HTML/PDF reports with traceability.
- **Output**: `reports/analysis_report.html`, `data/processed/sensitivity_analysis.csv`.

## Key Constraints
1. **No Fabrication**: All reported metrics must be the result of actual computation on the generated data.
2. **Strict Validation**: Scripts must halt on data integrity errors (e.g., missing values in `participant_id`, duplicate IDs).
3. **Traceability**: The final report must link statistical results back to specific code functions and data rows.
4. **Simulation Parameters**: The `code/simulation_parameters.json` file is the authoritative source for effect sizes and sample sizes. No hardcoded values are permitted in `simulate.py` or `analysis.py`.

## Execution
Run the full pipeline via `python code/quickstart_runner.py` (or per `quickstart.md`):
1. `python code/simulate.py`
2. `python code/preprocess.py --input... --output...`
3. `python code/analysis.py`
4. `python code/report.py`
