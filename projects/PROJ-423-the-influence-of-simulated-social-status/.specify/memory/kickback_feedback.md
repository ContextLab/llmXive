## Unresolved concerns

- The `data-model.md` defines a `participant_id` as an integer, but the contract schemas (`contracts/data.schema.yaml`, `contracts/dataset.schema.yaml`, `contracts/dataset_schema.schema.yaml`) define it as a string. This discrepancy needs resolution to ensure data consistency across components.
- The plan states "Limited RAM (~7GB) and disk space (~14GB).", but doesn't explicitly address how the simulation or meta-analysis will handle datasets exceeding these limits. This is a critical constraint that needs to be addressed in the plan, potentially through chunking strategies or sampling techniques as mentioned in `research.md`.
- The `research.md` lists several datasets (VIF, NOT, Answerable-or-Not) as examples for schema validation and preprocessing inspiration. However, the plan doesn't explicitly state how these example datasets will be used or if they are representative of the final data source. Clarification is needed to understand their role in the project.
- The `model_output.schema.yaml` includes a field `sensitivity_analysis` which is an array of objects with properties like `threshold_sd`, `interaction_p_value`, and `interaction_coefficient`. However, the plan doesn't detail how these sensitivity analysis results will be stored or used beyond mentioning that it will be conducted. The schema implies a specific output format that needs to be explicitly linked to the plan’s deliverables.
- The `quickstart.md` states "The data will be automatically generated or downloaded... No manual data preparation is required". This statement seems overly optimistic given the complexity of potential meta-analysis and the need for cleaning/preprocessing described in other documents. A more nuanced description acknowledging potential manual steps (e.g., verifying dataset integrity) would be beneficial.
- FR-007 states "Every figure, statistic, or interpretation in the paper MUST trace back to exactly one row in this project's data/ and one block in this project's code.". The plan does not explicitly detail how traceability will be enforced during analysis. A mechanism for linking results back to source data and code is crucial for reproducibility and needs to be outlined.
- Constitution Principle VII emphasizes standardized risk metric adherence, but the plan doesn't detail *how* this will be ensured during data generation/aggregation or preprocessing. Specifying a clear process for verifying instrument documentation and adhering to established measures is needed.
