# Data Model: Simulated Social Status & Risk-Taking

## Overview
This document defines the data structures, schemas, and transformations for the project. The primary data source is a **simulated dataset** generated to test the interaction between social status and observed behavior on risk-taking.

## Data Flow
1. **Power Analysis**: `code/power_analysis.py` calculates the required N.
2. **Generation**: `code/simulate.py` creates a raw CSV with random assignments and outcomes.
3. **Preprocessing**: `code/preprocess.py` cleans data, handles missing values, and bins variables.
4. **Analysis**: `code/analysis.py` fits models (OLS or LMM based on design), calculates VIF, and generates summary statistics.
5. **Reporting**: `code/report.py` generates plots and final tables.

## Raw Data Schema (`data/raw/simulation_output.csv`)
Generated by `simulate.py`.

| Column | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `participant_id` | int | Unique ID | Unique, > 0 |
| `status_level` | str | Status of observed agent | "High", "Low" |
| `observed_behavior` | str | Behavior of observed agent | "Risky", "Conservative" |
| `risk_taking_score` | float | Outcome score | >= 0 |
| `condition_seed` | int | Seed used for this participant | > 0 |

## Processed Data Schema (`data/processed/cleaned_data.csv`)
Generated by `preprocess.py`.

| Column | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `participant_id` | int | Unique ID | Unique |
| `status_level` | categorical | Factor (High/Low) | Levels: ["High", "Low"] |
| `observed_behavior` | categorical | Factor (Risky/Conservative) | Levels: ["Risky", "Conservative"] |
| `risk_taking_score` | float | Cleaned outcome | No NaN (imputed or excluded) |
| `is_outlier` | bool | Flag for outlier (based on 3.0 SD) | True/False |

## Configuration Artifacts

### `data/processed/structure_config.json`
**Generated Dynamically** by `code/analysis.py` (function `validate_data_structure`).
- **Generation Logic**: The script loads `data/processed/cleaned_data.csv`, counts unique `participant_id`s, and checks if any ID has multiple rows (indicating within-subjects).
- **Fields**:
  - `type`: "between-subjects" or "within-subjects" (Determined by checking if `participant_id` has multiple rows per condition).
  - `n_subjects`: Integer count of unique participants.
- **Constraint**: **NO** `n_observations` field. Only `type` and `n_subjects`.
- **Single Source of Truth**: This file is **not hardcoded**. It is a direct computation from the processed data, ensuring the configuration always matches the actual data reality (Constitution Principle IV).

### `code/config.py`
Holds simulation parameters:
- `RANDOM_SEED`: Integer.
- `N_PARTICIPANTS`: Integer (target, calculated by power analysis).
- `EFFECT_SIZES`: Dictionary of hypothesized effects.
- `OUTLIER_THRESHOLDS`: List [2.5, 3.0, 3.5].

## Data Hygiene Rules
- **Checksums**: All files in `data/raw/` and `data/processed/` must be checksummed (SHA-256) and recorded in the project state.
- **Immutability**: Raw data is never modified. Preprocessing writes to new files.
- **PII**: No PII is generated or stored.
