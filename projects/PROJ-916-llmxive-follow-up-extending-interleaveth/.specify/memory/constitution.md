# llmXive follow-up: extending "InterleaveThinker: Reinforcing Agentic Interleaved Generation" — Research Project Constitution

## Core Principles

### I. Reproducibility (NON-NEGOTIABLE)

Every result reported in this project MUST be reproducible by re-running the
project's `code/` against the project's `data/` on a fresh GitHub Actions
runner. Random seeds MUST be pinned in `code/`. External datasets MUST be
fetched from the same canonical source on every run.

### II. Verified Accuracy (inherits parent Principle II)

Every external citation in `idea/`, `technical-design/`,
`implementation-plan/`, or `paper/` MUST be verified by the
Reference-Validator Agent against the primary source before contributing
review points. Title-token-overlap with the cited source MUST be ≥
`CITATION_TITLE_OVERLAP_THRESHOLD` (default 0.7).

### III. Data Hygiene

Datasets MUST be checksummed and the checksum recorded under `data/`. No
data may be modified in place; every transformation MUST produce a new file
with a documented derivation. Personally identifying information MUST NOT
appear in committed data.

### IV. Single Source of Truth (inherits parent Principle I)

Every figure, statistic, or interpretation in the paper MUST trace back to
exactly one row in this project's `data/` and one block in this project's
`code/`. Derived numbers MUST NOT be hand-typed into the paper.

### V. Versioning Discipline

Every artifact under this project carries a content hash. The
Advancement-Evaluator Agent invalidates stale review records when the
hashed artifact changes. Every research-stage artifact change updates this
project's `state/projects/PROJ-916-llmxive-follow-up-extending-interleaveth.yaml` `updated_at` timestamp.

### VI. Modality-Agnostic Structural Validation

The project's primary hypothesis—that reasoning gains stem from structural decomposition rather than visual grounding—requires that the "Generator" agent's output be rigorously validated as a faithful textual proxy for visual data before any reasoning metric is computed. Consequently, the `data/` directory MUST contain a dedicated `simulator_validation/` subdirectory where the JSON scene descriptions generated by the text-only simulator are compared against the original InterleaveThinker image metadata (where available) or a gold-standard textual description set. Any discrepancy in object count, spatial relationship, or attribute accuracy between the simulator output and the ground truth MUST be logged as a `simulator_error_rate` metric in the `data/` checksum record. This principle is grounded in the "Methodology sketch" which explicitly defines the construction of a "deterministic, text-based image description simulator" and the "Expected results" which hinge on the assumption that "text descriptions cannot replicate" visual feedback only if the simulation fidelity is insufficient; without this validation step, the comparison between the text-only simulation and the image-based baseline is invalid.

### VII. Statistical Rigor in Agent Ablation

To isolate the contribution of the iterative Critic loop from the baseline single-pass generation, the project MUST execute a paired statistical analysis (paired t-test or Wilcoxon signed-rank test) on the reasoning scores (accuracy/F1) for every benchmark instance in the WISE and RISE datasets. The `code/` directory MUST include a script that outputs a `statistical_significance_report.md` containing the p-values and effect sizes for the comparison between (1) the full interleaved text-only pipeline and (2) the text-only generator without the Critic feedback step. This requirement is explicitly grounded in the "Methodology sketch" which mandates "Statistical Analysis: Perform paired t-tests or Wilcoxon signed-rank tests... to determine if the difference is statistically significant" and the "Ablation Study" section which aims to "Isolate the contribution of the Critic loop." Failure to provide these specific statistical metrics for the ablation condition will result in the project being deemed inconclusive regarding the structural decomposition hypothesis.

## Reproducibility Requirements

- A `requirements.txt` (or `pyproject.toml`) at `projects/PROJ-916-llmxive-follow-up-extending-interleaveth/code/`
  pins every Python dependency.
- The Code-Execution Agent runs each task in an isolated virtualenv built
  from this requirements file; no global packages are assumed.
- Every notebook or script under `code/` is runnable end-to-end without
  manual intervention.

## Data Hygiene

- Every file under `data/` is checksummed in the project's
  `state/projects/PROJ-916-llmxive-follow-up-extending-interleaveth.yaml` `artifact_hashes` map.
- Raw data is preserved unchanged; derivations are written to new
  filenames.
- No commits are accepted that fail the Repository-Hygiene Agent's PII
  scan.

## Verified Accuracy Gate

The Reference-Validator Agent runs at three points:

1. On every artifact write that introduces or modifies citations.
2. Inside the Advancement-Evaluator before awarding any review point.
3. As a blocking gate on the `research_review` → `research_accepted`
   transition.

A reviewer's score MUST be set to 0.0 if the reviewed artifact has any
citation in `unreachable` or `mismatch` status.
