# Data Model: llmXive follow-up: extending "InterleaveThinker: Reinforcing Agentic Interleaved Generation"

## Overview

This document defines the data structures used throughout the project, ensuring consistency between the simulator, agents, and statistical analysis. All data is stored in JSON or JSONL format for easy streaming and validation.

## Core Entities

### 1. SceneDescription

A structured JSON object representing a visual scene, generated by the text-based simulator.

*   **Source**: `simulator.py` (Perfect/Noisy modes)
*   **Usage**: Input for the Generator and Critic agents.
*   **Fields**:
    *   `objects`: List of objects in the scene.
    *   `relationships`: List of spatial/semantic relationships between objects.
    *   `attributes`: Global attributes of the scene (e.g., lighting, background).
    *   `metadata`: Simulation metadata (mode, error rate, timestamp).

### 2. TrajectoryLog

A record of the complete sequence of Planner, Generator, and Critic steps for a single benchmark sample.

*   **Source**: `pipeline.py`
*   **Usage**: Input for statistical analysis; artifact for reproducibility.
*   **Fields**:
    *   `sample_id`: Unique identifier for the benchmark sample.
    *   `prompt`: Original natural language prompt (caption).
    *   `ground_truth`: **Human-Annotated Scene Graph** (from Visual Genome/GQA). This is the independent ground truth for evaluation.
    *   `simulator_input`: The `SceneDescription` JSON (Perfect or Noisy) generated by the simulator.
    *   `steps`: List of steps (Planner, Generator, Critic) with their outputs and scores.
    *   `final_reasoning_score`: F1-score (or Graph Edit Distance) between Generator Output and `ground_truth`.
    *   `ablation_flag`: Boolean indicating if this was a "No-Critic" run.
    *   `actual_generator_error_rate`: The measured deviation between the Generator's output and the `ground_truth` (for stratification).

### 3. StatisticalReport

The output of the statistical analysis script.

*   **Source**: `stats/analysis.py`
*   **Usage**: `statistical_significance_report.md` generation.
*   **Fields**:
    *   `comparison_type`: e.g., "Full Loop vs. Single-Pass".
    *   `test_method`: e.g., "Wilcoxon signed-rank".
    *   `p_value`: Calculated p-value.
    *   `confidence_interval`: 95% CI for the difference.
    *   `effect_size`: Cohen's d.
    *   `significance`: Boolean (p < 0.05).

## Data Flow

1.  **Download**: Raw datasets (Visual Genome, GQA) are downloaded to `data/raw/` and checksummed.
2.  **Simulate**: `simulator.py` reads prompts from `data/raw/` and outputs `SceneDescription` JSONL to `data/intermediate/scenes/`.
3.  **Validate**: `simulator_validation/` compares `SceneDescription` against **Human-Annotated Scene Graphs**, logging `simulator_error_rate` (Graph Edit Distance).
4.  **Execute**: `pipeline.py` reads `SceneDescription` JSONL, runs the agentic loop, and outputs `TrajectoryLog` JSONL to `data/intermediate/trajectories/`.
5.  **Analyze**: `stats/analysis.py` reads `TrajectoryLog` JSONL, performs statistical tests, and outputs `StatisticalReport` JSON.
6.  **Report**: `statistical_significance_report.md` is generated from `StatisticalReport`.

## Data Hygiene & Checksums

*   All files in `data/raw/` are checksummed (SHA-256) and recorded in `state/projects/PROJ-916-llmxive-follow-up-extending-interleaveth.yaml`.
*   No file in `data/` is modified in place. Derivations are written to new files (e.g., `scenes_v1.jsonl`, `scenes_v2_noisy.jsonl`).
*   PII scanning is performed on all committed data artifacts.
