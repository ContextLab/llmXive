# Quickstart: Battery Degradation Prediction Pipeline

**Status**: code runnable; **result production blocked** pending a verified open battery cycling data source (see plan.md / research.md). No synthetic data is used anywhere (FR‑012).

## Prerequisites

```bash
git clone <repo> && cd <repo>
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Step 1 – Data Ingestion (requires verified data source)

```bash
python -m src.data.ingest --source <verified-battery-archive-endpoint> \
    --output data/raw/ --log-level INFO
```

- Downloads with retry ×3 (60 s backoff), checksums raw files, filters cells with incomplete histories or **fewer than 100 cycles**, and logs the SC‑005 completeness ratio.

## Step 2 – Preprocessing

```bash
python -m src.data.preprocess --input data/raw/ \
    --output data/processed/processed_v1.npz --seed 42
```

- Resamples to 100 timesteps/cycle, normalizes with statistics from the **first 50 cycles only** (FR‑010), builds `(N, 50, 100, 3)` tensors **for cells with ≥ 100 cycles**, and creates protocol‑holdout splits (FR‑011). Cells with < 100 cycles are discarded.

## Step 3 – Training (plain Bi‑LSTM)

```bash
python -m src.model.train --data data/processed/processed_v1.npz \
    --output models/bilstm_v1.pt --max-runtime 1800
```

- CPU‑only plain 2‑layer Bi‑LSTM (64 units each) with early stopping, 30‑min sweep (learning rate, hidden size); fallback defaults with warning.

## Step **4** – Baseline

```bash
python -m src.model.baseline --data data/processed/processed_v1.npz \
    --output models/baseline_v1.pkl
```

- Baseline incremental‑capacity features are **computed only from cycles 1‑50** (FR‑010).

## Step 5 – Evaluation & Uncertainty

```bash
python -m src.model.evaluate --model models/bilstm_v1.pt \
    --data data/processed/processed_v1.npz --output results/predictions.json
```

- R², RMSE, **split‑conformal calibrated** prediction intervals **for [deferred] coverage**, and power analysis (ΔR² = 0.05, α = 0.05) are reported.
- Coverage will be reported **as achieved**; the 0.90 target is a descriptive benchmark.

## Step 6 – Interpretability

```bash
python -m src.interpret.shap_analysis --model models/bilstm_v1.pt \
    --data data/processed/processed_v1.npz --output figures/shap_summary.png

python -m src.interpret.permutation_importance --model models/bilstm_v1.pt \
    --data data/processed/processed_v1.npz --output results/permutation_importance.csv

python -m src.interpret.integrated_gradients --model models/bilstm_v1.pt \
    --data data/processed/processed_v1.npz --output results/ig_attribution.npy

python -m src.interpret.feature_aggregation --shap results/shap_summary.npy \
    --perm results/permutation_importance.csv \
    --ig results/ig_attribution.npy \
    --output results/aggregated_feature_importance.json

python -m src.interpret.literature_mapping --aggregated results/aggregated_feature_importance.json \
    --output results/literature_match_report.txt
```

- `feature_aggregation.py` collapses raw SHAP/permutation/IG importances into per‑cycle/channel summaries and computes **derived early‑cycle signatures** (voltage variance, current slope, temperature fluctuation) that are directly comparable to the literature signatures required by SC‑010.
- `literature_mapping.py` implements the deterministic mapping to literature features (see `data-model.md`).

## Step 7 – Verification (runs today, on fixtures)

```bash
pytest -q tests/contract/ tests/unit/
```
