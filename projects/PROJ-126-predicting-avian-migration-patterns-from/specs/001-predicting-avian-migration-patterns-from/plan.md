# Implementation Plan: Predicting Avian Migration Patterns from Publicly Available eBird Data

**Input**: Feature specification from `/specs/001-predicting-avian-migration/spec.md`

## Summary

This project implements a data pipeline and predictive modeling system to forecast the "first arrival" dates of the American Robin (*Setophaga ruticilla*) within the verified Lake Powell region. The system ingests eBird Basic Dataset (EBD) checklists and MODIS remote sensing data, aligns them on a 0.5° spatiotemporal grid, and derives a target variable based on cumulative observation thresholds. A Gradient Boosting Regressor (XGBoost) is trained using a **purely temporal split** (Train: 2015-2020, Val: 2021, Test: 2022) to predict arrival dates from lagged temperature and NDVI. The plan emphasizes rigorous statistical validation via **Bootstrap Resampling** (replacing the circular LMM approach) and SHAP-based interpretability to disentangle collinear environmental drivers, all executed within the constraints of a CPU-only GitHub Actions runner. The scope is explicitly limited to the verified dataset region to ensure construct validity.

## Constitution Check

*Gates determined based on constitution file:*

1.  **Reproducibility (Principle I)**: The plan mandates pinned `requirements.txt`, random seed setting (42), and explicit data versioning via checksums. The pipeline is designed to be re-runnable from scratch on a fresh runner.
2.  **Verified Accuracy (Principle II)**: All dataset references (EBD, MODIS) are drawn strictly from the "Verified datasets" block provided in the prompt. No external URLs will be invented. Citations in `research.md` will be validated against the primary source.
3.  **Data Hygiene (Principle III)**: The plan enforces a "raw vs. processed" directory structure. Raw data is downloaded once and checksummed. Derived data (aggregated grids) are written as new files. No in-place modification of raw files.
4.  **Single Source of Truth (Principle IV)**: All metrics (RMSE, p-values) are generated by code and written to `data/processed/metrics.json`. The paper generation step will read directly from this file, preventing hand-typed errors.
5.  **Versioning Discipline (Principle V)**: The plan explicitly mandates that every research-stage artifact change updates the project's `state` file `updated_at` timestamp. Content hashes for input datasets and final models will be recorded in the `state` file.
6.  **Citizen Science Data Bias Mitigation (Principle VI)**: The plan explicitly includes a filtering step for "complete checklists" (duration ≥ 1 min, observers ≥ 1, distance ≤ 10 km) and aggregation to ° grids to match MODIS resolution. Additionally, observer effort is modeled to correct for detection bias.
7.  **Temporal Integrity in Phenology Modeling (Principle VII)**: The feature engineering step strictly separates target derivation (current week) from predictors (lagged -4 weeks). The training split is strictly **temporal** (2015-2020 vs 2022) to ensure the Gradient Boosting Regressor evaluates true predictive power on future migration events, adhering to the strict interpretation of Principle VII.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| **Temporal Split** | Required by Principle VII and to avoid spatial generalization errors on a localized dataset. | A spatial split (East/West) is invalid because the verified MODIS dataset is limited to Lake Powell; there is no "Western US" data in the verified source to test against. |
| **Bootstrap Resampling** | Required to statistically compare model performance without the circularity of modeling RMSE directly (LMM issue). | LMM treats RMSE as a raw observation, which is methodologically unsound for aggregate statistics. |
| **Observer Bias Control** | Required to prevent the model from learning "observer effort" instead of "biological migration". | Ignoring weather-dependent observer effort leads to spurious correlations between temperature and arrival dates. |
| **SHAP + Permutation on RMSE** | Required to disentangle collinearity and test significance of feature importance. | Comparing SHAP magnitudes directly does not provide statistical significance for the difference between drivers. |
