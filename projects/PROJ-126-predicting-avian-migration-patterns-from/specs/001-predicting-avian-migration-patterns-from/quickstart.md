# Quickstart: Predicting Avian Migration Patterns

## Prerequisites
- **Python** ≥ 3.11
- **Git** (any recent version)
- **Disk space**: ≥ 10 GB (raw downloads)
- **RAM**: ≥ 7 GB (pipeline uses streaming; 8 GB recommended)
- **NASA Earthdata token**: Register at https://urs.earthdata.nasa.gov/ and export as an environment variable  
  ```bash
  export NASA_EARTHDATA_TOKEN="YOUR_TOKEN_HERE"
  ```

## Installation

```bash
# 1. Clone the repository
git clone <REPO_URL>
cd projects/PROJ-126-predicting-avian-migration-patterns-from

# 2. Create and activate a virtual environment
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate

# 3. Install pinned dependencies
pip install -r code/requirements.txt
```

## Data Setup (automated)

```bash
# Run the data loader – downloads both EBD and MODIS assets for the **regional Pacific Northwest** extent
python code/data_loader.py
```
The script will:
- Stream the eBird CSV from HuggingFace to `data/raw/ebd_subset.csv`.
- Query **MODIS** MOD11A2 (LST) and MOD13Q1 (EVI) via `earthaccess` **restricted to the regional bounding box** (`REGIONAL_BBOX` in `config.py`).  
- Perform temporal interpolation for cloud gaps and flag cells with >30 % missing weeks.  
- If the regional download exceeds memory limits, the script automatically falls back to a **smaller sub‑region** and logs a warning.  
- Verify MD5 checksums and write them to `state/...yaml`.

## Run the Full Pipeline

```bash
bash code/run_pipeline.sh
```

The script executes the following stages in order:

1. **Preprocessing** – creates `data/processed/first_arrival_sweep.csv`.
2. **Model training** – fits three XGBoost models (Temp‑only, NDVI‑only, Combined) and saves them under `data/outputs/models/`.  
3. **Evaluation** – writes `data/processed/metrics.json` (RMSE, Pearson R, SBPT p‑values, feasibility metrics). **Note: the naive baseline is a simple mean‑arrival model that uses only the training‑set mean arrival week**.
4. **Visualization** – produces `migration_map.png` and `shap_summary.png` in `data/outputs/`.  
5. **Provenance** – logs file‑level provenance to `data/outputs/provenance.log`.

## Verification Checklist

1. **Metrics sanity**  
   ```bash
   cat data/processed/metrics.json
   ```
   - `combined_model_rmse` should be lower **than** `naive_baseline_rmse`.  
   - `p_value_sbpt` for the combined vs. baseline comparison must be `< 0.05` (Bonferroni‑adjusted).  

2. **Run unit tests**  
   ```bash
   pytest tests/ -v
   ```
