- [ ] T005 [US2] Extract fixation metrics (first‑fixation probability, dwell time, fixation latency) per ROI from raw eye‑tracking data and output a structured CSV.
  **Implementation**: `code/eye_tracking/parse_fixations.py` reads raw eye‑tracking files from `data/raw/ds003123/eye_tracking/` (format: gaze coordinates, timestamps, and trial IDs per participant). For each trial it identifies fixations within each ROI (face, weapon, background) using the masks from T004. It computes: (1) `first_fixation_prob` = proportion of trials in which the first fixation lands within the ROI, (2) `dwell_time_ms` = total fixation duration (sum of all fixation durations) within the ROI, (3) `fixation_latency_ms` = time from stimulus onset to first fixation entering the ROI (or null if no fixation enters). Results are written to `data/interim/fixations.csv` with columns: `trial_id`, `participant_id`, `stimulus_id`, `roi_type`, `dwell_time_ms`, `first_fixation_prob`, `fixation_latency_ms`. Trials with missing or corrupted gaze data are excluded and logged with a warning to `logs/fixation_warnings.log` (e.g., "trial_id=T001_P02: missing gaze data for 40% of trial duration").
  **Verification**: Processing a single participant's file yields rows with one entry per (trial, roi_type) combination; `test_fixation_extraction.py` checks that numeric values fall within plausible ranges (dwell_time_ms ≥ 0, first_fixation_prob ∈ [0, 1], fixation_latency_ms ≥ 0 or null), that `trial_id` values are unique per (participant, roi_type) pair, and that no row contains NaN in required fields. A second test confirms that excluded trials are logged and that the CSV row count matches the expected number of (participant × stimulus × roi_type) combinations.

- [ ] T006 [US2] Compute low‑level visual features (luminance, contrast, edge density) for each stimulus image and record them in a structured metadata file.
  **Implementation**: `code/analysis/feature_gen.py` loads each image from `data/raw/ds003123/stimuli/`, converts to grayscale, and computes: (1) `luminance` = mean pixel intensity (0–255 scale), (2) `contrast` = RMS contrast (standard deviation of pixel intensities), (3) `edge_density` = proportion of pixels with edges detected (Canny edge detector, threshold=100). Results are written to `data/interim/low_level_features.json` as a dictionary mapping `stimulus_id` → `{luminance, contrast, edge_density}`. The script also computes `scene_complexity` (number of detected objects via Detectron2 panoptic segmentation, used as a covariate) and appends it to the same file.
  **Verification**: A sanity‑check script verifies that every stimulus_id in the raw dataset has an entry in `low_level_features.json`; `test_feature_computation.py` asserts that luminance values fall within [0, 255], contrast values are non-negative, edge_density values fall within [0, 1], and scene_complexity values are non-negative integers. A second test confirms that the script processes all images without crashing and that the output file is valid JSON.

- [ ] T008 [US3, FR-004, FR-005, FR-006] Reduce collinearity via VIF diagnostics and PCA orthogonalization; fit linear mixed‑effects models A and B with FDR correction.
  **Implementation**: `code/analysis/collinearity_and_modeling.py` executes in sequence: (1) Load `data/processed/aligned_data.csv`, filter to rows with `excluded=False`. (2) Compute Variance Inflation Factors (VIF) for all fixed predictors (salience_score, luminance, contrast, edge_density, scene_complexity) using `pingouin.VIF()`. Write pre-orthogonalization VIF report to `logs/vif_pre_orthogonalization.json`. (3) If any VIF > 5, apply PCA orthogonalization: fit PCA on [luminance, contrast, edge_density], retain components explaining ≥95% variance, transform predictors, and replace the original three features with their principal components (PC1, PC2, ...). Recompute VIF on the orthogonalized feature set and write post-orthogonalization report to `logs/vif_post_orthogonalization.json`. (4) Fit **Model A** (random intercepts for participant and stimulus_id) and **Model B** (random intercepts + random slopes for salience_score per participant) using `statsmodels.MixedLM`. Dependent variable is dwell_time_ms (primary outcome); fixed predictors are salience_score and (orthogonalized or original) low-level features. (5) Extract fixed-effect estimates, standard errors, raw p-values, and 95% CIs for both models. (6) Apply Benjamini-Hochberg FDR correction to all p-values across both models. Write Model A results to `data/interim/model_a_results.csv` and Model B results to `data/interim/model_b_results.csv`, each with columns: `predictor`, `estimate`, `se`, `p_value`, `p_value_fdr_corrected`, `ci_lower`, `ci_upper`. (7) Compute sensitivity metric: `stability_metric = abs(model_a_estimate - model_b_estimate) / mean(abs(model_a_estimate), abs(model_b_estimate))` for the salience predictor. (8) Log all convergence warnings to `logs/lmm_convergence.log`.
  **Verification**: `test_collinearity_and_modeling.py` checks that VIF values are computed correctly, that post-orthogonalization VIF values are ≤5 (if orthogonalization was applied), that both model CSV files are produced with required columns, that FDR-corrected p-values are ≤ raw p-values and all ≤ 1, that 95% CIs are symmetric around the estimate, and that the stability metric is a non-negative number. A second test confirms that the script does not crash on the full aligned dataset and that the models converge (no fatal warnings in the log).

- [ ] T009 [US3, FR-008, SC-003] Run simulation‑based power analysis and determine validity for inference; compute and record semantic covariates (moral valence).
  **Implementation**: `code/analysis/power_and_semantic.py` executes in two parts: (1) **Power Analysis**: Using the observed data from `data/processed/aligned_data.csv` (excluding rows with `excluded=True`), extract variance components from Model B (random intercept variance for participant and stimulus_id, residual variance). Write semantic covariate metadata to `data/interim/semantic_covariates.json` with fields: `stimulus_id`, `moral_valence`, `source` (e.g., "annotation" or "vader_sentiment").
  **Verification**: `test_power_and_semantic.py` checks that the power report JSON contains all required fields, that `estimated_power` is between 0 and 1, that `power_status` is "valid" or "invalid" based on the threshold, and that the script completes without errors.
