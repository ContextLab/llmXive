# Tasks: The Influence of Visual Salience on Attentional Bias in Moral Judgements

**Inputs**: `specs/001-influence-of-visual-salience/spec.md`, `plan.md`, `data-model.md`, `contracts/` (dataset.schema.yaml, output.schema.yaml, salience.schema.yaml)

## Phase 1: Setup and first end‑to‑end analysis

- [ ] T001 Establish project layout, generate `requirements.txt`, and document a runnable entry point.  
  **Implementation**: `code/bootstrap.py` creates the standard directory tree (`code/`, `data/raw/`, `data/interim/`, `data/processed/`, `logs/`), writes a pinned `requirements.txt` with all dependencies (torch==2.2.0, statsmodels>=0.14.0, ultralytics>=8.0.0, detectron2>=0.7, pandas>=2.2.0, numpy>=1.26.0, scikit-image>=0.22.0, scikit-learn>=1.3.0, pingouin>=0.5.4, opencv-python>=4.8.0), and adds a `quickstart.md` command documenting `python -m code.main --stage smoke`.  
  **Verification**: Running `python code/bootstrap.py` exits with status 0, prints the directory tree, and the generated `requirements.txt` matches the pinned list. A unit test `tests/test_bootstrap.py` asserts file existence and exact content.

- [ ] T002 [US1] Verify the “Moral Foundations Eye‑Tracking Dataset” (OpenNeuro ds003123) is present at `data/raw/ds003123/` and record integrity checksums; fail loudly if absent.  
  **Implementation**: `code/ingestion/verify_data.py` checks that `data/raw/ds003123/` exists with expected sub‑directories (`sub-*/` for participants, `stimuli/` for images). It computes SHA‑256 checksums for all image and eye‑tracking files, writes them to `data/raw/checksums.json`, and raises `RuntimeError("DATA_MISSING_001: ds003123 not found at data/raw/ds003123/")` if the directory is missing or incomplete. No automatic download is attempted – the dataset must be placed manually before the pipeline runs.  
  **Verification**: `tests/test_verify_data.py` asserts that the script exits 0 when the dataset is present, that `checksums.json` contains an entry for every file, and that the exact error phrase “DATA_MISSING_001” is raised when the directory is absent. The script aborts on checksum mismatch (no silent fallback).

- [ ] T003 [US1] Compute pixel‑wise salience maps for all stimulus images using the DeepGaze II model in CPU‑only mode, with explicit error handling.  
  **Implementation**: `code/salience/generate_maps.py` iterates over all images in `data/raw/ds003123/stimuli/`, loads the DeepGaze II weights (CPU‑only), runs inference to produce a pixel‑wise salience map, and writes a `.npy` map to `data/interim/salience_maps/<stimulus_id>.npy`. Metadata for each image is appended to `data/interim/salience_metadata.json` with fields: `stimulus_id`, `map_path`, `resolution` (height, width), `generation_method="deepgaze_ii"`, `status="success"`, `excluded_reason=null`. If DeepGaze II fails on a particular image (e.g., due to extreme contrast), the script logs the error to `logs/salience_errors.log`, marks that image with `status="failed"` and an appropriate `excluded_reason`, and continues. No GPU fallback is used; the task must succeed on CPU or abort with a clear error.  
  **Verification**: `tests/test_salience_generation.py` runs the script on a 5‑image subset on a CPU‑only runner, verifies that each `.npy` file matches the source image resolution, validates `salience_metadata.json` against `contracts/salience.schema.yaml`, and confirms no CUDA errors. A second test checks that failures are correctly recorded with `status="failed"` and a non‑null `excluded_reason`.

- [ ] T004 [US2] Generate semantic ROI masks for “faces” (YOLOv8) and “weapons” (Detectron2) when pre‑segmented masks are absent from the dataset.  
  **Implementation**: `code/eye_tracking/segment_roi.py` first looks for existing masks under `data/raw/ds003123/masks/`. If found, they are copied to `data/interim/masks/` and provenance recorded in `data/interim/mask_provenance.json`. If missing, the script loads YOLOv8 (`ultralytics.YOLO("yolov8n.pt")`) for faces and Detectron2 (verified HuggingFace model) for weapons, both with confidence ≥ 0.85. For each stimulus image it produces binary PNG masks named `<stimulus_id>_face.png` and `<stimulus_id>_weapon.png` saved in `data/interim/masks/`. Images yielding no detections or low‑confidence detections are logged to `data/interim/flagged_images.csv` (columns: `stimulus_id`, `roi_type`, `num_detections`, `mean_confidence`) and recorded in `data/interim/detection_metadata.json`.  
  **Verification**: `tests/test_roi_segmentation.py` confirms that both mask types are generated for a sample image, that mask dimensions equal the source image, and that low‑confidence detections are excluded. A second test verifies that pre‑existing masks are correctly identified and copied without invoking the detectors.

- [ ] T005 [US2] Extract fixation metrics (first‑fixation probability, dwell time, fixation latency) per ROI from raw eye‑tracking data and output a structured CSV.  
  **Implementation**: `code/eye_tracking/parse_fixations.py` reads raw eye‑tracking files from `data/raw/ds003123/eye_tracking/`, uses the ROI masks from T004 to assign fixations to “face”, “weapon”, or “background”. For each trial it computes: (1) `first_fixation_prob` = proportion of trials where the first fixation lands in the ROI, (2) `dwell_time_ms` = sum of fixation durations within the ROI, (3) `fixation_latency_ms` = time from stimulus onset to first fixation entering the ROI (or null if none). Results are written to `data/interim/fixations.csv` with columns `trial_id, participant_id, stimulus_id, roi_type, dwell_time_ms, first_fixation_prob, fixation_latency_ms`. Trials with missing or corrupted gaze data are excluded and logged to `logs/fixation_warnings.log`.  
  **Verification**: `tests/test_fixation_extraction.py` processes a single participant’s file, checks that each (trial, roi_type) combination appears exactly once, that numeric fields are within plausible ranges (dwell ≥ 0, prob ∈ [0,1], latency ≥ 0 or null), and that excluded trials appear in the warning log.

- [ ] T006 [US2] Compute low‑level visual features (luminance, contrast, edge density) and scene complexity for each stimulus image; store in a structured metadata file.  
  **Implementation**: `code/analysis/feature_gen.py` loads each image from `data/raw/ds003123/stimuli/`, converts to grayscale, and computes: `luminance` = mean pixel intensity (0‑255), `contrast` = RMS contrast (std dev of pixel intensities), `edge_density` = proportion of edge pixels using Canny (threshold = 100). Scene complexity is obtained via Detectron2 panoptic segmentation (number of detected objects). All values are written to `data/interim/low_level_features.json` as a dict keyed by `stimulus_id`.  
  **Verification**: `tests/test_feature_computation.py` asserts that every stimulus ID has an entry, that luminance ∈ [0,255], contrast ≥ 0, edge_density ∈ [0,1], and scene_complexity is a non‑negative integer. The JSON file must be valid and parsable.

- [ ] T009 [US2] Compute semantic covariates (moral valence and scene complexity) for each stimulus image.  
  **Implementation**: `code/analysis/semantic_covariates.py` (1) extracts moral‑valence: if the dataset supplies a binary label, it is used; otherwise VADER sentiment analysis is applied to any available caption text, producing either a numeric sentiment score or the categorical values “moral” / “neutral”. (2) Retrieves scene‑complexity already computed in T006. The results are saved to `data/interim/semantic_covariates.json` containing `stimulus_id`, `moral_valence`, and `source`. Missing values are logged and cause associated trials to be flagged for exclusion in later alignment.  
  **Verification**: `tests/test_semantic_covariates.py` validates that every stimulus has a `moral_valence` entry (numeric or allowed string), that the `source` field is recorded, and that any missing valence triggers appropriate exclusion flags in alignment statistics.

- [ ] T007 [US2, FR-003] Align salience scores, ROI masks, fixation metrics, low‑level visual features, and semantic covariates into a single analysis dataset; flag excluded trials.  
  **Implementation**: `code/analysis/align_data.py` merges: (1) `data/interim/salience_metadata.json` (mean salience per ROI computed by averaging the `.npy` map within the corresponding mask), (2) `data/interim/low_level_features.json`, (3) `data/interim/fixations.csv`, (4) `data/interim/detection_metadata.json`, (5) `data/interim/semantic_covariates.json`. For each trial‑ROI combination a row is written to `data/processed/aligned_data.csv` containing all columns required by `contracts/dataset.schema.yaml`. Rows where any component is missing (e.g., failed salience map, missing fixation data, empty mask, missing semantic covariate) are marked `excluded=True`. Alignment statistics (total rows, excluded rows, exclusion rate, reason breakdown) are saved to `data/processed/alignment_stats.json`.  
  **Verification**: `tests/test_alignment.py` validates that `aligned_data.csv` conforms to `contracts/dataset.schema.yaml`, that there are no ID mismatches, that the exclusion flag is set correctly, and that `alignment_stats.json` accurately reflects the counts.

- [ ] T008 [US3, FR-004, FR-005, FR-006] Perform collinearity diagnostics, orthogonalize predictors if needed, fit linear mixed‑effects models A and B, and apply FDR correction.  
  **Implementation**: `code/analysis/collinearity_and_modeling.py` (1) loads `aligned_data.csv` (excluding rows with `excluded=True`), (2) computes VIF for fixed predictors (`salience_score`, `luminance`, `contrast`, `edge_density`, `scene_complexity`) using `pingouin.vif()`, writes pre‑orthogonalization VIF to `logs/vif_pre.json`. If any VIF > 5, PCA is applied to the three low‑level visual features, retaining components that explain ≥ 95 % variance; the transformed components replace the original features and post‑orthogonalization VIF are saved to `logs/vif_post.json`. (3) Fits **Model A** (random intercepts for participant and stimulus) and **Model B** (random intercepts + random slopes for `salience_score` per participant) with `statsmodels.MixedLM` using `dwell_time_ms` as the dependent variable and the (orthogonalized) predictors as fixed effects. (4) Extracts fixed‑effect estimates, standard errors, raw p‑values, and 95 % CIs; writes results to `data/interim/model_a_results.csv` and `data/interim/model_b_results.csv`. (5) Applies Benjamini‑Hochberg FDR correction across all fixed‑effect p‑values and adds a `p_value_fdr_corrected` column. (6) Computes the stability metric: `abs(model_a_estimate - model_b_estimate) / mean(abs(model_a_estimate), abs(model_b_estimate))` for the salience predictor and logs it. Convergence warnings are captured in `logs/lmm_convergence.log`.  
  **Verification**: `tests/test_collinearity_and_modeling.py` checks that VIF values are numeric, that post‑orthogonalization VIF ≤ 5 (if orthogonalization occurred), that both model CSVs contain the required columns, that FDR‑corrected p‑values are ≤ 1 and not greater than raw p‑values, that CIs are correctly ordered, and that the stability metric is non‑negative. It also asserts that model fitting completes without fatal errors.

- [ ] T010 [US3, FR-007, SC-004] Assemble final results JSON with sensitivity analysis, collinearity diagnostics, disclaimer enforcement, and validate against the output schema.  
  **Implementation**: `code/analysis/final_results.py` reads Model B fixed‑effect estimate, raw and FDR‑corrected p‑values, CIs, the stability metric from T008, VIF reports from T008, and `power_status` from T009. It builds `data/processed/results.json` with fields: `model_id` (e.g., “model_b_lmm_001”), `fixed_effect_estimate`, `p_value`, `p_value_fdr_corrected`, `confidence_interval`, `sensitivity_analysis` (with `model_a_estimate`, `model_b_estimate`, `stability_metric`), `collinearity_report` (both pre‑ and post‑orthogonalization VIF dicts), `disclaimer` (exact string “correlational only” if any p‑value < 0.05, otherwise `null`), and `power_status`. The script validates the JSON against `contracts/output.schema.yaml` via `code/utils/final_validator.py`; on failure it raises `RuntimeError("SCHEMA_VALIDATION_FAILED")` with details. Upon success, a checksum is written to `logs/results_checksum.log`.  
  **Verification**: `tests/test_final_results.py` confirms schema compliance, correct insertion of the disclaimer only when required, accurate propagation of the power status, and presence of all nested fields. It also checks that the checksum file is created and matches the file content.

- [ ] T011 [P, SC-001, SC-002] Compute and log success metrics: salience map generation rate, resource usage, and exclusion summary.  
  **Implementation**: `code/utils/success_metrics.py` reads `salience_metadata.json` to calculate `salience_success_rate = (# status=="success") / total_images`. It extracts peak RAM and total CPU seconds from `logs/resource.log`. It also reads `alignment_stats.json` for `exclusion_rate` and `reason_breakdown`. All metrics are written to `data/interim/success_metrics.json` and a human‑readable summary is appended to `logs/metrics_summary.log` (e.g., “Salience maps generated: 195/200 (97.5 %); peak RAM: 6.3 GB; exclusion rate: 8.2 %”).  
  **Verification**: `tests/test_success_metrics.py` checks that numeric values are within expected bounds (rates ∈ [0,1], RAM > 0), that the summary log contains the expected strings, and that the JSON file is well‑formed.

- [ ] T012 [P, SC-002] Monitor and enforce resource constraints (RAM ≤ 7 GB, CPU time ≤ 6 h) during pipeline execution.  
  **Implementation**: `code/utils/resource_validator.py` wraps the most intensive step (salience generation, T003) using `psutil`. It records per‑image RAM usage and elapsed CPU time in `logs/resource.log` (JSON entries with timestamp, `stimulus_id`, `ram_mb`, `cpu_seconds`). If peak RAM exceeds 7 GB or cumulative CPU time exceeds 6 h, the script logs a warning and raises `RuntimeError("RESOURCE_LIMIT_EXCEEDED: peak_ram={peak_gb} GB, limit=7 GB")`. The script does **not** attempt to skip images; it aborts loudly so the runner can retry on a GPU if appropriate.  
  **Verification**: `tests/test_resource_validator.py` simulates normal usage (well below limits) and ensures the script exits cleanly, and also simulates a breach to verify that the proper exception and message are raised and logged.

- [ ] T013 [P] Validate all output artifacts against their schemas and generate reproducible pipeline documentation.

  **Verification**: `tests/test_final_validator.py` supplies both valid and deliberately corrupted artifacts to ensure the validator correctly accepts good files and rejects bad ones with informative messages, and checks that `pipeline.md` contains the expected sections and command snippets.
