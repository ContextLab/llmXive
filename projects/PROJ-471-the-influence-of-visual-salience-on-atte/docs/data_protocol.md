# Data Protocol: The Influence of Visual Salience on Attentional Bias

This document details the data acquisition, ingestion, and processing protocols
implemented for the project "The Influence of Visual Salience on Attentional Bias
in Moral Judgements".

## 1. Data Source and Acquisition

### 1.1 Primary Dataset
- **Source**: OpenNeuro (ds003123)
- **Access Method**: Hugging Face `datasets` library via `load_dataset`.
- **Streaming**: The pipeline automatically switches to `streaming=True` if the
 estimated dataset size exceeds 7GB to comply with RAM constraints (T012).
- **Verification**: Before processing, `code/ingestion/verify_real_source.py`
 validates the dataset checksum and directory structure (`sub-*`) against the
 canonical OpenNeuro reference (T043).

### 1.2 Real Data Constraint
- **No Synthetic Fallback**: Per the project's Data Integrity guidelines (Phase 7),
 the pipeline **strictly forbids** synthetic data generation. If the real data
 fetch fails, the system raises a `RuntimeError` with code `DATA_MISSING_001`
 (enforced by `code/ingestion/fallback_guard.py`, T051).
- **Failure Mode**: Any `try/except` block that attempts to return `generate_synthetic_*`
 or `mock_*` data will trigger an immediate pipeline halt.

## 2. Preprocessing Pipeline

### 2.1 Salience Map Generation (User Story 1)
- **Primary Method**: DeepGaze II (CPU-only mode).
 - **Implementation**: `code/ingestion/salience_gen.py` (T013).
 - **Constraint**: Explicitly enforces `device='cpu'` to prevent GPU memory errors.
- **Fallback Method**: GBVS (Graph-Based Visual Saliency).
 - **Trigger**: Activated only if DeepGaze II fails on a specific high-contrast image.
 - **Validation**: Fallback maps are validated for dimension matching, non-zero variance,
 and mean salience > 0.01 (T013a).
 - **Exclusion**: GBVS maps are **excluded** from the primary success count (SC-001)
 but logged separately in `data/processed/salience_stats.json` (T013b).
- **Resource Monitoring**: `code/ingestion/salience_gen.py` tracks RAM usage (must stay < 7GB)
 and cumulative CPU time (limit 6 hours). Outputs are written to `data/interim/resource_usage.json` (T014).
- **Success Criteria**: A map is valid only if generated by DeepGaze II. If GBVS fallback
 frequency > 10%, the pipeline halts and writes `data/interim/invalid_fallback_flag.json` (T018c).

### 2.2 Eye-Tracking and Segmentation (User Story 2)
- **Face Segmentation**: `code/processing/segmentation.py` uses YOLOv8 (COCO `face` class)
 to generate semantic masks.
 - **Weapons Exclusion**: Per SCR-002, "Weapons" are explicitly excluded. The system
 verifies the existence of `specs/001-influence-of-visual-salience/SCR-002-Exclusion-of-Weapons.md`
 and logs a warning if the exclusion is active (T020d).
- **Fixation Metrics**: `code/processing/eye_tracking.py` parses raw TSV files, filters
 for "Face" ROI, and calculates First-Fixation Probability, Dwell Time, and Latency.
 - **Output**: `data/interim/fixation_metrics.csv` (T021).
- **Missing Data**: Trials with missing fixation data are excluded and logged (T023).

### 2.3 Data Alignment
- **Process**: `code/processing/alignment.py` merges salience scores with fixation metrics
 on `TrialID`.
- **Validation**: Ensures no ID mismatches and flags images with invalid masks (T025).
- **Output**: `data/processed/aligned_metrics.csv` with a "correlational only" disclaimer (T026).

## 3. Statistical Analysis Protocol (User Story 3)

### 3.1 Power and VIF Gates
- **Power Analysis**: `code/analysis/lmm_power.py` runs a simulation-based power analysis
 (using `simr`). If pilot data is missing, a medium effect size (d=0.5) is assumed.
 - **Gate**: If power < 0.8, the pipeline halts and writes `data/interim/power_gate_flag.json` (T029c).
- **VIF Calculation**: `code/analysis/vif_calc.py` calculates Variance Inflation Factor
 against generated low-level features (luminance, contrast, edge density).
 - **Gate**: If VIF > 5, the pipeline halts and writes `data/interim/vif_gate_flag.json` (T030).
 - **Constraint**: Low-level features are **never** used as covariates in the final LMM (SCR-001).

### 3.2 Linear Mixed Models (LMM)
- **Models**: `code/analysis/lmm_fit.py` fits Model A (random intercepts) and Model B
 (random intercepts + slopes for salience).
 - **Convergence Check**: If models fail to converge, `maxiter` is increased (T046).
 - **Exclusion**: The model formula explicitly excludes `luminance`, `contrast`, and
 `edge_density` columns.
- **FDR Correction**: `code/analysis/robustness.py` applies Benjamini-Hochberg correction
 to p-values (T031).
- **Result Interpretation**: `code/analysis/lmm_fit.py` logs results to `data/interim/result_interpretation.log`
 linking significance to "perceptual-cognitive interaction" or "attentional control hierarchy" theories (T035).

### 3.3 Final Output
- **Schema**: Results are validated against `code/contracts/output.schema.yaml` (T049a).
- **Disclaimer**: If any p-value < 0.05, the final `data/processed/results.json` includes
 the exact phrase "correlational only" (T049b, T036).

## 5. Execution Constraints

- **Compute Budget**: Total cumulative job time must not exceed 6 hours (T042).
- **Memory Limit**: Peak RAM must remain below 7GB (T014, T042).
- **Data Integrity**: No synthetic data generation allowed (T051).
- **Scope Freeze**: Processing halts if SCR-001 or SCR-002 documents are missing (T020, T020d).
