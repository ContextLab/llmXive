# Specification: Evaluating the Effectiveness of Differential Privacy in Federated Learning

## Project Overview
This project evaluates the impact of data heterogeneity on the effectiveness of Differential Privacy (DP) in Federated Learning (FL). We focus on the FEMNIST dataset to simulate realistic non-IID client distributions using Dirichlet sampling.

## User Stories

### US-1: Baseline Heterogeneity Simulation
**Goal**: Generate reproducible client data partitions from FEMNIST using Dirichlet distributions with varying α to establish a controlled baseline.
**Data Source**: FEMNIST (LEAF) exclusively. Shakespeare dataset is excluded per plan.md Gap Analysis.

**Functional Requirements:**
- **FR-001**: The system must support downloading and partitioning the FEMNIST dataset. The system must NOT support the Shakespeare dataset.
 - **Input**: Dataset name "femnist".
 - **Process**: Download raw data, partition using Dirichlet distribution with configurable α (0.1, 0.5, 1.0).
 - **Output**: Client-specific data partitions and metadata files.
 - **Constraint**: All data processing must be strictly limited to FEMNIST. Any attempt to load Shakespeare must raise a `ValueError` with the message: "Shakespeare excluded per plan.md Gap Analysis (no verified source)."
- **FR-002**: The partitioning logic must ensure that no client is assigned zero samples for a specific class in critical heterogeneity scenarios (α=0.1), or handle this edge case explicitly as defined in the implementation.
- **FR-003**: The system must generate metadata files describing the label distribution for each client.

### US-2: DP-FL Training and Convergence Measurement
**Goal**: Train models using FedAvg with Opacus-enabled DP across varying ε and α, logging global and per-client accuracy.
**Data Source**: FEMNIST partitions generated by US-1.

**Functional Requirements:**
- **FR-004**: The training system must execute 5 independent seeds for each configuration (α, ε) to ensure statistical validity.
- **FR-005**: The system must log per-client accuracy, distinguishing between "majority" and "minority" clients based on label frequency in the partition metadata.
- **FR-006**: The system must implement a "utility collapse" detection mechanism for extremely low ε values (e.g., ε < 0.05) and flag these runs.
- **FR-007**: The system must handle clients with zero gradient updates (skipping) without crashing, logging a warning as specified.

### US-3: Statistical Analysis and Threshold Sensitivity
**Goal**: Perform statistical tests (t-tests, Mann-Whitney U) and sensitivity analysis on α to validate the "critical heterogeneity" hypothesis.

**Functional Requirements:**
- **FR-008**: The analysis pipeline must filter out time-limited runs and utility collapse runs before performing statistical tests.
- **FR-009**: The system must perform paired t-tests comparing DP vs. Non-DP accuracy for the same seed and configuration.
- **FR-010**: The system must perform unpaired tests (or Mann-Whitney U fallback) comparing majority vs. minority client accuracies.
- **FR-011**: The system must generate sensitivity analysis plots showing accuracy gap vs. α and minority degradation vs. global accuracy.

## Data Model
- **Dataset**: FEMNIST (LEAF)
- **Partitions**: JSON metadata files containing `client_id`, `label_distribution`, `total_samples`.
- **Results**: CSV logs containing `seed`, `alpha`, `epsilon`, `global_accuracy`, `minority_accuracy`, `majority_accuracy`, `rounds_to_target`, `is_time_limited`, `is_utility_collapse`, `p_value_dp_vs_nondp`, `p_value_majority_vs_minority`.

## Constraints & Exclusions
- **Shakespeare Dataset**: Explicitly excluded from this project due to lack of verified sources in the plan.md Gap Analysis. All code and documentation must reflect this exclusion.
- **Privacy Budget**: Analysis is limited to ε values where the model does not collapse into random guessing.
- **Compute**: Experiments must respect the 5-seed limit per configuration.

## Verification
- All scripts must be reproducible via `python code/<path>.py` with specific CLI arguments.
- Output files must match the exact paths defined in the task descriptions (e.g., `data/raw/femnist.parquet`, `results/summary.csv`).
- Statistical results must be validated against the `results/validation_report.md`.
