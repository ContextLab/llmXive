# Data Model: llmXive follow-up: extending "Perception or Prejudice"

## Overview
All pipeline stages read/write structured artifacts validated against JSON schemas stored in `contracts/`. The schemas guarantee reproducibility, single source of truth, and enable automated contract testing.

## Core Schemas

### 1. `video_metadata.schema.yaml`
```yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: VideoMetadata
type: object
required:
  - video_id
  - expert_labels
properties:
  video_id:
    type: string
    minLength: 1
    description: "Stable identifier of the video sample."
  video_url:
    type: [string, "null"]
    description: "URL or hub path of the source video, if provided."
  transcript:
    type: [string, "null"]
    description: "Verbal transcript / caption text, if available."
  setting:
    type: [string, "null"]
    description: "Situational setting tag (e.g., \"job interview\"), if available."
  culture:
    type: [string, "null"]
    description: "Cultural background tag, if available."
  behavior_tags:
    type: array
    items:
      type: string
    description: "Ground‑truth behavioral evidence tags (may be empty)."
  expert_labels:
    type: object
    description: "Expert ground‑truth trait labels; keys are trait names."
    additionalProperties:
      type: [string, number, "null"]
  extra:
    type: object
    description: "Any additional source columns preserved verbatim."
    additionalProperties: true
additionalProperties: false
```

### 2. `context_profile.schema.yaml`
```yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: ContextProfile
type: object
required:
  - profile_id
  - setting
  - culture
  - norms
  - scripts
properties:
  profile_id:
    type: string
    description: "Identifier linking to a video metadata entry."
  setting:
    type: string
    description: "Situational tag (e.g., \"job interview\")."
  culture:
    type: string
    description: "Cultural context (e.g., \"East Asian\")."
  norms:
    type: array
    items:
      type: string
    description: "List of social norms relevant to the setting/culture."
  scripts:
    type: array
    items:
      type: string
    description: "Short situational scripts (e.g., \"maintain eye contact\")."
```

### 3. `model_output.schema.yaml`
```yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: ModelOutput
type: object
required:
  - model_name
  - video_id
  - condition
  - rating
  - reasoning
  - grounding_score
  - context_cited
  - valid_json
properties:
  model_name:
    type: string
    description: "Name of the MLLM (matches Table 2 of arXiv:2605.22109)."
  video_id:
    type: string
    description: "Identifier of the video sample."
  condition:
    type: string
    enum: [baseline, context, noise]
    description: "Prompting condition."
  rating:
    type: integer
    minimum: 1
    maximum: 5
    description: "Trait rating (1‑5)."
  reasoning:
    type: string
    description: "Free‑form justification generated by the model."
  grounding_score:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Numeric grounding confidence (0‑1)."
  context_cited:
    type: boolean
    description: "True if the reasoning references at least one phrase from the injected context (detected via fuzzy token overlap ≥ 0.8)."
  valid_json:
    type: boolean
    description: "True if the model output conforms to the expected JSON schema."
```

### 4. `metric_record.schema.yaml`
```yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: MetricRecord
type: object
required:
  - model_name
  - condition
  - prejudice_rate
  - holistic_grounding_rate
  - integration_failure_rate
  - n_valid
  - n_invalid
  - n_ambiguous
properties:
  model_name:
    type: string
    description: "Identifier of the MLLM (matches Table 2 of arXiv:2605.22109)."
  condition:
    type: string
    enum: [baseline, context, noise]
    description: "Experimental condition under which metrics were computed."
  prejudice_rate:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Primary PR: #(grounding invalid) / #(all predictions)."
  prejudice_rate_all:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Supplementary PR across all predictions (used for sanity checks)."
  rating_accuracy:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Proportion of valid predictions whose rating exactly matches the expert label."
  holistic_grounding_rate:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Proportion of correct ratings with valid grounding (HR)."
  integration_failure_rate:
    type: [number, "null"]
    minimum: 0.0
    maximum: 1.0
    description: "Proportion of outputs that did not cite any injected context phrase; **only applicable for context and noise conditions** (baseline IR is null)."
  n_valid:
    type: integer
    minimum: 0
    description: "Samples retained after excluding invalid JSON or timeouts (FR‑010)."
  n_invalid:
    type: integer
    minimum: 0
    description: "Number of excluded samples (invalid output)."
  n_ambiguous:
    type: integer
    minimum: 0
    description: "Number of samples flagged with grounding‑uncertainty (FR‑011)."
  n_correct:
    type: integer
    minimum: 0
    description: "Number of valid samples with a correct (exact‑match) rating; denominator for HR."
  grounding_assessment_method:
    type: string
    description: "Hybrid method: semantic similarity (≥ 0.70) + keyword checklist; calibrated on a pilot and validated on a held‑out set (methodology‑431136ee)."
```

## Data Flow Diagram (conceptual)
```
raw video metadata ──► video_metadata.schema.yaml
               │
               ▼
   knowledge_base.json ──► context_profile.schema.yaml
               │
               ▼
   inference (baseline / context / noise)
               │
               ▼
   model_output.schema.yaml
               │
               ▼
   metrics.py ──► metric_record.schema.yaml
               │
               ▼
   analysis.py → results.md / figures
```

Each stage reads the previous artifact, validates against its schema, and writes the next artifact to `data/derived/`. Contract tests enforce schema compliance before downstream stages run.
