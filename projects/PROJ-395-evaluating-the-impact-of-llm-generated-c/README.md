# PROJ-395: Evaluating the Impact of LLM-Generated Code on Memory Usage

This project investigates whether code generated by Large Language Models (LLMs) exhibits systematically different memory consumption patterns compared to human-written reference solutions.

## Project Structure

```
projects/PROJ-395-evaluating-the-impact-of-llm-generated-c/
├── code/ # Core implementation modules
│ ├── config.py # Configuration parameters (seeds, timeouts, limits)
│ ├── utils.py # Error handling, retry logic, CSV I/O helpers
│ ├── download.py # Dataset fetching and verification
│ ├── generate.py # LLM solution generation
│ ├── profile.py # Memory profiling harness
│ ├── analyze.py # Statistical analysis and reporting
│ ├── features.py # Code feature extraction
│ ├── setup_directories.py # Directory initialization
│ └── state_manager.py # Artifact versioning and hashing
├── data/
│ ├── raw/ # Raw downloaded datasets
│ ├── processed/ # Processed measurement artifacts
│ └── dataset_manifest.yaml # Dataset versioning metadata
├── tests/ # Unit and integration tests
├── state/ # Versioned snapshots of code and data
└── README.md # This file
```

## Prerequisites

- Python 3.11+
- pip
- Access to HuggingFace Hub (for dataset/model downloads)

## Setup Instructions

1. **Clone and navigate to the project directory:**
 ```bash
 cd projects/PROJ-395-evaluating-the-impact-of-llm-generated-c/
 ```

2. **Create a Python 3.11 virtual environment:**
 ```bash
 python3.11 -m venv venv
 source venv/bin/activate # On Windows: venv\Scripts\activate
 ```

3. **Install dependencies:**
 ```bash
 pip install -r requirements.txt
 ```

4. **Configure environment:**
 - Ensure you have internet access for downloading datasets and models.
 - (Optional) Set HuggingFace token if required for private datasets:
 ```bash
 export HF_TOKEN=your_token_here
 ```

## Usage

### 1. Setup Project Directories
Initialize the required directory structure:
```bash
python code/setup_directories.py
```

### 2. Download Datasets
Fetch HumanEval or MBPP benchmarks with verification:
```bash
python code/download.py --dataset mbpp --split test
```
*Output:* `data/raw/mbpp_test.parquet`, `data/dataset_manifest.yaml`

### 3. Generate LLM Solutions
Generate code solutions using the configured model (TinyLlama):
```bash
python code/generate.py --problems 30 --output data/processed/llm_solutions.json
```

### 4. Profile Memory Usage
Run the profiling harness on generated and reference solutions:
```bash
python code/profile.py \
 --solutions data/processed/llm_solutions.json \
 --references data/raw/mbpp_test.parquet \
 --output data/processed/memory_measurements.csv
```
*Output:* `data/processed/memory_measurements.csv` (schema: problem_id, source_type, peak_memory, steady_state, status, total_resource_cost)

### 5. Statistical Analysis
Perform paired statistical tests and generate reports:
```bash
python code/analyze.py \
 --measurements data/processed/memory_measurements.csv \
 --output data/processed/analysis_report.json
```
*Output:* `data/processed/analysis_report.json` (p-values, effect sizes, confidence intervals)

### 6. Feature Correlation Analysis (Optional)
Extract code features and analyze correlations:
```bash
python code/features.py --solutions data/processed/llm_solutions.json --output data/processed/features.csv
python code/analyze.py --measurements data/processed/memory_measurements.csv --features data/processed/features.csv --output data/processed/feature_report.json
```

## Configuration

Edit `code/config.py` to adjust:
- Random seeds for reproducibility
- Model parameters (e.g., `model_name = "TinyLlama/TinyLlama-1.1B-Chat-v1.0"`)
- Execution timeouts (default: 60s)
- Memory limits (default: 7GB)
- Stability thresholds (IQR > 15% of median triggers re-run)

## Testing

Run unit and integration tests:
```bash
pytest tests/ -v
```
