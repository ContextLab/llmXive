# Data Model: Dream-State Learning

## Overview

This document defines the data structures, schemas, and flow for the Dream-State Learning experiment. All data is derived from the verified GLUE dataset and processed into specific formats for the wake and dream phases.

## Data Flow

1.  **Raw Ingestion**: GLUE dataset downloaded to `data/raw/` via `datasets` library.
2.  **Preprocessing**:
    -   **Wake Data**: Raw text samples with labels (MNLI train).
    -   **Dream Data**: Generated pseudo-samples (masked inputs) stored temporarily during the training loop.
3.  **Evaluation**: Held-out subsets for few-shot testing (QNLI val).
4.  **Results**: Metrics (accuracy, loss, p-values) stored in `data/results/`.

## Schema Definitions

### 1. Raw Dataset Record
Represents a single sample from the GLUE dataset.

```yaml
# contracts/dataset.schema.yaml
$schema: "http://json-schema.org/draft-07/schema#"
type: object
properties:
  id:
    type: string
    description: "Unique identifier for the sample"
  text:
    type: string
    description: "The raw input text"
  label:
    type: integer
    description: "The ground truth label (if applicable)"
  split:
    type: string
    enum: ["train", "validation", "test"]
    description: "Dataset split"
required:
  - id
  - text
  - split
```

### 2. Dream Pseudo-Sample
Represents a generated sample during the dream phase.

```yaml
# contracts/dream_sample_schema.schema.yaml
$schema: "http://json-schema.org/draft-07/schema#"
type: object
properties:
  original_id:
    type: string
    description: "ID of the source sample used for generation"
  generated_tokens:
    type: array
    items:
      type: string
    description: "Tokens generated by the model"
  masked_input:
    type: string
    description: "The masked version of the generated tokens (input for DAE)"
  target_original:
    type: string
    description: "The original ground truth input text (target for reconstruction)"
  entropy_score:
    type: number
    description: "Average entropy of the generated tokens (bits per token)"
  perplexity_score:
    type: number
    description: "Perplexity of generated sample against held-out corpus"
required:
  - original_id
  - generated_tokens
  - masked_input
  - target_original
  - entropy_score
  - perplexity_score
```

```yaml

    type: number
    description: "Estimated statistical power"

    type: string
    description: "Any caveats (e.g., 'insufficient power', 'pilot study')"

  - test_type
  - alpha
  - effect_size
  - p_value
  - significant
```

    type: "integer"

  - "retry_count"
  - "discarded"

## Data Hygiene Rules

1.  **Immutability**: Raw data in `data/raw/` is never modified. All transformations create new files in `data/processed/`.
2.  **Checksums**: Every file in `data/raw/` must have a corresponding `.sha256` file.
3.  **PII**: No personally identifiable information is allowed in `data/`. The GLUE dataset is cleaned of PII by the source provider.
4.  **Versioning**: Every dataset version is tagged with a content hash in `state/artifact_hashes.yaml` using the `artifact_hashes.schema.yaml`.
5.  **Logging**: All wake/dream transitions, entropy metrics, and warm-up status are logged in `logs/` with structured JSON format (T019).
6.  **Statistical Analysis**: All t-tests and effect size calculations are performed using `scipy.stats.ttest_rel` and logged (T025).
7.  **Unit Tests**: Unit tests cover entropy calculation, masking logic, and data loading (T054).
8.  **Security**: Input validation and PII scanning are implemented (T055).
9.  **Optimization**: Batching and data loading are optimized for CPU performance (T053).
10. **Refactoring**: Code is modularized and refactored for maintainability (T052).
