## Unresolved concerns

- The plan proposes deriving 'substrate class' (secondary/tertiary) from SMILES using RDKit rules if missing. This introduces a construct validity risk: the derived label may not match the experimental conditions under which the rate constant was measured (e.g., a molecule labeled 'secondary' by structure might have reacted via SN2 in the source data). Using a derived label to stratify a model predicting experimental rates conflates structural potential with observed mechanism, potentially biasing the model to predict 'structural class' rather than 'rate constant'.
- The plan states: 'If N < 500, the study is underpowered... we will reduce model complexity.' This is a post-hoc adjustment that invalidates the statistical power of the final result. If the dataset is small, the study should be framed as a feasibility demonstration or use a simpler baseline (e.g., linear regression) as the primary model, rather than training a GNN and then claiming it was 'underpowered' after the fact. The methodology must pre-define the model complexity based on the expected N, not adapt it to the data size after ingestion.
- The plan relies on a 'stratified random sample of 8,000 rows' if the dataset exceeds 10k. For a scientific study claiming to predict rate constants, random sampling from a potentially heterogeneous chemical space (different solvents, temperatures, leaving groups) risks creating a test set that does not represent the full distribution of the reaction space. The methodology should specify a stratification strategy based on chemical diversity (e.g., scaffold splitting or leaving group splitting) rather than random sampling to ensure the model generalizes to unseen chemistry, not just unseen molecules from the same distribution.
- The plan correctly identifies the study as 'observational' and frames claims as 'associational'. However, it proposes using SHAP values to 'identify structural determinants of rate'. SHAP values explain model predictions, not causal drivers. In an observational setting with collinear features (e.g., steric and electronic effects), SHAP may attribute importance to a proxy feature rather than the true causal driver. The methodology must explicitly state that SHAP results are 'model attributions' and not 'causal determinants', and the perturbation study (FR-008) must be designed to test robustness, not causality.
- The plan proposes using Bootstrap to generate confidence intervals for the difference in metrics (MPNN vs. Linear) and claims significance if the 95% CI excludes 0. While valid for a single comparison, the plan also involves hyperparameter optimization (50 configs) and multiple metrics (R², MAE). The methodology does not account for the 'selection bias' introduced by choosing the best hyperparameters based on validation performance. The final test set comparison should be adjusted (e.g., using a nested cross-validation or a hold-out test set that was never used for model selection) to avoid overfitting the test set during the hyperparameter search.
- FR-006 requires sweeping 'descriptor inclusion cutoffs' (threshold-based). The plan (research.md, data-model.md) implements a sensitivity sweep on 'top-k descriptors' (count-based). This is a semantic mismatch; the plan does not address the specific threshold variable mandated by the spec, leaving FR-006 unbacked.
- FR-007 requires flagging VIF > 5 pairs for 'descriptive joint analysis'. The plan (research.md) proposes implementing a 'static dictionary' to generate specific chemical interpretations (e.g., 'Electrophilic potential'). This exceeds the spec's requirement and risks hallucination, failing to provide a task that strictly satisfies the 'flagging' requirement without over-interpretation.
- SC-004 requires measuring SHAP consistency for the model trained on the 'full dataset'. The plan (research.md) proposes re-training on a 'small stratified sample (N=2000/500)' to measure consistency. This changes the experimental condition (data subset vs. full dataset), leaving the specific success criterion unmeasured.
- Edge Cases require filtering based on a 'steric hindrance index > 2.0'. The plan (research.md) defines a custom 'proxy' (LogP + Rotatable Bonds) with a hardcoded threshold of 2.0 but lacks a verification step or justification that this specific proxy/threshold correlates with the exclusion of non-SN1 mechanisms. The plan does not address the validation of this chemical rule.
- FR-001 requires ingesting data from 'NIST/Reaxys/UCI'. The plan (research.md) explicitly states it 'cannot use' NIST/Reaxys because the provided URLs are irrelevant, and relies solely on HuggingFace datasets. The plan does not address the requirement to ingest from the specified sources or provide a formal exception/clarification for the missing sources.
- The plan states: 'If missing [substrate class], we will derive substrate class from the SMILES using RDKit rules (counting carbon neighbors of the leaving group).' This is chemically infeasible for SN1 reactions. The leaving group (e.g., Cl, Br, OH2+) is often implicit or requires specific reaction context to identify. Counting neighbors of an undefined 'leaving group' atom in a static SMILES string without reaction mapping will fail or produce high false positives. The dataset must explicitly provide substrate class labels, or the plan must cite a specific, verified algorithm for reaction-center detection that works on the cited HuggingFace datasets. Relying on an unverified heuristic for a core stratification variable invalidates the study design.
- The plan assumes the 'DTS-SN1-15-01-2024' dataset contains 'Rate Constant' as a direct column. SN1 kinetics are highly dependent on temperature and solvent. If the dataset only provides 'rate' without associated temperature/solvent metadata, the model cannot learn the correct physical relationship (Arrhenius behavior) or generalize. The plan must verify that the cited HuggingFace datasets include explicit temperature and solvent columns, or the model architecture must be fundamentally changed to handle missing covariates (which is not feasible for quantitative prediction). Assuming the variable exists without verification is a fatal data fit error.
- The plan cites 'SN18-All-20240204' (winglian) as a 'Supplemental' source but notes it only has 'SMILES, Rate'. If this dataset lacks temperature/solvent, it cannot be used for quantitative rate prediction (which requires normalization to a standard temperature or explicit modeling of T). Including it without verifying the presence of covariates risks contaminating the training set with non-comparable data points, violating the 'Data Hygiene' principle. The plan must explicitly confirm the schema of this dataset or exclude it.
- The plan states: 'Dataset size ~10k-50k molecules'. The cited HuggingFace datasets (DTS-SN1, SN1-Miner) are likely smaller or have different scales. Asserting a specific size range without citing the source of this estimate (e.g., 'based on the row count of DTS-SN1-15-01-2024 which is X') violates the 'Cite the source, don't pre-assert the number' constraint. If the actual dataset is <1000 rows, the MPNN will overfit; if >50k, the 6-hour CPU limit may be breached. The plan must cite the actual row count of the primary dataset or use '[deferred]' with a citation to the dataset URL.
- The plan states: 'The NIST URLs in the verified block are irrelevant (cybersecurity/LLM data)'. This contradicts the spec's assumption that NIST/Reaxys are valid sources. While the plan correctly pivots to HuggingFace, it should explicitly state that the *specific* NIST URLs provided in the project's 'Verified Datasets' block (if any) were checked and found to be non-kinetic, rather than making a general claim about NIST. This is a minor clarification to ensure the 'Verified Accuracy' principle is strictly followed regarding the specific citations used.

While sampling is not synthetic generation, the plan fails to explicitly define the sampling strategy (e.g., 'stratified by substrate class') in the Plan document itself, relying on the Research doc. However, the plan does not specify *where* these settings are enforced (e.g., `code/config.py` vs `main.py`). Per Principle I, the Plan should explicitly reference the file/line where these determinism controls are implemented to ensure the 'Reproducibility' claim is verifiable.

- The plan validates the MPNN against a 'Linear Regression' baseline using topological indices and Gasteiger charges. However, the MPNN's input features (node/edge attributes) are derived from the *same* chemical graph and descriptors (Gasteiger, topology) used for the linear baseline. If the MPNN simply learns a non-linear mapping of these same inputs, a significant performance gap is expected by definition of model capacity, not necessarily due to capturing 'complex steric effects' distinct from the linear model. The validation lacks a 'null model' that accounts for the specific non-linearities of the descriptor space itself, risking a tautological confirmation that 'complex models beat simple models' without proving the *specific* chemical mechanism is captured better.
- The plan states: 'If a required variable (e.g., specific solvent) is missing... the plan will proceed with the available variables (SMILES, Rate)...' SN1 reaction rates are *fundamentally* dependent on solvent polarity and nucleophilicity (Hammett equation extensions). Training a model on SMILES alone to predict rate constants without solvent covariates is scientifically unsound; the model will learn a noisy average of solvent effects, conflating structural effects with unobserved environmental variables. This violates the independence of predictors from the outcome's true drivers, making the resulting R² metric a measure of 'average solvent noise' rather than 'structural predictability'.
- The plan proposes running VIF on 'Gasteiger charges and topological indices' to flag collinearity. However, Gasteiger charges are *derived* from the molecular graph topology (atom connectivity and electronegativity). They are not independent predictors; they are a mathematical transformation of the same underlying graph structure. Flagging them as 'collinear' is a category error—they are *definitionally* dependent. The analysis should instead test for redundancy between *different* classes of descriptors (e.g., quantum vs. topological), not between a graph and its derived electronic properties.
- The plan uses Bootstrap to generate CIs for (MPNN - Linear) but states 'No family-wise error correction... is strictly required for a single primary comparison.' However, the plan also lists 'R², MAE' as metrics and compares against 'Random' and 'Linear' baselines. This constitutes multiple hypothesis tests (MPNN vs Random on R², MPNN vs Random on MAE, MPNN vs Linear on R², etc.). Failing to correct for multiple comparisons (e.g., Bonferroni or Holm-Bonferroni) inflates the Type I error rate, making the claim of 'statistical significance' (p < 0.05) scientifically unreliable.
- The plan assumes 'substrate class' (secondary/tertiary) can be derived from SMILES using RDKit rules. While often true, SN1 reactivity also depends on resonance stabilization (e.g., benzylic/allylic) and steric bulk that simple 'carbon neighbor counting' may miss. If the derived class is inaccurate, the stratification (FR-002) becomes flawed, leading to data leakage where the model learns the 'derived class' proxy rather than the true kinetic mechanism. The plan lacks a validation step to verify the chemical accuracy of the derived substrate class against known chemical rules.
