# Evaluating the Impact of Code Generation Models on Code Documentation Completeness

A research pipeline to evaluate the effectiveness of code generation models in mono-lingual settings by comparing human-written docstrings with those generated by fine-tuned transformer models.

## Overview

This project implements a comprehensive evaluation framework that:
1. Extracts public method signatures and human-written docstrings from top PyPI repositories
2. Generates docstrings using quantized code generation models (Salesforce/codegen-350M-mono)
3. Calculates Parameter Coverage Scores and performs statistical analysis
4. Produces reproducible research artifacts with strict versioning

## Prerequisites

- Python 3.9+
- pip package manager
- Git (for repository cloning)
- 7GB+ available RAM for model generation
- 14GB+ available disk space

## Usage

### Quick Start

The entire pipeline can be executed by running the following steps in order:

```bash
# Step 1: Generate frozen repository list (20 top PyPI repos)
python code/utils/repo_fetcher.py

# Step 2: Clone repositories
python code/utils/git_clone.py

# Step 3: Extract methods and docstrings
python code/extract.py

# Step 4: Generate docstrings with LLM
python code/generate.py --temperature 0.2 --input-dir data/raw/repos --output-dir data/processed

# Step 5: Post-process (handle empty docstrings)
python code/post_process.py

# Step 6: Aggregate results
python code/aggregate.py

# Step 7: Analyze coverage and statistics
python code/analyze.py --step=coverage
python code/analyze.py --step=similarity
python code/analyze.py --step=stats
python code/analyze.py --report
```

### Individual Module Usage

#### Repository Extraction

```bash
# Extract methods from all repositories in frozen list
python code/extract.py
```

Output: `data/raw/repos/{repo_slug}.json`

#### Docstring Generation

```bash
# Generate docstrings with 4-bit quantization (with fallback)
python code/generate.py --temperature 0.2 --input-dir data/raw/repos --output-dir data/processed
```

Output: `data/processed/generation_batch_{repo_slug}.json`

#### Analysis Pipeline

```bash
# Calculate parameter coverage scores
python code/analyze.py --step=coverage

# Calculate semantic similarity
python code/analyze.py --step=similarity

# Run Wilcoxon statistical test
python code/analyze.py --step=stats

# Generate final report
python code/analyze.py --report
```

Outputs:
- `data/processed/results_with_coverage.json`
- `data/processed/results_with_scores.json`
- `data/processed/results_with_stats.json`
- `data/processed/final_report.json`

## Configuration

### Random Seeds

The project enforces reproducibility through pinned random seeds:
- NumPy
- Python random
- PyTorch
- Transformers

Set via `code/config.py` (default: `SEED = 42`)

### Model Quantization

The pipeline uses 4-bit quantization via `bitsandbytes` with automatic fallback:
1. Attempt 4-bit quantization
2. If failed, attempt 8-bit quantization
3. If failed, attempt full precision
4. If all fail, raise `QuantizationError`

### Memory Limits

Generation is constrained to 7GB RAM. [UNRESOLVED-CLAIM: c_830fff26 — status=not_enough_info] Exceeding this limit triggers:
- Immediate process abort
- Logging to `logs/monitor.log`
- `MemoryLimitException` raised

```

[LLM Generation] → data/processed/generation_batch_{repo_slug}.json

 ↓
[Aggregation] → data/processed/results.json
 ↓
[Analysis] → data/processed/results_with_coverage.json
 ↓
[Similarity] → data/processed/results_with_scores.json
 ↓
[Statistics] → data/processed/results_with_stats.json
 ↓
[Report] → data/processed/final_report.json
```

## Constraints

- **Sample Size**: Maximum 1,000 methods per repository (FR-001)
- **Repository Count**: Exactly 20 repositories (frozen list)
- **Memory Limit**: 7GB RAM during generation
- **Execution Time**: Target < 6 hours on CPU
- **Quantization**: 4-bit preferred, with 8-bit/full precision fallback
- **Temperature**: Fixed at 0.2 for deterministic generation
