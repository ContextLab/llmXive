# Implementation Plan: Evaluating the Impact of Code Generation Models on Code Documentation Completeness

**Branch**: `001-eval-code-doc-completeness` | **Date**: 2026-08-09 | **Spec**: `specs/001-eval-code-doc-completeness/spec.md`

## Summary

This feature implements a reproducible pipeline to evaluate the documentation completeness of code generated by LLMs versus existing human documentation. The technical approach involves:
1.  **Extraction**: Parsing the top 20 Python PyPI repositories using the `ast` module to extract method signatures and existing docstrings, capped at methods per repo (fixed sample).
2.  **Generation**: Loading a CodeGen model in 4-bit quantization on CPU to generate docstrings for the extracted methods with a fixed temperature..
3.  **Analysis**: Calculating a primary **Parameter Coverage Score** (AST-based, using `docstring_parser`) and an auxiliary **Semantic Similarity Score** (embedding-based), followed by a Wilcoxon signed-rank test to determine statistical significance and practical effect size.

## Technical Context

**Language/Version**: Python 3.10+ (required for `ast` compatibility and modern type hint parsing).
**Primary Dependencies**:
-   `datasets` (Hugging Face) for potential data loading (if mirroring used).
-   `transformers`, `torch`, `bitsandbytes` (CPU fallback configured) for model inference.
-   `sentence-transformers` for auxiliary similarity metrics.
-   `docstring_parser` for robust docstring parameter extraction.
-   `scipy` for statistical testing (Wilcoxon).
-   `requests` for API interactions.
-   `pyyaml` for contract validation.
**Storage**: Local JSON files (`data/`) for intermediate datasets; `state/` for versioning hashes.
**Testing**: `pytest` for unit tests on AST parsing and coverage logic; integration tests for the full pipeline on a single repo.
**Target Platform**: GitHub Actions Free Tier (Ubuntu-latest, 2 CPU, ~7GB RAM, CPU-only).
**Project Type**: Data Science / Research Pipeline (CLI scripts).
**Performance Goals**: Complete processing of 20 repos (fixed 100 methods each = 2,000 total) within 6 hours.
**Constraints**:
-   Max a reasonable number of methods per repository (Fixed Sample, per Constitution Principle VII).
-   Maximized RAM usage within feasible system constraints. (Constitution Principle VI, FR-006).
-   Fixed temperature and 4-bit quantization (Constitution Principle VII).
-   No GPU available; CPU-only execution required.
-   **Note**: If 4-bit quantization fails on CPU, the system falls back to 8-bit or full precision to prevent OOM crashes.
**Scale/Scope**: A set of repositories, [deferred] method samples (fixed a priori).

> **Note**: Exact dataset sizes (number of methods found) and empirical coverage rates are deferred to the research phase.
