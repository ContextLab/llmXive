# Implementation Plan: llmXive follow-up: extending "Reproducing, Analyzing, and Detecting Reward Hacking in Rubric-Based R"

**Branch**: `001-llmxive-followup` | **Date**: 2026-07-13 | **Spec**: `specs/001-llmxive-followup/spec.md`
**Input**: Feature specification from `/specs/001-llmxive-followup/spec.md`

## Summary

This feature implements a statistical detector for "reward hacking" in LLM training trajectories by analyzing the divergence gap ($G(t)$) between biased and unbiased reward signals. The system ingests CHERRL training logs, computes time-series divergence metrics, flags anomalies using z-score thresholds, and validates generalization across four rubric types (Lexical, Format, Tone, Self-praise) against ground-truth hacking derived from $J_{\text{gold}}$ drops. The implementation strictly adheres to statistical independence checks (FR-006, FR-008) and runs entirely on CPU within GitHub Actions constraints.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: `pandas`, `numpy`, `scipy` (for Wilcoxon tests), `datasets` (Hugging Face), `pyyaml`, `pytest`  
**Storage**: `data/raw` (downloaded CHERRL logs, checksummed) and `data/processed` (derived divergence signals, labels)  
**Testing**: `pytest` (unit tests for math logic, integration tests for pipeline), `ruff`/`black` for linting  
**Target Platform**: GitHub Actions `ubuntu-latest` (vCPU, 7GB RAM)  
**Project Type**: Data analysis pipeline / Research tool  
**Performance Goals**: Complete analysis of N≥5 seeds within 4 hours; memory usage < 6GB.  
**Constraints**: No GPU; must handle edge cases (zero variance, missing timesteps); strict adherence to data independence (Constitution Principle VI).  
**Scale/Scope**: Processing time-series logs (thousands of timesteps per seed) for 4 bias types across multiple random seeds.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

1.  **Principle I (Reproducibility)**: **PASS**. Plan mandates pinned `requirements.txt`, deterministic random seeds in `code/`, and fetching data from verified arXiv/HuggingFace sources only.
2.  **Principle II (Verified Accuracy)**: **PASS**. Plan requires citation of the CHERRL paper (arXiv:2606.04923) and verified dataset URLs from the input block. No fabricated URLs will be used.
3.  **Principle III (Data Hygiene)**: **PASS**. Plan includes `data/raw` and `data/processed` separation, checksumming of raw downloads, and immutable derivation steps.
4.  **Principle IV (Single Source of Truth)**: **PASS**. All metrics in `quickstart.md` and `research.md` will trace to specific rows in the processed Parquet files generated by the pipeline. The `contracts/metrics.schema.yaml` is designated as the SSoT for metric definitions.
5.  **Principle V (Versioning Discipline)**: **PASS**. Artifacts will carry content hashes; `state` updates will be triggered by artifact changes.
6.  **Principle VI (Statistical Independence)**: **PASS**. The plan explicitly includes FR-006 and FR-008 as blocking gates before ground-truth generation. If $r > 0.8$ (in non-hacked phases for FR-008), the pipeline halts.
7.  **Principle VII (Generalization)**: **PASS**. The evaluation phase (US-3) is designed to calculate F1-scores per rubric type and test for variance $\le 0.15$ (SC-003).
