## Unresolved concerns

- The plan assumes the Million Song Dataset (MSD) provides a `listen_timestamp` per user‑track pair (see Phase 2 T010 and the `ingested_cohort.parquet` schema). In reality, MSD contains only track‑level metadata (e.g., release year, popularity) and does **not** include individual listening events or timestamps. Consequently, the calculated `adolescent_exposure_ratio` cannot be derived from the available data, undermining the construct validity of the primary predictor and rendering the core hypothesis untestable with the proposed data.
- The JSON‑Schema for `data/processed/user_track_pairs_thr{n}.parquet` sets `total_listens` minimum to 3, but FR‑009 (and the specification) require filtering out rows with `total_listens < 5`. This mismatch will cause schema validation failures and violates the functional requirement. Adjust the schema minimum to 5 (or remove the minimum constraint) to align with the spec.
- The plan cites the Million Song Dataset (MSD) as the source of user‑track listen timestamps (see T001 – `https://huggingface.co/datasets/MSD-Team/LLMTest/resolve/main/LLMPersian_Train.jsonl`). MSD contains only track metadata and audio features; it does **not** include per‑user listening histories or timestamps required to compute the adolescent exposure ratio. Using MSD therefore cannot satisfy FR‑001 (adolescent_exposure_ratio) and makes the core research question unanswerable with the cited data.
- The `total_listens` field in `contracts/dataset.schema.yaml` has `minimum: 3`, but the plan (FR‑009) requires filtering out rows with `total_listens < 5`. This creates a contradiction: the schema would accept values 3‑4 that the plan later deems invalid.
- In Phase 4 (Task T030) the plan states: "Filters out rows with `total_listens < 5` (FR‑009)." This minimum listen threshold conflicts with the `minimum: 3` constraint defined in the dataset contract, leading to inconsistent validation rules.
- The plan applies a logit transformation to `adolescent_exposure_ratio` without handling boundary cases where the ratio equals 0 or 1. Logit(0) and logit(1) are undefined (→ ‑∞/∞), which will cause model fitting to fail or produce extreme coefficient estimates. A standard practice is to apply a continuity correction (e.g., `logit((ratio*(N‑1)+0.5)/N)`) or to exclude/adjust rows with ratio = 0 or = 1 before transformation. This methodological omission could invalidate the primary hypothesis test.
