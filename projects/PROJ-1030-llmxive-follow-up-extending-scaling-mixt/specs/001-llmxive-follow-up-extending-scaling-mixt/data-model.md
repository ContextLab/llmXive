# Data Model: llmXive follow-up: extending "Scaling Mixture-of-Experts Video Pretraining for Embodied Intelligence"

## Overview

This document defines the data structures used for feature extraction, label generation, and model training. All data is stored in `data/processed/` with checksums recorded in `state/`. Raw data checksums are stored in `data/raw/.checksums.json`.

## Entities

### 1. VideoClip
**Description**: A temporal sequence of frames representing a robot action.
**Source**: BridgeData V2 / RoboNet.
**Fields**:
- `clip_id`: `string` (Unique identifier)
- `video_path`: `string` (Local path or stream URL)
- `frame_count`: `integer`
- `resolution`: `tuple(int, int)`
- `action_type`: `string`

### 2. ActivationPattern
**Description**: High-dimensional internal state of the Video Model.
**Source**: `extract_features.py`.
**Fields**:
- `clip_id`: `string` (FK to VideoClip)
- `latent_vector`: `array(float32)`
- `expert_mask`: `array(bool)`
- `layer_index`: `integer`
- `extraction_timestamp`: `timestamp`
- `chunk_index`: `integer`

### 3. EstimatedState3D
**Description**: Reconstructed 3D state estimates derived from video (Intermediate Artifact).
**Source**: `generate_labels.py` (Monocular Depth Estimator).
**Fields**:
- `clip_id`: `string` (FK to VideoClip)
- `depth_map`: `array(float32)`
- `camera_pose`: `array(float32)`
- `object_poses`: `array(float32)`
- `confidence_score`: `float`
- `kinematic_valid`: `boolean` (True if trajectory continuity check passed)

### 4. PhysicalLabel
**Description**: Ground-truth validity label generated by physics simulation (Final Output).
**Source**: `generate_labels.py` (PyBullet Simulation).
**Fields**:
- `clip_id`: `string` (FK to VideoClip)
- `label`: `enum` ({"valid", "invalid", "null"})
- `violation_type`: `string`
- `simulation_success`: `boolean`
- `reconstruction_confidence`: `float`
- `kinematic_valid`: `boolean` (Inherited from EstimatedState3D)

### 5. ClassifierInput
**Description**: Aggregated dataset for training.
**Source**: `train_classifier.py`.
**Fields**:
- `features`: `array(float32)`
- `target`: `integer`
- `clip_id`: `string`

## Data Flow Diagram

1.  **Raw Data**: `BridgeData` -> `Streamed Video Clips` (Temp) -> **Checksum Generated** -> `data/raw/.checksums.json`
2.  **Feature Extraction**: `Video Clips` -> `ActivationPattern` (NumPy)
3.  **Label Generation**: `Video Clips` -> `EstimatedState3D` (Intermediate, includes kinematic check) -> `PhysicalLabel` (CSV)
4.  **Training**: `ActivationPattern` + `PhysicalLabel` -> `ClassifierInput`
5.  **Output**: `Model Weights` + `Metrics Report`

## Storage Constraints & Strategies

-   **Memory Management**:
    -   `ActivationPattern` and `EstimatedState3D` are **not** stored in memory simultaneously for all clips.
    -   Processing is done in **chunks**.
    -   Intermediate results are written to disk immediately.
-   **Disk Usage**:
    -   Raw video clips deleted after processing.
    -   Checksums recorded in `data/raw/.checksums.json` and merged into `state/manifest.yaml`.
    -   Total expected disk usage: < 5 GB.

## Data Validation Rules

-   `confidence_score` in `EstimatedState3D` must be >= 0.0 and <= 1.0.
-   `kinematic_valid` must be `true` for a sample to receive a "valid"/"invalid" label.
-   `label` in `PhysicalLabel` must be one of {"valid", "invalid", "null"}.
-   `clip_id` must be unique across all entities.
-   `expert_mask` must be binary (0 or 1).
