## User Scenarios & Testing

### User Story 1 - Feature Extraction from LingBot-Video (Priority: P1)

The researcher MUST be able to download the pre-trained LingBot-Video model and a subset of video clips, then extract latent activation vectors and expert activation masks from intermediate DiT layers for each clip on a CPU-only environment without GPU acceleration.

**Why this priority**: This is the foundational data generation step. Without extracting the internal states (predictors) from the foundation model, no analysis can occur. It directly addresses the core hypothesis that physical laws are encoded in these specific latent patterns.

**Independent Test**: A script can be run that downloads the model and a set of sample clips, extracts the features, and saves them as NumPy arrays. The test passes if the script completes within 2 hours on a standard CPU runner (4 vCPU, x86_64 architecture) and produces non-empty arrays with the expected dimensions.

**Acceptance Scenarios**:
1. **Given** the LingBot-Video model weights and a video dataset are available, **When** the extraction script runs on a CPU-only environment with `torch.no_grad()`, **Then** it outputs a NumPy file containing latent vectors and binary expert masks for all processed clips.
2. **Given** the extraction process is running, **When** the system encounters a video clip that exceeds the 7 GB RAM limit, **Then** the system must process the clip in smaller temporal chunks or subsample frames to stay within memory bounds, ensuring the job does not crash.
3. **Given** the model is loaded, **When** the script attempts to access intermediate DiT layers, **Then** it successfully retrieves the specific expert activation masks without requiring full video generation or decoding.

### User Story 2 - Independent Ground-Truth Labeling via 3D Reconstruction (Priority: P2)

The system MUST generate ground-truth labels ("valid" or "invalid" physical states) for the extracted video clips by first reconstructing 3D state estimates (positions, velocities) using a monocular depth/pose estimator, and then running these estimates through a separate, lightweight CPU-based physics simulation engine (e.g., PyBullet). This ensures labels are independent of the foundation model's internal states while acknowledging the necessity of 3D reconstruction.

**Why this priority**: This establishes the target variable for the classification task. The validity of the study depends on the labels being generated by a distinct computational process (physics engine) based on reconstructed 3D states, preventing circularity with the foundation model's latent space.

**Independent Test**: A script can be run that takes the video clips, runs them through the reconstruction pipeline to get 3D states, and then runs the physics simulation. The test passes if it outputs a CSV or JSON file with binary labels for each clip, and the labels differ for clips with known physical violations (e.g., gravity defiance) vs. valid clips.

**Acceptance Scenarios**:
1. **Given** a set of video clips representing robot actions, **When** the physics simulation engine runs on CPU using reconstructed 3D states, **Then** it outputs a binary label indicating whether the action resulted in a physical constraint violation (e.g., object interpenetration).
2. **Given** a clip with a known physical violation (e.g., object floating), **When** the simulation runs on the reconstructed state, **Then** the generated label must be "invalid" with [deferred] consistency.
3. **Given** the simulation engine is running, **When** the physics step fails due to numerical instability or the reconstruction confidence is below a predefined threshold., **Then** the system logs the error, assigns a "null" label, and excludes that sample from the final training set to prevent label noise.

### User Story 3 - Lightweight Classifier Training & Evaluation (Priority: P3)

The system MUST train a shallow Multi-Layer Perceptron (MLP) or Random Forest classifier on CPU using the extracted activation patterns as input and the simulation-derived labels as targets, achieving an F1-score ≥ 0.75 on a held-out test set (temporally split, [deferred] of data), and report feature importance.

**Why this priority**: This validates the hypothesis. If the classifier cannot predict validity from the internal states, the hypothesis is falsified. This step delivers the final research result.

**Independent Test**: A training script can be run that ingests the features and labels, trains the model, and outputs evaluation metrics (F1-score, precision, recall, class balance) and a feature importance plot. The test passes if the model trains in <30 minutes and achieves F1-score ≥ 0.75 (or explicitly reports the null result if accuracy is near random).

**Acceptance Scenarios**:
1. **Given** the feature matrix and label vector, **When** the classifier trains on a CPU with a small grid search (e.g., a limited set of hyperparameter combinations), **Then** the training completes within 30 minutes.
2. **Given** the trained model, **When** it is evaluated on a held-out test set ([deferred] stratified by clip duration and object type), **Then** it reports F1-score, precision, and recall metrics.
3. **Given** the model is trained, **When** the analysis script runs, **Then** it visualizes the most important expert activations, identifying if specific sub-networks correlate with physical violations.

### Key Entities

- **VideoClip**: A temporal sequence of frames representing a robot action, identified by a unique ID.
- **EstimatedState3D**: A vector of 3D positions, velocities, and orientations inferred from the video clip using a monocular depth/pose estimator.
- **ActivationPattern**: A high-dimensional vector and binary mask representing the internal state of the LingBot-Video model for a specific clip.
- **PhysicalLabel**: A binary value ("valid" or "invalid") indicating whether the action in the clip violates physical constraints, generated by an external physics engine based on `EstimatedState3D`.
- **ClassifierModel**: A lightweight machine learning model (MLP or Random Forest) trained to predict `PhysicalLabel` from `ActivationPattern`.

## Assumptions

- The LingBot-Video model weights and the associated dataset (or a valid proxy like RoboNet) are publicly available and can be downloaded via `wget` within the CI runner's 10 GB disk limit.
- The CPU-based physics simulation engine (e.g., PyBullet) can generate valid labels for the selected video clips within a feasible job limit, even for the full a large-scale clip subset, provided the 3D reconstruction step is successful.
- The internal activation patterns of the LingBot-Video model contain sufficient information to predict physical validity; if the model learns no such representation, the study will correctly report a null result (accuracy near random).
- The video clip subset is representative of the broader domain of embodied intelligence tasks and contains a sufficient mix of valid and invalid physical states for training.
- The "expert activation masks" are accessible via the model's standard inference API without requiring modifications to the model architecture or retraining.
- The physics simulation engine is deterministic enough to produce consistent labels for the same input clip across runs, ensuring label stability.
- The dataset variables (video frames) contain sufficient visual information to allow a monocular depth/pose estimator to reconstruct 3D state variables (positions, velocities) required to simulate the physical constraints of interest (gravity, collision).
- The 3D reconstruction process is robust enough that samples with confidence <0.9 are rare enough not to compromise the statistical power of the final analysis.
