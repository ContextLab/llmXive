## Unresolved concerns

- FR-001 and FR-008 require the system to flag records missing 'degradation pathway' labels for manual curation or exclusion (and halt if ALL are missing). T013's logic explicitly generates a synthetic dataset with a deterministic seed as a fallback when APIs fail, effectively bypassing the mandatory validation and curation workflow described in the spec. There is no task covering the 'flag for curation' step for missing labels in the real data scenario.
- T014 implements a 'Halt Condition' that raises a `FatalError` if *all* records are missing labels. This contradicts FR-008 which mandates that if labels are missing, the system MUST apply a synthetic label distribution or flag for curation (and only halt if *no* records exist or if the *entire* dataset fails validation after the synthetic application attempt). The task logic is missing the 'apply synthetic labels' step for the partial-missing case.
- FR-004 explicitly requires data augmentation via 'edge dropout and subgraph sampling' to expand the training set. T025's verification logic only checks that the final row count is 'exactly 2x' the input, failing to verify that the specific *methods* (edge dropout and subgraph sampling) were actually used. A task covering the verification of the *method* (not just the count) is missing.
- SC-004 requires a power analysis 'calculated via G*Power simulation'. T017a explicitly proposes an amendment to use `statsmodels` as a proxy and T017b executes this proxy. However, there is no task covering the *ratification* of this amendment proposal in Phase 2 (Foundational) as required by the plan's 'Ratification' section. The amendment proposal exists in T017a but the ratification step is missing.
- FR-006 and SC-002 require a χ² statistical test with ≥1000 iterations for null distribution generation to validate structure-mechanism relationships. T029b implements a 'Null Distribution Generation' task specifically for *ester bonds* only via edge feature shuffling. There is no task covering the generation of the null distribution for *all* identified structural motifs as required by the broader spec.
- Constitution I (Reproducibility) and II (Verified Accuracy) require pinned seeds and verified execution. T001b (Generate `state/setup_log.txt`) and T008 (Setup pytest framework with seed pinning) are marked as failed/missing artifacts (no `setup_log.txt`, no `conftest.py` with seed pinning). The tasks exist but are marked as incomplete/failed, meaning the foundational reproducibility constraints are not currently satisfied in the task list.
- SC-005 requires verifying that Integrated Gradients identifies ester bonds in the top attribution scores for ≥90% of hydrolysis cases. T030 relies on a 'Manually Curated Proxy' subset generated by T030a (rule-based logic) rather than the 'manually curated subset of ≥10 hydrolylysis cases' or 'topological consistency check' explicitly defined in the spec. The task for the 'topological consistency check' (if labels are synthetic) is missing.
- Tasks T053 and T054 are marked as 'REMOVED' in the 'Revision Concerns' section. However, the 'Implementation Phases' in plan.md still list T053 and T054 as active tasks in Phase 5. This creates a stale tag situation where the tasks.md says they are removed, but the plan.md implies they are still part of the implementation. The tasks should be fully removed from the list or the plan should be updated.
- T013 (Ingest) attempts to generate synthetic data as a fallback BEFORE T014 (Label Identification) runs. This violates the 'Producer before Consumer' flow: T013 produces the raw dataset, but T014 is required to identify missing labels and trigger the synthetic label application logic. T013's description implies it applies synthetic labels immediately upon API failure, bypassing the explicit validation and flagging workflow defined in T014 and FR-008. The order must be: T013 (Download) -> T014 (Identify Missing) -> T013/T014 (Apply Synthetic).
- T014 (Identify Missing Labels) depends on T013, but T013's description states it 'generate[s] synthetic data... as a fallback' and 'Apply[s] synthetic labels' if APIs fail. This creates a circular dependency or a logic break: if T013 already applied synthetic labels, T014 has nothing to identify. The flow must be strictly: T013 (Download/Save Raw) -> T014 (Scan for Missing) -> T014 (Apply Synthetic/Flag) -> T015 (Preprocess). T013 must NOT apply labels; it must only save raw data.
