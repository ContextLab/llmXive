# Research: llmXive follow-up: extending "The Mirage of Optimizing Training Policies: Monotonic Inference Polici"

## Problem Statement

The "Mirage of Optimizing Training Policies" suggests that optimizing training policies without considering inference quantization leads to suboptimal performance. This project investigates whether **training-side signals** (gradient norms, local curvature) can predict the **hardware-measured policy gap** (KL divergence between full-precision and quantized outputs). If successful, this enables a "Monotonic Inference Policy" (MIPU) loop that avoids expensive synchronous hardware checks.

## Methodology Sketch

1.  **Data Generation (US-001)**:
    *   Select a representative subset of prompts (e.g., GSM8K).
    *   **Full-Precision Run**: Compute gradient norms and local curvature (Hessian diagonal approximation) for each prompt using a full-precision model (e.g., Llama-3-8B). The model is fine-tuned on GSM8K using next-token prediction loss to generate gradients.
    *   **Quantized Run**: Execute inference on the same prompts using a CPU-based quantized engine (`llama.cpp` or ONNX Runtime) for INT4, INT8, and FP8.
    *   **Ground Truth**: Calculate exact KL divergence between full-precision and quantized logits. A 'quantization noise' feature is generated by subtracting the full precision logits from the quantized ones.
    *   **Output**: A `training_sample.parquet` with features (`grad_norm`, `curvature`) and targets (`kl_div_int4`, `kl_div_int8`, `kl_div_fp8`).

2.  **Predictor Training (US-002)**:
    *   **Model**: Kernel Ridge Regression (KRR) or small MLP (CPU-tractable).
    *   **Training Strategy**: Joint training on data from all three quantization levels (INT4, INT8, FP8) with stratified splitting to ensure representation.
    *   **Features**: Principal components of gradient norms and curvature.
    *   **Target**: Log-transformed KL divergence (normalized).
    *   **Validation**: Pearson correlation (r > 0.8) on held-out test set.

3.  **Bound Verification & Statistical Validation (US-003)**:
    *   **Bound Check**: Verify |predicted - actual| < 0.1 (normalized) for all levels.
    *   **Consistency**: Report correlation consistency across INT4, INT8, FP8.
    *   **MIPU Simulation**: Run a small-scale RL task comparing the proxy-based loop vs. the full-hardware-sync baseline.
    *   **Statistical Test**: Paired t-test (with Bonferroni correction) on final reasoning scores.

## Dataset Strategy

| Dataset | Source/URL | Usage | Verification |
|---------|------------|-------|--------------|
| **GSM8K** | `datasets.load_dataset("gsm8k", "main")` | Prompt source for inference and gradient extraction. | Verified via Hugging Face `datasets` library. |
| **Llama-3-8B** | `huggingface.co/meta-llama/Meta-Llama-3-8B` | Base model for full-precision and quantized inference. | Verified via Hugging Face Hub. |
| **Quantization Engines** | `llama-cpp-python` (CPU) or `onnxruntime` | Ground-truth generation (INT4/8/FP8). | Verified via pip install; no external dataset URL needed. |

**Note on Data Availability**: The project relies on **open, directly-downloadable datasets** (GSM8K, Llama-3-8B). No access-gated data (e.g., ADNI, UK Biobank) is used. The quantized inference engine (`llama.cpp`) is a software tool, not a dataset, and runs locally on the CI runner.

**Dataset Fit**: The GSM8K dataset is selected for its reasoning tasks, which are sensitive to quantization artifacts. The Llama-3-8B model is accessible via Hugging Face and supports the required quantization levels via `llama.cpp`.

**Feasibility**: The full dataset is streamed or sampled to fit within 7GB RAM. If the full GSM8K set is too large, a statistically powered sample (n ≥ 300) is used, with power limitations acknowledged.

## Decision/Rationale

**CPU-First Approach**:
*   **Rationale**: The primary analysis (KRR training, statistical tests) is computationally lightweight and runs efficiently on CPU.
*   **GPU Escape Hatch**: If `llama.cpp` inference for 8B models exceeds the 6-hour limit on CPU, the execution stage auto-offloads to a Kaggle GPU.

**Quantization Levels (INT4, INT8, FP8)**:
*   **Rationale**: These levels represent the current state-of-the-art for edge and server inference. Testing consistency across them ensures the bound is robust, not an artifact of a single quantization scheme.

**Statistical Rigor**:
*   **Multiple Comparisons**: Bonferroni correction applied to p-values from t-tests.
*   **Collinearity**: PCA used to address potential collinearity between gradient norms and curvature.
*   **Causal Claims**: The study is observational; claims are framed as associational (training signals *correlate* with hardware gaps), not causal.

## Assumptions & Risks

*   **Assumption**: GSM8K prompts are representative of the reasoning tasks required to stress-test the quantization gap, and a pre-trained Llama-3-8B model is accessible via Hugging Face.
*   **Risk**: If `llama.cpp` fails to load specific quantization formats on the CI runner, the system logs the error and skips the sample (Edge Case handling).
*   **Risk**: If the dataset lacks sufficient non-zero divergence cases (e.g., simple prompts), the statistical power may be low. A sensitivity analysis will be performed to adjust the sample size or prompt selection.
