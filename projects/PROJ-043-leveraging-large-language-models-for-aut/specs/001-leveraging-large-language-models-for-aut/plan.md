# Implementation Plan: Leveraging LLMs for Automated Code Refactoring

**Branch**: `001-leveraging-llm-refactoring` | **Date**: 2026-07-14 | **Spec**: `specs/001-leveraging-llm-refactoring/spec.md`
**Input**: Feature specification from `specs/001-leveraging-llm-refactoring/spec.md`

## Summary

This project implements an observational study to determine if structural characteristics of Python functions (LOC, nesting depth, etc.) predict the magnitude of *relative* improvement when refactored by the WizardCoder-Python-13B LLM. The pipeline downloads a sample of Python functions from the BigCode dataset, computes static metrics, invokes the LLM for zero-shot refactoring and a null baseline, calculates *relative* delta metrics (to avoid circularity), and fits a Ridge Regression model (for continuous scores) and a GLM (for count data) with robust standard errors. The study is constrained to CPU-first execution on GitHub Actions, using the HuggingFace Inference API for the LLM and local static analysis tools (`radon`, `pylint`).

**Methodological Correction**: The specification (FR-005) requests a "paired t-test". However, since the null baseline is an identity transformation (Delta=0), a paired t-test against a variable baseline is methodologically trivial. This plan implements a **one-sample t-test** against zero, which is the statistically correct approach for this design. This deviation is documented to ensure scientific validity.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: `datasets` (HuggingFace), `transformers`, `radon`, `pylint`, `scikit-learn`, `statsmodels`, `pandas`, `numpy`, `requests`, `glm` (for GLM).  
**Storage**: Local filesystem (`data/` for raw/processed JSON/CSV, `cache/` for API responses).  
**Testing**: `pytest` (unit tests for metric calculation, integration tests for pipeline flow).  
**Target Platform**: Linux (GitHub Actions free-tier runner).  
**Project Type**: Research pipeline / CLI tool.  
**Performance Goals**: Complete sampling (400 attempts) and analysis within 6 hours; API latency < 60s per call with retry logic.  
**Constraints**: No local GPU; strict memory limit (constrained RAM); API rate limits handled via exponential backoff and batching.  
**Scale/Scope**: A subset of valid functions retained for final analysis. (minimum 100 required to proceed).

**Dataset Strategy**:
- **Primary Source**: `bigcode/the-stack-dedup` (canonical BigCode product).
- **Verification Constraint**: The prompt's "Verified datasets" block notes "BigCode: NO verified source found". The implementation will attempt the canonical HuggingFace path. **Critical**: If this path is inaccessible or fails validation, the pipeline will **halt with a clear error** (Hard Failure). It will NOT switch to `codeparrot-clean` or any other dataset, as this would violate FR-001 and Constitution Principle II (Verified Accuracy) by introducing an unverified distribution shift.
- **Sampling**: Random sampling of up to 400 attempts. Stops early if a sufficient number of valid functions are found.

**API Strategy**:
- **Endpoint**: HuggingFace Inference API for `WizardCoder-Python-13B`.
- **Feasibility Check**: **Critical Feasibility Note**: The WizardCoder-13B model is typically a local model requiring significant GPU VRAM or a specific paid/inference endpoint. The plan assumes the free-tier GitHub Actions CPU can run this via API. **If the specific API endpoint URL is unavailable, paid, or rate-limited beyond retries, the pipeline halts.** No silent fallback to a smaller model is permitted as it would alter the experimental intervention.
- **Batching**: To comply with Constitution Principle VII (API-Efficiency), the pipeline groups functions into **batches of ≤10** for API requests. Each batch is sent sequentially with exponential backoff on rate limits.
- **Caching**: All API responses are cached by function hash to disk (`data/cache/`) to prevent redundant calls.

## Constitution Check

*GATE: Must pass before Phase 0 research.*

1.  **Principle I (Reproducibility)**: Plan includes `requirements.txt` with pinned versions and random seed pinning (`numpy`, `random`, `datasets`). Data is fetched from canonical sources (HuggingFace) on every run.
2.  **Principle II (Verified Accuracy)**: The pipeline attempts the canonical BigCode path. **If the "Verified datasets" block in the prompt implies this path is invalid, the run halts.** No fabricated URLs are used. No fallback to unverified sources.
3.  **Principle III (Data Hygiene)**: Intermediate results (raw JSON, refactored code, metrics) are cached to `data/` with checksums. No in-place modification of raw data.
4.  **Principle IV (Single Source of Truth)**: All metrics (R², p-values) in the final output will be generated by `code/` scripts and stored in `data/`; no hand-typed numbers in `paper/`.
5.  **Principle V (Versioning)**: Artifact hashes will be recorded in the project state file.
6.  **Principle VI (Static-Analysis Grounding)**: Predictors (LOC, nesting) are derived strictly via `radon` and `ast` parsing on raw text, independent of LLM output.
7.  **Principle VII (API-Efficiency)**: Caching by function hash is implemented. **Batch processing of ≤10 functions per request is enforced.** Retry logic (limited number of attempts, exponential backoff) is included.
