# Implementation Plan: Evaluating the Impact of Code Generation Models on Code Testability

**Branch**: `294-evaluating-the-impact-of-code-generation` | **Date**: 2026-06-25 | **Spec**: `specs/294-evaluating-the-impact-of-code-generation/spec.md`
**Input**: Feature specification from `/specs/294-evaluating-the-impact-of-code-generation/spec.md`

## Summary

This project evaluates whether code generated by Large Language Models (LLMs) exhibits different structural testability properties compared to human-written reference solutions. The technical approach involves downloading the HumanEval benchmark (pinned to a specific commit), generating code using the Salesforce/codegen-mono-4b model (Primary) and a quantized CodeLlama-3B model (Sensitivity), executing test suites to measure **Dynamic Branch Coverage** (via `coverage.py`) and functional correctness, and computing structural metrics (Cyclomatic Complexity, Static Branch Count via `radon`). Statistical significance is assessed via Wilcoxon Signed-Rank tests on the paired differences for valid pairs, with a primary analysis on the full sample (including failed code) to avoid selection bias. Sensitivity analysis includes Levene's Test for variance differences and a post-hoc power analysis (Achieved Power) with Confidence Intervals.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Dual Metric Approach (Static vs Dynamic) | Required to resolve construct validity. Static analysis cannot measure coverage. | Using only static analysis would fail the Constitution VI mandate and the research question on 'testability'. |
| Full-Sample Analysis | Required to avoid collider bias from filtering by correctness. | Filtering by `pass_rate` creates a non-comparable subset (Correct Human vs Correct LLM), distorting the relationship between source and complexity. |
| Deterministic CPU Fallback | Required to ensure pipeline completion on free-tier CI. | Relying on external GPU offload is non-deterministic and risks failure. The 350M model is verified to fit. |

## Compute Feasibility Strategy

- **CPU-First**: The pipeline is designed for a constrained CPU and RAM environment.
  - **Data**: HumanEval (a standardized benchmark of coding tasks) is small (<10MB).
  - **Generation**: 
    - **Primary**: `Salesforce/codegen-mono-4b` (8-bit) is attempted first. 
    - **Deterministic Fallback**: If OOM or timeout occurs, the script automatically switches to `Salesforce/codegen-mono-350M` (verified to fit <2GB RAM on CPU). This ensures the pipeline completes within 6 hours without external dependencies.
  - **Analysis**: `radon` and `coverage.py` are lightweight. `scipy` is CPU-optimized.
- **GPU Escape Hatch**: Optional offload to Kaggle if `KAGGLE_USERNAME` is set, but not required for completion.

## Data Availability Strategy

- **Source**: `openai/openai_humaneval` on HuggingFace (verified URL: `https://huggingface.co/datasets/openai/openai_humaneval`).
- **Download**: Programmatic via `datasets` library. No manual portal interaction.
- **Streaming**: Not required for a subset of tasks, but `streaming=True` is supported if the dataset grows.
- **Integrity**: SHA256 checksums verified against the specific commit hash.
- **Dataset Size**: A set of tasks (Source: Chen et al., HuggingFace Dataset Card).

## Missing Data & Bias Analysis Protocol

1.  **MCAR Test**: Perform Little's test on task difficulty proxies (e.g., prompt length) to check if missingness (generation failure) is random.
2.  **Bias Analysis**: If non-random, compare the distribution of task difficulty between included and excluded pairs.
3.  **Reporting**: Report the direction and magnitude of potential bias. If significant, the primary analysis will use the Full Sample (all code) with robust methods, and the "Correct Code Only" analysis will be labeled as a sensitivity check with limitations.
4.  **Missing Metrics**: If `radon` fails to parse code, record as `null`. Perform a bias analysis comparing task difficulty between valid and invalid metrics. Use median imputation only if MCAR is supported; otherwise, report as missing with a limitation.
