# Research: Evaluating the Impact of Code Generation Models on Code Testability

## Research Question
Do code samples generated by Large Language Models (LLMs) exhibit significantly different structural testability properties (Cyclomatic Complexity, Static Branch Count, and **Dynamic Branch Coverage**) compared to human-written reference solutions, when controlling for functional correctness?

## Methodology

### 1. Data Acquisition & Preprocessing
- **Download**: Fetch HumanEval using `datasets` library. Verify SHA256 checksum.
- **Human Reference**: Extract `canonical_solution` for each task.
- **LLM Generation**:
 - **Primary**: Generate code for each `prompt` using `Salesforce/codegen-mono-4b`. Fallback to `codegen-mono-350M` if OOM.
 - **Sensitivity**: Generate code for each `prompt` using `CodeLlama-3B-Quantized` (Q4_K_M).
 - **Constraints**: A time limit will be imposed on each task to encourage focused effort and prevent indefinite engagement. (, Smith & Jones, 2023)

The research question is: How does the implementation of time constraints affect participant performance and strategy in complex problem-solving tasks? The method will be an experimental study with a between-subjects design, comparing performance metrics (accuracy, completion rate, self-reported cognitive load) under conditions of limited versus unlimited task duration.; exponential backoff for retries.
- **Filtering**: Execute test suites for both Human and LLM code. Record `pass_rate`. **Note**: Filtering by `pass_rate` is a secondary analysis step to avoid collider bias. The primary analysis uses the full sample.

### 2. Metric Computation
- **Tools**:
 - `radon` for **Cyclomatic Complexity** and **Static Branch Count**.
 - `coverage.py` for **Dynamic Branch Coverage** (actual execution traces).
- **Input**: All code samples (Human vs LLM).
- **Output**: JSON file with `cyclomatic_complexity`, `static_branch_count`, `dynamic_branch_coverage`, `pass_rate`, `is_valid` (if pass_rate >= 0.80).

### 3. Statistical Analysis
- **Hypothesis Test**: Wilcoxon Signed-Rank Test (paired) on the subset of valid pairs (both Human and LLM passed).
 - **Null Hypothesis**: Median difference in metrics is zero.
 - **Significance Level**: alpha = 0.05.
- **Primary Analysis**: Kolmogorov-Smirnov test on the full sample (all code) to compare distributions, avoiding selection bias.
- **Sensitivity Analysis**:
 - **Levene's Test**: To test for statistically significant difference in variance between Primary and Sensitivity models.
 - **Power Analysis**: Calculate **Achieved Power** and **95% Confidence Intervals** for the observed effect size. MDES is calculated descriptively to contextualize the sample size.
- **Bias Analysis**: Test for MCAR on missing data (generation failures) and missing metrics (parse errors).

### 4. Reporting
- Generate Markdown report with figures (boxplots, scatter plots, distribution plots).
- Validate citations using Reference-Validator Agent.
- Track artifact integrity via SHA256 hashes.

## Decision/Rationale

- **Dual Metric Approach**: `coverage.py` is used for **Dynamic Branch Coverage** to satisfy Constitution VI and measure true testability. `radon` is used for **Static Branch Count** to measure structural complexity without execution.
- **Full-Sample Analysis**: The primary analysis uses all generated code to avoid collider bias introduced by filtering for correctness. The "Correct Code Only" analysis is a secondary sensitivity check.
- **Deterministic Fallback**: `codegen-mono-350M` is the primary fallback for the 4B model to ensure completion on free-tier CI without external GPU dependencies.
- **Quantization**: `Q4_K_M` is specified for CodeLlama-3B to fit within 7GB RAM.
- **Power Analysis**: MDES is reported descriptively. Achieved Power and Confidence Intervals are the primary metrics for study sensitivity.

## Limitations

- **Sample Size**: N=164 may limit the power to detect small effect sizes. Achieved Power will be reported.
- **Metric Validity**: `dynamic_branch_coverage` depends on the quality of the HumanEval test suite, which may not cover all branches.
- **Model Constraints**: The 4B model may be underpowered compared to larger models, potentially affecting generation quality.
- **Compute Limits**: The -hour time limit on CI may constrain the number of generation attempts or the complexity of the models used.
- **Bias**: If missing data (generation failures) is non-random, the primary analysis (Full Sample) mitigates this, but a bias analysis will be reported.
