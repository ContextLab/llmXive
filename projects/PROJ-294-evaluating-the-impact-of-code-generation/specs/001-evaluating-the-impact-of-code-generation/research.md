# Research: Evaluating the Impact of Code Generation Models on Code Testability

## Objective

To determine if code generated by LLMs (specifically Salesforce/codegen-mono) exhibits statistically significant differences in structural complexity and test suite sensitivity compared to human-written reference solutions in the HumanEval benchmark.

**Note on Scope**: The study measures "Code Complexity" (Cyclomatic, Halstead) and "Test Suite Sensitivity" (Coverage/Pass Rate relative to the fixed oracle). It does not claim to measure intrinsic "testability" (ease of testing) as the metrics are constrained by the fixed test harness.

## Methodology

### 1. Data Acquisition
- **Dataset**: HumanEval (164 tasks).
- **Source**: `openai/openai_humaneval` via HuggingFace Datasets.
- **Verification**: SHA256 checksums of downloaded files will be verified against known values.
- **Fields**: `task_id`, `prompt`, `canonical_solution`, `test`, `entry_point`.

### 2. Code Generation
- **Model**: `Salesforce/codegen-mono-4b-multi` (or similar variant available on HF).
- **Strategy**: Generate one solution per task.
- **Constraints**:
  - Max tokens: a constrained limit.
  - Temperature: deterministic-ish.
  - Retry logic: A limited number of attempts on failure.
- **Sensitivity Analysis**: Repeat generation with `CodeLlama-7b` (quantized) to assess model variance.

### 3. Metrics Calculation
- **Cyclomatic Complexity**: `radon.cc` (McCabe).
- **Halstead Volume**: `radon.halstead`.
- **Branch Coverage**: `coverage.py` (potential branch coverage). *Note: This measures the test suite's ability to cover branches, not the code's intrinsic testability.*
- **Pass Rate**: Execute `test` strings against generated code. **Binary**: 1.0 if all tests pass, 0.0 otherwise (including syntax errors).

### 4. Statistical Analysis
- **Tests**:
  - **Wilcoxon Signed-Rank**: Paired comparison of continuous metrics (Complexity, Halstead).
  - **McNemar**: Paired comparison of binary outcomes (Pass/Fail). **Handling of Failed Generation**: Syntax errors and non-executable code are treated as "Fail" (0) to preserve the paired nature of the data and avoid exclusion bias.
  - **Fisher's Exact**: Alternative for small sample sizes (if needed).
  - **Permutation Test**: Non-parametric validation of differences.
- **Power Analysis**:
  - **Sensitivity Analysis (MDES)**: Calculate the Minimum Detectable Effect Size given N=164 and alpha=0.05. (A Priori is invalid for fixed N).
  - **Post-Hoc**: Calculate achieved power given N=164.
- **Multiple Comparisons**: Apply Bonferroni correction for family-wise error rate.
- **Collinearity**: Check Variance Inflation Factor (VIF) for Complexity and Halstead. If VIF > 5, use Principal Component Analysis (PCA) to derive a composite "Complexity" score or report them as a single correlated dimension.
- **Caveats**: 
  - **Test Suite Limitations**: McNemar's test results are conditional on the HumanEval test suite's sufficiency. Differences may reflect the test suite's limitations rather than intrinsic model properties.
  - **Metric Definition**: Pass Rate is a measure of functional correctness, not testability.

## Statistical Rigor & Feasibility

- **Multiple Comparisons**: Bonferroni correction applied (alpha = 0.05 / number of tests).
- **Sample Size**: N=164 (HumanEval). Power analysis will confirm if this is sufficient for expected effect sizes (typically small to medium in code gen).
- **Causal Claims**: Observational study (LLM vs Human). Claims will be framed as "associational" or "comparative" unless randomization is explicitly introduced (not the case here).
- **Collinearity**: Complexity and Halstead are highly correlated; results will be reported with VIF checks and potentially a composite score to avoid unstable estimates.
- **Compute**:
  - **CPU**: `radon`, `coverage.py`, statistical tests run on CPU.
  - **GPU**: LLM inference (CodeGen, CodeLlama) may require GPU. If CPU inference fails or is too slow, the plan offloads to Kaggle GPU (scaled down: 8-bit quantization, fewer samples if necessary).
  - **Memory**: ~7GB RAM limit. Streaming dataset or batching generation to fit.

## Decision/Rationale

- **CPU First**: All static analysis and statistics are CPU-tractable.
- **GPU Escape**: LLM inference is the only GPU-bound step. We will use `device="cuda"` if available, else fall back to CPU with smaller batch sizes or quantization.
- **No Stratified Sampling**: The study uses the full set of tasks to avoid selection bias and maximize statistical power.
