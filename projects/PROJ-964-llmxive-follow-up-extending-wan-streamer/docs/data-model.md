# Data Model Specification

This document describes the data structures, schemas, and contracts used throughout
the llmXive pipeline.

## Overview

The pipeline processes audio-visual data through several stages:
1. Raw Extraction
2. Filtering & Labeling
3. Stratified Sampling
4. Model Training
5. Hybrid Inference

Each stage produces artifacts that must adhere to strict schema contracts defined
in the `contracts/` directory.

## Schema Definitions

The following sections detail the expected columns, types, and constraints for
each major dataset artifact.

### 1. Raw Extract

Generated by `code/data/extract_latents.py`. Contains latent vectors and event
labels derived from source logs.

- **Source File**: [contracts/raw_extract_schema.yaml](../contracts/raw_extract_schema.yaml)
- **Key Columns**: `timestamp`, `semantic_feature`, `prosodic_feature`, `turn_label`

### 2. Filtered Events

Generated by `code/data/preprocess.py` (filtering step). Retains only valid events
with non-null features.

- **Source File**: [contracts/filtered_event_schema.yaml](../contracts/filtered_event_schema.yaml)
- **Key Columns**: `frame_id`, `latent_delta_magnitude`, `high_priority`

### 3. Sampled Dataset

Generated by `code/data/preprocess.py` (sampling step). Stratified sample for
training and evaluation.

- **Source File**: [contracts/sampled_dataset_schema.yaml](../contracts/sampled_dataset_schema.yaml)
- **Key Columns**: `frame_id`, `latent_delta_magnitude`, `uncertainty_score` (target)

### 4. Model Output

Generated by `code/models/gru_estimator.py` during inference. Predictions and
uncertainty estimates.

- **Source File**: [contracts/model_output_schema.yaml](../contracts/model_output_schema.yaml)
- **Key Columns**: `predicted_delta`, `uncertainty`, `skip_flag`

### 5. Hybrid Output

Generated by `code/inference/hybrid_sim.py`. Final results including latency and
FID metrics.

- **Source File**: [contracts/hybrid_output_schema.yaml](../contracts/hybrid_output_schema.yaml)
- **Key Columns**: `latency`, `fid_score`, `counterfactual_flag`

### 6. Threshold Configuration

Defined in `code/config/detection_thresholds.yaml`. Parameters for event detection.

- **Source File**: [contracts/detection_thresholds_schema.yaml](../contracts/detection_thresholds_schema.yaml)
- **Key Fields**: `audio_energy_threshold`, `delta_threshold`

## Validation Rules

All artifacts are validated against their respective schema files before being
passed to the next stage. Validation logic is implemented in `code/utils/validators.py`.

- **Null Checks**: All required fields must be non-null.
- **Type Checks**: Numeric fields must be float/int; categorical fields must match allowed values.
- **Range Checks**: Features must fall within expected physical ranges (e.g., energy >= 0).
