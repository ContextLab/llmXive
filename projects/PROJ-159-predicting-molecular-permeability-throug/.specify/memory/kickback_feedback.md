## Unresolved concerns

- The research question (predicting permeability) cannot be answered because the 'Verified datasets' block explicitly lacks a source for the target variable (experimental gas permeability coefficients). The plan proposes a fallback to 'simulated' permeability based on geometric descriptors. This creates a circular validation loop where the model predicts a proxy derived from the same structural features it is supposed to learn from, rendering the research question unanswerable as stated.
- The proposed baseline (Linear Regression using Surface Area/Pore Volume) and the GNN input (atomic graphs) are not independent. If the GNN learns to predict the target, it is likely just re-learning the geometric descriptors that define the target (if simulated) or the structural correlates (if real). The ablation study (removing cross-edges) tests the *architecture* but does not isolate the *mechanism* of permeability without a ground-truth target that is independent of the graph construction.
- The plan limits the dataset to ~500 pairs for memory constraints. For a regression task predicting a continuous variable (permeability) with a complex model (GNN), this sample size is likely underpowered to detect non-trivial improvements over baselines, especially given the high variance expected in porous material properties. The plan acknowledges 'Power is limited' but proceeds without a power analysis or justification for why 500 samples are sufficient to validate the 'joint interaction' hypothesis.
- FR-001 requires downloading 'gas permeability datasets'. The plan (Section 'Research: Dataset Strategy') explicitly states 'NO verified source found' for permeability labels and proposes a 'simulated' target or pipeline failure. The plan lacks a concrete task to resolve this data gap (e.g., a specific fallback dataset, a synthetic data generation module, or a formal scope reduction to structural analysis only). Without a defined path to obtain the target variable, FR-001 and SC-001/SC-002 are unbacked.
- FR-005 requires evaluating against a 'linear regression baseline (using hand-crafted descriptors such as surface area and pore volume)'. The plan mentions 'Linear Regression' in the model section but does not specify the implementation of the 'hand-crafted descriptors' (e.g., which library to use for surface area calculation, how to handle missing geometric data). The data-model.md defines the graph but not the specific scalar descriptors required for this baseline, leaving the implementation of FR-005 ambiguous.
- FR-007 requires a sensitivity analysis sweeping thresholds {0.01, 0.05, 0.1} nm. The plan mentions 'Sensitivity: Sweep cross_contact distance threshold' but does not explicitly confirm the specific values {0.01, 0.05, 0.1} nm in the implementation steps or the `sensitivity.py` task description. While the values are in the spec, the plan should explicitly map the task to these exact values to ensure SC-004 is measurable.
- The plan identifies a 'Critical Gap' where the 'Verified datasets' block contains MOF/Zeolite structures but lacks a verified source for experimental gas permeability coefficients (the target variable). The plan proposes a fallback to 'simulated' permeability based on geometric descriptors. This is a methodology failure: a regression model trained on simulated targets (derived from the same structural features used as inputs) will learn a trivial identity function or geometric correlation, not the complex physicochemical permeability mechanism. The research question (predicting permeability) cannot be answered without a real experimental target dataset. The plan must either identify a real permeability dataset (e.g., from literature compilations like the NIST/ICSD or specific MOF permeability databases) or reframe the study to a structural property prediction task, not permeability prediction.
- The spec assumes a 'Permeability of gases in MOFs' dataset on Figshare exists and contains sufficient pairs. However, the research.md explicitly states 'NO verified source found' for permeability. This contradiction indicates the plan is built on an unverified assumption that the dataset exists. If the dataset does not exist or is not in the 'Verified' block, the entire regression pipeline (FR-003, FR-005) is infeasible as written. The plan must resolve this data availability contradiction before proceeding.
- The plan assumes the existence of a 'gas permeability dataset' with experimental values (FR-001, FR-005), but the research.md explicitly states: 'NO verified source found' for the target variable. The plan does not define a fallback mechanism (e.g., synthetic data generation or study reframing) to satisfy FR-001 if the label data is missing, creating a fatal gap where the pipeline cannot execute the core regression task defined in the spec.
- The plan claims 'Pass' for Constitution Principle II (Verified Accuracy) and Principle IV (SSoT), yet the research phase identified a missing verified source for the primary target variable. The plan fails to address how the 'Single Source of Truth' for the target metric will be established if the verified dataset block lacks the necessary labels, violating the requirement that all metrics trace to verified code/data.
- The 'Gas-MOF Pair' entity defines 'Permeability' as a required field but notes it 'May be missing/simulated'. This contradicts the 'required' constraint in the `dataset.schema.yaml` contract which lists `target_permeability` as mandatory. The proposed 'Fallback' strategy to 'generate a simulated permeability target based on geometric descriptors' creates a circular validation. If the target is derived from the same geometric descriptors (surface area, pore volume) that the GNN or baselines use as inputs (or learn from the graph structure), the model is mathematically guaranteed to correlate with the target.
