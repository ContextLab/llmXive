## Unresolved concerns

- The plan proposes assigning feature classes (Color/Pattern/Texture) via a deterministic rule (e.g., `clip_id % 3`) and generating synthetic prompts. This creates a fundamental construct validity failure: the 'ground truth' for the fidelity metric (LPIPS/SSIM) is the visual content of the video, but the 'text prompt' being tested is synthetic and unverified against that content. If the video shows a 'plaid shirt' but the synthetic prompt for that clip ID is 'red shirt', the LPIPS score measures the model's failure to hallucinate the wrong color, not the fidelity loss of text-to-image transfer. The proposed 'confidence check' using a lightweight VLM/heuristic is circular and insufficient to validate the semantic alignment required for a causal claim about text-driven fidelity.
- The plan relies on One-Way ANOVA to test differences in fidelity across feature classes. However, the sample size (500 clips total, ~166 per class) and the proposed synthetic tagging method introduce massive uncontrolled confounds. The 'feature class' is not an inherent property of the data but an artificial label assigned by the stratifier. Any observed difference in LPIPS scores could be driven by the specific visual complexity of the clips assigned to each bin (e.g., if `clip_id % 3` accidentally groups all high-texture videos into the 'Texture' bin) rather than the text prompt modality. The design lacks a mechanism to control for visual complexity or semantic richness as a confound.
- The plan states the goal is to measure 'fidelity degradation... when switching from image-based to text-based references.' However, the methodology only describes running the text-driven adapter and comparing against the 'ground-truth video frames' (LPIPS/SSIM). It does not explicitly define or plan for the 'image-based reference' baseline run required to calculate the 'degradation' (delta). Without a parallel run using the original image-based FashionChameleon reference on the exact same clips, the claim of 'degradation' is unsupported; the plan only measures absolute text-to-video fidelity, not the relative loss compared to the image baseline.
- FR-002 mandates: 'For the 500-clip benchmark subset, the system MUST use human-verified text prompts to ensure ground-truth accuracy.' The plan.md (Technical Context & Research Strategy) explicitly states the dataset 'does not contain explicit semantic tags' and the mitigation is to 'assign tags... based on a deterministic rule (e.g., clip_id % 3)' and 'create a synthetic ground truth mapping.' The plan does not include a task or mechanism to generate or source 'human-verified' prompts for the 500-clip subset, directly contradicting the mandatory requirement in FR-002.
- FR-006 requires: 'report the variation in false-positive and false-negative rates against the ground-truth motion labels.' The plan.md (Research Strategy) admits Human3.6M 'lacks explicit semantic tags' and relies on 'synthetic ground truth mapping' for feature classes. While it mentions 'basic pose/motion metadata,' it does not define a mechanism to derive 'ground-truth motion labels' required for the FP/FN calculation in FR-006. The plan assumes these labels exist or are trivially derived without a corresponding task to generate or validate them.
- SC-002 requires measuring 'local pattern density and texture roughness' against the baseline. The plan.md (Technical Context) states the dataset lacks 'pattern density' or 'texture roughness' tags and the plan uses a 'synthetic ground truth mapping' (e.g., mapping clip IDs to classes). The plan does not include a task to validate that the synthetic mapping actually corresponds to the visual reality of 'pattern density' or 'texture roughness' in the video frames, making the measurement in SC-002 potentially invalid (measuring synthetic tags against synthetic tags rather than visual ground truth).
- The plan cites 'Human3.6M' as the source for 'garment attributes (color, pattern, texture)' and 'ground-truth motion labels'. Human3.6M is a human pose estimation dataset containing skeletal joints and camera parameters, NOT garment semantic segmentation or texture labels. The plan admits this gap but proposes a 'synthetic ground truth mapping' (e.g., `clip_id % 3`) to assign these tags. This renders the fidelity benchmark invalid: measuring LPIPS/SSIM between a generated 'plaid' shirt and a video frame that is actually 'solid red' (because the synthetic tag was arbitrary) measures prompt hallucination or random noise, not the fidelity of the text-to-garment adapter. The dataset does not support the research question.
- The mitigation strategy relies on a 'lightweight VLM' to verify prompt-video alignment for the synthetic tags. However, the plan simultaneously asserts a strict CPU-only constraint (<7 GB RAM) and a 50ms/frame latency target. Running a VLM (even a lightweight one) for every frame in a 500-clip benchmark to validate synthetic tags will likely exceed the 7 GB RAM limit and the 50ms latency budget, creating a circular feasibility failure. If the VLM is skipped, the 'synthetic ground truth' remains unverified and the benchmark is scientifically invalid.
- The plan assumes the 'FashionChameleon' backbone is accessible and compatible with the CPU-only GitHub Actions runner. FashionChameleon (and similar video generation models) typically require significant VRAM (often >12GB) even for inference. The plan's assumption that a 'lightweight adapter' can be inserted into a frozen backbone to fit within 7 GB RAM on CPU is highly optimistic and likely infeasible without quantization or model distillation, which are not explicitly planned. If the backbone itself exceeds 7 GB, the entire pipeline fails before the adapter is even tested.
- Constitution Principle V (Versioning Discipline) is marked 'Pass' in the plan's Constitution Check table, but the plan does not explicitly describe the mechanism for tracking content hashes for code and data artifacts as required by the Constitution. The plan mentions 'Content hashes tracked' in the table but lacks the specific implementation detail (e.g., 'hashes recorded in state/*.yaml' or 'checksums in data/manifest.json') required to satisfy the 'NON-NEGOTIABLE' nature of Principle V and the specific 'Data Hygiene' section of the Constitution.
- Constitution Principle II (Verified Accuracy) is marked 'Pass', but the plan's 'Technical Context' and 'Research' sections rely on the 'Verified Datasets' block. The plan does not explicitly state that the Reference-Validator Agent will run on the citations before execution, nor does it describe the 'Title-token-overlap' check mechanism mandated by the Constitution. The plan assumes verification rather than describing the enforcement of the 'Verified Accuracy Gate'.
- The plan states 'Human3.6M dataset... does not contain explicit semantic tags' and proposes a 'synthetic ground truth mapping'. While the Research doc elaborates on this, the Plan's 'Technical Context' section should explicitly reference the `data/stratifier.py` module (defined in the Project Structure) as the component responsible for this derivation to ensure the Plan and Data Model are tightly coupled. Currently, the link is implied but not explicit in the Plan's narrative.

- The plan proposes a 'synthetic ground truth mapping' (e.g., `clip_id % 3` -> Color/Pattern/Texture) to assign garment attributes to Human3.6M clips. This creates a circular validation: the 'ground truth' for the fidelity metric (LPIPS/SSIM) is defined by the synthetic label, not the visual content. If the video shows a 'plaid' shirt but is assigned the 'Color' label by the rule, the fidelity score measures alignment with the wrong semantic concept. The metric validates the model against a random assignment, not the actual garment properties, rendering the scientific claim ('which attributes degrade') invalid.
- The plan relies on a 'confidence check' using a 'lightweight VLM' to verify prompt-video alignment. However, Human3.6M is a motion capture dataset of actors in plain clothing (often solid colors) without the complex 'plaid', 'texture', or 'pattern' variations required for the hypothesis. A VLM cannot verify a 'plaid' prompt against a solid shirt; it will either fail or hallucinate. The plan assumes the existence of visual features (texture/pattern) in the dataset that are empirically absent, making the hypothesis (H1) untestable with this data source.
- The plan proposes a One-Way ANOVA to test differences in fidelity across 'Color', 'Pattern', and 'Texture' classes. However, if the class labels are assigned synthetically (via `clip_id % 3`) rather than derived from actual visual features, the independent variable (Feature Class) is statistically independent of the dependent variable (Fidelity Score) by construction. Any observed difference would be noise, and any lack of difference would be meaningless. The analysis cannot distinguish between 'model failure on texture' and 'random assignment noise'.
- FR-002 mandates using 'human-verified text prompts' for the 500-clip subset to ensure 'ground-truth accuracy'. This is scientifically impossible with the Human3.6M dataset as described, which lacks the necessary semantic diversity (patterns/textures) to verify such prompts. The requirement assumes a dataset property (rich garment semantics) that contradicts the known characteristics of Human3.6M (motion-focused, plain clothing), leading to a fundamental data-source mismatch.
