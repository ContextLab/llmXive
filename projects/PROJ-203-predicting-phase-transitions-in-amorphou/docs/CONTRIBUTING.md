# Contributing to the Phase Transitions Pipeline

Thank you for your interest in contributing to this project! This document outlines the guidelines for contributing to the codebase, documentation, and data artifacts.

## Code Style

- **Formatting**: Use `black` and `isort` as configured in `code/pyproject.toml`.
- **Linting**: Follow `ruff` rules (flake8, isort, complexity).
- **Naming**: Use descriptive names for functions and variables. Avoid abbreviations unless standard (e.,g., `Tg`, `VIF`).
- **Comments**: Document complex logic with docstrings and inline comments.

## Development Workflow

1. **Fork the repository**.
2. **Create a feature branch** (`git checkout -b feature/my-feature`).
3. **Make your changes** and ensure all tests pass.
4. **Commit your changes** with a descriptive message.
5. **Push to the branch** and create a Pull Request.

## Testing

- **Unit Tests**: Located in `tests/unit/`. Run with `pytest tests/unit/`.
- **Integration Tests**: Located in `tests/integration/`. Run with `pytest tests/integration/`.
- **Evaluations**: Ensure all model outputs match expected metrics (RMSE, ROC-AUC) within tolerance.

## Data Management

- **Raw Data**: Never modify `data/raw/` files. New raw data must be added via a dedicated data ingestion task.
- **Processed Data**: Generated by the pipeline. Do not manually edit `data/processed/` files.
- **Logs**: Simulation and execution logs are stored in `data/logs/`.

## Documentation

- Update `docs/quickstart.md` if you change the pipeline execution flow.
- Add new documentation files to `docs/` as needed.
- Ensure all new features are documented in the `README.md` and `specs/` documents.

## Pull Request Guidelines

- **Title**: Clear and concise description of the change.
- **Description**: Detail the problem solved, the solution implemented, and any breaking changes.
- **Code**: Ensure code is linted, formatted, and passes all tests.
- **Tests**: Include tests for new functionality.

## Review Process

- Code reviews will be conducted by maintainers.
- Feedback will be provided within 48 hours.
- Approved changes will be merged into the main branch.

## Contact

For questions or suggestions, please open an issue or contact the maintainers.
