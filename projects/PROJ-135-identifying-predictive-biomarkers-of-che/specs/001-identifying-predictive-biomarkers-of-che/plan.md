# Implementation Plan: Identifying Predictive Biomarkers of Chemotherapy Response in Public Cancer Datasets

**Branch**: `001-chemo-biomarker-discovery` | **Date**: 2024-01-15 | **Spec**: `spec.md`
**Input**: Feature specification from `specs/001-chemo-biomarker-discovery/spec.md`

## Summary
This project implements a computational pipeline to identify gene-expression signatures predictive of chemotherapy response across multiple tumor types. The approach involves downloading TCGA RNA-seq and GEO microarray data using official R packages (TCGAbiolinks, GEOquery) within a Dockerized environment, harmonizing identifiers, performing differential expression (DE) analysis using the DESeq2 Wald test, meta-analyzing p-values (Stouffer's method with fallback), and training elastic-net logistic regression models with nested cross-validation and external validation. The pipeline adheres to strict reproducibility, data hygiene, and statistical rigor requirements, executing on a CPU-first GitHub Actions runner via a Docker container that provides the necessary R environment.

## Technical Context

**Language/Version**: Python 3.11 (orchestration), R 4.3 (statistical core)  
**Primary Dependencies**:
- **Python**: `pandas`, `numpy`, `scikit-learn`, `statsmodels`, `biopython`, `requests`, `pyyaml`, `huggingface_hub`, `scipy`, `rpy2` (for R integration if not using Docker), `docker` (for container management).
- **R (via Docker)**: `TCGAbiolinks`, `DESeq2`, `GEOquery`, `sva` (ComBat-seq), `pROC`, `meta`, `ggplot2`, `dplyr`.
**Storage**: Local filesystem (`data/raw/`, `data/processed/`, `results/`).  
**Testing**: `pytest` (unit, integration, contract).  
**Target Platform**: Linux (GitHub Actions free-tier runner: CPU, 7 GB RAM).  
**Project Type**: Data Science Pipeline / CLI.  
**Performance Goals**: Complete end-to-end in ≤6 hours; RAM ≤7 GB.  
**Constraints**: No local GPU; must handle large datasets via streaming or sampling; must handle missing GEO annotations gracefully (skip/warn).  
**Scale/Scope**: + TCGA tumor types, Multiple GEO datasets, ≤50 genes in final panel.

> **Dockerized R Environment**: To satisfy the mandatory R package requirements (FR-001, FR-002, FR-004, FR-005) while adhering to the GitHub Actions free-tier constraints, the plan mandates the use of a pre-built Docker container (e.g., `biocontainers/deseq2` or a custom `Dockerfile` based on `rocker/r-ver`) for all R-based steps. The Python orchestration layer will invoke R scripts via `docker run` or `rpy2` if the environment is pre-configured. This ensures the use of the official DESeq2 and TCGAbiolinks packages without altering the scientific method.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **I. Reproducibility**: Plan includes pinned `requirements.txt`, Dockerfile for R environment, random seed setting, and explicit data checksumming steps.
- **II. Verified Accuracy**: Plan mandates that all dataset URLs are strictly from the `# Verified datasets` block; no invented URLs. All R packages are from official CRAN/Bioconductor.
- **III. Data Hygiene**: Plan includes steps to download raw data to `data/raw/` without modification, compute checksums, and write derived data to `data/processed/`.
- **IV. Single Source of Truth**: All metrics (AUC, p-values) are generated by code and traced to specific output files.
- **V. Versioning Discipline**: Artifacts (code, data) will be hashed; `state/` files updated on change.
- **VI. Cross‑Cohort Validation**: Plan explicitly includes "Leave-One-Cancer-Type-Out" and external GEO validation steps.
- **VII. Statistical Rigor**: Plan includes Bonferroni correction, FDR control, DESeq2 Wald test, and explicit handling of collinearity and power limitations.

**Resolution of Unresolved Concerns**:
- **T023d (Coarse Task)**: Split into:
  1.  `Implement LOO Loop Controller`: Orchestrates the LOO loop, checks for minimum tumor types, and manages state.
  2.  `Implement per-type DE execution`: Executes DE analysis for a single tumor type using DESeq2.
  3.  `Implement aggregation logic`: Aggregates results from LOO iterations and computes final metrics.
- **T034 (Coarse Task)**: Split into:
  1.  `Implement LOO Pre-check`: Validates input data and checks if LOO is valid (≥2 tumor types remaining).
  2.  `Implement LOO Re-training Logic`: Retrains the model on the reduced dataset (excluding one tumor type).
  3.  `Implement LOO Evaluation and Save`: Evaluates the retrained model on the held-out tumor type and saves results.
- **T041 (Coarse Task)**: Split into:
  1.  `Implement summary.md merge logic`: Reads existing summary flags and merges with new results.
  2.  `Implement final summary generation`: Generates the final `results/summary.md` with all metrics and limitations.
- **T013 (Hard Halt)**: Replaced "halt if <2 GEO" with "skip invalid GEO, log warning, proceed if ≥2 valid remain; else fail gracefully". The pipeline will now attempt to download each GEO dataset individually. If a dataset fails (e.g., missing annotations), it is skipped with a warning. The pipeline halts only if a critically low number of valid datasets remain after processing all requested ones.
