## Unresolved concerns

- The plan states that MNAR missingness is generated “with probability proportional to the **original (unpermuted) outcome**”. However, the research.md specification requires MNAR to depend on the **permuted outcome** to preserve the null hypothesis. This inconsistency undermines the validity of the MNAR simulation and may bias the Type I error assessment.
- The project claims to assess the validity of statistical significance in *Randomized Controlled Trials* (RCTs) while the data sources are non‑RCT observational datasets on which synthetic treatment/outcome variables are added. This extrapolation limits external validity; the claim should be qualified or the methodology revised to acknowledge the simulated nature of the RCT.
- For binary outcomes the plan uses a Wilcoxon rank‑sum test under Complete‑Case analysis. Wilcoxon is designed for ordinal/continuous data and is not appropriate for binary outcomes, where a chi‑square test or logistic regression would provide a valid test statistic. This threatens construct validity of the binary‑outcome results.
- All missingness mechanisms (MCAR, MAR, MNAR) are defined independently of the treatment assignment. In real RCTs, dropout can be treatment‑dependent (differential attrition), a key confound. Not modeling treatment‑dependent missingness may lead to overly optimistic conclusions about CC robustness.
- The plan assumes 2000 Monte‑Carlo iterations give a standard error of ≈0.005 for a 0.05 error rate, deeming this sufficient to detect a 10 % relative increase. No formal power analysis is provided to confirm that the Binomial test will have adequate power to detect such a modest effect across 72 conditions. This leaves the study under‑powered for its primary claim.
- The plan states it will “download publicly verified datasets (MCAR parquet, MAR csv)” and then synthesize treatment and outcome columns because no verified RCT dataset exists. This violates FR‑001, which requires loading *public RCT datasets* with genuine treatment and outcome variables. Using non‑RCT data and fabricating a treatment variable does not satisfy the functional requirement for real RCT data, making the dataset choice inappropriate for the research question.
- Phase 5 states ‘Store results in `ComparisonResult` (contract)’ but there is no JSON‑Schema contract file for `ComparisonResult` in the contracts directory; only `simulation_output.schema.yaml` (for `SimulationOutput`) exists. This creates a mismatch between the plan and the available contracts.
- The plan never mentions generating the `p_value_distribution` artifact, yet a `p_value_distribution.schema.yaml` contract is present. Either the plan should include a step that creates this artifact, or the unused contract should be removed to keep the contract set aligned with the implementation plan.
- The plan specifies using a Wilcoxon rank‑sum test for binary outcomes ("Wilcoxon (binary) per FR‑007"). Wilcoxon is a non‑parametric test for continuous or ordinal data and is not appropriate for a truly binary outcome; a chi‑square test, Fisher's exact test, or a logistic regression‑based test would be statistically valid. This mismatch may bias Type I error estimates for binary outcomes.
- The plan proposes testing whether `error_CC > 2·error_MI` using a Binomial test with FDR correction ("Test whether CC error > 2·MI error with FDR‑corrected q < 0.05 (SC‑005)"). Comparing two estimated proportions (error rates) via a Binomial test is inappropriate; a two‑proportion z‑test, chi‑square test for independence, or a bootstrap confidence‑interval comparison should be used. Using the Binomial test creates a methodological flaw that could invalidate the claimed validation of the ratio criterion.
