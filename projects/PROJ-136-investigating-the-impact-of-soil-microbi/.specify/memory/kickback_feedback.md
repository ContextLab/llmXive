## Unresolved concerns

- The plan proposes a 'synthetic matching simulation' using random noise or proxy distributions to generate 'disease incidence' labels for the OTU data. This fundamentally breaks the research question. The hypothesis is that *soil microbiome diversity* impacts *plant disease resistance*. Generating synthetic disease labels (random noise) severs the biological link between the predictor (microbiome) and the outcome (disease). No statistical model (GLMM, Beta Regression) can validly test a biological hypothesis on data where the outcome variable is artificially generated and uncorrelated with the predictor by design. This is an idea-root flaw: the proposed method cannot answer the research question.
- The plan states: 'generate a synthetic disease incidence column... (randomly assigned or based on a simple correlation with a proxy variable if available)'. If the labels are random, the null hypothesis is true by construction, and any 'significant' result is a Type I error (false positive) or a result of the specific noise generation algorithm, not biology. If the labels are based on a 'proxy variable' (e.g., climate), the analysis becomes a test of 'Microbiome vs. Climate' or 'Climate vs. Disease', not 'Microbiome vs. Disease'. The confound of the proxy variable is not modeled; it is the *source* of the outcome. This invalidates the causal/associational claim regarding microbiome diversity.
- The 'Synthetic Fallback' is described as a way to 'test the statistical code'. While valid for software unit testing, the plan presents this as a path to produce 'statistical findings' (US-2, US-3). The spec requires reporting 'diversity coefficient significance' and 'effect size'. Running a GLMM on synthetic data yields coefficients that reflect the synthetic generation process, not the biological reality. Reporting these as 'findings' (even with a disclaimer) is methodologically unsound because the 'findings' are artifacts of the simulation, not evidence for the hypothesis. The plan conflates 'code validation' with 'hypothesis testing'.
- The data model includes `is_synthetic_label` and `disease_incidence` (nullable). The analysis pipeline (US-2) requires fitting a model to `disease_incidence`. If `is_synthetic_label` is true, the model is fitting noise. The plan fails to define a valid statistical approach for the 'Fallback Path' that actually answers the research question. It essentially admits the question cannot be answered with available data but proceeds to generate 'results' anyway. A valid methodology for a 'missing data' scenario would be to report 'Insufficient Data to Test Hypothesis' rather than generating synthetic results that cannot support the claim.
- FR-001 requires downloading 16S rRNA tables from EMP/MG-RAST with ≥100 samples. The plan (Section 'Critical Feasibility Note') explicitly states 'no verified open-source dataset exists' for the required matched data and relies on a 'proxy-strategy' using separate datasets. The plan does not contain a specific task or phase to execute the download of the EMP/MG-RAST agricultural subset as mandated by FR-001, nor does it explain how the ≥100 sample target is met if the primary source is deemed unavailable. This is an unbacked functional requirement.
- FR-002 mandates rarefying OTU tables to 10k reads using QIIME 2. While the plan mentions 'QIIME 2 rarefaction' in the summary and Phase 2, the 'Rejected Tasks' section explicitly states T018 (preprocessing) is incomplete and the artifact `data/processed/rarefied-table.qza` is absent. The plan describes the *intent* but lacks the concrete implementation step or verified output artifact required to satisfy the 'System MUST' constraint of FR-002 in the current state.
- FR-008 requires the system to verify variables in the disease dataset and record [MISSING_VARIABLE] markers if absent. The plan acknowledges the missing disease dataset but the 'Rejected Tasks' section notes T014 (data download) is missing the implementation for disease records. Without the implementation of the download and verification logic for the disease dataset (which the plan admits doesn't exist in a verified form), the system cannot execute the verification step required by FR-008 to generate the specific marker output. The plan relies on a 'synthetic fallback' rather than the explicit verification and marking workflow defined in FR-008.
- FR-015 requires an a priori power analysis to determine minimum sample size. The plan mentions 'Power Analysis (FR-015)' in the Research section and lists 'power_analysis.py' in the project structure, but the 'Rejected Tasks' section does not explicitly confirm the completion of the power analysis implementation or artifact. More critically, the plan's 'Fallback Path' (generating synthetic labels) bypasses the need for a real sample size determination based on real data variance, potentially rendering the power analysis moot or unbacked by the actual data acquisition strategy described.
- SC-006 requires measuring data acquisition quality against 'disease dataset completeness'. The plan explicitly states 'NO verified source found' for the disease dataset. The plan's strategy is to use synthetic data or a subset of OTU data. There is no corresponding plan element that defines how 'disease dataset completeness' will be measured or reported when the dataset is fundamentally missing, creating a gap in the success criterion measurement.
- The plan assumes a 'proxy-strategy' of joining separate OTU and Disease datasets via GPS/Date. The 'Verified Datasets' block in research.md confirms NO verified source exists for matched disease incidence. Joining disparate datasets (e.g., EMP soil data + generic GPS data) via metadata is statistically invalid for this hypothesis as the GPS coordinates in the OTU dataset will not match the GPS coordinates in any available disease dataset. This approach cannot answer the research question (diversity vs. disease) and will result in a synthetic/fake correlation, violating Constitution Principle II (Verified Accuracy).
- The plan proposes generating 'synthetic disease incidence labels' for OTU samples to validate the statistical pipeline. While this validates the *code*, it fundamentally breaks the *research question*. The spec requires measuring the impact of microbiome diversity on *actual* plant disease resistance. Using synthetic labels to produce a 'result' (even if flagged) misrepresents the feasibility of the study. The plan must explicitly state that the research question is unanswerable with current open data, rather than proceeding with a synthetic simulation that cannot yield biological insights.
- The plan lists 'Target ~100 samples (if matched)' as a performance goal. Given the confirmed absence of a verified dataset containing both OTU and disease data, this target is impossible to meet with real data. The plan should not set a sample size target for a join that is known to fail. This creates a false expectation of feasibility.

However, the block explicitly lists 'Disease Incidence: NO verified source found.' Marking this as PASS is contradictory. The plan proposes a 'synthetic fallback' to validate code, but the Spec (US-1 Acceptance 1) explicitly requires '≥30 matched samples containing complete metadata'. However, the Research.md and Constitution Check explicitly state 'NO verified source found' for disease data. The plan proceeds to implement a 'Synthetic Fallback' (generating fake disease labels) which contradicts Constitution Principle III (Data Hygiene) and Principle VII (Transparency) by introducing non-empirical data into the 'matched_samples.csv' artifact without a clear, non-fabricated source. This is a direct violation of Principle II (no fabricated URLs/data) and Principle III (no modification of data in place, no fabrication). - The plan proposes generating 'synthetic disease incidence labels' (random noise or simple correlation) to validate the statistical pipeline when real matched data is missing. This creates a circular/tautological validation: the analysis will mathematically 'confirm' the pipeline works on synthetic data by construction, but this result has zero empirical validity for the biological hypothesis. Validating a model's ability to detect a signal on data where the signal was artificially injected (or is random) does not validate the model's ability to detect the *real* biological signal. This renders the 'methodological validation' scientifically meaningless for the research question.
- The plan admits no verified dataset exists with matched OTU and disease data. Proceeding with a 'fallback' that uses synthetic labels to run GLMMs/ANCOM is a category error. Statistical models (GLMM, ANCOM) are designed to infer relationships from observed data distributions. Running them on synthetic labels (even if flagged) produces coefficients and p-values that are artifacts of the synthetic generation process, not biological reality. The plan conflates 'code execution' (does the script run?) with 'scientific validation' (does the analysis support the hypothesis?). The latter is impossible without real data.
- The plan specifies fitting binomial GLMMs with 'disease incidence' as the response. If the response is synthetic (as admitted in the fallback), the resulting p-values and effect sizes are mathematically determined by the synthetic generation parameters, not by soil microbiome properties. This violates the principle of independence between predictors and validation targets. The 'validation' of the pipeline becomes a tautology: 'The pipeline works because we fed it data we created to make the pipeline work.'
- The plan includes an a priori power analysis (FR-015) assuming an effect size of 0.1. However, since the primary data path fails and the fallback uses synthetic data, the power analysis is disconnected from reality. Calculating power for a study that cannot be performed (due to missing data) and then running the analysis on synthetic data to 'demonstrate' the pipeline is methodologically unsound. Power analysis requires assumptions about the *true* effect size in the population, which cannot be estimated from synthetic data.
