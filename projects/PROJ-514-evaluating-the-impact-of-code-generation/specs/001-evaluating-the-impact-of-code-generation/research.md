# Research Plan: Evaluating the Impact of Code Generation on Code Smell Frequency

## Overview

This research project investigates whether code generated by Large Language Models (LLMs) exhibits a different frequency of code smells compared to human-written code. The study utilizes a **Balanced Blocked Design** to ensure statistical validity while managing computational constraints.

## Methodology

### Data Collection Strategy

The study employs a balanced sampling strategy to ensure equal representation of human-written and LLM-generated code. [UNRESOLVED-CLAIM: c_9848c935 — status=not_enough_info]

- **Human Samples**: Collected from 50 active, long-lived public repositories.
- **LLM Samples**: Generated based on tasks derived from the same issue descriptions used for human samples.
- **Sample Size**: 150 total samples (3 per repository/task), ensuring a 1:1 ratio.

### Analysis Method

- **Static Analysis**: PMD CLI is used to detect four specific code smell categories:
 1. Long Method
 2. Duplicated Code
 3. Feature Envy
 4. Long Parameter List
- **Statistical Test**: Blocked Permutation Test (stratified by repository) to control for repository-specific coding styles.
- **Correction**: Bonferroni correction applied for multiple hypothesis testing (4 tests).

## Balanced Blocked Design Justification

The original specification proposed a highly unbalanced design (1000 human samples vs. 50 LLM samples). This approach was deemed statistically suboptimal for the following reasons:

1. **Statistical Power**: In hypothesis testing comparing two groups, power is maximized when sample sizes are equal. A 20:1 ratio significantly reduces the power to detect differences in the smaller group (LLM samples), increasing the risk of Type II errors (false negatives).
2. **Variance Estimation**: Unbalanced designs make variance estimation less robust, particularly when the smaller group has high variability, which is expected in LLM outputs.
3. **Blocking Efficiency**: The "Blocked Design" (using repository as a block) relies on matching pairs or groups within blocks. A balanced design ensures that every human sample has a corresponding LLM sample within the same repository context, maximizing the efficiency of the blocking variable.
4. **Computational Constraints**: While 1000 human samples might be feasible, generating 1000 high-quality LLM samples with diverse prompts and models is computationally expensive and introduces higher variance in generation quality. A balanced, smaller set (150/150) allows for more rigorous control over prompt quality and model selection without sacrificing statistical power.

Therefore, we adopted a **Balanced Blocked Design** with 150 human samples and 150 LLM samples (1:1 ratio), distributed across 50 repositories (3 samples per source per repo).

## Data Sources & Reproducibility

- **Human Data Source**: Public GitHub repositories selected via API query (`stars:>100`, `created:<2019-01-01`, `pushed:>2022-01-01`).
- **LLM Data Source**: HuggingFace Inference API (or equivalent) using specific model versions and seeds logged in `data/raw/api_logs.json`.
- **Static Analysis Tool**: PMD CLI with custom rulesets for the four target smell categories.
- **Seed Pinning**: All random operations (sampling, generation) are controlled by a seed defined in `code/utils/config.py` to ensure reproducibility.

## Limitations

- **Repository Bias**: The selection criteria (`stars:>100`, `pushed:>2022`) bias the sample towards active, popular projects, which may not represent legacy or niche codebases.
- **Task Complexity**: The generated tasks are derived from issue descriptions, which may vary in complexity. The blocked design mitigates this by pairing human and LLM samples from the same issue context.
- **Model Variance**: Results are specific to the models and prompts used. Generalizability to other LLM architectures requires further study.
