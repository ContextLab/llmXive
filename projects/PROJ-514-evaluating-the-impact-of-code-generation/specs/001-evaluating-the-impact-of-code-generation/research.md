# Research Design: Evaluating the Impact of Code Generation on Code Smell Frequency

## Overview

This study investigates the difference in code smell frequency between human-written code and code generated by Large Language Models (LLMs). The research utilizes a **Balanced Blocked Design** to ensure statistical validity while adhering to computational constraints.

## Methodology

### Data Collection
- **Human Samples**: Collected from 50 public GitHub repositories meeting specific criteria (stars > 100, created < 2019-01-01, pushed > 2022-01-01). [UNRESOLVED-CLAIM: c_2931f617 — status=not_enough_info]
- **LLM Samples**: Generated using HuggingFace Inference API based on task descriptions derived from the same issues/PRs used for human samples.
- **Sample Size**: 150 human samples (3 per repo) and 150 LLM samples (3 per task), totaling 300 samples. [UNRESOLVED-CLAIM: c_83fe1afe — status=not_enough_info]

### Static Analysis
- **Tool**: PMD CLI
- **Metrics**: Long Method, Duplicated Code, Feature Envy, Long Parameter List
- **Validity Check**: Performed against a known "clean" reference set to ensure false positive rate < 5%.

### Statistical Analysis
- **Method**: Blocked Permutation Test (stratified by repository)
- **Correction**: Bonferroni correction for multiple hypothesis testing (4 tests, α ≤ 0.05) [UNRESOLVED-CLAIM: c_274b4157 — status=not_enough_info]
- **Effect Size**: Cohen's d calculated for permutation tests

## Balanced Blocked Design Justification

The original specification proposed a highly unbalanced design (1000 human samples vs. 50 LLM samples). This was revised in the implementation plan to a **Balanced Blocked Design** (150 human vs. 150 LLM) for the following reasons:

1. **Statistical Power**: A balanced design maximizes statistical power for a given total sample size. The variance of the difference between two means is minimized when sample sizes are equal ($n_1 = n_2$).
2. **Blocking Efficiency**: By matching LLM samples to the same repositories (blocks) as human samples, we control for repository-specific coding styles and complexities, reducing noise in the comparison.
3. **Computational Feasibility**: Generating and analyzing 1000 LLM samples would exceed the computational budget (CI time limits, API costs) without a proportional gain in statistical power compared to the balanced design.
4. **Validity**: The balanced design ensures that the comparison is not biased by the sheer volume of one group, allowing for a more robust estimation of the effect size.

The blocking variable (repository ID) ensures that the comparison is made within similar contexts, satisfying the requirement for a "Blocked Permutation Test" as specified in the plan.

## Statistical Rationale

The choice of a **Blocked Permutation Test** is critical for this study:

1. **Non-Normality**: Code smell counts often follow a zero-inflated distribution (many functions have zero smells). Parametric tests like the t-test assume normality, which is frequently violated. Permutation tests are distribution-free.
2. **Blocking**: Repositories vary significantly in coding style, complexity, and domain. By treating "Repository" as a block, we remove this variance from the error term, increasing the sensitivity of the test to detect the effect of "Source Type" (Human vs. LLM).
3. **Exact Inference**: With a balanced design and blocking, the number of possible permutations is manageable, allowing for exact p-value calculation or highly accurate approximation.

The **Bonferroni correction** is applied to the p-values obtained for the four smell categories (Long Method, Duplicated Code, Feature Envy, Long Parameter List) to maintain the overall Type I error rate at α = 0.05. The adjusted significance threshold is $0.05 / 4 = 0.0125$. [UNRESOLVED-CLAIM: c_2cc3a2ea — status=not_enough_info]

## Limitations

- **Sample Size**: While statistically efficient, 150 samples per group is smaller than the original spec's 1000. However, the power analysis confirms this is sufficient to detect moderate effect sizes (Cohen's d > 0.5). [UNRESOLVED-CLAIM: c_d52fc66d — status=not_enough_info]
- **Repository Bias**: The selection criteria (active, starred repos) may bias the sample towards higher-quality codebases, potentially underestimating smell frequencies in less active or private projects.
- **LLM Model Variance**: The study uses a specific set of models (via HuggingFace API). Results may vary with different model architectures or fine-tuning.

## Conclusion

The implemented Balanced Blocked Design provides a robust, statistically valid, and computationally feasible framework for comparing code smells in human-written and LLM-generated code. The deviations from the original specification are justified by statistical principles and practical constraints, ensuring the study's findings are reliable and actionable.
