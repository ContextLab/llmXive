# Implementation Plan: llmXive follow-up: extending "SynthDocBench" with Decoupled Retrieval

**Branch**: `001-llmxive-retrieval-extension` | **Date**: 2026-09-06 | **Spec**: `specs/001-llmxive-retrieval-extension/spec.md`
**Input**: Feature specification from `/specs/001-llmxive-retrieval-extension/spec.md`

## Summary

This feature extends the SynthDocBench evaluation to test the hypothesis that decoupling retrieval from visual attention eliminates the "middle-third" positional bias in long-document VLM performance. The approach involves: (1) locally generating synthetic long documents with precise positional metadata, (2) constructing a CPU-based retrieval index from OCR text, (3) executing a two-step inference pipeline injecting retrieved snippets, and (4) quantifying accuracy recovery and correlating it with native context window sizes.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: `transformers`, `torch` (CPU-only), `faiss-cpu`, `pandas`, `scikit-learn`, `datasets`, `pytesseract`, `pdf2image`, `reportlab` (for synthetic doc gen)  
**Storage**: Local filesystem (`data/` for raw/derived, `code/` for scripts)  
**Testing**: `pytest` (contract tests against YAML schemas, unit tests for retrieval logic)  
**Target Platform**: Linux (GitHub Actions free-tier: 2 CPU, 7 GB RAM)  
**Project Type**: Research benchmark / CLI pipeline  
**Performance Goals**: Full pipeline (feasible sample size determined dynamically) ≤ 6 hours; retrieval p95 latency ≤ 2s; RAM peak ≤ 7 GB.  
**Constraints**: No GPU on CI (CPU-first); no external API calls; strict token limits for injected text; reproducible random seeds.  
**Scale/Scope**: Up to 200 synthetic documents (subject to feasibility); Several VLMs (stratified by context size: short, medium, and long).
