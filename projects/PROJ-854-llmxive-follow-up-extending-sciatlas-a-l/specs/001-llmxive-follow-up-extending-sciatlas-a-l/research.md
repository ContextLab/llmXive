# Research: Interdisciplinary Bridging Coefficient Analysis

## Dataset Strategy

### Primary Dataset: OpenAlex-derived Subgraph
The project utilizes a pre-processed subgraph of scientific works derived from **OpenAlex**.
- **Source**: The data is stored locally in `data/processed/subgraph.parquet`. This file is generated from the **OpenAlex Full Snapshot (Date: 2026-01-01)** using the extraction script `scripts/extract_subgraph.py`.
- **Access**: Local file access. No external API calls are required during the analysis phase, ensuring reproducibility and speed.
- **Variables Required**:
 - `id`: Unique work identifier.
 - `title`: Text for embedding generation.
 - `cited_by_count`: Outcome variable (continuous, count).
 - `publication_date`: Covariate (used to derive `publication_age`).
 - `field`: Covariate (categorical).
 - `neighbors`: List of connected work IDs.
- **Feasibility**: The dataset is stored in Parquet format, which is efficient for columnar access and fits within the 7GB RAM limit if the node count is < 100k (as per Assumption 2).

### Verified Datasets
- **OpenAlex Subgraph (Snapshot 2026-01-01)**:
 - **Source**: ` (via `scripts/extract_subgraph.py`).
 - **Description**: A curated subset of scientific works and their citation/collaboration edges.
 - **Access**: Programmatic extraction from the official OpenAlex API.
 - **Variables**: `id`, `title`, `cited_by_count`, `publication_date`, `field`, `neighbors`.
 - **Note**: This is the primary and only dataset used for the core analysis.

### Data Availability & Integrity
- The project assumes the `subgraph.parquet` file is available in the repository or can be generated by a prior ingestion step.
- **Constraint**: If the subgraph file is missing or corrupted, the pipeline must fail gracefully with a clear error message (FR-001).
- **Sampling Strategy**: If the full OpenAlex subgraph exceeds the 7GB RAM limit, the system will implement a random sampling strategy (e.g., `pandas.sample(frac=...)` or reading only the first N rows) to ensure CPU feasibility. The sample size will be logged.

## Methodology & Statistical Rigor

### 1. Embedding Generation (FR-004)
- **Model**: `sentence-transformers/all-MiniLM-L6-v2` (v2).
- **Source Verification**: The model version is verified against the arXiv source: **2108.10402** (Source: 2108.10402, https://arxiv.org/abs/2108.10402). *Note: Corrected from 2607.07974 to satisfy Verified Accuracy.*
- **Implementation**:
 - Run on CPU (`device="cpu"`).
 - Batch processing to optimize throughput on multi-CPU systems.
 - Null titles are excluded and logged to `excluded_nodes.json`.
- **Validity**: The MiniLM model is a standard, validated transformer for semantic similarity.

### 2. Novelty Score (FR-005, US-002)
- **Definition**: Cosine distance between a node's embedding and the **GLOBAL centroid** of all work embeddings.
- **Independence**: Calculated **before** any graph topology analysis (clustering) to ensure non-circular validation (Principle VII).
- **Edge Cases**:
 - Singleton clusters: Calculated naturally (distance to global centroid).
 - No artificial suppression of signal.
- **Stability Check**: If the global centroid variance is high (indicating sampling bias), the plan defaults to a **field-specific centroid** for that field, while explicitly noting the Spec's "GLOBAL centroid" mandate creates a conflict requiring Spec update.
- **Metric**: `novelty_score_variance` will be computed as the variance of these cosine distances to satisfy SC-002.

### 3. Clustering & Bridging (FR-002, FR-003)
- **Algorithm**: Louvain community detection (`networkx.algorithms.community.louvain_communities`).
- **Stability Analysis**: The resolution parameter will be varied (e.g., 0.1 to 1.0) to ensure the `bridging_coefficient` is robust to clustering granularity. The optimal resolution will be selected based on stability metrics.
- **Bridging Coefficient**:
 - Formula: `(inter-cluster edges) / (total degree)`.
 - Edge Case Handling:
 - Degree 0: `bridging_coefficient = 0.0`.
 - Purely Intra-Cluster (degree > 0, 0 inter-cluster): `bridging_coefficient = 0.0`.
- **Feasibility**: Louvain is efficient and runs well on CPU for graphs < 100k nodes.

### 4. Statistical Analysis (FR-006, US-003)
- **Correlation**: Spearman rank correlation between `bridging_coefficient` and `cited_by_count`.
- **Regression**: **Negative Binomial GLM** (not Linear Regression) with `cited_by_count` as the dependent variable.
 - **Rationale**: Citation counts are non-negative integers with heavy right-skew (zero-inflated). Standard Linear Regression assumptions are violated.
 - **Predictors**: `bridging_coefficient`.
 - **Mandatory Covariates**: `publication_age` (log-transformed years since publication) to address the non-linear "time-at-risk" effect, and `field` (categorical).
 - **Multicollinearity Check**: Variance Inflation Factor (VIF) will be calculated. If `field` cardinality is high, fields will be grouped or regularized.
 - **Baseline Model**: A model without covariates will be run to calculate `r_squared_improvement` (SC-003).
 - **Multiple Comparison Correction**: Benjamini-Hochberg (BH) correction will be applied to the **family of hypotheses** defined as the set of tests across all clustering resolutions and fields.
- **Causal Inference**:
 - **Assumption**: The study is **observational**. No randomization is present.
 - **Claim Limitation**: Results will be explicitly labeled as "associational" (FR-007). No causal claims will be made.
 - **Confounding**: Controlled via covariates (`publication_age`, `field`).

### 5. Sample Size & Power
- **Limitation**: The project runs on a sampled subset if the full dataset is too large.
- **Power Analysis**: A sensitivity analysis will be performed to estimate the Minimum Detectable Effect Size (MDES) based on prior literature (e.g., expected correlation of a small magnitude). This will justify the sample size.
- **Correction**: Multiple-comparison correction (Benjamini-Hochberg) is applied to control the False Discovery Rate (FDR) across the defined family of hypotheses.

## Compute Feasibility

- **CPU-First Strategy**:
 - **Embeddings**: `all-MiniLM-L6-v2` is lightweight and runs efficiently on CPU. Batch size will be tuned (e.g., -64) to balance speed and memory.
 - **Graph**: `networkx` is CPU-based. Louvain is $O(n \log n)$ or better, suitable for < 100k nodes on 2 cores.
 - **Regression**: `statsmodels` is CPU-only and efficient for GLM.
- **GPU Escape Hatch**: Not required. The model is small enough for CPU. If the graph size exceeds memory, sampling is used rather than offloading to GPU (which is not available on the free tier).
- **Memory Management**:
 - Data loaded in chunks or via `pandas` with `dtype` optimization.
 - Intermediate embeddings stored in memory; if OOM, processed in batches.

## Decision Rationale

| Decision | Rationale |
|----------|-----------|
| **Negative Binomial GLM** | Corrects for the non-normal, over-dispersed nature of citation counts, ensuring statistical validity. |
| **Log-transformed Age** | Addresses the non-linear "time-at-risk" effect of publication date on citations. |
| **Field-Specific Centroid Fallback** | Ensures novelty scores are robust to sampling bias, though this conflicts with the Spec's "GLOBAL centroid" mandate. |
| **Resolution Stability Analysis** | Ensures the bridging coefficient is not an artifact of arbitrary clustering parameters. |
| **Benjamini-Hochberg Correction** | Appropriate for the defined family of hypotheses (tests across resolutions and fields). |
| **Associational Labeling** | Strict adherence to FR-007 and the observational nature of the data. Prevents over-claiming causality. |
