## Unresolved concerns

- FR-001 and US-1 explicitly require extending '16 existing' environments. Task T013d implements a dynamic discovery mechanism that raises a `ValueError` if the count is not exactly 16. This creates a brittle hard-fail condition that contradicts the spec's requirement for a fixed set of 16 environments and risks halting the project if the upstream registry count drifts, leaving the requirement 'extend 16 environments' unfulfillable in a dynamic context.
- FR-002 and US-2 require generating counterfactual explanations that identify structural flaws. Tasks T021a and T021b implement a 'Deterministic Rule Derivation' step that calculates the `correct_action` from the schema *before* passing it to the LLM. This pre-supplies the answer, effectively bypassing the LLM's reasoning capability required to test the hypothesis that counterfactuals improve policy discovery. The task covers the 'output' but fails to cover the 'generation' logic required by the spec.
- SC-003 requires a mixed-effects model analysis (FR-005). Task T036 depends on `data/evolution_results.csv` as input. However, Task T032b (which produces this CSV) is marked as incomplete/rejected in the analyze report. There is no alternative task defined to generate the required input data for the statistical analysis, leaving SC-003 and FR-005 unimplementable.
- SC-004 requires measuring the 'rate of successful counterfactual explanation generation'. Task T038 aggregates counts from T021 and T023. However, T023 logs fallbacks to `data/fallbacks.log` without a defined mechanism to export these counts to the aggregation logic in T038. There is no task to parse `fallbacks.log` or write a summary metric, leaving the calculation of the success rate (SC-004) unimplemented.
- Tasks T007b ('Create the data/rules_schema.json file') and T007c ('Populate data/rules_schema.json') are redundant. Splitting the creation and population of the same schema file into two separate tasks introduces unnecessary friction. A single task covering the generation and population of the schema would suffice to cover the plan element.
