## Unresolved concerns

- The plan defines 'True Novel' compositions as those returning 'Not Found' on API query. However, the methodology for generating the candidate pool to query is missing. Enumerating all 5-element combinations from the periodic table (~118 elements) yields ~10^10 combinations, which is computationally intractable to query sequentially against an API with rate limits. The plan must specify a sampling strategy (e.g., random sampling from a reduced elemental subset, or grid search in descriptor space) to generate a feasible candidate set for the 'True Novel' analysis. Without this, the 'True Novel' set cannot be generated within the 6-hour constraint.
- The plan proposes a 'Permutation test for error degradation' to compare Hold-out vs. Training errors. However, the Hold-out set is defined by exclusion from training, not by a random permutation of labels. A permutation test shuffles labels to create a null distribution of 'no relationship'; it does not test if a specific held-out set has significantly different error than the training set. The correct methodology for comparing error distributions between two independent sets (Training vs. Hold-out) is a non-parametric test like the Mann-Whitney U test or a bootstrap confidence interval on the difference of means. Using a permutation test here is a methodological error that invalidates the statistical claim in FR-006.
- The plan calculates 'distance from training convex hull' for the 'True Novel' set. However, the 'True Novel' set is defined by API absence, not by geometric distance. If the API coverage is sparse, a composition could be 'True Novel' (unindexed) but still lie well within the convex hull of the training data (interpolation regime). Conversely, a 'Hold-out Known' composition could be far outside the hull. The methodology conflates 'unindexed' with 'extrapolation'. The analysis must explicitly distinguish between 'geometric extrapolation' (distance from hull) and 'database novelty' (API absence). The correlation test (Spearman) in FR-007 assumes that 'True Novel' implies 'far from hull', which is not guaranteed by the definition. The plan must clarify if the 'True Novel' set is filtered by distance or if the analysis acknowledges that 'True Novel' includes both interpolation and extrapolation cases.
- FR-002 (True Novel Generation) is unbacked by a specific algorithmic step in the plan. Phase 0 Step 3 mentions 'Generate random 5-element combinations' but fails to specify the source list of elements or the combinatorial logic required to produce the candidate pool. Without this, the plan does not provide a task to satisfy the requirement of enumerating 'True Novel' compositions as defined in the spec.
- FR-006 (Permutation Test) and FR-007 (Spearman Correlation) are listed in the spec but lack explicit implementation steps in Phase 2. Phase 2 Step 3 mentions 'Statistical Tests' generally but does not explicitly mandate the permutation test for error degradation (FR-006) or the Spearman rank correlation for variance vs. distance (FR-007) as distinct, actionable tasks.
- FR-009 (DFT Validation) is mentioned in Phase 3 Step 1, but the plan states 'Attempt DFT calculation... OR explicitly state unvalidated assumption'. The spec requires the system to 'attempt' DFT if feasible. The plan's phrasing suggests a binary choice rather than a conditional execution flow based on feasibility, potentially leaving the 'attempt' requirement unbacked if the 'OR' path is taken without a feasibility check step.
- The plan assumes 'True Novel' candidates can be generated by querying 'source API' (Phase 0, Step 3) and retaining those returning 'Not Found'. However, the cited datasets (`dataset_thermalcond_aflow`, `all_apis_for_multiapi`) are static Parquet files hosted on Hugging Face. They do not expose a live, queryable API endpoint for 'Not Found' checks. The plan conflates the static dataset source with a dynamic API service (e.g., Materials Project API) which is not cited as a data resource. Without a live API or a complete local index of all known HEAs to query against, the 'True Novel' generation logic is infeasible as described.
- The 'Verified URL' for `all_apis_for_multiapi` points to a static Parquet file (`.../train-00000-of-00001-bd8d5e4d08813d65.parquet`). The plan relies on this dataset to 'Query source API' for 'True Novel' generation (Phase 0, Step 3). A static Parquet file cannot be queried for 'Not Found' responses in real-time. The plan fails to cite a valid, accessible, queryable data resource (e.g., a live API endpoint or a complete local database dump) required to distinguish 'True Novel' from 'Known' compositions.
- Plan Step 3 ('Generate Candidates') states: 'Query source API; retain those returning "Not Found"' for True Novel generation. However, the Plan does not define the algorithm for generating the candidate pool to query (e.g., 'iterate all 5-element combinations from ELEMENT_SOURCE_LIST'). This creates a logical gap where the plan references an undefined input set, violating the requirement that every plan step operates on entities the data model actually defines or explicitly generates. The 'Unresolved concerns' block from the previous stage explicitly flagged this missing generation logic.
- Plan Step 3 mentions 'Permutation test for error degradation (if ground truth exists)'. The Data Model defines 'TrueNovel' as having 'Ground Truth: Unavailable'. The plan should explicitly state that for the 'True Novel' set, the permutation test is skipped and replaced by the Spearman correlation (as defined in FR-007), rather than using a conditional 'if' that implies the possibility of ground truth existing for this specific set, which contradicts the Data Model definition.
- Plan Step 1 ('DFT Check') suggests attempting DFT calculation 'if feasible within 6h'. The Constitution Principle VI (Extrapolation Integrity) and FR-009 require that if ground truth is unavailable (which it is for True Novel), the report MUST explicitly state the uncertainty metric is an 'unvalidated assumption'. The plan should be more explicit that the DFT step is a 'best effort' and the primary deliverable is the explicit statement of unvalidated assumption if DFT is skipped, to ensure strict adherence to the Constitution.
- The plan proposes a 'Spearman rank correlation (variance vs. distance)' for the 'True Novel' set. This analysis is circular/tautological because the 'distance from training convex hull' is calculated in the *same descriptor space* used to train the model. Random Forests inherently assign higher variance to points far from the training manifold in feature space. Correlating the model's internal uncertainty metric (variance) with the geometric distance in the input space (distance) is a self-fulfilling prophecy, not an empirical validation of predictive power. It validates the model's geometry, not its ability to predict thermodynamic stability in unexplored chemistry. A valid validation requires an independent ground truth (e.g., DFT) or a 'Hold-out Known' set where the ground truth is known but the composition was excluded from training.
- The plan evaluates 'Hold-out Known' performance by comparing $R^2$ to training $R^2$. While this measures extrapolation error, the 'Hold-out Known' set is defined as 'compositions present in the source API but excluded from training'. If the source API (AFLOW/MP) is the *same* source used for training, the 'Hold-out' set is merely a random split of the same distribution, not a true extrapolation test. True extrapolation requires testing on compositions with elemental combinations or stoichiometries *not* represented in the training distribution (e.g., new element pairs). If the 'Hold-out' set shares the same chemical space, the $R^2$ degradation will be minimal, and the claim of 'evaluating extrapolative capability' is methodologically unsound.
- The plan states: 'Attempt DFT calculation on a small subset... OR explicitly state unvalidated assumption'. Relying on an 'unvalidated assumption' for the 'True Novel' set renders the core research question ('Evaluating the Predictive Power') unanswerable for the novel set. Without DFT (or experimental) ground truth for the 'True Novel' set, the study cannot determine if the model's 'uncertainty' correlates with *actual* prediction error, only with *geometric* distance. The methodology must commit to a feasible DFT validation strategy (even if small) or reframe the research question to 'Evaluating Uncertainty Calibration' rather than 'Predictive Power'.
