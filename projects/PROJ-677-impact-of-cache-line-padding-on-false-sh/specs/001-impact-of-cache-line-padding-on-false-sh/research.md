# Research: Impact of Cache Line Padding on False Sharing in Concurrent Counters

## 1. Problem Statement & Research Question

**Question**: How does cache-line padding of thread-local counters affect memory bus contention and throughput under high-frequency concurrent updates on multi-core processors?

**Hypothesis**: Padded counters (each in a separate 64-byte cache line) will exhibit significantly higher throughput than packed counters (multiple counters in one cache line) under multi-threaded workloads due to reduced false sharing.

## 2. Dataset Strategy

Since this is a systems benchmarking study, the "dataset" is synthetic, generated by the C++ benchmark harness.

| Dataset/Source | Type | Access Method | Variables Needed | Verified Fit |
|----------------|------|---------------|------------------|--------------|
| Synthetic Workload (C++ Benchmark) | Generated | `./benchmark_binary --threads=N --config=packed/padded` | `thread_count`, `configuration`, `iteration_count`, `wall_clock_time_ms` | ✅ **Perfect Fit**: The benchmark is designed to generate exactly these variables. No external dataset needed. |

**Rationale**: External datasets (e.g., ADNI, HCP) are irrelevant for low-level CPU cache behavior. The synthetic workload allows precise control over thread count, iteration count, and memory layout, ensuring the study directly addresses the research question.

## 3. Statistical Methodology

### 3.1. Primary Analysis
- **Test**: Two-sample t-test (independent samples) comparing throughput (ops/sec) between `packed` and `padded` configurations at each thread count (1, 2, 4, 8).
- **Effect Size**: Cohen's d for each comparison.
- **Significance Threshold**: α = 0.05 (raw), q ≤ 0.05 (FDR-adjusted).
- **Multiplicity Control**: Benjamini-Hochberg FDR procedure across the 4 thread counts.
- **Power Analysis**: Prior to full execution, a pilot run (n=3) will be used to estimate variance. `statsmodels.stats.power.tt_solve_power` will calculate the required n to achieve [deferred] power for detecting Cohen's d ≥ 0.5. If calculated n > 5, the benchmark will execute n runs.

### 3.2. Assumptions & Limitations
- **Normality**: Assumed via Central Limit Theorem (n ≥ 5 or calculated n; t-test is robust).
- **Homogeneity of Variance**: Welch's t-test variant will be used if variances differ significantly.
- **Causality**: Observational; threads are not randomly assigned to cores. Findings framed as **associational**. However, **CPU pinning** (Task T025) and **performance governors** are used to minimize OS scheduler noise and thermal throttling confounds, strengthening the internal validity of the comparison.
- **Power**: Determined by pilot-based calculation. If variance is high (common in CI), n will be increased accordingly to avoid Type II errors.

### 3.3. Measurement Validity
- **Atomic Operations**: `std::atomic<long>` ensures increments are not optimized away.
- **Hardware Transparency**: `hardware_spec.yaml` records CPU model, cache line size, and compiler flags.
- **Reproducibility**: Random seeds pinned; CI-based re-runs.
- **Noise Control**: CPU pinning (`taskset`) and performance governor (`cpupower`) are mandatory to reduce uncontrolled variance from the CI environment.

## 4. Hardware Detection Strategy

The `hardware_detect.py` script will:
1. Query `/proc/cpuinfo` for CPU model and core count.
2. Query `getconf LEVEL1_DCACHE_LINESIZE` (or equivalent) for cache line size.
3. Output to `data/hardware_spec.yaml` with keys: `cpu_model`, `core_count`, `cache_line_size`, `compiler_flags`.
4. **Verification**: Output validated against `contracts/hardware_spec.schema.yaml` to ensure all required keys are present.

## 5. Decision/Rationale

- **CPU-First**: All computations (C++ benchmark, Python analysis) are CPU-tractable. No GPU required.
- **Synthetic Data**: External datasets are unnecessary; synthetic generation provides exact control.
- **Statistical Rigor**: FDR control, effect size reporting, and **pilot-based power analysis** ensure robust interpretation.
- **CI Noise Mitigation**: Mandatory CPU pinning and performance governors address the high variance inherent in shared CI runners.
