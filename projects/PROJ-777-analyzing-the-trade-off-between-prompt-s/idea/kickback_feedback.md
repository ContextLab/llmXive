## Unresolved concerns

- FR-002 mandates ±10 token tolerance 'UNLESS the prompt is truncated'; FR-015 says truncation 'waives' the tolerance. But FR-002 also states 'the tolerance constraint is waived and the actual count is recorded as the truncated length.' These are consistent in outcome but the phrasing in FR-002 is redundant given FR-015 already covers truncation handling. More critically: FR-002 says variants are constructed to target '100, 200, 300, and 400 tokens' but the Methodology Sketch lists '50, 100, 200, 300, 400 tokens' (5 bins, not 4). This is a direct contradiction on the number of prompt variants.
- Assumption states 'A sample size of 164 problems (falling back to 100 if necessary) is hypothesized to be sufficient to detect a moderate effect size (Cohen's w ≥ 0.3) with ≥80% power at α = 0.05 for a within-subjects design with 5 conditions and binary outcomes.' But FR-002 specifies 4 token bins (100, 200, 300, 400), not 5. The assumption references '5 conditions' which contradicts the FR. The Methodology Sketch lists 5 bins (50, 100, 200, 300, 400), creating a three-way inconsistency.
- FR-011 mandates semantic equivalence validation using cosine similarity < 0.95 threshold and cites Liu et al. 2023. The Methodology Sketch says 'Variants with similarity < 0.95 are discarded and regenerated. If a problem cannot yield 5 valid variants after 3 attempts, it is excluded from the analysis.' But FR-011 does not mention the 3-attempt limit or exclusion logic—only the threshold. This is a material gap: the FR should specify the retry/exclusion behavior to be testable.
- SC-006 states 'the optimal bin must remain within a ±10 token window across the sensitivity sweep to be considered stable.' FR-012 says 're-running the ANOVA with a ±5% variation in the token count bins.' These are measuring different things (absolute token window vs. percentage variation). The spec should clarify whether the ±5% variation in FR-012 is the input perturbation and the ±10 token window in SC-006 is the output stability criterion, or if one should be removed.
- FR-010 frames findings as 'associational (not causal)' and FR-019 says 'System MUST use the replicated pass@1 and pass@10 data as the dependent variable in the Repeated-Measures ANOVA.' But the spec does not clarify whether pass@10 is treated as a separate dependent variable in the ANOVA or only as a secondary metric. FR-006 specifies the ANOVA model as 'Score_transformed ~ ModelSize * TokenCount + Error(ProblemID)' using pass@1 proportions, but FR-018 and FR-019 require pass@10 computation. The spec should explicitly state whether pass@10 is analyzed in the same ANOVA or reported separately.
- FR-001 says 'If the estimated runtime exceeds the 6-hour limit, the system MUST fallback to randomly sampling a stratified set of problems.' SC-004 measures 'computational feasibility...does not exceed 6 hours.' SC-010 requires 'at least 100 problems (or the full dataset when feasible).' But the spec does not define what 'stratified' means in FR-001 (stratified by what?—difficulty, test case count?). The Methodology Sketch says 'stratified by problem difficulty proxies like number of test cases' but this is not in the FR. This ambiguity makes FR-001 untestable.
- NFR-002 states 'The system MUST NOT utilize GPU acceleration, 8-bit/4-bit quantization, or CUDA-specific libraries.' But the Methodology Sketch says 'bigcode/starcoderbase (4-bit quantized to fit 7GB RAM).' This is a direct contradiction: the NFR forbids 4-bit quantization, but the methodology requires it for the third model. One must be revised.
- FR-003 says 'System MUST measure the exact token count for every generated prompt using the specific model's tokenizer before inference.' FR-002 says token counts 'MUST be within ±10 tokens of the target.' But FR-003 does not specify when the measurement occurs (before or after truncation, before or after elaboration). If a prompt is truncated (FR-015), is the 'exact' token count the pre-truncation or post-truncation value? This ambiguity affects data interpretation.
- Target token bins are stated as '100, 200, 300, and 400 tokens' but the methodology sketch mentions '50, 100, 200, 300, 400 tokens' (5 variants). FR-002 lists only 4 bins. This discrepancy makes it unclear how many prompt variants must be generated and tested.
- FR-006 mandates 'arcsine square-root transformation' but does not specify the exact formula, software library, or validation procedure. How will the implementer verify the transformation was applied correctly? Suggest: 'transformed_score = arcsin(sqrt(pass_rate))' with reference to scipy.stats or equivalent.
- FR-011 cites 'Liu et al., 2023, *Prompt Semantics*; https://arxiv.org/abs/2305.12755' but the URL and citation format are inconsistent with the rest of the spec. Clarify: is this a verified primary source? Constitution Principle II requires citation verification.
- SC-006 states 'optimal bin must remain within a ±10 token window across the sensitivity sweep' but does not define what 'remain within' means operationally. Does this mean: (a) the bin index stays the same, (b) the peak token count shifts by ≤10 tokens, or (c) the confidence interval of the peak overlaps? Clarify the exact test.
- SC-010 requires 'at least 100 problems (or the full dataset when feasible)' but does not specify how 'feasibility' is measured. FR-001 references a 6-hour limit and linear extrapolation, but SC-010 does not state the decision rule. Suggest: 'If estimated runtime from first 10 problems × 16.4 exceeds 5.5 hours, fall back to 100-problem stratified sample.'
- SC-013 requires 'no missing rows' in the CSV but does not define what constitutes a 'missing row.' Does a row with pass@1=0 (failed test) count as present? Does a row with a truncated prompt count as present? Clarify: 'Every (problem_id, model_name, variant_id) triplet must have exactly one row with all fields populated; rows with failed inference or truncation are included with failure flags, not omitted.'
- SC-014 requires 'confidence-interval plots' but does not specify the confidence level (95%? 99%?) or the method (bootstrap, parametric, Bayesian?). FR-006 mentions ANOVA but does not state how CIs are derived from the model. Clarify the exact procedure.
- FR-017 states 'n = 10 independent code samples' but does not specify how 'independence' is operationalized. Are samples independent if they use distinct random seeds? If temperature is fixed at 0.8, are they truly independent? Clarify: 'Each sample is generated with a distinct random seed (0–9) and fixed temperature (0.8), ensuring stochastic independence in the sampling process.'
- SC-003 states 'a statistically significant difference in these locations (p < 0.05) confirms the hypothesis' but does not specify the statistical test. How is 'difference in locations' tested? A chi-square test on bin indices? A post-hoc pairwise comparison? Clarify the exact test and correction method.
- Target token bins stated as '100, 200, 300, and 400 tokens' but idea/methodology sketch specifies '50, 100, 200, 300, 400 tokens' (5 variants). Spec drops the 50-token minimal variant.
- Semantic equivalence check uses 'sentence-transformers/all-MiniLM-L-v2' but idea/methodology sketch specifies 'sentence-transformers/all-MiniLM-L6-v2' (different model variant). Spec drifts the validation tool.
- The dependent variable in the ANOVA is defined as 'pass@1 proportions' (k/10), but pass@10 is a deterministic function of the pass@1 outcomes (binary: 1 if ANY of 10 samples passes). Using both as separate dependent variables in the same ANOVA violates independence of observations and creates a circular validation: pass@10 is entirely determined by the pass@1 data, so testing both against the same predictors (ModelSize × TokenCount) is redundant and statistically invalid.
- The spec assumes 'a sample size of 164 problems (falling back to 100 if necessary) is hypothesized to be sufficient to detect a moderate effect size (Cohen's w ≥ 0.3) with ≥80% power.' However, no power analysis is shown for the actual design (Repeated-Measures ANOVA with 5 within-subject conditions, 3 models, binary outcomes). The cited Cohen's w is for chi-square tests, not ANOVA on proportions. This is a category error in statistical justification.
- The arcsine square-root transformation is applied to 'stabilize variance' for ANOVA on proportions, citing Zar (1999). However, modern practice (Warton & Hui, 2011) shows this transformation is often unnecessary for logistic regression or generalized linear models, and the spec does not justify why ANOVA on transformed proportions is superior to a logistic mixed model. The choice is stated as fact rather than justified against alternatives.
- Semantic equivalence validation uses cosine similarity < 0.95 as the threshold for 'semantic drift failure,' citing Liu et al. (2023). However, the spec does not justify why 0.95 is the correct threshold for 'near-identical textual meaning' in the context of code-generation prompts. A threshold of 0.95 on sentence embeddings is domain-specific and may be too strict (excluding valid variants) or too loose (allowing drift). No empirical justification is provided.
- FR-017 requires n=10 independent samples per triplet. FR-018 requires pass@10 computation. FR-019 states both pass@1 and pass@10 are used as dependent variables in ANOVA. This creates a logical inconsistency: if pass@10 is computed from the same 10 samples as pass@1, they are not independent observations. The spec must clarify whether pass@10 is a separate outcome metric (reported but not analyzed) or a dependent variable in the ANOVA.
- SC-003 claims 'a statistically significant difference in [optimal bin] locations (p < 0.05) confirms the hypothesis.' However, the hypothesis is about an *interaction effect* (whether the slope of prompt-length effect changes with model size), not about post-hoc differences in optimal bins. Testing the location of the peak is a descriptive finding, not a test of the interaction. The success criterion conflates two different statistical claims.
- FR-002 states the system 'MUST construct a gradient of prompt variants... to create target token bins of, 100, 200, 300, and 400 tokens.' The list is missing the first target (50 tokens is mentioned in the methodology sketch but not in FR-002). This is an inconsistency in the stated requirements.
- FR-012 requires sensitivity analysis with ±5% variation in token bins. SC-006 requires the optimal bin to 'remain within a ±10 token window' across the sensitivity sweep. These two criteria are incommensurable: a ±5% variation in bins (e.g., 100±5 = 95–105 tokens) is not the same as a ±10 token window. The spec must clarify which is the actual stability criterion.
- The assumptions section states 'The use of pass@1 introduces stochastic variance that may obscure the true "diminishing returns" curve; the identified optimal bin is interpreted with this variance in mind.' This is a methodological caveat, not an assumption about the environment or data. It should be moved to the methodology or limitations discussion, not listed as an assumption.
