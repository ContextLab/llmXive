## Unresolved concerns

- The 'verified' OSM sources do not plausibly contain the required constructs. FR-001 requires buildings, land-use, trees, roads per city bbox. The listed URLs include 'Osman_Un_Corpus' (an Arabic NLP text corpus), a 'megaearth-osm-sentinel2' classification table, a zoom-5 slippy-tile tar.gz, and a country-level parquet for Antigua/Barbuda (AG) — none is a canonical per-city OSM feature extract covering the 10 configured US cities. Construct validity of every predictor depends on this; the plan must verify these sources actually expose the four feature layers for each CITY_LIST entry or name a source that does.
- The outcome variable (LST) has no obtainable source, so the design as planned cannot answer the research question end-to-end: every model, CV, and sensitivity result is contingent on a spec amendment that does not yet exist. The DATA_GAP contract is honest, but the plan should state explicitly that no modeling phase can be validated until the amendment lands, and gate Phases 4–10 on it.
- The Unexplained Variance Gap is defined against a single unverified constant (0.68, Zhou et al. 2020 — flagged unverified, and the prior reviewer already caught a fabricated 0.60/Oke attribution on this same metric). A headline metric built on an unverified ceiling has no construct validity; the plan should either (a) drop the metric until the citation is verified, or (b) compute it only as a clearly-labeled provisional sensitivity, not a required schema field in three contracts.
- This effective-sample-size formula is a crude first-order approximation (proper estimators, e.g. Clifford–Richardson or Griffith, differ substantially for strongly autocorrelated rasters). Acceptable as a reported caveat, but the report should state it is an approximation, not a power calculation — currently only 'power caveat' is mentioned without naming the limitation.
- FR-002 mandates ingestion of Landsat LST from USGS EarthExplorer, but the plan documents that EarthExplorer is credential/interactive-gated and no verified open LST URL exists. The plan correctly refuses to fabricate data (SC-002) and implements a DATA_GAP contract, but FR-002 as written is unsatisfiable by the planned pipeline — the spec must be amended to name a verified, programmatically downloadable LST product or authorize a checksummed local asset. Until then FR-002 and the end-to-end execution of SC-002/US-01 have no executable backing.
- FR-010's UpperBound_R² = 0.68 (Zhou et al. 2020) has no verified source in the project's verified block; the plan computes the metric from the spec-stated constant and labels it provisional. The spec's citation is unverified, so FR-010's 'literature-grounded ceiling' claim is not backed by a verified reference — spec amendment or Reference-Validator verification is required before the metric can be reported as literature-grounded.
- The primary OSM source 'Mead0w1ark/megaearth-osm-sentinel2/.../classes_final.parquet' is a machine-learning classification table (OSM+Sentinel2), not a per-city OSM vector extract of buildings/land-use/trees/roads. URL reachability aside, this dataset does not plausibly provide the geometry-bearing layers FR-001 requires for the 10 configured US cities.
- 'arbml/Osman_Un_Corpus/.../train-00000-of-00001-c160156ed7df8ea7.parquet' is an Arabic NLP text corpus, not OpenStreetMap vector data. Citing it as an OSM vector source is a wrong-dataset error; it cannot yield building/land-use/tree/road geometries.
- The PeakNav tile archive is a single zoom-5 slippy tile (no feature geometry at analysis resolution), and the open2roam extract covers country=AG (Antigua), not any of the 10 US cities in config.py CITY_LIST. Neither fallback can supply city-scale OSM vectors for the planned analysis.
- City boundaries are claimed to be 'derived from the verified OSM sources above', but since none of the cited sources actually contain OSM place polygons for the target cities, the boundary-derivation strategy has no viable data foundation. The plan needs a genuinely appropriate OSM extract source (e.g., Geofabrik regional extracts or an OSM PBF/parquet source covering the configured cities) added to the verified block.
- Field-name disagreement: data-model ModelResult defines `city_name`, but model_output.schema.yaml requires `city_id`. Pick one identifier so contract tests and the data model agree.
- The two metrics schemas disagree on the p-value field: metrics.schema.yaml requires `p_values` (an object) while output.schema.yaml requires `p_value` (a number). Also, an object-typed `p_values` cannot be represented in a CSV row as both schemas claim; specify a serialization (e.g., JSON string column) or align the types.
- The LST data gap is declared BLOCKING for end-to-end execution, yet the spec amendment resolving it is scheduled as Phase 12 (last). Phases 2–10 cannot be executed or validated without it. Reorder so the amendment (or an authorized local-asset contract) precedes execution phases, or explicitly mark Phases 2–10 as contract-only until the amendment lands.
- Quickstart instructs users to manually place LST GeoTIFFs under data/raw/lst/, but the constitution mandates thermal imagery 'MUST be retrieved from their canonical repositories for each run' on a fresh runner. The plan flags the gap but the quickstart presents the manual path as an operating procedure; state explicitly that this is a temporary, amendment-pending deviation from Principle I, not the steady-state workflow.
- Phase 4 writes `data/results/exploratory.csv`, but the data-model File Formats table lists no exploratory output location. Add it for traceability.
- The permutation-FDR step (FR-008) never specifies the permutation scheme. Under strong spatial autocorrelation (which the plan itself measures via Moran's I), naive i.i.d. permutation of the outcome breaks the spatial dependence structure and yields anti-conservative permutation p-values. Specify a spatially constrained permutation (e.g., block/toroidal shifts or permuting within spatial blocks) in correction.py, or justify the i.i.d. scheme.
- N_eff = N/(1 + Moran's I) is a crude heuristic, not a standard effective-sample-size estimator (e.g., Clifford–Richardson / Dutilleul correction). It is acceptable as a reported descriptive quantity, but the plan should state it is a heuristic lower-bound-style adjustment and not use it to justify power claims; currently it 'feeds' the power caveat without qualification.
- The Unexplained Variance Gap (0.68 − Observed_R²) is a difference against a spec-stated constant whose source is unverified (Zhou et al. 2020, flagged). The plan correctly labels it provisional, but the metric is scientifically meaningful only if the ceiling is empirically established for comparable predictors/resolution; the report should state that a negative gap (Observed_R² > 0.68) would indicate the ceiling is invalid, not that the model 'exceeds literature' — add this interpretation guard.
