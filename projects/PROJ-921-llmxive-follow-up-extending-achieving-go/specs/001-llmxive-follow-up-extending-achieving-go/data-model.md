# Data Model: llmXive follow-up: extending "Achieving Gold-Medal-Level Olympiad Reasoning via Simple and Unified S"

## Overview

This document defines the data structures used throughout the pipeline, ensuring alignment with the `contracts/` schemas and the "Single Source of Truth" principle. All data is stored in JSONL or Parquet formats for efficient streaming and processing. The data model has been updated to explicitly support the **Linear Mixed Effects (LME)** analysis by including `domain` and `is_ill_structured` fields.

## Core Entities

### 1. Prompt (Unified)
A text-based problem statement, unified across deterministic and ill-structured domains.
- **Fields**:
  - `id`: Unique string identifier (UUID).
  - `source`: String (e.g., "MMLU", "OpenSci").
  - `text`: String (the full prompt text).
  - `type`: Enum ("deterministic", "ill-structured"). **Critical for LME**.
  - `domain`: String ("deterministic" or "ill-structured"). **Explicitly mapped to the LME `Domain` variable**.
  - `ground_truth`: String (optional, for deterministic prompts).

### 2. Response
The text generated by a model.
- **Fields**:
  - `prompt_id`: Reference to `Prompt.id`.
  - `model_id`: String (e.g., "SU-01", "Baseline").
  - `candidate_index`: Integer (0, 1, or 2).
  - `text`: String (generated content).
  - `domain`: String (copied from `Prompt.domain` to enable LME grouping). **Critical for LME**.
  - `generation_time`: Float (seconds).
  - `token_count`: Integer.
  - `status`: Enum ("success", "truncated", "timeout", "oom").
  - `is_correct`: Boolean (only for deterministic prompts).

### 3. Score
The evaluation of a response.
- **Fields**:
  - `response_id`: Reference to `Response` (composite key: prompt_id + model_id + candidate_index).
  - `novelty`: Integer (1-5).
  - `feasibility`: Integer (1-5).
  - `consistency`: Integer (1-5).
  - `reasoning`: String (raw semantic output from proxy model). **Standardized field name to match `score.schema.yaml`**.
  - `entropy`: Float (model output entropy).
  - `variance`: Float (variance of scores if multiple evaluators used).
  - `confidence`: Enum ("high", "low").
  - **Principle VI Compliance**: The `reasoning` field explicitly preserves the **raw semantic output** of the evaluator model alongside the scalar scores to prevent loss of context regarding "rigidity" or "false certainty".

### 4. BenchmarkResult
Aggregated metrics.
- **Fields**:
  - `model_id`: String.
  - `dataset_id`: String.
  - `metric_type`: Enum ("accuracy", "creativity", "correlation", "lme_interaction").
  - `value`: Float.
  - `p_value`: Float (if applicable).
  - `n_samples`: Integer.

### 5. LME_Result
Results from the Linear Mixed Effects model (Primary Test).
- **Fields**:
  - `fixed_effect_model_type`: Float (Coefficient for Model Type).
  - `fixed_effect_domain`: Float (Coefficient for Domain).
  - `interaction_effect`: Float (Coefficient for Model_Type * Domain). **Primary Metric**.
  - `interaction_p_value`: Float (P-value for interaction).
  - `random_effect_variance`: Float (Variance of random intercept).
  - `method`: String (e.g., "REML").

## Data Flow

1. **Raw Data**: Downloaded from verified sources (JSONL/Parquet) → `data/raw/`.
2. **Unified Prompts**: `data/intermediate/prompts_unified.jsonl` (Includes `domain` field).
3. **Curated OpenSci**: `data/intermediate/open_sci_reason.jsonl` (Filtered for ill-structured).
4. **Generation Outputs**: `data/intermediate/responses_SU01.jsonl`, `responses_Baseline.jsonl` (Includes `domain` and `is_correct`).
5. **Scores**: `data/intermediate/scores.jsonl` (Includes `reasoning` for Principle VI).
6. **Aggregated Results**: `data/final/results.parquet` (Includes simple stats and LME results).

## Data Hygiene

- **Checksums**: All files in `data/raw/` are checksummed (SHA-256).
- **Immutability**: Raw data is never modified. Derivations are new files.
- **PII**: No PII allowed. Scrubbing applied if necessary.
