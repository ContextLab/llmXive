# Implementation Plan: Predicting the Yield Strength of High‑Entropy Alloys

**Branch**: `001-predicting-the-yield-strength-of-high-en` | **Date**: 2026-10-23 | **Spec**: [spec.md](../specs/001-predicting-the-yield-strength-of-high-en/spec.md)  
**Input**: Feature specification from `/specs/001-predicting-the-yield-strength-of-high-en/spec.md`

## Summary
Create a fully reproducible, provenance‑tracked pipeline that (1) fetches a **verified open Zenodo dataset** of HEA yield‑strength measurements, (2) computes deterministic compositional descriptors, (3) validates all artifacts against JSON/YAML schemas, (4) performs a power analysis with explicit effect‑size justification, (5) removes multicollinear descriptors (VIF > 5), (6) trains a Random Forest regressor with 5‑fold cross‑validation, (7) evaluates on a held‑out test set and, if available, on an independent external Zenodo validation set, (8) conducts descriptor‑target correlation analysis, (9) computes permutation importance with Holm‑Bonferroni correction, (10) repeats the full training‑evaluation three times to assess stability, and (11) generates a single‑source‑of‑truth markdown report. All steps run on the CPU‑first GitHub Actions free tier (≤ 7 GB RAM, ≤ 6 h).

## Technical Context
- **Language/Version**: Python 3.11  
- **Primary Dependencies**: `pandas`, `numpy`, `scikit-learn`, `statsmodels`, `scipy`, `jsonschema`, `pyyaml`, `tqdm`, `matplotlib`, `seaborn`, `requests`, `joblib`  
- **Storage**: `data/` for raw/derived files, `output/` for models, metrics, reports  
- **Testing**: `pytest`, `jsonschema` validation tests  
- **Target Platform**: Linux GitHub Actions runner (CPU‑first)  
- **Constraints**: All random seeds pinned in `code/`; external datasets fetched from the same canonical Zenodo source on every run; no GPU required

## Phase‑by‑Phase Plan (covers **all** FR‑NNN and SC‑NNN)

| Phase | Tasks | FR / SC addressed |
|-------|-------|-------------------|
| **0. Project Setup** | • Create virtual environment, install `requirements.txt` (pinned). | **FR‑001**, **FR‑018** |
| **1. Data Acquisition** | • **If a verified open HEA yield‑strength dataset is available** (e.g., Zenodo DOI `` containing experimentally measured `yield_strength` for single‑phase alloys), download it programmatically via `requests.get` or `datasets.load_dataset`. <br>• Store raw file as `data/hea_raw.jsonl`. <br>• Validate against `contracts/dataset.schema.yaml`. <br>• **If no verified dataset exists**, abort with a clear error and flag the need for scope revision. | **FR‑001**, **FR‑018** |
| **2. User Composition Input Validation** | • If a user supplies a CSV of compositions, validate each record against `contracts/hea_composition.schema.yaml`. <br>• Abort with clear error if any required field is missing. | **FR‑009**, **FR‑018** |
| **3. Descriptor Calculation** | • Load deterministic elemental property table `data/elemental_properties.csv`. <br>• Compute mixing entropy, atomic‑size mismatch (δ), electronegativity variance (Δχ), VEC, melting‑point variance. <br>• Output `data/descriptors.parquet`. <br>• Validate against `contracts/descriptor.schema.yaml`. | **FR‑002**, **VI** |
| **4. Power Analysis** | • Convert target **R² ≥ 0.6** to Cohen’s *f²* using `f² = R² / (1‑R²)`. <br>• Use `statsmodels.stats.power.FTestPower` with α = 0.05, power ≥ 0.80, and the computed *f²* to determine the required sample size *N*. <br>• Record required *N*, achieved power, and the effect‑size justification in `output/power_analysis.json`. <br>• Abort if actual N < required N. | **FR‑015**, **FR‑022**, **FR‑023**, **SC‑009** |
| **5. Train‑Test Split & VIF** | • Fixed seed `42`; 80/20 split → `data/train.parquet`, `data/test.parquet`. <br>• Compute VIF for each descriptor (statsmodels). <br>• Drop any descriptor with VIF > 5; log actions in `output/vif_summary.json`. | **FR‑016**, **SC‑010**, **FR‑018** |
| **6. Model Training** | • `RandomForestRegressor(n_estimators=500, max_features='sqrt', random_state=42)`. <br>• 5‑fold CV on training set; store CV scores. <br>• Persist model to `output/rf_model.joblib`. | **FR‑003**, **VII** |
| **7. Descriptor‑Target Correlation (Training)** | • Pearson *r* and two‑tailed *p* for each descriptor (training data only). <br>• Flag descriptors with |r| > 0.5 & p < 0.01; save to `output/descriptor_corr.json`. | **FR‑014**, **SC‑007** |
| **8. External Validation Data** | • **If a second verified Zenodo dataset is available** (e.g., DOI `` with non‑overlapping records), download it as `data/hea_external.jsonl`. <br>• Validate and compute descriptors as in Steps 1‑3. <br>• **If no independent verified dataset exists**, the external‑validation phase is omitted and the limitation is recorded in the report. | **FR‑017**, **FR‑018** |
| **9. Performance Evaluation (Held‑out Test)** | • Predict on `data/test.parquet`. <br>• Compute R², Pearson *r*, two‑tailed *p*; bootstrap 95 % CI (≥ 1000 resamples). <br>• Save to `output/metrics.json` and validate against `contracts/metrics.schema.yaml`. | **FR‑004**, **SC‑001**, **SC‑002**, **SC‑003**, **VII** |
| **10. Performance Evaluation (External Set)** | • If external data was obtained, predict on it; compute same metrics; store `output/external_metrics.json`. | **FR‑017**, **SC‑008** |
| **11. Permutation Importance** | • `sklearn.inspection.permutation_importance` on held‑out test set with **500 permutations per feature**. <br>• Non‑parametric permutation test; apply Holm‑Bonferroni (α = 0.05). <br>• Save scores and raw / corrected *p*‑values to `output/perm_importance.json`; validate against `contracts/importance.schema.yaml`. | **FR‑005**, **FR‑006**, **SC‑003** |
| **12. Stability Assessment** | • Repeat Phases 5‑11 three times with seeds `[111, 222, 333]`. <br>• Record top‑5 feature rankings per run in `output/stability_rankings.json`. <br>• Compute max rank difference; abort if > 1. | **FR‑021**, **SC‑006** |
| **13. Provenance & Reporting** | • Assemble `report.md` with sections: dataset stats, VIF summary, power analysis, descriptor‑target correlations, model performance (incl. CI), permutation importance (corrected *p*), stability results, external‑validation documentation (if any), and a provenance log (run ID, seeds, package versions, timestamps). <br>• Generate `manifest.json` and validate against `contracts/manifest.schema.yaml`. | **FR‑008**, **FR‑010**, **SC‑004**, **SC‑011**, **FR‑024**, **SC‑005** |
| **14. Contract Validation (FR‑018)** | • Run `jsonschema` validation on **all** generated artifacts (raw dataset, descriptor table, VIF summary, metrics, importance, stability rankings, manifest, runtime summary). <br>• Halt pipeline on any validation failure. | **FR‑018** |
| **15. CI Integration** | • GitHub Actions workflow (`.github/workflows/ci.yml`) runs the full pipeline, validates contracts, lints (`ruff` ≤ 5 warnings) and formats (`black --check`). <br>• Writes `output/pipeline_runtime.json` with status, total runtime, and resource usage. | – (future) |

All phases are ordered so that data acquisition precedes any consumption, model training precedes evaluation, and figures/tables are generated before being embedded in the final report.
