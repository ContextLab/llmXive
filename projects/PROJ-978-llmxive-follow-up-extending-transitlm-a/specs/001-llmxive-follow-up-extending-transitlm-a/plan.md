# Implementation Plan: llmXive follow-up: extending "TransitLM: A Large-Scale Dataset and Benchmark for Map-Free Transit Ro"

## Summary

This project extends the TransitLM benchmark to identify the "cognitive horizon"—the specific route length and topological complexity threshold where local adjacency statistics (sufficient for short routes) fail to uniquely determine valid global transit paths. The approach involves downloading the TransitLM SFT dataset, filtering for four Chinese cities (via station name parsing and mapping), and stratifying routes by length (short <15, medium 15-30, long >30). 

A **deterministic, fixed-lookup lightweight model** (retrieving top-N neighbors and selecting the highest frequency transition) will be compared against a **baseline LLM** (Qwen-1.5-1.8B, quantized, CPU-only). 

The analysis employs a **dual-method statistical approach**:
1.  **Survival Analysis (Kaplan-Meier & Cox PH)**: To model the cumulative probability of route validity decay (answering "when do routes fail?") and the hazard of failure at each hop.
2.  **Point-wise Chi-Squared Scan**: To identify the specific "inflection point" where the validity gap between models exceeds a significant threshold (answering "at what length does the gap emerge?"). This involves testing validity proportions at *every* individual route length (L=1 to L=max), not just broad strata. This satisfies Constitution Principle VI.

The implementation must run entirely on CPU (GitHub Actions free-tier). The baseline LLM feasibility is a hypothesis to be tested; if it exceeds the 6-hour runtime or 7GB RAM limit, the result is recorded as "timeout/infeasible" rather than offloaded, ensuring reproducibility. If the baseline fails, the divergence claim is marked as "inconclusive" for that subset.

## Constitution Check

*Gates determined based on constitution file:*

1.  **Reproducibility (NON-NEGOTIABLE)**: Plan includes pinned `requirements.txt` and random seeds. Data will be fetched from canonical Hugging Face sources with checksumming. City filtering uses a deterministic mapping file.
2.  **Verified Accuracy**: All citations to TransitLM and methodology will be validated against primary sources (paper/dataset card) before implementation.
3.  **Data Hygiene**: Raw data will be downloaded to `data/raw/` with checksums. Preprocessing will produce new files in `data/processed/`. No in-place modification.
4.  **Single Source of Truth**: All metrics (validity, survival curves) will be generated by code and stored in `data/analysis/`. The paper will reference these files.
5.  **Versioning Discipline**: Artifacts will carry content hashes. The plan will update the project state timestamp upon generation.
6.  **Topological Threshold Stratification**: The plan explicitly implements the <15, 15-30, >30 stratification. **Crucially, the inflection point detection uses a point-wise Chi-squared test on validity proportions at every route length** (as required by Principle VI), interpreting "connectivity" as the statistical link between length and validity. Survival analysis is used as a complementary visualization for global decay.
7.  **Resource-Constrained Baseline Fidelity**: The lightweight model is a **fixed lookup strategy** (deterministic retrieval), satisfying Principle VII. The baseline is CPU-only; if it fails, the failure is recorded, and the divergence claim is marked as inconclusive, not offloaded.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Dual Statistical Method (KM + Point-wise Chi-Squared) | KM models cumulative decay; Point-wise Chi-squared identifies the specific threshold (15% margin) required by the spec. | Using only KM cannot identify a specific length threshold; using only Chi-squared ignores the cumulative nature of route failure. |
| Fixed Lookup Strategy | Required by Constitution Principle VII. | A trained probabilistic model violates the "fixed lookup" constraint and introduces unnecessary complexity. |
| Valid Path Space Generation | Required to address the "uniqueness" tautology. | Comparing against a single ground truth path conflates "error" with "alternative valid path". |
| Sampled Dataset | Required to fit the specified CI window with a CPU baseline. | Running the full dataset with a CPU baseline is infeasible; sampling is a necessary trade-off for reproducibility. |
