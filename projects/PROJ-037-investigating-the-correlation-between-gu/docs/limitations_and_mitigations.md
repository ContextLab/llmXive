# Limitations and Mitigations

This document outlines the known limitations of the PROJ-037 pipeline and the specific mitigations implemented to address them.

## 1. Data Limitations

### 1.1. Missing "Diet Timing" Data
- **Issue**: The American Gut Project (AGP) does not collect "diet timing" data, which is required by feature requirement FR-004.
- **Mitigation**: The pipeline uses "diet type" (e.g., vegetarian, omnivore) as a proxy variable in the GLM adjustment.
- **Documentation**: This deviation is explicitly flagged in the `code/analysis.py` output and the final report generated by `code/report.py`.

### 1.2. Sample Size Constraints
- **Issue**: Bootstrap resampling (1000 iterations) requires a sufficient sample size to be statistically valid.
- **Mitigation**: The pipeline checks the sample size (N) before resampling. If N < 40, resampling is skipped, and the status is recorded in `data/outputs/validation_status.json` with the reason "Insufficient sample size".

### 1.3. Data Availability and Access
- **Issue**: AGP and Open Humans data require registration and may have access restrictions.
- **Mitigation**: The `code/ingestion.py` script uses `requests` to fetch data from canonical URLs. If data is unavailable, the script fails loudly (no synthetic fallback) to ensure data integrity.

## 2. Methodological Limitations

### 2.1. Causality vs. Association
- **Issue**: Correlation does not imply causation. The research question initially sought "significant correlation," which can be misinterpreted as causal.
- **Mitigation**: All analysis modules (`code/analysis.py`, `code/report.py`) and documentation explicitly frame findings as **associational**. The term "correlation" is used in the statistical sense only.
- **Reference**: Per reviewer Linus Pauling, correlation is a necessary but insufficient condition for understanding; this pipeline identifies statistical associations for further investigation, not causal mechanisms.

### 2.2. Negative Results Interpretation
- **Issue**: Specification SC-002 incorrectly treated confidence intervals including zero as invalid.
- **Mitigation**: The `code/validation.py` module treats CIs including zero as valid negative results, providing a more accurate representation of the data.

### 2.3. Continuous vs. Categorical Variables
- **Issue**: Using PERMANOVA for continuous variables is statistically inappropriate.
- **Mitigation**: PERMANOVA is restricted to categorical sleep variables. dbRDA is used for continuous variables as per the plan mitigation.

## 3. Performance Limitations

### 3.1. Runtime Constraints
- **Issue**: The pipeline must complete within 6 hours for N=200.
- **Mitigation**: Parallel processing is implemented for alpha/beta diversity, correlation tests, and FDR correction via `code/performance_optimizer.py`. Memory optimization is applied to dataframes.

## 4. Security and Privacy

- **Issue**: Handling of participant data (AGP/Open Humans).
- **Mitigation**: Data loading and saving are handled by `code/security.py` using `secure_load_csv` and `secure_save_csv` to ensure integrity and proper permissions.

## 5. Future Work

- Integration of "diet timing" data if it becomes available in future AGP releases.
- Expansion to molecular mechanism analysis (Phase 6) if computational resources allow.
- Validation in independent cohorts to assess generalizability.
