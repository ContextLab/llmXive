## Unresolved concerns

- T046 computes textual covariates, but spec FR-007 requires including 'caption length (number of tokens)' as a covariate. T046 counts noun phrases and named entities but does not explicitly cover the 'caption length' calculation required by FR-007.
- T021a is marked [S] (Sequential) with a note to avoid CPU contention with T014-T017. However, T021a (CLIP inference) and T014-T017 (BERT/spaCy feature extraction) are independent data-flow producers. They do not share state or output artifacts that the other consumes. Marking them as mutually exclusive [S] creates an artificial serialization bottleneck that violates the 'Producer before consumer' parallelism principle. They should be [P] or managed via resource limits, not task ordering.
- T033 (Sensitivity Analysis) depends on T013b/T013c (Deterministic Regeneration). The task description states T033 'explicitly triggers T013b/T013c per seed'. However, T013b/T013c are defined as single execution tasks in Phase 1. The dependency graph implies T033 must *invoke* logic from T013b, not wait for T013b to complete once. The current ordering suggests T013b runs once before T033, but T033 needs to run the *regeneration logic* multiple times. This is a semantic dependency violation: the 'producer' (regeneration logic) is not correctly scoped as a reusable component for the 'consumer' (T033 loop).
- T045 (Constitution Enforcement Test Execution) is marked [S] and placed in Phase 6. The description states it must pass 'before any training (T029) or feature extraction (T014) tasks are considered complete'. However, T014 and T029 are in Phase 2 and 4 respectively. If T045 is a blocking gate for the *completion* of T014/T029, then T045 must logically precede the *finalization* of those tasks, or T014/T029 must be split into 'Implementation' and 'Validation' sub-tasks. Currently, T014/T029 are marked complete before T045 runs, violating the 'gate' requirement implied by the text.
- T013b and T013c are marked [S] (Sequential). While they likely depend on T009 (Data Download), the text does not explicitly state the dependency on T009 in the task description, only in the 'Note'. For strict ordering clarity, the dependency 'Requires T009' should be explicit in the task body, not just the note, to ensure the deterministic pre-filter and human reviewers see the producer-consumer link immediately.
- T021a instructs implementing CLIP score generation via inference, but spec FR-003 mandates using 'pre-computed' scores from the dataset and raising an error if missing. The task lacks a concrete deliverable that aligns with the spec's requirement to consume existing data rather than generate it, creating a deterministic conflict for the implementer.
- T022 specifies normalizing CLIP and Human ratings to [0,1] range. Spec FR-003 explicitly requires 'Z-score normalization (subtract mean, divide by standard deviation)'. The task description contradicts the spec's mathematical definition, making the deliverable non-deterministic regarding the target variable calculation.
- T030 defines the deliverable as 'permutation importance analysis'. Spec FR-006 requires a specific 'permutation-based significance test' with N=1,000 shuffles, null distribution generation, p-value calculation, and Benjamini-Hochberg correction. T030 is too coarse and misses the specific statistical deliverables (null distribution, p-values) required by the spec.
- T033 describes a sensitivity analysis over random seeds for model training. Spec FR-006 and SC-005 require a sensitivity analysis over 'significance thresholds' (0.01, 0.05, 0.1) and a robustness check on 'data variance' (sampling seeds) outputting a specific JSON structure. The task fails to name the correct deliverable (threshold sweep results) and conflates it with model seed variance.
- T015 instructs assigning 'default depth=0' for short captions. Spec FR-011 explicitly requires the system to 'exclude the sample from the training matrix and log the exclusion reason'. The task's deliverable (imputing 0) directly contradicts the spec's exclusion logic, making the task unexecutable as written without violating the spec.
- T031 allows 'dynamically reduce n_iter' if time budgets are exceeded. Spec FR-006 mandates a fixed iteration count of N=1,000 by default with pinned seeds for reproducibility. The task's conditional logic violates the fixed statistical method requirement, making the deliverable non-deterministic and non-reproducible.
- T014 names the function 'compute_semantic_entropy' and implies a specific calculation. Spec FR-001 strictly defines the metric as 'Linguistic Uncertainty Proxy' calculated as 'ln(perplexity)'. The task uses a different term ('semantic entropy') which may imply a different algorithm (e.g., Monte Carlo sampling) not authorized by the spec, creating ambiguity in the deliverable.
- T002 lists 'torch' in requirements.txt. While needed for CLIP (T021a), the plan and spec emphasize a strict CPU-only environment for the *training* pipeline (XGBoost). The task description does not clarify if 'torch' is strictly for the CLIP inference step (which conflicts with FR-003) or if it's a bloat dependency, creating ambiguity in the setup deliverable.
- T022 specifies 'Normalize CLIP and Human ratings to [0,1]' before calculating deviation. Spec FR-003 explicitly mandates 'Z-score normalization (subtract mean, divide by standard deviation)'. These are mathematically distinct operations; T022 silently weakens the FR-003 requirement, altering the target variable definition.
- T015 instructs to 'Assign default depth=0 for short captions'. Spec FR-011 explicitly requires the system to 'exclude the sample from the training matrix and log the exclusion reason with the specific caption ID' for such cases. Imputing a default value violates the exclusion constraint and risks data leakage.
- T030 describes implementing generic 'permutation importance'. Spec FR-006 mandates a specific 'permutation-based significance test' with N=1,000 shuffles to generate a null distribution, followed by Benjamini-Hochberg correction and a sensitivity sweep over significance thresholds (0.01, 0.05, 0.1). T030's scope is insufficient to satisfy the statistical rigor required by FR-006.
- T033 focuses on sensitivity analysis over random seeds for model training. Spec FR-006 and SC-005 require a sensitivity analysis over the *significance threshold* (p-value sweep) and a robustness check on *data variance* (different sampling seeds) resulting in a JSON table of mean rank and std dev across these specific sweeps. T033 misses the threshold sweep requirement.
- T021a implements CLIP score generation via inference on 'openai/clip-vit-base-patch32'. Spec FR-003 states the system must use 'pre-computed CLIP score' data from the 'pick-a-pic' dataset and raises a DataSchemaError if unavailable. - T031 allows 'dynamically reduce n_iter' if time budgets are exceeded. Spec FR-006 mandates a fixed iteration count of N=1,000 by default with pinned seeds to ensure reproducibility. Allowing dynamic reduction without a specific fallback protocol violates the reproducibility constraint and the fixed statistical method defined in the spec.
- T014 defines the function as computing 'semantic entropy'. Spec FR-001 strictly defines the metric as a 'Linguistic Uncertainty Proxy' calculated as the natural logarithm of perplexity (ln(perplexity)). While related, 'semantic entropy' is a distinct statistical concept; the task description risks implementing a different algorithm than the one mandated by FR-001.
