# Data Model: The Influence of Visual Salience on Moral Judgments of Simulated Scenarios

## Overview
The data model defines every artifact from raw ingestion to final analysis, ensuring traceability, reproducibility, and compliance with the project constitution and contract schemas.

## Entity‑Relationship Summary
```
[Scenario] 1---N [Stimulus Variant] N---M [Response]
      |                                 |
      v                                 v
[Participant] ------------------------> [Response]
```

## Schemas (see `contracts/`)

### Scenario (derived from `contracts/dataset.schema.yaml`)
- `scenario_id` (string) – unique identifier.  
- `original_image_path` (string) – path to the raw image.  
- `metadata` (object) – tags, object list, etc.  
- `ambiguity_score` (float) – mean human coding rating (1‑5).  
- `ambiguity_label` (boolean) – retained if the mean ≥ 3.5 & κ ≥ 0.6.  

### Stimulus Variant (see `contracts/stimulus.schema.yaml`)
- `variant_id` (string)  
- `scenario_id` (FK)  
- `salience_level` (`low`/`medium`/`high`)  
- `manipulation_params` (object: `contrast_adjustment`, `brightness_adjustment`, `version`)  
- `clip_similarity` (float ≥ 0.95)  
- `rms_contrast_change` (float ≥ 15)  
- `moral_intent_preservation_score` (float ≥ 0.90)  
- `semantic_integrity` (`passed`/`failed`)  
- `image_path` (string)  

### Participant (see `contracts/participant.schema.yaml`)
- `participant_id` (string)  
- `start_time`, `end_time` (ISO‑8601)  
- `total_responses` (integer)  
- `exclusion_flag` (bool)  
- `exclusion_reason` (optional string)  

### Response (see `contracts/response.schema.yaml`)
- `response_id` (string) – **generated UUID for each survey entry**.  
- `participant_id` (FK)  
- `variant_id` (FK)  
- `salience_level` (string) – redundant copy for convenience.  
- `blame_rating` (int 1‑7)  
- `timestamp` (ISO‑8601)  
- `order_index` (int) – presentation order for order‑effect control.  
- `valid` (bool) – **TRUE if the response passed cleaning; FALSE otherwise** (added in Phase 3).  

### Analysis Output (see `contracts/analysis_schema.yaml`)
- `analysis_id` (string) – **UUID generated by the analysis script**.  
- `model_type` (enum: `Cumulative_Link_Mixed_Model`, `Linear_Mixed_Effects_Model`, `Wilcoxon_Signed_Rank_Test`)  
- `fixed_effects` (object: coefficient name → number)  
- `random_effects_variance` (object: random effect name → variance)  
- `p_value` (0 – 1) – raw p‑value for the main effect of salience.  
- `p_value_corrected` (0 – 1) – Bonferroni‑adjusted.  
- `effect_size` (object: odds ratio, `ci_lower`, `ci_upper`).  
- `convergence_status` (string: `converged`/`warning`/`failed`).  
- `post_hoc_tests` (array of objects: `comparison`, `odds_ratio`, `p_value_uncorrected`, `p_value_bonferroni`).  
- `exclusion_rate` (0 – 1)  
- `sample_size` (integer) – number of valid responses after cleaning.  
- `order_covariate_included` (bool) – true if `order_index` is used.  
- `power_analysis` (object: `observed_power`, `power_flag`, `precision_check` with `ci_width`, `threshold`, `flag`).  

## Data Flow
1. **Ingestion & Filtering** → `candidates_filtered.csv`.  
2. **Human Coding** → `scenarios.csv`.  
3. **Manipulation** → `stimuli_manifest.csv` + image files.  
4. **Survey** → `responses_raw.csv`.  
5. **Cleaning** → `responses_cleaned.csv` (adds `valid`) and `participants_excluded.csv`.  
6. **Analysis** → `analysis_results.json`.  

All files are listed in `data/checksums.txt`. No in‑place modifications; each transformation writes a new artifact with a derivation log (Principle III).  

## Constraints
- All numeric thresholds (CLIP ≥ 0.95, RMS contrast ≥ 15 %, κ ≥ 0.6, moral‑intent ≥ 0.90, etc.) are enforced programmatically and validated against the corresponding contract schemas.  
- Participant IDs are anonymized via a SHA‑256 hash of the raw platform ID.  

## Contract Coverage
- `contracts/dataset.schema.yaml` validates `scenarios.csv`.  
- `contracts/stimulus.schema.yaml` validates each row of `stimuli_manifest.csv`.  
- `contracts/response.schema.yaml` validates raw and cleaned response files (including `response_id`, `order_index`, and `valid`).  
- `contracts/analysis_schema.yaml` validates `analysis_results.json`.
