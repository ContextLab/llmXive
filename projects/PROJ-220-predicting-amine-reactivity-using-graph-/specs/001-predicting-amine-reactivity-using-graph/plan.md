# Implementation Plan: Predicting Amine Reactivity Using Graph Neural Networks and Public Databases

**Branch**: `001-predicting-amine-reactivity` | **Date**: 2026-08-16 | **Spec**: `specs/001-predicting-amine-reactivity/spec.md`
**Input**: Feature specification from `specs/001-predicting-amine-reactivity/spec.md`

## Summary

This project implements a pipeline to predict SN2 reaction rates for primary and secondary amines using Graph Neural Networks (GNNs) trained on **experimental** kinetic data from ChEMBL and the NIST Kinetics Database. The approach involves ingesting verified reaction data, constructing heterogeneous molecular graphs with Gasteiger partial charges and pKa features, training a heterophily-aware GNN (GAT) and a traditional baseline (Random Forest), and performing SHAP-based interpretability analysis. The interpretability results are validated by correlating learned feature importance with a **computed** vector of established chemical descriptors (Hammett, Taft, Verloop) generated for the specific dataset molecules. The entire pipeline is designed to run within the constraints of a GitHub Actions free-tier runner (CPU-only, <7GB RAM, <6h) by leveraging streaming data loading and efficient sampling strategies.

## Citation Validation Gate

Before any data ingestion, the `validate_citations.py` script MUST run with the following logic:
1.  **URL Reachability**: Verify the dataset URL returns HTTP 200.
2.  **Checksum Match**: Verify the downloaded file checksum matches the one recorded in `state/...yaml`.
3.  **Title Overlap**: If a citation is present, verify the dataset title matches the cited source with overlap ≥ 0.7.
4.  **Trigger**: This gate triggers automatically in the `data/ingestion.py` script before any `load_dataset` or API call. If validation fails, the pipeline exits with error code.

## Versioning Workflow

To satisfy Constitution Principle V, the following workflow is enforced:
1.  **Artifact Generation**: When a script (e.g., `train.py`) generates an artifact (e.g., `model.pt`), it immediately calls `utils/versioning.py:update_state()`.
2.  **Hash Calculation**: The script computes a SHA-256 hash of the artifact content.
3.  **State Update**: The script updates the project's `state/projects/PROJ-220-...yaml` file, adding the `artifact_id` and `hash` to the `artifact_hashes` map and updating `updated_at`.
4.  **Atomic Write**: The state file is written atomically to prevent corruption.
5.  **Trigger**: This update is triggered as the final step of any data transformation or model training phase.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| **Heterophily-aware GNN** | Standard GNNs (GCN) fail on reaction graphs where node features (reactant vs. transition state) are highly dissimilar (heterophilous). | A standard GCN would likely underfit the specific electronic effects of the reaction center, failing SC-003 (interpretability alignment). |
| **Streaming Data Loading** | The NIST/ChEMBL datasets may exceed 7GB RAM if fully loaded. | Loading the full dataset into memory would cause OOM errors on the GitHub Actions free tier, violating FR-008. |
| **SHAP on CPU** | SHAP is computationally expensive. | Using a simpler feature importance (e.g., tree-based) would not provide the atomic-level resolution required to validate against Hammett/Taft descriptors (SC-003). |
| **Descriptor Computation** | External descriptors (Hammett, Taft) are required for validation but are not in the raw data. | Using pre-computed values is impossible for a custom dataset; they must be computed on-the-fly using `mordred`/`rdkit` to ensure construct validity. |
