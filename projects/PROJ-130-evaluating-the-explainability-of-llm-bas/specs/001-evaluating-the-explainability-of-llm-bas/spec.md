# Specification: Evaluating the Explainability of LLM-Based Bug Fixes

## Overview
This project evaluates the internal coherence and external validity of explanations generated by LLMs when fixing software bugs. We correlate explainability metrics (attention, saliency, coherence) with patch correctness.

## User Stories

### US-1: Generate Patches and Assess Correctness
As a researcher, I want to generate patches for Defects4J bugs using CodeLlama-7B-Instruct and assess their correctness via the test suite, so that I have a labeled dataset of correct/incorrect fixes.

**Acceptance Criteria:**
1. Defects4J v2.0 is downloaded and verified.
2. Patches are generated in diff format with accompanying rationale text.
3. Correctness is determined by passing/failing the Defects4J test suite.
4. Safety flags are recorded for unsafe patches.

### US-2: Extract Explainability Scores
As a researcher, I want to compute attention weights, saliency maps, and internal coherence scores for generated patches, so that I can quantify the quality of the LLM's reasoning.

**Acceptance Criteria:**
1. Attention weights are extracted from the model's last decoder layer.
2. Integrated Gradients saliency is computed for tokenized diffs.
3. **Acceptance Scenario 3**: The system computes the internal coherence of the rationale text against the code change semantics using cosine similarity and outputs a `coherence_score`.
4. Missing rationales are handled gracefully with null scores.

### US-3: Statistical Analysis and Correlation Testing
As a researcher, I want to compute correlations between explainability scores and correctness, so that I can validate the hypothesis that better explanations correlate with better fixes.

**Acceptance Criteria:**
1. Point-biserial correlations are computed.
2. Logistic regression models are fitted and evaluated via AUC-ROC.
3. Paired t-tests with Bonferroni correction are performed.
4. Confound controls (bug complexity) are included.

## Functional Requirements

### FR-001: Data Acquisition
The system must download Defects4J v2.0 from the official GitHub repository and verify the SHA256 checksum.

### FR-002: Patch Generation
The system must prompt CodeLlama-7B-Instruct with a specific template to generate diffs and rationale text.

### FR-003: Correctness Assessment
The system must execute the Defects4J test suite with a 60s timeout per bug.

### FR-004: Attention Extraction
The system must extract per-token attention weights from the last decoder layer.

### FR-005: Saliency Computation
The system must apply Captum's Integrated Gradients to compute saliency magnitude.

### FR-006-REV: Internal Coherence Measurement
The system must compute the internal coherence of generated rationales against code change semantics using a sentence transformer model (`all-MiniLM-L6-v2`).
- **Metric**: Cosine similarity between the rationale embedding and the diff embedding.
- **Threshold**: A coherence score >= 0.6 is considered valid.
- **Range**: The output `coherence_score` must be in the range [0, 1].
- **Handling**: If no rationale is present, the score is recorded as null.
*(Note: This requirement replaces the original FR-006 which specified BLEU/ROUGE metrics.)*

### FR-007: Correlation Analysis
The system must compute point-biserial correlations between scores and correctness.

### FR-008: Logistic Regression
The system must fit logistic regression models to predict correctness from scores.

### FR-009: Significance Testing
The system must perform paired t-tests with Bonferroni correction.

### FR-010: Safety Flagging
The system must detect and flag unsafe patches.

### FR-011: Reproducibility
The system must pin random seeds and record model revisions.

### FR-012: Integrity Verification
The system must verify dataset checksums.

## Scenario Constraints (SC)

### SC-001: Dataset Size
The system must handle the full Defects4J dataset (approx. 835 bugs). [UNRESOLVED-CLAIM: c_bb96a23e — status=not_enough_info]

### SC-002: Model Constraints
CodeLlama-7B-Instruct must run in 16-bit precision on CPU.

### SC-003: Timeout Limits
Test execution must not exceed 60 seconds per bug.

### SC-004: Memory Limits
Explainability computation must not exceed 16GB RAM per process.

### SC-005: Coherence Threshold
The coherence threshold for valid rationales is 0.6.

### SC-006: Missing Data
Missing rationales must result in a null coherence score, not a default value.

### SC-007: Cosine Similarity Range
The cosine similarity metric used for coherence scoring must produce values in the range [0, 1] (normalized). The system must normalize the raw cosine similarity (which ranges [-1, 1]) to [0, 1] using the formula: `(cosine_sim + 1) / 2` or ensure the embedding model outputs normalized vectors such that the dot product is in [0, 1]. For `all-MiniLM-L6-v2`, vectors are typically L2-normalized, resulting in dot products in [-1, 1]; the system must apply the transformation `(sim + 1) / 2` to map to [0, 1] for the `coherence_score`.
