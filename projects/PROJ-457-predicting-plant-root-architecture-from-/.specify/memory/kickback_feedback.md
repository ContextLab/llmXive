## Unresolved concerns

- FR-002 (Merge with ISRIC) has no implementation task. T013 only fetches PlantPheno/RootReader. The plan explicitly excludes ISRIC, but the spec mandates it. A task to explicitly handle the 'ISRIC unavailable' path (e.g., 'Log FR-002 failure and proceed with root-only data') is missing, leaving the requirement untestable.
- FR-003 (KNN Imputation) is explicitly excluded by AM-001, but there is no task to implement the *alternative* (exclusion of missing rows) that the plan mandates. T015d handles missing nutrients, but the specific logic for 'exclusion vs imputation' decision and the associated logging required to satisfy the 'Spec Deviation' narrative is fragmented. A dedicated task for 'Implement Missing Data Exclusion Logic (FR-003 Deviation)' is needed to ensure the deviation is testable.
- FR-011 (Sensitivity Analysis) requires comparing against 'literature-reported physiological ranges'. T028a fetches these ranges, but there is no task to *perform* the comparison logic defined in FR-011 (±10% variation) and SC-006 (biological plausibility check). T028b does sensitivity, but the explicit 'compare against literature' step required by FR-011 is not clearly mapped to a task that outputs the 'plausibility' verdict.
- FR-009 (Frame findings as associational) requires the final report to explicitly state 'associational' not 'causal'. T034c compiles the report, but there is no specific task or check to enforce the insertion of this specific phrasing or to validate that the report does not contain causal language. This makes FR-009 untestable.
- Task T009 references 'contracts/dataset.schema.yaml' as a prerequisite for a contract test, but the task to *create* this schema file (T009a) is listed as a separate, untagged item in the 'Notes' section or implied. The task list should explicitly include a task to generate the schema files referenced by the contract tests to ensure traceability.
- Task T035a calculates 'P/N Availability Rate' as a redefinition of SC-001. However, SC-001 is defined in the spec as 'proportion of root phenotype datasets successfully merged with soil nutrient data'. The task does not explicitly link this new metric to the *failure* of SC-001, nor does it provide a task to formally update the Success Criteria definition in the report to reflect this deviation. This creates a gap in traceability for SC-001.
- Task T014d (Create Formal Amendment Record AM-001) is listed as a prerequisite for T015d (Filter by Missing Nutrients) and T015h (Record FR-003 Deviation Log). However, T014d depends on T014 (Check P/N Availability), which in turn depends on T013 (Data Ingestion). The current ordering places T014d *after* T014 but *before* T015d, which is correct. However, T015h and T015i (Deviation Logs) are listed as prerequisites for T034a (Read Deviation Logs) in Phase 5, but T015h/T015i themselves depend on T015d/T015g. The chain T013 -> T014 -> T014d -> T015d -> T015h -> T034a is valid. The issue is T015m (Record SC-002 Failure) depends on T015k and T014d. T015k (Count Available Datasets) depends on T013. This is valid. The real issue is T035a (Calculate P/N Availability Rate) depends on T015 and T014d. T015 is a phase header, not a task. T035a should depend on T015f (Write Species Counts) or T015k. The dependency on 'T015' is ambiguous and breaks the deterministic ordering check.
- Task T035a lists 'T015' as a prerequisite. 'T015' is a section header (Phase 3: User Story 1 - ...), not a specific task ID. The task should explicitly depend on the specific tasks that produce the data it consumes (e.g., T013 for raw data, T014 for P/N flag, T015f for species counts). Relying on a section header as a dependency violates the 'Producer before Consumer' rule and makes the execution order ambiguous.
- Task T034b (Read Metrics) lists T035a, T035b, and T035c as prerequisites. However, T035c is not defined anywhere in the tasks.md file. This creates a broken dependency chain where a task cannot be executed because its prerequisite is missing. This is a hard ordering violation.
- Task T015g (Verify ISRIC Source) is marked as a prerequisite for T015i (Record FR-002 Deviation Log). However, T015g is also listed as a prerequisite for T015h (Record FR-003 Deviation Log) in the text description of T015h, but T015h's explicit prerequisite list only includes T015d. While T015g logically precedes T015h, the explicit dependency list in T015h is incomplete, potentially allowing T015h to run before T015g if the scheduler only checks explicit prerequisites.
- Task T009 (Contract test) lists 'T009a (Schema Definition)' as a prerequisite, but T009a is not defined in the task list. The schema definition task is missing, creating a broken dependency for the contract test.
- Task T020 (Contract test) lists 'T020a (Schema Definition)' as a prerequisite, but T020a is not defined in the task list. Similar to T009, this creates a broken dependency.
- Task T030 (Contract test) lists 'T030a (Schema Definition)' as a prerequisite, but T030a is not defined in the task list. This creates a broken dependency for the reporting contract test.
- Task T009 references a prerequisite 'T009a (Schema Definition)' which does not exist in the task list. The task description assumes the existence of `contracts/dataset.schema.yaml` without defining a task to create it, making the task unexecutable as the implementer cannot create a contract test against a non-existent schema file.
- Task T020 references a prerequisite 'T020a (Schema Definition)' which does not exist in the task list. Similar to T009, the task assumes `contracts/model_results.schema.yaml` exists but provides no task to generate it, blocking execution.
- Task T030 references a prerequisite 'T030a (Schema Definition)' which does not exist in the task list. The task cannot be executed without the `contracts/output.schema.yaml` file, which is not created by any preceding task.
- Task T013 instructs to 'download/parse RootReader and PlantPheno data' but fails to specify the exact dataset identifiers, URLs, or HuggingFace dataset names required to fetch them. Without these specific identifiers, the implementer cannot deterministically execute the fetch operation.
- Task T028a instructs to fetch data from 'plant-physiology/nutrient-ranges' on HuggingFace but does not provide the specific dataset version, split, or column mapping logic required to extract the ranges. The fallback values are provided, but the primary fetch logic lacks the necessary parameters for deterministic execution.
- Task T001 is too coarse, covering project initialization, directory creation, and logging setup in a single task. While the deliverable is named, the scope covers multiple distinct setup actions that should be atomized for better parallelization and verification granularity.
- Tasks T002a and T002b are split but could be consolidated or refined. T002a assumes `requirements.txt` exists with specific packages, but T002b overwrites it. The dependency on the file existing before T002a runs is not explicitly defined as a separate creation task, creating a potential execution gap if the file is missing.
- Task T014d requires creating `artifacts/sc_amendments.json` with specific keys, but the task does not specify the exact JSON structure or the mechanism to ensure the file is valid JSON if the keys are missing. The verification step is vague ('Confirm file exists') rather than validating the content structure.
- Task T035a requires calculating 'P/N Availability Rate' but does not define the exact formula or the specific column names in the raw dataset to use for the numerator and denominator. The task assumes the implementer knows the schema of the raw data, which is not provided in the task description.
- Task T037a creates a state file with a specific path `state/projects/PROJ-457-predicting-plant-root-architecture-from-.yaml`. The task does not specify the initial YAML structure or keys required, only that it has an 'initial structure', which is ambiguous for deterministic execution.
- Task T014d creates a formal amendment (AM-001) to exclude FR-002 (ISRIC merge) and FR-003 (KNN imputation). While the plan authorizes this deviation, the task does not explicitly define the *verification step* for the Success Criteria (SC-001, SC-002) that rely on these FRs. The spec requires SC-001 to measure 'proportion merged'; if the merge is excluded, the task must explicitly state how SC-001 is redefined or marked as 'N/A' in the metrics file to prevent a silent failure of the acceptance criteria.
- Task T015m calculates SC-001 as 0.0 due to ISRIC exclusion. This violates the semantic intent of SC-001 ('proportion... successfully merged') which implies a testable success condition. Setting it to 0.0 without a corresponding redefinition of the success criterion (e.g., 'SC-001 is N/A due to data unavailability') constitutes a silent weakening of the requirement. The task must update the metrics file to explicitly flag SC-001 as 'unmeasurable' or 'excluded' rather than reporting a failure value that contradicts the project's 'Spec Deviation' status.
- Task T028a implements a fallback to hardcoded literature ranges (P=[0.05, 0.15], N=[0.02, 0.08]) if the HuggingFace dataset is missing. This violates Constitution Principle II (Verified Accuracy) and FR-011, which mandate that coefficients be validated against *verified* literature. Hardcoded values are not verified citations. The task must be revised to fail loudly or require a verified source, rather than silently accepting unverified constants.
- Task T009 (Contract test for merged dataset schema) assumes the existence of `contracts/dataset.schema.yaml` and the columns 'phosphorus' and 'nitrogen'. However, the Plan and T014 explicitly state that if P/N columns are missing, the project proceeds with root-only data. The task does not account for the schema variation where nutrient columns are absent, creating a logical dead-end where the test will fail if the primary deviation (missing nutrients) occurs, violating the requirement to handle the 'Unverifiable' state gracefully.
