# llmXive Geometry Extension

**Repository for extending the llmXive project with geometric subspace experiments**
This repository implements the full experimental pipeline described in the
*llmXive Follow‑up – Extending on the Geome* specification. It includes
dataset download, mask generation, OPD training, evaluation, statistical
analysis, and resource‑monitoring utilities.

## Overview

The project is organized around three user stories:

1. **US‑1** – Verify that a low‑dimensional subspace identified by OPD is
 sufficient to recover full‑parameter performance.
2. **US‑2** – Show that the OPD‑derived subspace benefits OPD but not generic
 SFT, while a random subspace harms SFT performance.
3. **US‑3** – Demonstrate that the entire pipeline runs on a CPU‑only CI runner
 within 7 GB RAM and 6 h wall‑clock limits.

All scripts live under `src/`, tests under `tests/`, data under `data/`,
and results under `results/`. Contract tests (schema validation) are stored
in `contracts/`.

## Quick‑Start Guide

1. **Clone the repository**
 ```bash
 git clone
 cd llmxive-geometry-extension
 ```

2. **Create a virtual environment and install dependencies**
 ```bash
 python -m venv.venv
 source.venv/bin/activate # on Windows use `.venv\\Scripts\\activate`
 pip install -r requirements.txt
 ```

3. **Download the GSM8K dataset** (≈ 2 GB)
 ```bash
 python -m src.data.download_gsm8k
 ```
 This script streams the dataset from Hugging Face, caches it under
 `data/gsm8k/`, and writes SHA‑256 checksums to `data/checksums.txt`.

4. **Run the full pipeline** (US‑1, US‑2, and US‑3)
 ```bash
 python -m src.pipeline.run_all
 ```
 The orchestrator will:
 - Generate OPD masks, random masks, and perform SVD sweeps.
 - Train baseline, frozen‑subspace OPD, and frozen‑subspace SFT runs for
 30 seeds each.
 - Evaluate held‑out GSM8K accuracy.
 - Perform statistical analyses (power analysis, TOST, t‑tests).
 - Produce summary CSVs in `results/` and a CI metrics file
 `ci_metrics.json`.

5. **Inspect results**
 ```bash
 ls results/
 cat results/us1_summary.csv
 cat results/us2_summary.csv
 cat results/experiment_summary.csv
 ```

6. **Run the test suite** (optional but recommended)
 ```bash
 pytest -q
 ```

## Prerequisites

- Python **3.11** or later.
- `git` (to clone the repository).
- Internet connection (for the initial dataset download).
- Sufficient disk space (~5 GB) for cached dataset and intermediate files.
- A CPU‑only environment is sufficient; the pipeline is designed to stay
 under 7 GB RAM and 360 min wall‑clock per run.

## Installation

The project uses a plain `requirements.txt` (generated by `poetry init`).
Install it with:

```bash
pip install -r requirements.txt
```

Key dependencies include:

- `datasets` – for streaming GSM8K.
- `torch` – for model loading and training.
- `llama-cpp-python` – TinyLlama 4‑bit GGML loader.
- `statsmodels` – statistical power analysis and TOST.
- `pandas`, `numpy`, `scipy` – data handling and numeric utilities.
- `ruff`, `black` – linting/formatting (configured in `.ruff.toml` and
 `pyproject.toml`).

## Dataset Preparation

The dataset script (`src/data/download_gsm8k.py`) streams the three GSM8K
splits (`train`, `validation`, `test`) and stores them under
`data/gsm8k/`. After download, run the checksum validation test:

```bash
pytest tests/integration/test_download_gsm8k.py
```

## Running the Experiments

The pipeline is modular; you can run individual stages if desired:

- **Baseline OPD**: `python -m src.pipeline.orchestrate_baseline_seeds`
- **Mask Generation (OPD & Random)**: `python -m src.model.mask` (internal)
- **Frozen‑Subspace OPD**: `python -m src.pipeline.orchestrate_frozen_opd_seeds`
- **Frozen‑Subspace SFT**: `python -m src.pipeline.orchestrate_sft_seeds`
- **Statistical Analysis**: `python -m src.eval.stats`

The top‑level driver `src.pipeline.run_all` executes the full sequence
in the correct order and writes a unified summary CSV.

---

## Results & Reporting

All generated CSV files reside in `results/`:

- `us1_summary.csv` – OPD equivalence test outcomes.
- `us2_summary.csv` – Mask‑type comparison statistics.
- `experiment_summary.csv` – Unified summary for the whole project.

The CI metrics file `ci_metrics.json` records peak RAM (GB) and total
wall‑clock time (minutes) for the entire run.

## Testing & CI

Contract tests validate schema compliance for inputs/outputs. Run the full
suite locally:

```bash
pytest
```

The GitHub Actions workflow (`.github/workflows/ci.yml`) automatically
installs dependencies, caches the GSM8K download, runs the full pipeline,
and uploads `ci_metrics.json` as an artifact.
