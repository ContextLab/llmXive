# Tasks: Physics-Teacher Distillation for Few-Step Autoregressive Video Generation

**Inputs**: Active `spec.md` (002-llmxive-physics-teacher-distillation), `plan.md`, data-model/contracts, original research idea.

This is a research implementation plan for the smallest complete study testing whether deterministic CPU physics solvers can replace neural teachers in few-step autoregressive diffusion distillation. All computation is CPU-only (FR-003); the physics engines and the ≈50 M-parameter student model (per FR-002) are sized and scheduled to fit the free runner (~7 GB RAM, ≤6 h wall-clock) using small spatial resolution, gradient accumulation, and activation checkpointing. Note: the plan's `src/` tree is superseded by the project's `code/` convention; tasks below use `code/` paths consistently.

**Plan-root conflicts flagged for kickback** (the tasks follow the spec, which is authoritative):
- The plan's "~10 M parameters" contradicts spec FR-002's ≈50 M-parameter mandate; tasks implement the spec scale.
- The plan's "≤6 epochs" cap contradicts the spec's 20-epoch non-convergence fallback; tasks train up to 20 epochs with early-stop.
- The plan's T7.3 (writing `state/projects/PROJ-827-...yaml`) is platform-owned; tasks checksum final artifacts into a project-owned manifest instead.
- The control baseline (plan T2.4) and Trajectory-Pixel Correlation metric (plan T4.4) are authorized by no FR/SC in spec.md; they are retained per the plan's methodology rationale and flagged for spec amendment.
- SC-007 and SC-009 in spec.md specify the same FID measurement twice; a single FID computation is reported (spec consolidation flagged).

## Phase 1: Setup and first end-to-end analysis

- [ ] T001 [P] [US1] Environment, contracts, and the deterministic physics-teacher data generators.
  1. Write `code/requirements.txt` pinning every dependency (Python 3.11; `pybox2d`, `torch==2.2.0`, `torchvision`, `numpy`, `pandas`, `scikit-image`, `lpips`, `scipy`, `statsmodels`, `pytest`, `imageio`, `tqdm`) — the constitution's Reproducibility Requirement; all subsequent code runs in an isolated virtualenv built from it.
  2. Amend `specs/001-llmxive-follow-up-extending-causal-forci/contracts/evaluation_results.schema.yaml` BEFORE any metrics are written: (a) add `"control_baseline"` to the `model_type` enum (alongside `physics_teacher`, `neural_teacher`) so control-baseline rows are representable; (b) remove `fid` from the per-sequence required fields (FID is a set-level metric; it will be written to a dedicated aggregate file, see T007). Update the schema's embedded copy in `specs/001-llmxive-follow-up-extending-causal-forci/data-model.md` to match.
  3. Implement the deterministic rigid-body generator in `code/src/data_generation/generate.py` (+ `utils.py`): Box2D, fixed seed and fixed Δt per sequence, 16 frames, rendering to `.mp4` and state vectors (positions, velocities per frame) to `.npz`, metadata JSON conforming to `specs/001-llmxive-follow-up-extending-causal-forci/contracts/physics_trajectory.schema.yaml` and `specs/001-llmxive-follow-up-extending-causal-forci/contracts/video_sequence.schema.yaml` (SHA256 checksums included). NaN/corruption detection discards the sequence with a logged warning (FR-001, FR-006, edge case).
  4. Implement the deterministic fluid generator in `code/src/data_generation/generate_fluid.py`: a simplified, CPU-only Navier-Stokes solver (stable-fluids style, explicit diffusion/advection on a small grid) with a `viscosity` parameter, fixed seed and fixed Δt, 16 frames, same `.mp4`/`.npz`/JSON outputs and schema validation — this provides the fluid-dynamics axis required by FR-008's ablation.
  Focused tests in `code/tests/test_generation.py` verify: (a) identical outputs on repeated runs with the same seed for BOTH generators (SC-001), (b) zero NaNs, (c) momentum conservation within solver tolerance for a frictionless two-body collision, (d) fixed friction=0.5 yields the exact deterministic trajectory, (e) the fluid solver is deterministic under fixed seed and its viscosity parameter measurably changes the velocity field. Generate a first small end-to-end batch (e.g., 32 rigid-body and 16 fluid sequences) into `data/physics/train/` and `data/physics/test/` to prove the pipeline runs on CPU.
  - Verification: `pytest code/tests/test_generation.py` passes; `data/physics/` contains valid `.mp4`/`.npz`/JSON triples validated against the schemas at `specs/001-llmxive-follow-up-extending-causal-forci/contracts/`; the amended evaluation_results schema validates with `control_baseline` rows and without per-sequence `fid`.

- [ ] T002 [P] [US2] Implement the student model and training loop in `code/src/models/student_diffusion.py`: a 2-step autoregressive diffusion student with the spec-mandated ≈50 M parameters (FR-002), made CPU-feasible via small spatial resolution (e.g., 64×64), batch size 8 with gradient accumulation and activation checkpointing; pixel-space MSE loss; conditioning on current frame + physics trajectory state vectors; training loader in `code/src/data_generation/loader.py` feeding (current frame, trajectory) → next frame. Training runs up to 20 epochs with early-stop when validation MSE ≤ 0.05, so the spec's edge-case fallback is reachable: if validation MSE > 0.07 after 20 epochs, switch to a higher learning-rate schedule for a further 5 epochs; if convergence still fails, abort and log the failure. CPU-only — no CUDA, no quantization libraries (FR-002, FR-003). Unit tests in `code/tests/test_student.py` verify forward/backward shapes, parameter count ≈50 M (within ±10%), determinism under fixed seed, that a single overfit batch drives MSE toward zero, and that the higher-LR fallback branch fires on a synthetic non-converging loss curve (edge-case reachability).
  - Verification: `pytest code/tests/test_student.py` passes. NOTE on ordering: the implementation and unit tests are parallel-safe with T001, but the smoke-train verification gate — a 50-step smoke train run on the T001 batch reducing loss monotonically on CPU — executes only AFTER T001's batch exists; T002's verification is not complete until T001 lands.

- [ ] T003 [US2] Run the first end-to-end training and evaluation slice: train the student on the small T001 physics batch for a few epochs, generate 16-frame sequences from held-out trajectories, and compute SSIM + PSNR against ground-truth frames in `code/src/evaluation/metrics.py`, writing per-sequence rows to `data/results/first_slice_metrics.csv` conforming to the (T001-amended) `specs/001-llmxive-follow-up-extending-causal-forci/contracts/evaluation_results.schema.yaml` per-sequence fields (model_type = `physics_teacher`; SSIM ∈ [0,1], PSNR in dB; no per-sequence fid — set-level FID is deferred to T007). Document the runnable command in the feature's `quickstart.md`.
  - Verification: the documented command executes; `data/results/first_slice_metrics.csv` contains real measured SSIM/PSNR values for the physics-teacher student on shared held-out test sequences (baseline comparison is deferred to T007, after the baselines exist).

**Checkpoint**: The documented command executes end-to-end on CPU and its numerical outputs are real measured values. Do not proceed to full-scale runs with invented or placeholder metrics.

## Phase 2: Complete the study and validate its evidence

- [ ] T004 [US1] Scale data generation to the full study size (a few thousand rigid-body training sequences plus comparable validation/test splits, and a fluid-sequence pool sufficient for the T009 ablation — at least 300 fluid sequences covering the viscosity range; exact counts chosen to fit disk/RAM and recorded in `data/physics/manifest.json` with per-file checksums). Re-run the SC-001 checks (deterministic reproducibility on a sampled subset of both generators, zero NaN/corruption rate) at full scale and record the outcomes in `data/results/data_generation_report.json`. Perform the a priori power analysis in `code/src/evaluation/statistical.py`: required paired-t sample size for α=0.05, power=0.8, Cohen's d=0.5; verify the test-set size meets it or flag results as exploratory (SC-004 assumption; plan T4.0).
  - Verification: `data/results/data_generation_report.json` shows 100% reproducibility on the sampled check and 0 NaN for both generators; power analysis output states achieved power or the exploratory caveat.

- [ ] T005 [US2] Train the physics-teacher student model at full scale in `code/src/models/train_student.py`: up to 20 epochs (early-stop when validation MSE ≤ 0.05; spec edge-case fallback at epoch 20 if MSE > 0.07), batch size 8 with gradient accumulation and activation checkpointing, checkpoint saved to `data/models/student_physics.pt`, loss curve to `data/results/student_physics_training.json` (FR-002, SC-002). Profile wall-clock time and peak RAM during training (e.g., `resource`/`psutil` sampling) and assert ≤6 h and ≤7 GB; record measurements in the training JSON (SC-005). Verify convergence criteria: final validation MSE ≤ 0.05 and ≥10% relative improvement over the first epoch.
  - Verification: training JSON contains measured final MSE, relative improvement, wall-clock, peak RAM; all within SC-002/SC-005 bounds or the failure is honestly logged per the edge-case policy.

- [ ] T006 [US3] Build and train the two baselines (FR-007, SC-008, plan T2.2–T2.4) in `code/src/models/neural_teacher.py` and `code/src/models/train_baseline.py`: (a) the neural-teacher baseline — the identical ≈50 M-parameter student architecture trained on the original Causal Forcing++ dataset loaded from its public HuggingFace source (loader fails loudly on fetch error; no synthetic fallback); (b) the control baseline — the same architecture trained on the synthetic physics dataset, isolating the data-distribution confound (retained per plan T2.4; flagged for spec authorization, see header). Same architecture and hyperparameters as T005; checkpoints to `data/models/baseline_neural.pt` and `data/models/baseline_control.pt`, training records to `data/results/baseline_training.json`. Baseline convergence target: validation MSE ≤ 0.05 within the same compute constraints.
  - Verification: both checkpoints exist; `data/results/baseline_training.json` reports measured validation MSE for each baseline; runs stay within the CPU/RAM budget.

- [ ] T007 [US3] Compute the full evaluation suite on the shared held-out test set in `code/src/evaluation/metrics.py` (FR-004, FR-009, SC-003, SC-007/SC-009 — single consolidated FID computation): SSIM, PSNR, and LPIPS (CPU `lpips` package) per sequence for the physics-teacher model, neural-teacher baseline, and control baseline (control rows use `model_type = "control_baseline"` per the T001 schema amendment); set-level FID between the physics-teacher generated video set and the neural-teacher baseline set, written to `data/results/fid_aggregate.json` (NOT per-sequence); and the Trajectory-Pixel Correlation (Pearson r between physics velocities and optical-flow vectors) as a direct teacher-signal quality metric (flagged for spec authorization, see header). Write per-sequence results to `data/results/evaluation_metrics.csv` and `data/results/evaluation_metrics.json` conforming to the amended `specs/001-llmxive-follow-up-extending-causal-forci/contracts/evaluation_results.schema.yaml` (SSIM ∈ [0,1], PSNR in dB, LPIPS ≥ 0). Compare measured SSIM and LPIPS against the SC-003 thresholds (SSIM ≥ 0.80, LPIPS ≤ 0.30) and record per-metric pass/fail in `data/results/sc003_threshold_check.json`.
  - Verification: metrics exist for every test sequence and all three model types; values are real measurements computed from the actual generated frames; `data/results/fid_aggregate.json` contains the set-level FID; `data/results/sc003_threshold_check.json` reports threshold outcomes honestly (met or not met).

- [ ] T008 [US3] Perform the statistical analysis in `code/src/evaluation/statistical.py` (FR-005, SC-004): paired t-tests on sequence-level SSIM and LPIPS between physics-teacher and neural-teacher models, Bonferroni-adjusted α = 0.025, reporting p-values, effect sizes (Cohen's d), and significance decisions; plus the α-sensitivity sweep over {0.01, 0.05, 0.10}. Write to `data/results/statistical_analysis.json` and `data/results/statistical_analysis.csv`.
  - Verification: JSON contains p-values and significance decisions for both metrics at all three α levels; test-set pairing is per-sequence and documented.

- [ ] T009 [US3] Run the ablation study in `code/src/ablation/run_ablation.py` (FR-008, SC-006), covering ALL THREE spec dimensions: rigid-body axes — friction ∈ {0.2, 0.5, 0.8} and elasticity ∈ {0.1, 0.5, 0.9} (reusing the T001 Box2D generator with parameter overrides); fluid-dynamics axis — viscosity ∈ {0.1, 0.5, 1.0} (reusing the T001 simplified Navier-Stokes generator from `code/src/data_generation/generate_fluid.py`).   - Verification: every parameter setting across all three axes has measured metrics for its 100 sequences; regression JSON reports r and p-value per metric-parameter pair; the table is generated directly from the results files.
