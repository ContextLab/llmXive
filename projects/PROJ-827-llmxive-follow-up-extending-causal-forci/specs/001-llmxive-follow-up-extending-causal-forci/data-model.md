# Data Model: llmXive Follow-up: Physics-Teacher Distillation

## Overview
The project manipulates three core entities, each governed by a JSON schema in `contracts/`:

1. **PhysicsTrajectory** – deterministic sequence of state vectors generated by Box2D.  
2. **VideoSequence** – 16‑frame MP4 video aligned with a PhysicsTrajectory.  
3. **EvaluationResults** – per‑sequence metrics (SSIM, PSNR, LPIPS, optional FID, Trajectory‑Pixel Correlation) and any additional ablation metadata.

All entities are version‑hashed, checksummed, and recorded in `outputs/manifest.json`. No placeholder values are permitted; every field reflects a real measurement.

## Data Flow (textual)

```
Box2D world (seeded) → generate.py → PhysicsTrajectory (.npz) + VideoSequence (.mp4)
│
├─► Student model loader (frame + trajectory) → student_diffusion.py → checkpoint
│
├─► Neural‑teacher loader (frame only) → neural_teacher.py → checkpoint
│
└─► Evaluation (metrics.py) consumes videos + trajectories → EvaluationResults (JSON/CSV)
    └─► Statistical analysis aggregates EvaluationResults → final reports
```

All intermediate files reside under `data/` (raw) or `outputs/` (derived) and are referenced by checksum in the manifest, satisfying Principles I, III, IV.
