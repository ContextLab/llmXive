# Research: Evaluating the Impact of Code Generation on Software Security

## Objective
Quantify how code generated by a public LLM *associates* with human‑written vulnerable code in terms of static‑analysis‑detected security issues.

## Dataset Strategy
| Role | Dataset | Source URL(s) | Notes |
|------|---------|---------------|-------|
| Human‑written vulnerable code (baseline) | **OWASP Top 10 LLM Dataset** (v1.0) | https://huggingface.co/datasets/cedricf/owasp_top_10_llm/resolve/main/dataset_info.json | Contains human‑authored vulnerable snippets across OWASP Top categories; serves as the “human” side of each pair. |
| LLM‑generated vulnerable code | Same OWASP Top 10 LLM Dataset (used as prompts) | https://huggingface.co/datasets/cedricf/owasp_top_10_llm/resolve/main/dataset_info.json | Prompts are fed to a CodeGen model to produce functionally equivalent LLM samples. |
| Additional SQL‑injection examples | Mahabharat OWASP SQL‑Injection CSV | https://huggingface.co/datasets/mahabharat/OWASP/resolve/main/Sqlinjection.csv | Provides extra samples for the “Injection” category to ensure ≥ 5 distinct OWASP types. |

*Rationale*: The original spec mentioned Devign/CodeXGLUE, which are not directly downloadable in CI. The verified OWASP LLM dataset is openly accessible and contains labeled vulnerable code, satisfying FR‑001 and SC‑005. The Mahabharat CSV augments the injection category without violating the verified‑datasets constraint.

## Methodological Decisions
| Decision | Rationale |
|----------|-----------|
| **LLM Generation** | Use **Salesforce/codegen‑350M‑multi** via HuggingFace `transformers`. Deterministic (`temp=0`), CPU‑friendly, fits the free runner. |
| **Functional Equivalence Test** | Require **both** (a) passing bundled unit tests with **≥ 90 % coverage** **and** (b) **semantic similarity ≥ 0.85** (sentence‑transformers). Both conditions must hold before a pair is marked `functional_equivalence_verified`. This directly satisfies FR‑001. |
| **Static Analysis Tools** | Semgrep (Docker, OWASP rule set) and SonarQube Community Edition (Docker) as primary tools; **CodeQL** (Docker) added as an independent secondary validator for FR‑009. All emit structured JSON, meeting Constitution VI. |
| **Statistical Test** | Primary: McNemar’s test for paired binary outcomes per vulnerability type (`statsmodels`). If any cell = 0, switch to exact McNemar. Bonferroni correction for multiple testing (Constitution VII). |
| **Bias Correction** | Estimate each tool’s precision/recall on a held‑out subset of the OWASP dataset; **apply weighting only to effect‑size reporting after the raw McNemar test** (addresses potential tool‑specific false‑positive/negative bias). |
| **Sensitivity Analysis** | Perform a **±0.05** sweep around the default confidence threshold (e.g., 0.45, 0.5, 0.55) for Semgrep confidence and mapped SonarQube severity. This satisfies FR‑006 and SC‑003. |
| **Manual Audit** | Randomly audit **≥ 20 %** of flagged findings (stratified by type) using lightweight fuzzing (`afl‑fast`) **and** a manual review; compute a calibration factor that rescales bias‑corrected counts. |
| **Power Consideration** | Target **≈ 300 paired samples** using a McNemar‑appropriate power calculation (`statsmodels.stats.power.GofPower(method='mcnemar')`) to achieve > 80 % power for detecting an odds‑ratio ≈ 2.0, especially for low‑frequency OWASP categories. Sample size is a design target, not a hard constraint. |
| **Associational Language** | All conclusions are framed as *associations* (observational design), respecting the non‑causal nature mandated by the constitution. |
| **Intent‑to‑Treat Handling** | All generated LLM samples are retained in the dataset; those failing syntax or equivalence checks are flagged and counted but **included** in the paired analysis as “non‑equivalent” to avoid selection bias (addresses methodology‑a6ee90c3). |
| **Security‑Pattern Post‑Analysis Check** | A security‑focused pattern test is run **after** static analysis on the audited subset to verify that the original vulnerable construct is still present, avoiding pre‑filter bias (addresses scientific_soundness‑345bd1f6). |

## Expected Deliverables
1. **Paired dataset** (`data/paired/human/*.py`, `data/paired/llm/*.py`) with SHA‑256 manifest.  
2. **Static analysis results** (`data/raw/semgrep_results.json`, `data/raw/sonarqube_results.json`, `data/raw/codeql_results.json`, `data/raw/bandit_results.json`).  
3. **Aggregated vulnerability table** (`data/outputs/vuln_counts.csv`)  
4. **Statistical analysis table** (`data/outputs/analysis_results.csv`)  
5. **Sensitivity sweep summary** (`data/outputs/sensitivity.csv`)  
6. **Manual audit log** (`data/outputs/audit_log.csv`)  
7. **Final markdown report** (`reports/report.md`) containing tables, bar charts, and interpretive text.
