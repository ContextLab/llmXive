## Unresolved concerns

- FR-005 (Log resource usage metrics) is mentioned in 'Resource Constraint Verification' (US-3) but lacks a specific plan element describing the *format* or *location* of these logs (e.g., 'JSON logs for state trajectories' is mentioned in Technical Context, but FR-005 requires logging for *every* generated sequence to verify feasibility. - SC-005 (Reduce permanence violations by ≥ 25%) is not addressed. The plan discusses reducing 'state inconsistency events' generally in Methodology section 2, but does not explicitly define the metric 'permanence violations' (objects alive in video but dead in logic) nor the specific 25% reduction target required by SC-005. This success criterion is missing a corresponding measurement plan.
- FR-007 (Ground Truth Validation) requires a manually annotated subset of ≥ 50 frames. The plan mentions 'Ground Truth subset: ≥50 manually annotated frames' in 'Scale/Scope', but the 'Methodology' section does not explicitly describe the *process* of creating this subset or the *validation logic* (FR-007) that flags the drift score as invalid if accuracy < 85%. The plan assumes the validation happens but does not detail the mechanism to enforce the 'invalid' flagging required by FR-007.
- SC-006 (Ground Truth Validation must confirm ≥ 85% accuracy, otherwise inconclusive) is not explicitly linked to a plan element. While FR-007 is mentioned, the plan does not explicitly state that the *entire experiment* is deemed 'inconclusive' if this threshold is not met, as required by SC-006. The plan needs to define the 'inconclusive' outcome and its handling.
- The plan assumes the AlayaWorld model weights are 'provided via a local artifact' without citing a specific source, repository, or accession ID. While the plan acknowledges no verified URL exists, proceeding with a 'local artifact' assumption for a core research component (the video generation model) without a defined provenance or verification path violates the 'Verified Accuracy' and 'Reproducibility' principles. The dataset/model source must be explicitly identified (e.g., a specific HuggingFace repo, GitHub release, or internal path with checksum) to ensure the experiment is reproducible and the data is real. Relying on an undefined 'local artifact' makes the feasibility of the entire pipeline unassessable.
- The 'Project Structure' section lists `contracts/` as a Phase 1 output, but the `contracts/` directory in the source code section lists specific schema files (e.g., `symbolic_state.schema.yaml`). The plan does not explicitly map the generation of these specific schema files to the 'contracts/*' design document mentioned in the lens requirements, creating a minor ambiguity in the artifact lineage.
- The 'Technical Context' section lists `datasets` (for streaming) as a dependency, but the 'Dataset Strategy' in `research.md` and the 'Data Model' do not explicitly define how the `datasets` library is used for streaming the AlayaWorld video sequences versus the local ground truth. The plan should clarify if `datasets` is used for the local artifact streaming or if it is only for the fallback synthetic data, to ensure consistency with the 'Streaming' constraint in `research.md`.
- Circular Validation: The 'Semantic Drift Score' is defined as the difference between the Symbolic State (Predictor) and the Visual State (Outcome). However, the Visual State is derived via CV primitives (template matching/optical flow) that are validated against a Ground Truth subset. If the CV pipeline fails to detect objects (accuracy < 85%), the 'Visual State' becomes a noisy proxy for the 'Symbolic State' itself (since the Ground Truth is derived from the same action sequence logic). The plan risks validating the metric against a quantity that is definitionally correlated with the predictor, especially if the CV model is tuned to the specific visual features of the symbolic ground truth. The independence of the 'Visual State' from the 'Symbolic State' is not guaranteed; they share the same input actions and potentially the same visual priors.
- Statistical Method Mismatch: The plan proposes a paired t-test on drift scores across 10 random seeds. However, the drift score is a composite metric derived from CV detection accuracy, which is itself a random variable with high variance (especially with template matching on video). The assumption of normality for the drift score distribution across only 10 samples is weak. Furthermore, the 'paired' nature assumes the same seeds produce comparable drift distributions, but the hybrid mechanism introduces a non-linear, state-dependent intervention that may violate the independence of errors required for a standard t-test. A non-parametric test (e.g., Wilcoxon signed-rank) or a permutation test would be more robust for this small sample size and non-normal data.
