# Data Model: llmXive follow-up: extending "AlayaWorld: Long-Horizon and Playable Video World Generation"

## Overview

This document defines the data structures used for the symbolic engine, visual state extraction, and result logging. All data is stored in JSON or CSV formats to ensure portability and ease of parsing on the CI runner.

## Symbolic State Log

The deterministic ground truth generated by the symbolic engine.

```yaml
# contracts/symbolic_state.schema.yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: "Symbolic State Log"
type: object
properties:
  sequence_id:
    type: string
    description: "Unique identifier for the action sequence (e.g., 'seq_001_seed_42')"
  timestamp:
    type: string
    format: date-time
    description: "ISO 8601 timestamp of log generation"
  state_trajectory:
    type: array
    items:
      type: object
      properties:
        frame_id:
          type: integer
          description: "Frame index (0 to N)"
        objects:
          type: array
          items:
            type: object
            properties:
              object_id:
                type: string
                description: "Unique ID for the object (e.g., 'sword_1')"
              hp:
                type: integer
                description: "Current health points"
              inventory:
                type: array
                items:
                  type: string
                description: "List of items held by the object"
              position:
                type: object
                properties:
                  x:
                    type: number
                  y:
                    type: number
                required: [x, y]
              status:
                type: string
                enum: ["alive", "dead", "hidden", "unknown"]
                description: "Logical status of the object"
      required: [frame_id, objects]
  action_log:
    type: array
    items:
      type: string
    description: "List of user actions applied (e.g., ['summon', 'hit'])"
required: [sequence_id, timestamp, state_trajectory, action_log]
```

## Visual State Log

The state extracted from video frames using sparse optical flow and color histograms.

```yaml
# contracts/visual_state.schema.yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: "Visual State Log"
type: object
properties:
  sequence_id:
    type: string
  timestamp:
    type: string
    format: date-time
  frame_analysis:
    type: array
    items:
      type: object
      properties:
        frame_id:
          type: integer
        detected_objects:
          type: array
          items:
            type: object
            properties:
              object_id:
                type: string
              confidence:
                type: number
                minimum: 0.0
                maximum: 1.0
              bounding_box:
                type: object
                properties:
                  x:
                    type: number
                  y:
                    type: number
                  width:
                    type: number
                  height:
                    type: number
                required: [x, y, width, height]
              status:
                type: string
                enum: ["alive", "dead", "hidden", "unknown"]
              is_phantom:
                type: boolean
                description: "True if object detected but not in symbolic log"
              is_low_confidence:
                type: boolean
                description: "True if detection confidence < 0.85 (e.g., occlusion)"
      required: [frame_id, detected_objects]
required: [sequence_id, timestamp, frame_analysis]
```

## Drift Score & Results

The final metrics and resource logs.

```yaml
# contracts/results.schema.yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: "Drift Score and Resource Log"
type: object
properties:
  sequence_id:
    type: string
  condition:
    type: string
    enum: ["baseline", "hybrid"]
  semantic_drift_score:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Scalar metric of visual-logical divergence"
  permanence_violations:
    type: integer
    description: "Count of objects alive in video but dead in logic"
  phantom_objects:
    type: integer
    description: "Count of objects in video but not in logic"
  cv_validation_accuracy:
    type: number
    minimum: 0.0
    maximum: 1.0
    description: "Accuracy on the 50-frame validation set"
  validation_status:
    type: string
    enum: ["valid", "invalid", "inconclusive"]
  resource_metrics:
    type: object
    properties:
      peak_ram_mb:
        type: number
      wall_clock_seconds:
        type: number
      timestamp:
        type: string
        format: date-time
    required: [peak_ram_mb, wall_clock_seconds, timestamp]
  statistical_test_status:
    type: string
    enum: ["passed", "aborted", "not_run"]
    description: "Result of Wilcoxon/Shapiro-Wilk tests"
required: [sequence_id, condition, semantic_drift_score, resource_metrics]
```

## Frame-Level Error Series

The time-series of frame-level errors used for variance-stability checks.

```yaml
# contracts/error_series.schema.yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: "Frame-Level Error Series"
type: object
properties:
  sequence_id:
    type: string
  condition:
    type: string
    enum: ["baseline", "hybrid"]
  error_series:
    type: array
    items:
      type: number
      description: "Frame-level error (e.g., 1 - IoU, or state mismatch flag)"
  rolling_variance:
    type: number
    description: "Rolling variance of the error series"
  is_stable:
    type: boolean
    description: "True if variance is within acceptable threshold"
required: [sequence_id, condition, error_series, rolling_variance, is_stable]
```
