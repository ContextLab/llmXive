# Implementation Plan: llmXive Follow-up: Extending "Zone of Proximal Policy Optimization"

## Summary

This project implements a simulation to evaluate **Confidence-Adaptive Pruning (CAP)** within the Zone of Proximal Policy Optimization (ZPPO) framework. The core innovation is dynamically pruning negative candidates from the prompt based on the student model's historical confidence, retaining only "fluctuating" (proximal) error modes. The plan covers: (1) synthetic rollout log generation seeded by spec parameters with explicit learning dynamics; (2) implementation of static baseline ZPPO; (3) implementation of CAP-ZPPO with threshold-based filtering and attention-weighted updates; (4) statistical comparison of Area Under the Convergence Curve (AUCC) and final accuracy; (5) validation against held-out MMLU tasks to detect catastrophic forgetting; and (6) rigorous versioning and data hygiene steps.

## Constitution Check

1.  **Principle I (Reproducibility)**: All random seeds will be pinned in `code/`. Synthetic data generation uses `numpy.random.default_rng(seed)`. MMLU data is fetched from verified Hugging Face URLs.
2.  **Principle II (Verified Accuracy)**: Citations for MMLU datasets will reference the verified URLs provided in the spec. The ZPPO baseline logic will be validated against the original paper's described behavior (convergence curve shape).
3.  **Principle III (Data Hygiene)**: Raw synthetic logs and MMLU subsets will be checksummed. **Step 6** of the implementation plan explicitly defines the generation of checksums and their recording in `state/projects/PROJ-923-llmxive-follow-up-extending-zone-of-prox.yaml`.
4.  **Principle IV (Single Source of Truth)**: All figures and statistics in the final report will trace to `data/metrics/` CSVs generated by `code/`. The `contracts/` directory serves as the Single Source of Truth for schema validation, and `code/` imports these specific schema files.
5.  **Principle V (Versioning)**: **Step 6** of the implementation plan defines the mechanism to update the project state file (`state/projects/PROJ-923-llmxive-follow-up-extending-zone-of-prox.yaml`) with content hashes and `updated_at` timestamps upon completion.
6.  **Principle VI (CAP Integrity)**: **Step 3** explicitly implements the `epsilon` and `1-epsilon` thresholds for classifying candidates, adhering strictly to the constitutional definition of the proximal zone.
7.  **Principle VII (Non-Circular Validation)**: **Step 4** ensures evaluation is performed on held-out MMLU tasks (specific subject subsets not in the training buffer) to prevent overfitting.

## Implementation Steps

1.  **Data Generation & Loading**: Generate synthetic rollout logs with explicit learning dynamics (student confidence updates based on expert gap and prompt length). Load MMLU held-out data.
2.  **Baseline Simulation (Static ZPPO)**: Run the static NCQ loop. Record convergence curves.
3.  **CAP Simulation (Dynamic Pruning)**: Run the CAP-ZPPO loop. **This step implements Principle VI**. It dynamically prunes candidates and updates student confidence using the attention-weighted rule.
4.  **Statistical Analysis & Validation**: Compare AUCC and final accuracy. **This step implements Principle VII** by using the held-out set. Perform paired t-tests.
5.  **Reporting**: Generate the final report with plots and statistical summaries.
6.  **Versioning & State Update**: **This step implements Principle V**. Run a post-processing script to checksum all artifacts in `data/`, update `state/projects/PROJ-923-llmxive-follow-up-extending-zone-of-prox.yaml` with hashes and timestamps, and verify Principle III compliance.
