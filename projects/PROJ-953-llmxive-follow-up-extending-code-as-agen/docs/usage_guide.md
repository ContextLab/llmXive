# Usage Guide: llmXive Code-as-Agent Harness

This guide provides detailed examples for running the llmXive pipeline, interpreting the generated results, and understanding the decision boundaries for dynamic execution.

## Prerequisites

Before running the pipeline, ensure you have:
1. Completed the setup steps in `docs/quickstart.md`.
2. Downloaded the real datasets (SWE-bench, AgentBench) as described in the quickstart.
3. Verified that the `data/raw/` and `data/processed/` directories are populated.

## Pipeline Execution Flow

The pipeline consists of three main stages. You can run them individually or sequentially.

### 1. Data Ingestion (T011)

Downloads and parses the raw datasets into a standardized format.

```bash
python code/scripts/ingest.py
```

**Expected Output:**
- `data/raw/swe_bench_subset.parquet`
- `data/raw/agentbench_subset.parquet`
- `data/logs/ingest_sample_log.json` (logs sample size and RAM limits)

**Key Parameters:**
- The script uses `streaming=True` to handle large datasets within memory constraints.
- If the stream exceeds the 6GB RAM limit, it stops at N=500 (or the calculated cap) and logs the limitation. **No synthetic data is generated.**

### 2. Ground Truth Generation (T013, T011b)

Executes the baseline tests to determine the true outcome (Pass/Fail/Timeout).

```bash
# Setup environment (one-time)
bash code/scripts/env_setup.sh

# Run baseline execution
python code/scripts/baseline_runner.py
```

**Expected Output:**
- `data/processed/raw_outcomes.json`
- `data/processed/ground_truth.csv` (generated by T011b after merge)

**Interpretation:**
- `dynamic_execution_outcome`: One of `Pass`, `Fail`, `Timeout`, or `Unparseable`.
- **Timeout Handling:** Tasks exceeding the configured duration (default 600s) are explicitly marked as `Timeout/Fail`. They are NOT skipped or marked as `Unknown`.

### 3. Feature Extraction (T019, T020)

Converts code artifacts into structural metrics and dependency graphs.

```bash
python code/scripts/extract_features.py
python code/scripts/finalize_features.py
```

**Expected Output:**
- `data/graphs/{task_id}.json` (serialized dependency graphs)
- `data/processed/features.csv`

**Metrics Calculated:**
- `dependency_depth`: Maximum depth of the AST dependency graph.
- `cyclomatic_complexity`: McCabe complexity score.
- `semantic_complexity_score`: Count of semantic nodes (functions, classes, imports).
- `lines_of_code`: Fallback metric if semantic nodes are missing.

**Fallback Logic:**
If `tree-sitter` fails to parse a code snippet (status `Unparseable`), the task is filtered out before metric calculation. If semantic nodes are missing in a valid parse, `lines_of_code` is used as the fallback metric.

### 4. Model Training & Threshold Analysis (T028)

Trains predictive models and determines safe decision boundaries.

```bash
python code/scripts/train_model.py
```

**Expected Output:**
- `models/logistic_regression.pkl`
- `models/random_forest.pkl`
- `models/decision_boundary.pkl`
- `data/processed/threshold_sweep.json`
- `data/processed/model_report.json`

**Interpreting Results:**

#### Threshold Sweep (`threshold_sweep.json`)
This file contains the False Negative Rate (FNR) for specific thresholds:
```json
{
 "thresholds": [0.01, 0.05, 0.1],
 "fnr_0.01": 0.0005,
 "fnr_0.05": 0.002,
 "fnr_0.1": 0.008,
 "min_achievable_fnr": 0.0005,
 "unsafe_flag": false
}
```
- **Safety Constraint:** If `min_achievable_fnr` > 0.1% (0.001), the `unsafe_flag` will be `true`.

#### Model Report (`model_report.json`)
Contains the final analysis and framing:
```json
{
 "framing": "associational",
 "correlation_coefficient": 0.45,
 "unsafe_flag": false,
 "minimum_fnr": 0.0005
}
```
- **Framing:** Explicitly set to `"associational"` to comply with FR-006. This indicates the model identifies correlations, not causation.

## Understanding the Decision Boundary

The decision boundary determines when the system should trigger a full dynamic execution based on structural complexity.

1. **Input:** Structural metrics (e.g., Cyclomatic Complexity, Dependency Depth).
2. **Model:** Logistic Regression or Random Forest predicts the probability of `Need Dynamic Execution`.
3. **Threshold:** A probability threshold (e.g., 0.05) is applied.
 - If `probability > threshold`: Trigger dynamic execution.
 - If `probability <= threshold`: Skip dynamic execution (rely on static analysis or trust).

**Safety First:**
The threshold is chosen to minimize the False Negative Rate (FNR). An FNR means we incorrectly skip a task that *needed* dynamic execution. The goal is to keep FNR ≤ 0.1%.

## Troubleshooting

### "No real source reachable" Error
If `ingest.py` fails to download from HuggingFace, it will raise an exception. Check your internet connection and HuggingFace token configuration. **Do not attempt to run with synthetic data.**

### "Unparseable" Tasks
Tasks marked as `Unparseable` in `ground_truth.csv` are excluded from feature extraction. This is expected behavior for code snippets that violate Python syntax or `tree-sitter` limitations.

### GPU Warnings
If you see warnings about unused CUDA drivers, this is expected. The pipeline is CPU-only. Ensure `torch` is installed without CUDA support if you encounter memory issues.
