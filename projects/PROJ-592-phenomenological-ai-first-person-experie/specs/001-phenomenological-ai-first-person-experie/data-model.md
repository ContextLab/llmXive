# Data Model: Phenomenological AI: First-Person Experience Modeling in Language Models

## Overview

This document defines the data structures, schemas, and relationships for the Phenomenological AI project. It ensures that all data generated, processed, and stored adheres to the project's data hygiene and reproducibility principles.

## Entities

### 1. Phenomenological Report
A text output generated by an LLM in response to a specific prompt strategy.

**Fields**:
-   `id`: Unique identifier (UUID).
-   `prompt_id`: Identifier for the prompt used.
-   `strategy`: One of `Direct`, `Hypothetical`, `Comparative`, `Role-play`.
-   `model`: Model checkpoint ID (e.g., `meta-llama/Llama-7b-chat-hf`).
-   `text`: The generated report text.
-   `seed`: Random seed used for generation.
-   `timestamp`: Generation timestamp.
-   `metadata`: JSON object with additional generation details (e.g., temperature, top-p).

**Storage**: `data/raw/reports/<id>.json` (JSON format).

### 2. Validity Score
A composite metric computed for each report.

**Fields**:
-   `report_id`: Foreign key to `PhenomenologicalReport.id`.
-   `logical_coherence`: Score from 0 to 1 (NLI-based, secondary).
-   `output_reproducibility`: Score from 0 to 1 (embedding-based, aggregated per prompt).
-   `marker_specificity`: Ratio from 0 to 1 (targeted markers / total markers).
-   `composite_score`: Weighted sum of the three components (0.33 each).
-   `computed_at`: Timestamp of computation.

**Storage**: `data/derived/validity_scores.csv`.

### 3. Qualitative Rating
Human evaluation of a report.

**Fields**:
-   `report_id`: Foreign key to `PhenomenologicalReport.id`.
-   `rater_id`: Identifier for the rater.
-   `coherence_rating`: Rating on a scale (e.g., 1-5).
-   `notes`: Optional qualitative notes.
-   `timestamp`: Rating timestamp.

**Storage**: `data/qualitative/ratings.csv`.

### 4. Statistical Result
Results of statistical tests.

**Fields**:
-   `test_type`: e.g., `LMM`, `Cohen's κ`.
-   `p_value`: P-value of the test.
-   `statistic`: Test statistic value.
-   `correction`: e.g., `Benjamini-Hochberg`.
-   `significant`: Boolean indicating significance.
-   `model_random_effect`: Boolean indicating if Model ID was included as a random effect.

**Storage**: `data/derived/statistical_results.json`.

## Relationships

-   **One-to-Many**: A `PhenomenologicalReport` can have multiple `ValidityScore` entries (if re-computed) but typically one final score.
-   **One-to-Many**: A `PhenomenologicalReport` can have multiple `QualitativeRating` entries (one per rater).
-   **One-to-Many**: A `ValidityScore` is derived from one `PhenomenologicalReport`.
-   **Nested Structure**: Data is nested by `Prompt ID` and `Model ID` for statistical analysis.

## Data Flow

1.  **Generation**: `runner.py` generates `PhenomenologicalReport` files in `data/raw/`. **Metadata includes Model ID**.
2.  **Computation**: `metrics.py` reads reports, computes `ValidityScore`, and writes to `data/derived/validity_scores.csv`.
3.  **Human Rating**: Raters read reports and write `QualitativeRating` to `data/qualitative/ratings.csv`.
4.  **Analysis**: `statistics.py` reads scores and ratings, computes `StatisticalResult` using LMM with Model ID as random effect, and writes to `data/derived/statistical_results.json`.

## Data Hygiene

-   **Immutability**: Raw reports in `data/raw/` are never modified.
-   **Checksums**: All files in `data/` are checksummed (SHA-256) and recorded in `state/`.
-   **PII**: No PII is stored. Human raters are anonymized by `rater_id`.
-   **Versioning**: All data files carry a content hash.

## Schema Validation

All data must conform to the schemas defined in `src/contracts/`. The `orchestration/main.py` will validate data before processing.
