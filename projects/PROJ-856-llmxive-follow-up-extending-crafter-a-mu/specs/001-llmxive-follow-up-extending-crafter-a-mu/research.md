# Research: llmXive follow-up: extending "Crafter: A Multi‑Agent Harness for Editable Scientific Figure Generation"

## Objective
Evaluate whether a **structured typed‑edit harness** reduces **objective latency** (`time‑to‑success`), **iteration count**, and **subjective cognitive load** (NASA‑TLX) relative to a **natural‑language chat interface** when participants correct localized errors in scientific figures, while controlling for participant expertise.

## Dataset Strategy
| Need | Availability | Action |
|------|--------------|--------|
| Failed figure generations with ground‑truth layout vectors (≈ a moderate number of items) | **CrafterBench** – *NO verified source found* (see verified datasets block). | Use a **deterministic synthetic surrogate** generated by `curate_failed_figures.py` (seed = 42) for CI verification. The pipeline is written to accept a real CrafterBench subset if/when a verified open download becomes available; at that point the same code can ingest it without modification. |
| Pre‑trained visual similarity model | CLIP ViT‑B/32 (available via `torchvision` / `transformers`) – CPU‑only weights download from HuggingFace. | Load on CPU; weights auto‑downloaded on first run. |
| Human participant logs | Not needed for CI; will be collected in the field study. | `human_data_collection.py` (stub) will ingest real logs when available. |
| NASA‑TLX questionnaire | Publicly described in the NASA‑TLX literature. | Integrated into UI; scores (0‑100) stored per task. |
| Participant expertise questionnaire | Self‑report (0‑5 Likert). | Collected at session start; stored as `expertise_level` in `ParticipantSession`. |

## Methodology
1. **Within‑Subjects Counterbalanced Design**  
   - Each **real** participant completes the same 50 tasks.  
   - Interface order is **randomized** (seed = 42 + participant ID) **and fully counterbalanced** across participants.  
   - A **5‑minute wash‑out interval** separates the two interface blocks to mitigate carry‑over learning (FR‑010).  
   - **Task order** is shuffled per participant (seed = 42 + participant ID) to further reduce practice effects.  

2. **A‑Prior Power Analysis**  
   - `power_analysis.py` computes the minimum N for a paired Wilcoxon test with **α = 0.025** (Bonferroni‑adjusted) and effect size *d* ≈ 0.5.  
   - Required N is approximately a moderate sample size (on the order of tens).; the pipeline aborts if the planned N < required, ensuring the target power = 0.80 (FR‑009).  

3. **Instrumentation (Construct Validity)**  
   - Every edit triggers `interaction_logger.py`, which writes a JSONL line with millisecond timestamps, iteration number, payload, **and NASA‑TLX score** (`subjective_load`).  
   - For **real** participants, timestamps reflect actual wall‑clock time → valid measure of cognitive load.  
   - For **synthetic** verification, deterministic timestamps are generated (seeded) to ensure reproducibility.  

4. **Success Definition**  
   - **Exact vector match** (`vector_match.py`): JSON equality of the final layout vector vs. ground‑truth.  
   - **Semantic equivalence** (`semantic_similarity.py`): CLIP ViT‑B/32 cosine similarity **≥ 0.95** (as stipulated in FR‑005).  
   - **Overall success** = both conditions true (`overall_success`).  

5. **Statistical Testing**  
   - Paired Wilcoxon signed‑rank test (`scipy.stats.wilcoxon`) on per‑participant differences for `time_to_success_ms`, `iteration_count`, **and** `subjective_load`.  
   - No preliminary normality test (per FR‑006).  
   - **Bonferroni correction** for the three metrics (α = 0.025 each).  
   - Effect size *r* = Z / √N; A conventional confidence interval for the median difference via bootstrap (1 000 resamples).  
   - **Exploratory covariate analysis**: Linear mixed‑effects model includes `expertise_level` as a fixed effect to control for prior experience (FR‑012).  

6. **Retention & Validity Checks**  
   - `retention_check.py` ensures **≥ 25** of 30 synthetic sessions have at least one successful correction.  
   - Tasks with corrupted ground‑truth vectors are skipped; N is adjusted accordingly.  
   - **Aborted tasks** (timeout > 15 min) are **excluded from all three primary analyses** (latency, iteration, NASA‑TLX) to avoid asymmetric bias (FR‑011).  

7. **Edge‑Case Handling**  
   - **Timeout** → logged as `"aborted"`; excluded from analysis.  
   - **Corrupted ground‑truth** → task skipped, warning logged, N adjusted.  
   - **Semantic score 0.94–0.95** → flagged for manual review; excluded from primary analysis.  

## Decision / Rationale
| Component | CPU‑first or GPU‑escape? | Reason |
|-----------|--------------------------|--------|
| Synthetic data generation | **CPU‑first** (NumPy, Pandas) | Minimal resource usage. |
| CLIP ViT‑B/32 semantic similarity | **CPU‑first** (torch CPU backend) | Model size (on the order of a few hundred MB) fits comfortably on a 2‑core runner. |
| Statistical analysis | **CPU‑first** (SciPy, Statsmodels) | Pure CPU libraries. |
| Full pipeline (CI verification) | **CPU‑first** | Entire pipeline stays within runtime and memory budget. |
| Real‑world similarity model (if larger model later) | **GPU‑escape** (Kaggle) – not required now. | Placeholder for future scaling. |
