## Unresolved concerns

- The plan describes a full human experiment and analysis to answer the research question, implying a causal relationship between visual complexity and cognitive load. The design is observational (within‑subject exposure to varied backgrounds) and does not include random assignment or manipulation of visual complexity, so it cannot support causal inference. This conflicts with the claim of “relationship persists when controlling for …” and risks overstating conclusions.
- Participant familiarity with meeting content is listed as a factor to control in the spec, yet the plan provides no mechanism (e.g., pre‑screening, content randomization, or covariate) to measure or balance familiarity across trials, leaving a potential confound unaddressed.
- Pilot validation accepts any metric with Pearson r ≥ 0.5 as adequate. A modest correlation may not ensure that the chosen metrics truly capture perceived visual complexity, weakening construct validity. A higher threshold or additional validation (e.g., factor analysis) would be more appropriate.
- Power analysis is performed with `statsmodels.stats.power.TTestIndPower` for d > 0.5, which assumes independent groups. The actual analysis uses a linear mixed‑effects model with repeated measures, so the power calculation may be inaccurate and could result in an under‑powered study.
- The LMM includes only a random intercept for participant ID. It does not model potential trial‑order effects, learning/fatigue, or random slopes for visual‑complexity, leaving important within‑subject confounds uncontrolled.
- The plan cites an external HuggingFace dataset (https://huggingface.co/datasets/fwerkor/CID-Dataset/…) as the source for “FWER Null‑Simulation Data”. FR‑007 requires a null‑simulation that reflects the same statistical structure (visual‑complexity metrics and cognitive‑load outcomes) used in the primary analysis. Using an unrelated dataset of generic “complex‑logic” jobs does not provide appropriate null data for this study and may invalidate the family‑wise error‑rate check. Replace the external dataset with a synthetic null‑simulation generated in‑pipeline (e.g., random draws of the three visual‑complexity metrics and random TLX/RT values with zero true effect) or provide a dataset explicitly designed for null‑simulation of the study variables.
- Principle II (Verified Accuracy) requires that every external citation be validated by the Reference‑Validator Agent. The plan lists citations (e.g., Benjamini‑Hochberg, NASA‑TLX validation) but does not provide concrete reference entries (author, year, DOI/URL) that can be checked, nor does it indicate that they have been verified. Add a bibliography section with full citations and ensure they meet the title‑token overlap threshold.
- The analysis step references the `analysis_result.schema.yaml` contract, but the plan does not explicitly state that the JSON output `data/derived/analysis_results.json` will be validated against this schema. Include a verification step (e.g., `pytest -m test_schemas.py`) that checks the generated file against the contract.
- The plan mentions “Validate those metrics against human‑rated complexity scores from a pilot study (US‑0)” but does not reference the `human_rating.schema.yaml` contract defined in the data model. Add a note that pilot rating records will be validated against this schema.
