# Data Model: llmXive follow-up: extending "Leveraging Verifier-Based Reinforcement Learning in Image Editing"

## Overview
The project produces a series of intermediate and final artifacts. Each artifact is described by a JSON/YAML schema that the implementation tests will validate.

## 1. Raw Dataset (`raw_parquet`)
- **Location**: `data/raw/` (downloaded parquet files from the three verified URLs).  
- **Schema** (informal): columns `image_id`, `prompt`, `source_image_path`, etc. (as provided by InstructPix2Pix). No modification is performed.

## 2. Curated Prompt CSV (`curated_prompts.csv`)
| Column | Type | Description |
|--------|------|-------------|
| `prompt_id` | string | Deterministic UUID for the prompt. |
| `instruction_type` | enum(`conflicting`, `neutral`) | Ground‑truth label. |
| `prompt_text` | string | Full natural‑language instruction. |
| `synthetic_score` | float (0.0‑1.0) | Feasibility score generated by the rule‑based heuristic (Section 2 of research.md). **Used only for conflict generation; not used in any evaluation metric.** |
| `human_score` | float (0.0‑1.0) | Independent human‑annotated feasibility score (collected on a representative prompt sample). **Primary ground‑truth for evaluation.** |
| `checksum` | string | SHA256 of the original parquet row (data hygiene). |

## 3. Constraint Graph JSON (`graph_<prompt_id>.json`)
```yaml
graph_id: string          # same as prompt_id
nodes:
  - id: string            # e.g., "node_1"
    label: string         # principle text
    type: enum("principle")
edges:
  - source: string        # node id
    target: string        # node id
    label: enum("temporal-precedes", "contradiction")
    weight: float
metadata:
  parser_version: string
  parse_timestamp: string   # ISO‑8601
```

## 4. Baseline Scores CSV (`baseline_scores.csv`)
| Column | Type | Description |
|--------|------|-------------|
| `prompt_id` | string | Links to `curated_prompts.csv`. |
| `verifier_score` | float (0.0‑1.0) | Alignment score from baseline verifier. |
| `human_score` | float (0.0‑1.0) | **Primary ground‑truth** (copied from curated CSV). |
| `alignment_delta` | float | `verifier_score - human_score`. |

## 5. Augmented Scores CSV (`augmented_scores.csv`)
Same schema as baseline, but verifier is run with graph context **and** includes two control rows:
- `control_filler` (random JSON filler)
- `control_empty` (empty `{}` graph)

## 6. Human Validation CSV (`human_validation.csv`)
| Column | Type | Description |
|--------|------|-------------|
| `prompt_id` | string | Links to `curated_prompts.csv`. |
| `human_rating` | float (0.0‑1.0) | Rating collected from human annotators (average over raters). |
| `annotation_source` | string | e.g., `"MTurk"` or `"internal_form"`. |

## 7. Final Evaluation Report (`report.json`)
```yaml
report_version: "1.0.0"
generated_at: "2026-10-16T12:34:56Z"
runtime_seconds: integer
memory_peak_gb: number
tests:
  primary:
    $ref: "#/definitions/test_result"
  robustness:
    $ref: "#/definitions/test_result"
multiple_comparison_correction:
  method: enum("benjamini_hochberg", "bonferroni")
  alpha: number
  adjusted_p_values:
    primary: number
    robustness: number
definitions:
  test_result:
    type: object
    required:
      - test_name
      - method
      - p_value
      - effect_size
      - ci_95
      - corrected
    properties:
      test_name:
        type: string
      method:
        type: string
        enum: ["paired_t_test", "wilcoxon"]
      p_value:
        type: number
        minimum: 0
        maximum: 1
      effect_size:
        type: number
        description: "Cohen's d for t‑test or rank‑biserial for Wilcoxon."
      ci_95:
        type: array
        minItems: 2
        maxItems: 2
        items:
          type: number
      corrected:
        type: boolean
        description: "True if p‑value has been corrected for multiple comparisons."
```

All CSV files are UTF‑8 encoded, line‑terminated with `\n`. JSON files are pretty‑printed with 2‑space indentation.
