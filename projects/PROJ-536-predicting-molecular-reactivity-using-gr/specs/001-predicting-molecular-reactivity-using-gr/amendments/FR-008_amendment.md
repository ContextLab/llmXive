# Spec Amendment Request – FR-008
**Feature:** Predicting Molecular Reactivity Using Graph Neural Networks and Reaction Datasets
**Amendment ID:** FR-008
**Date:** 2026-10-25
**Author:** llmXive automated pipeline

## Current Specification (excerpt from `spec.md`)
```
FR-008: System MUST ensure all models (GNN and baselines) are trained and evaluated on data splits
stratified by reaction class to prevent confounding due to class imbalance.
```

## Issue
The implementation plan (`plan.md`) and the data preprocessing logic (`src/data/preprocess.py`) adopt a **Scaffold Split** (grouping by Murcko scaffold) as the scientifically correct method to avoid data leakage.
This contradicts the current wording of FR‑008, which mandates stratification by *reaction class*.
Using reaction‑class stratification would leak structural information because reactions sharing the same scaffold can appear in both train and test sets, violating the construct validity of the study. [UNRESOLVED-CLAIM: c_07e5a27c — status=not_enough_info]

## Proposed Amendment
Replace the wording of FR‑008 to reflect the Scaffold Split methodology:

```
FR-008 (Amended): System MUST ensure all models (GNN and baselines) are trained and evaluated on data splits
generated by a **Scaffold Split** (grouping reactions by their Murcko scaffold) to prevent
data leakage and confounding due to class imbalance.
```

## Rationale
1. **Scientific Validity** – Scaffold‑based splitting is a widely accepted practice for evaluating graph‑based models in chemistry, as it ensures that chemically similar molecules are not shared across train and test splits. [UNRESOLVED-CLAIM: c_82c5a3a6 — status=not_enough_info]
2. **Alignment with Plan** – The plan explicitly describes the Scaffold Split in the “Technical Context” section and implements it in `src/data/preprocess.py`. Updating the spec eliminates the inconsistency flagged in the plan’s “Critical Methodology Update”.
3. **Regulatory Compliance** – The amendment satisfies the constitutional principle that the specification must accurately describe the implemented methodology (Constitution IV).

## Impact
- No code changes are required beyond the existing Scaffold Split implementation. [UNRESOLVED-CLAIM: c_cf62a2ab — status=not_enough_info]
- All downstream tasks (training, evaluation, baseline comparison) already rely on the Scaffold Split, so the amendment brings the spec into agreement with the actual pipeline. [UNRESOLVED-CLAIM: c_1946179f — status=not_enough_info]
- Documentation (quickstart, README) should reference the Scaffold Split as the split strategy.
