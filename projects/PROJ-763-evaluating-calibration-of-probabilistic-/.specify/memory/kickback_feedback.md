## Unresolved concerns

- The plan specifies '4 chains, 500 draws' for the Bayesian model. For a hierarchical model with lead-time decay priors on a moderate dataset, 500 draws per chain is likely insufficient for stable R-hat estimation and effective sample size (ESS) convergence, risking false convergence signals. The methodology lacks a minimum ESS threshold or a dynamic draw adjustment to ensure valid posterior inference.
- The plan proposes using Diebold-Mariano (DM) tests with HAC estimators on 'loss series' derived from aggregated metrics (e.g., mean Brier score per lead time). DM tests require time-series of *individual* forecast errors to account for serial correlation in the loss differential. Aggregating to a single mean per lead time destroys the time-series structure, rendering the HAC estimator invalid and the p-values unreliable. The analysis unit must be the sequence of daily/weekly forecast errors, not the aggregated metric.
- The plan uses a 'Blocked/Expanding window split' for Isotonic Regression but does not explicitly define the block size or the expansion step. For weather data with strong seasonality, a simple expanding window without blocking for seasonal cycles (e.g., training on all previous years, testing on current year) risks data leakage or failure to capture seasonal calibration shifts. The methodology needs a specific blocking strategy (e.g., 'train on years 1-N, test on year N+1') to ensure temporal validity.

The dataset is not a real, accessible source in the plan's current state; the pipeline cannot run without a valid, reachable URL. This is a fatal data resource gap.

- The plan proposes using the Diebold-Mariano (DM) test to compare Brier/CRPS scores between 'raw', 'isotonic', and 'bayesian' methods. However, the 'isotonic' and 'bayesian' methods are trained on the *same* training split used to generate the 'raw' baseline for that split, or the 'raw' baseline is computed on the test set while recalibration is trained on the train set. If the comparison is between 'raw test' vs 'recalibrated test', the DM test is valid. BUT, if the plan implies comparing the *training* performance or if the 'raw' baseline is derived from the same data used to fit the recalibrator without a strict hold-out, the loss series are not independent. More critically, the plan states: 'For sensitivity analysis runs, the system MUST use bootstrapped confidence intervals instead of paired tests.' This implies the primary DM test is for the main split. The core issue is the definition of the 'loss series'. The DM test requires paired loss differences (L1_t - L2_t) for t=1..T. If the recalibration model is fitted on the training set and applied to the test set, the 'raw' and 'recalibrated' forecasts for the test set are paired. This is valid. However, the plan mentions 'sensitivity analysis runs (60/40, 80/20)'. If the DM test is run *across* these different splits (treating splits as time points), it violates the independence assumption of the DM test (splits are not time-ordered observations of the same process). The plan must clarify that DM is run *within* a single fixed test set, not across sensitivity splits. If the plan intends to compare methods across splits, it is a meta-analysis, not a DM test. The current phrasing 'applied to the series of differences across all lead times' (Spec SC-001) is ambiguous: is the series across lead times (which are correlated) or across time steps? DM requires time-series independence or HAC correction for time dependence. Lead times are not time steps; they are distinct forecast horizons. Comparing methods across lead times using DM is methodologically unsound unless the 'series' is the time series of forecasts for a *single* lead time. The plan says 'applied separately for each lead time' (FR-006), which is correct, but SC-001 says 'across all lead times', which is contradictory and suggests a tautological or invalid aggregation.
- The plan specifies a 'Structured decay prior (e.g., beta_lead ~ Normal(0, sigma_decay) where sigma_decay decreases with lead time)'. This prior structure imposes a specific physical assumption (forecast skill decays with lead time) directly into the prior distribution of the calibration parameters. While scientifically motivated, this creates a risk of 'prior dominance' where the posterior is driven by the prior rather than the data, especially for sparse events. The plan mentions a 'Prior Sensitivity Analysis' to 'decouple prior influence'. However, if the prior is *defined* by the physics of forecast degradation, and the goal is to *evaluate* calibration, there is a circularity risk: the model is forced to behave in a way that matches the physics assumption, and then the results are used to claim the model is well-calibrated. The validation target (calibration metrics) is being compared against a model that was *constrained* by the very assumption being tested. The plan must ensure the 'Prior Sensitivity Analysis' includes a 'Flat Prior' or 'Weakly Informative Prior' that does *not* encode the decay assumption, to serve as a true control. Without a non-physics-informed prior baseline, the 'improvement' claimed by the physics-informed prior is not an empirical discovery but a tautology of the prior specification.
- The plan states: 'If the normality assumption of differences is violated (Shapiro-Wilk, p < 0.05), the system MUST automatically switch to the Wilcoxon signed-rank test.' The Diebold-Mariano test is designed for time series data with potential autocorrelation. The Wilcoxon signed-rank test assumes independent and identically distributed (i.i.d.) observations. Forecast errors (and thus loss differences) are typically autocorrelated in time. Switching to Wilcoxon when normality fails ignores the autocorrelation structure, leading to invalid p-values (inflated Type I error). The correct approach for non-normal, autocorrelated loss differences is to use a robust version of the DM test (e.g., with HAC estimators, which the plan already mentions for the primary test) or a bootstrap method that preserves the time-series structure. Switching to Wilcoxon is a methodological error that invalidates the statistical inference for the non-normal case.
