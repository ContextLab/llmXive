# Implementation Plan: Evaluating Calibration of Probabilistic Weather Forecasts

**Branch**: `001-evaluating-calibration-weather` | **Date**: 2026-07-13 | **Spec**: `specs/001-evaluating-calibration-weather/spec.md`
**Input**: Feature specification from `specs/001-evaluating-calibration-weather/spec.md`

## Summary

This project evaluates the calibration of probabilistic weather forecasts from the SubseasonalRodeo dataset. The technical approach involves downloading the dataset, aligning GFS ensemble forecasts with ground-truth observations, and computing baseline calibration metrics (Brier score, CRPS, reliability diagrams). It then implements two recalibration methods: Isotonic Regression (non-parametric) and a Bayesian Hierarchical Logistic Regression model (sharing strength across lead times). The plan strictly adheres to CPU-first execution on GitHub Actions, utilizing streaming for data and scaled-down MCMC chains for the Bayesian component to fit within 2 CPU cores, ~7 GB RAM, and a 6-hour time limit.

**Critical Data Constraint**: The project relies on the SubseasonalRodeo dataset. As of this planning stage, no verified, open, programmatic source for this specific dataset (containing subseasonal ensembles and aligned ground truth) has been confirmed. The pipeline is designed to **fail immediately** if the primary download source is unreachable. No automated fallback to non-substitute datasets (e.g., NOAA Buoy, GFS Zip) is permitted, as these do not support the subseasonal calibration research question.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|:--- |:--- |:--- |
| **Bayesian Hierarchical Model** | Required by FR-005 and SC-002 to borrow strength across lead times for sparse events. | A simple per-lead-time logistic regression would fail to address data sparsity in heavy precipitation categories (US-3). |
| **Chronological Split** | Required by US-2 to prevent look-ahead bias in time-series forecasting. | Random splitting would leak future information into the training set, invalidating the calibration assessment. |
| **Stratified Sampling** | Required to fit CPU constraints while preserving temporal distribution. | Random sampling destroys temporal autocorrelation; stratified sampling preserves seasonal/lead-time distribution. |
| **HAC-Corrected DM Test** | Required for valid time-series comparison (methodological soundness). | Standard DM test assumes stationarity; weather data is non-stationary. (Note: FR-006 mandates Shapiro-Wilk pre-test, which is suboptimal, but we implement it as required). |

## Versioning Mechanism

To satisfy Constitution Principle V, the following mechanism is implemented:
1. After the pipeline completes, `scripts/hash_artifacts.py` is executed.
2. This script computes SHA-256 hashes for all files in `data/raw/`, `data/processed/`, and `results/`.
3. The hashes are written to `state/projects/PROJ-763-evaluating-calibration-of-probabilistic-.yaml` under `artifact_hashes`.
4. The Advancement-Evaluator Agent uses these hashes to invalidate stale review records.

## Statistical Plan & Methodological Notes

- **Bayesian Training**: The Bayesian model is trained on a **stratified random sample** of the full training set (preserving the distribution of seasons and lead times). This ensures the 'lead-time decay' prior learns from a representative distribution. The test set is the full held-out period.
- **Comparison**: All models (Baseline, Isotonic, Bayesian) are evaluated on the **exact same** test set. The Bayesian model's training set is a representative subset of the full training set, ensuring distributional equivalence.
- **Diebold-Mariano Test**: The plan implements FR-006's requirement for a Shapiro-Wilk pre-test (switching to Wilcoxon if non-normal). **However**, the research team notes that this two-stage procedure is methodologically unsound and inflates Type I error rates. The recommended approach (HAC-corrected DM test) is noted in the code comments, and a spec amendment is recommended to remove the Shapiro-Wilk requirement.
- **Robustness Check**: The Bayesian model will be trained on multiple stratified random seeds. If results vary significantly, the plan will report the variance.

## Success Metrics

- **SC-001**: BS reduction (Isotonic vs Baseline) with 95% CI excluding 0 or Cohen's d ≥ 0.2.
- **SC-002**: CRPS reduction (Bayesian vs Isotonic) with CI excluding negative values. (Valid because test sets are identical and training distributions are preserved via stratification).
- **SC-003**: Reliability slope deviation ≤ 0.05 from 1.0.
- **SC-004**: PIT KS statistic < 0.05.
- **SC-005**: Runtime ≤ 30 mins (target) / ≤ 6 hours (max).
- **SC-006**: R-hat ≤ 1.05.
