# Data Model: llmXive follow-up: extending "TriSplat: Simulation-Ready Feed-Forward 3D Scene Reconstruction"

## Overview

This document defines the data structures used for input, processing, and output in the reconstruction pipeline. The data model is designed to be lightweight, streaming-compatible, and strictly typed to ensure reproducibility and validation against the `contracts/` schemas.

## Core Entities

### 1. Scene Configuration
Represents the parameters for a single reconstruction run.

-   `scene_id`: Unique identifier for the scene (e.g., `re10k_val_scene_001`).
-   `view_count`: Number of input views (2, 3, 4, or 5).
-   `baseline_distance`: Approximate camera baseline distance (float, meters).
-   `input_paths`: List of file paths to source images.
-   `target_path`: File path to the target novel view image.
-   `gt_depth_path`: File path to the ground-truth depth map.
-   `resolution`: Target resolution tuple (width, height) = (320, 240).
-   `seed`: Random seed for reproducibility.

### 2. Reconstruction Result
Represents the output of a single reconstruction run.

-   `scene_id`: Reference to the input configuration.
-   `mesh_path`: Path to the generated `.obj` or `.ply` file.
-   `mesh_valid`: Boolean flag indicating if the mesh is manifold and non-empty.
-   `metrics`:
    -   `chamfer_distance`: Float (meters).
    -   `psnr`: Float (dB).
    -   `inference_latency`: Float (seconds).
    -   `peak_memory_mb`: Integer.
-   `convergence_status`: String (`"converged"`, `"max_iter_reached"`, `"failed"`).
-   `iterations`: Integer (number of iterations performed).
-   `error_log`: String (optional, for non-convergence warnings).

### 3. Statistical Summary
Aggregated results across multiple scenes.

-   `view_count`: Integer.
-   `n_scenes`: Integer (sample size).
-   `mean_chamfer`: Float.
-   `std_chamfer`: Float.
-   `mean_psnr`: Float.
-   `std_psnr`: Float.
-   `mean_latency`: Float.
-   `p_value`: Float (from significance test).
-   `test_type`: String (`"t_test"`, `"wilcoxon"`).
-   `threshold_exceeded`: Boolean (True if error increase > 15%).

## Data Flow

1.  **Ingestion**: `Scene Configuration` is generated by `run_batch.py` (random sampling of 50 scenes, 4 view counts).
2.  **Processing**: `Reconstruction Result` is produced by `geometry_only.py` for each configuration.
3.  **Aggregation**: `Statistical Summary` is computed by `utils/stats.py` from the collection of `Reconstruction Result` objects.
4.  **Output**: All results are serialized to JSON and stored in `data/processed/results/`.

## Storage Strategy

-   **Raw Data**: Downloaded RealEstate10K shards are stored in `data/raw/` with checksums.
-   **Processed Data**: Downscaled images and generated meshes are stored in `data/processed/`.
-   **Logs**: All metrics and error logs are stored in JSON format for easy parsing and validation.

## Schema References

-   `contracts/dataset_schema.schema.yaml`: Defines the structure of the input scene configuration.
-   `contracts/output_schema.schema.yaml`: Defines the structure of the reconstruction result.
-   `contracts/metrics_schema.schema.yaml`: Defines the structure of the statistical summary.
