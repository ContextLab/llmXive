# Data Fallback Protocol

## Overview

The **Data Fallback Protocol** is a critical component of the DreamX-Lite project, ensuring that all experiments and evaluations are conducted on real, verified data sources. This protocol defines the behavior of the data loading system when the primary data source (DreamX-World) is unavailable.

## Protocol Steps

### Step 1: Attempt Primary Data Source (DreamX-World)

1. **Check Availability**: The system first checks if the DreamX-World dataset is available at the configured path (`DREAMX_DATA_PATH`).
2. **Load Data**: If available, the dataset is loaded using `load_dreamx_world_data()` from `code/utils/io.py`.
3. **Validation**: The loaded data is validated for integrity (e.g., checksum verification).
4. **Success**: If validation passes, the data is used for the current task.

### Step 2: Fallback to Secondary Data Source (ScanNet)

1. **Check Availability**: If DreamX-World is unavailable, the system checks for the ScanNet fallback dataset at `SCANNET_DATA_PATH`.
2. **Load Data**: If available, the dataset is loaded using `load_scannet_fallback()` from `code/utils/io.py`.
3. **Validation**: The loaded data is validated for integrity.
4. **Success**: If validation passes, the data is used, and the result is tagged with `data_source: scannet`.

### Step 3: Abort on Missing Data

1. **Failure Condition**: If neither DreamX-World nor ScanNet data is available, the system **aborts** the primary claim generation.
2. **Error Logging**: A clear error message is logged, indicating the missing data sources.
3. **Status Flag**: The result is marked as `Pending Data Access` with `data_source: none`.
4. **No Synthetic Fallback**: The system **never** falls back to synthetic or placeholder data. This is a strict policy to maintain the integrity of all experimental results.

## Implementation Details

### Code Location

The Data Fallback Protocol is implemented in `code/utils/io.py`:

```python
def load_data(data_type: str) -> pd.DataFrame:
 """
 Load data with fallback logic.

 Args:
 data_type: 'dreamx' or 'scannet'

 Returns:
 DataFrame with loaded data.

 Raises:
 FileNotFoundError: If neither source is available.
 """
 if data_type == 'dreamx':
 try:
 return load_dreamx_world_data()
 except FileNotFoundError:
 logging.warning("DreamX-World data not found. Attempting ScanNet fallback.")
 try:
 return load_scannet_fallback()
 except FileNotFoundError:
 logging.error("Both DreamX-World and ScanNet data are missing. Aborting.")
 raise FileNotFoundError("No valid data source available.")
 elif data_type == 'scannet':
 return load_scannet_fallback()
 else:
 raise ValueError(f"Unknown data type: {data_type}")
```

### Logging

All data loading attempts and failures are logged with the following levels:
- **INFO**: Successful data load.
- **WARNING**: Primary data source unavailable, fallback attempted.
- **ERROR**: Both data sources unavailable, process aborted.

### Result Tagging

Every result generated by the pipeline includes a `data_source` field:
- `dreamx`: Primary data source used.
- `scannet`: Fallback data source used.
- `none`: No data source available (process aborted).

## Compliance

This protocol ensures compliance with the following project requirements:
- **FR-004**: Handle SfM failures gracefully (extended to data loading).
- **NFR-003**: Ensure all results are derived from real data sources.
- **Data Integrity**: No synthetic or placeholder data is ever used.

## Future Enhancements

- **Automated Data Fetching**: Implement automated downloading of DreamX-World or ScanNet data if not locally available.
- **Data Versioning**: Add support for multiple versions of datasets with automatic selection based on compatibility.
- **Extended Fallback Chain**: Support additional fallback data sources if needed in the future.
