## Unresolved concerns

- The plan proposes using Fisher's Exact Test for success rates with N=50 trials per condition. Fisher's Exact is designed for small sample sizes (typically <20) or sparse contingency tables. With N=50, a Chi-Square test or a two-proportion Z-test is statistically more powerful and standard. Using Fisher's here suggests a misunderstanding of statistical power for the proposed sample size, potentially leading to Type II errors (missing a real effect).
- The plan assumes a 'Paired t-test' for latency without verifying normality of the difference distribution. Inference latency in simulation often follows a heavy-tailed or skewed distribution (due to occasional physics solver stalls). Without a stated plan to check normality (e.g., Shapiro-Wilk) or a fallback to a non-parametric test (e.g., Wilcoxon Signed-Rank), the t-test may yield invalid p-values.
- The plan relies on 'GFM Weights (EuroSAT)' and 'GFM Weights (DFC2020)' from Hugging Face. These are remote sensing datasets (satellite imagery). The Geometric Action Model (GAM) for robotics requires 3D point cloud or RGB-D data. Using 2D satellite image weights for a 3D robotic manipulation task violates construct validity; the latent space geometry will not correspond to physical 3D constraints, rendering the 'symbolic-latent' hypothesis untestable.
- The plan targets '50 distinct novel topologies' and '~500 total simulation steps' (10 steps/trial). This sample size is insufficient to detect moderate effect sizes in a zero-shot generalization setting where success rates might be low (e.g., <20%). A power analysis is missing; if the baseline success rate is 10%, 50 trials yields very low power to detect a 10% improvement. The study risks being underpowered to answer the research question.
- The plan states: 'Claims are framed as associational performance differences rather than causal claims.' However, the research question explicitly asks if the symbolic solver 'achieves zero-shot generalization' (a causal claim about the method's capability). Framing the conclusion as merely associational when the experimental design (controlled A/B test on the same test set) supports causal inference weakens the study's validity. If the design supports causality, the conclusion should reflect that; if not, the design is flawed.
- FR-003 mandates verifying differentiability by ensuring gradients flow 'through the decoder' to solver parameters. However, Constitution Principle VI and FR-002 explicitly mandate that the GFM encoder/decoder weights are FROZEN and the decoder is not modified. A frozen, non-differentiable decoder (eval() mode) cannot propagate gradients. The plan must either define a differentiable decoder wrapper (contradicting 'frozen') or rephrase the verification to check gradients only up to the decoder's input, not through it.
- User Story 2 requires the system to 'verify that the symbolic logic is decoupled from decoder fidelity by isolating the solver's constraint satisfaction check from the decoder's reconstruction error.' The spec does not define the mechanism or metric for this isolation verification. Without a defined test (e.g., 'reconstruction error must remain < X while constraint satisfaction > Y'), this requirement is untestable.
- The second edge case contains corrupted text: 'exceeds the A time-limited CI window will be established. The research question, method, and references remain unchanged as per the original planning document.?'. This breaks the acceptance criteria for handling solver timeouts. The text must be corrected to define the timeout threshold and the specific failure logging behavior.
- FR-001 requires 'zero overlap with the original GAM training distribution' but does not specify the reference dataset or the method for verifying this zero overlap (e.g., 'compare topology hashes against a provided reference manifest'). Without a defined reference or verification method, this requirement cannot be implemented or tested.
- SC-005 measures feasibility against 'completing all trials within a CI time limit' but does not define the specific time limit (e.g., '6 hours' or '300 seconds per step'). While the plan mentions these numbers, the spec itself must contain the explicit threshold to be a measurable success criterion.
- The plan cites 'GFM Weights (EuroSAT)' and 'GFM Weights (DFC2020)' from Hugging Face as sources for the Geometric Foundation Model. EuroSAT and DFC2020 are satellite imagery datasets (2D RGB), whereas the project requires a 3D latent geometric model for robot policy learning (GAM). These datasets are semantically inappropriate for the required modality (3D geometry vs. 2D satellite imagery). The plan must cite a dataset or repository containing the actual pre-trained GAM/GFM weights for 3D manipulation tasks, not a placeholder satellite image dataset.
- The plan states: 'Reference Statistics: Computed locally by loading a sample of the original GAM training data (if accessible)...'. The plan fails to cite the source for this 'original GAM training data'. Without a verified URL or repository reference for the training set used to compute the latent mean/covariance, the drift detection mechanism (Constitution VI) cannot be reproduced or validated. The plan must cite the specific dataset or repository containing the original GAM training distribution.
- Constitution Principle VI (Latent-Space Symbolic Fidelity) is marked '✅ Pass' in the plan, yet the plan's 'Technical Context' and 'Complexity Tracking' sections describe a 'differentiable symbolic solver' that computes gradients 'through the decoder's Jacobian'. The Constitution VI explicitly mandates that the GFM encoder/decoder weights remain FROZEN and that the solver operates in latent space without modifying the backbone. If the decoder is frozen (eval mode), gradients cannot flow through it to the solver parameters unless a specific differentiable wrapper is implemented. The plan conflates 'frozen weights' with 'non-differentiable interface', creating a direct contradiction with the constitutional requirement for gradient verification (FR-003) and Principle VI.
- Constitution Principle VII (Zero-Shot Topology Generalization) is marked '✅ Pass', but the plan's 'Data Acquisition Plan' in research.md (referenced by the plan) and the 'Technical Context' imply fetching 'GFM Training Stats' from a local generation step. However, the plan's 'Constitution Check' table does not explicitly map a verification step for 'zero overlap' between the generated test set and the training distribution, which is the core of Principle VII. The plan states 'Checksum validation against original training metadata' in research.md, but the plan.md itself lacks a specific task or step that enforces this validation as a gate before trial execution, risking a violation of the 'strictly absent' requirement.
- The 'Project Structure' section lists `contracts/` as a Phase 1 output, but the 'Contracts' directory in the input artifacts contains multiple schema files (e.g., `trial_log.schema.yaml`, `trial_log_schema.schema.yaml`, `stats_report_schema.schema.yaml`) that appear to be duplicates or conflicting definitions for the same entity (Trial Log). The plan does not address this redundancy or specify which schema is the Single Source of Truth (Constitution Principle IV), creating ambiguity in the data model implementation.
- The 'Technical Context' lists 'diff-taichi' as a primary dependency, but the 'Contracts' directory includes `gradient_flow_log.schema.yaml` which requires a 'numerical_finite_difference' method for verification. The plan does not explicitly state how the 'diff-taichi' symbolic solver (which uses automatic differentiation) will be validated against a 'numerical_finite_difference' schema, or if the schema is intended for a fallback verification method. This creates a potential mismatch between the implementation tool and the verification contract.
- The plan proposes verifying differentiability by ensuring 'gradients flow from the constraint violation loss, through the decoder, to the solver parameters' (FR-003). However, the plan simultaneously mandates freezing the GFM encoder/decoder weights and running them in `eval()` mode (Plan Summary, US-2). In PyTorch, a frozen module in `eval()` mode typically has `requires_grad=False` and does not propagate gradients. If the decoder is truly frozen and non-differentiable, the gradient path to the solver is broken by definition. If the decoder must be differentiable for the solver to work, it cannot be 'frozen' in the standard sense. This creates a circular/contradictory validation: the plan requires a gradient path that the architectural constraint (frozen weights) explicitly severs. The validation target (gradient flow) is impossible given the predictor construction (frozen decoder).
- The plan relies on 'GFM Weights (EuroSAT)' and 'GFM Weights (DFC2020)' from Hugging Face as the source for the Geometric Foundation Model (GFM) encoder/decoder. EuroSAT and DFC2020 are satellite imagery datasets (land use/land cover). The Geometric Action Model (GAM) for robot policy learning requires a model trained on 3D robotic manipulation data (e.g., RT-1, RT-2, or specific robotic vision datasets). Using a vision model trained on 2D satellite imagery as the 'Geometric Foundation Model' for 3D robot kinematics is a category error. The latent space of a satellite image encoder does not represent 3D rigid-body or soft-body kinematic states. Consequently, the 'zero-shot generalization' claim is invalid because the base model (GFM) lacks the necessary geometric priors for the task domain. The validation target (robot task success) is definitionally disconnected from the predictor's training domain.
- The plan proposes using a 'Paired t-test' for inference latency comparison. Latency data in real-time systems is rarely normally distributed; it is typically right-skewed with heavy tails (due to OS jitter, GC pauses, or solver timeouts). The plan acknowledges a 'timeout mechanism' (Edge Cases) which introduces censored data. Applying a standard paired t-test to latency data with potential outliers and censored values violates the normality assumption of the test, rendering the p-values and confidence intervals statistically invalid. A non-parametric test (e.g., Wilcoxon Signed-Rank) or a survival analysis approach (for censored data) is required. The chosen methodology is unsound for the data type described.
- The plan requires generating a 'topology-shift' test set with 'zero overlap' with the original GAM training distribution. However, the plan does not define the 'original GAM training distribution' in terms of topology parameters (e.g., link counts, joint types, material stiffness). Without a defined reference distribution (e.g., a specific dataset of training topologies), the claim of 'zero overlap' is unverifiable and potentially tautological (i.e., 'we generated random topologies, so they are different from the training set' without knowing what the training set is). The validation target (novelty) cannot be independently verified without access to the specific training topology metadata, which is not cited as a verified dataset.
