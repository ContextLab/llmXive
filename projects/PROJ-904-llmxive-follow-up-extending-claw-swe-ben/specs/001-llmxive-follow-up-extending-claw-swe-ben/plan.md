## Summary

This feature implements a rigorous experimental benchmark to quantify the trade-off between context compression fidelity and model scaling (1B vs. 7B parameters) on CPU-only hardware. The system ingests the Claw-SWE-Bench dataset, filters for high-complexity instances (>500 lines of relevant history via import graph traversal), and executes a matrix of experiments: multiple model sizes × 4 context strategies (Naive Baseline, TF-IDF/BM25, Diff-Aware Sliding, Rule-Based Semantic Summarization). Results are analyzed via a Generalized Linear Mixed Model (GLMM) or Firth's GLM to test for interaction effects on pass rates, determining if context optimization can substitute for parameter scaling.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: `transformers` (CPU-optimized), `datasets` (streaming), `scikit-learn` (TF-IDF), `statsmodels` (GLMM/Firth), `sentencepiece` (tokenization), `pytest` (testing), `networkx` (import graph).  
**Storage**: Local ephemeral storage on GitHub Actions runner; raw data streamed from Hugging Face; derived data written to versioned files in `data/`; results aggregated to `data/results.csv`.  
**Testing**: `pytest` (unit tests for compression modules), integration tests for end-to-end execution with timeout guards.  
**Target Platform**: Linux (GitHub Actions Free Tier: 2 vCPU, 7GB RAM).  
**Project Type**: Computational Research Benchmark / CLI Tool.  
**Performance Goals**: ≤60 min runtime per instance; total wall-clock ≤72h for 400 instances via parallel batching; memory ≤7GB via aggressive quantization (Q4_K_M for all models).  
**Constraints**: No local GPU; strict RAM budget; no external API calls for context retrieval (must be CPU-native); deterministic failure mode classification based on sandbox execution logs.  
**Scale/Scope**: ~400 filtered task instances from SWE-bench; 4 context strategies; 2 model sizes.

- **Principle I (Reproducibility)**: Plan ensures all code is in `code/`, seeds are pinned, and datasets are fetched from canonical HF sources. Random seeds will be hardcoded in `code/experiments/run.py`.
- **Principle II (Verified Accuracy)**: Citations to SWE-bench and TF-IDF methodologies will be validated against the provided `# Verified datasets` block. No external URLs will be invented.
- **Principle III (Data Hygiene)**: Raw data will be streamed. Derived datasets (filtered) will be written to *new versioned filenames* (e.g., `data/filtered_swe_bench_v1.parquet`) and checksummed. No in-place modification.
- **Principle IV (Single Source of Truth)**: All Pass@1 metrics and GLM p-values will be derived from a single `data/results.csv` generated by `merge_results.py`, ensuring traceability.
- **Principle V (Versioning Discipline)**: The plan commits to uploading `state/` artifacts and `data/` checksums to GitHub Actions Artifacts and committing the `state/` file to a `results/` branch to ensure persistence beyond ephemeral runners.
- **Principle VI (Context-Fidelity vs. Scaling)**: The experimental design explicitly isolates "Context Strategy" and "Model Size" as orthogonal variables to test the interaction effect, directly addressing the core research question.
- **Principle VII (Resource-Constrained Execution)**: The plan mandates CPU-only execution, Q4_K_M quantization for *both* 1B and 7B models, and strict 60-minute timeouts per instance to ensure feasibility on the free-tier runner.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| GLMM / Firth's GLM | Required to handle sparse binary data (low Pass@1 rates) and avoid separation issues in standard GLM. | Standard GLM fails to converge or produces infinite standard errors with <5% success rates. |
| Import Graph Traversal | Required to define 'complexity' based on code dependencies rather than arbitrary directory depth. | Directory depth is arbitrary and does not correlate with problem difficulty; import graph reflects actual code scope. |
| JSONL Intermediate Output | Required to allow `merge_results.py` to aggregate results from separate baseline/high-fidelity scripts into a single SSoT. | Separate CSVs or different formats would break the Single Source of Truth principle. |
| Sandbox Log Analysis | Required to accurately classify 'missing_context' vs 'reasoning_error' based on execution errors, not model text. | Inferring from model text is unreliable; sandbox logs provide ground truth on file access errors. |
| Q4_K_M for All Models | Required to isolate 'Model Size' from 'Quantization Noise'. | Using different quantization levels confounds the scaling effect with quantization artifacts. |
| Semantic Summarization Redefinition | Required to ensure the 'high-fidelity' strategy actually preserves logic (variables, control flow) rather than discarding it via heuristic sentence selection. | The original 'first/last sentence' heuristic was found to discard critical logic, invalidating the 'high-fidelity' construct. |
