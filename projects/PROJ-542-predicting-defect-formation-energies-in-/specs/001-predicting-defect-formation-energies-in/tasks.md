## Phase 1 – Data acquisition, feature engineering, and validation  

| Goal: Produce a verified feature matrix from real Materials Project data. |
|--------------------------------------------------------------------------|

- [ ] **T001** [US‑1] Create `quickstart.md` that documents the single command to run the full pipeline (`python -m src.pipeline.run`).  
  *File:* `quickstart.md`  
  *Verification:* Run the documented command on a fresh GitHub Actions runner; stdout must contain the exact phrase **“Pipeline completed successfully”**. A pytest `src/tests/test_quickstart.py` asserts this behavior, satisfying FR‑010 and SC‑004.

- [ ] **T002** [US‑1] Implement `src/data/download.py` to fetch oxygen‑vacancy defect formation energies for perovskites from the Materials Project API (API key read from `MP_API_KEY`).  
  *Outputs:* `data/raw/materials_defects.csv` (≥ 500 rows) and `data/checksums/raw_defects.sha256` (generated by T005).  
  *Verification:*  
  1. Script exits with code 0.  
  2. If `MP_API_KEY` is missing, the script aborts with the message **“Materials Project API key not provided”**.  
  3. If the API returns zero records, the script aborts with **“No data found for specified filters.”** (FR‑007).  
  4. When successful, the CSV validates against `contracts/raw_dataset.schema.yaml` (FR‑001).  

- [ ] **T003** [US‑1] Implement `src/data/featurize.py` to compute the twelve compositional descriptors (atomic radius, Pauling electronegativity, oxidation state, valence electron count for A, B, X) using **pymatgen**.  
  *Outputs:* `data/processed/features.csv` and a log `data/processed/featurize.log`.  
  *Verification:*  
  1. Rows with undeterminable oxidation states are dropped; the log reports the number of excluded rows (FR‑008).  
  2. The resulting CSV contains exactly 12 descriptor columns plus the target `formation_energy`, with **no missing values in the target column** (FR‑002).  
  3. The script invokes `src/utils/check_descriptor_gaps.py` (T007) and aborts if any descriptor gaps are detected.  

- [ ] **T004** [US‑1] Implement `src/data/validate.py` to enforce dataset size and perform a simple power analysis.  
  *Outputs:* `data/processed/validation.log`.  
  *Verification:*  
  1. If the feature matrix has **< 50 rows**, the script raises a `ValueError` with the message **“Insufficient samples for 5‑fold cross‑validation (minimum 50 required).”** (FR‑009).  
  2. If rows < 500, the script logs a warning and prints a power‑analysis estimate (e.g., “Power = 0.73 for detecting ΔRMSE = 0.1 eV, σ ≈ 0.3 eV, α = 0.05”). The log must exist (fulfills the missing‑artifact issue for T004).  

- [ ] **T005** [Constitution‑III] Compute a SHA‑256 checksum for `data/raw/materials_defects.csv` **immediately after download** and write it to `data/checksums/raw_defects.sha256`.  
  *File:* `src/utils/checksum.py` (invoked by the pipeline).  
  *Verification:* CI test reads the CSV, recomputes the SHA‑256 digest, and asserts it matches the value in the `.sha256` file.  

- [ ] **T006** [Constitution‑III] Compute a SHA‑256 checksum for `data/processed/features.csv` **after featurization** (including gap checking) and write it to `data/checksums/features.sha256`.  
  *Verification:* Same as T005, but for the processed feature matrix.  

- [ ] **T007** [FR‑006] Run `src/utils/check_descriptor_gaps.py` to scan `features.csv` for any missing descriptor values.  
  *Output:* `data/processed/descriptor_gaps.log`.  
  *Verification:* If the log contains any entries, the pipeline aborts with the message **“Descriptor gaps detected – see descriptor_gaps.log”**. Otherwise the script exits silently with code 0.

## Phase 2 – Model training, evaluation, and fallback augmentation  

| Goal: Train baseline models, evaluate them, and automatically augment descriptors if performance thresholds are not met. |
|---------------------------------------------------------------------------------------------------------------|

- [ ] **T008** [US‑2] Implement `src/models/split.py` to create a deterministic **80/20 GroupShuffleSplit** (group = composition string) ensuring no composition appears in both splits.  
  *Outputs:* `data/processed/train.csv`, `data/processed/test.csv`, and a log `data/processed/split.log`.  
  *Verification:*  
  1. Both CSV files exist.  
  2. `split.log` records the number of samples in each set and confirms **zero intersection** of composition groups (FR‑011).  

- [ ] **T009** [US‑2] Implement `src/models/train.py` to perform **5‑fold GroupKFold** cross‑validation for **RandomForestRegressor** and **GradientBoostingRegressor** (scikit‑learn, `n_jobs=1`, `random_state=42`).  
  *Outputs:* `models/rf_cv.pkl`, `models/gb_cv.pkl`, and `data/processed/cv_metrics.json`.  
  *Verification:*  
  1. Script runs on CPU‑only (no CUDA imports).  
  2. `cv_metrics.json` conforms to the **`cv_metrics`** portion of `contracts/model_performance.schema.yaml` (contains `rmse_mean`, `rmse_std`, `mae_mean`, `mae_std`, `r2_mean`, `r2_std` for both models).  
  3. A pytest `src/tests/test_cv_metrics.py` validates the JSON against the schema.  

- [ ] **T010** [US‑3] Implement `src/models/evaluate.py` to:  
  1. Load the model with the lowest mean CV RMSE.  
  2. Predict on `data/processed/test.csv`.  
  3. Compute **RMSE**, **MAE**, **R²**.  
  4. Bootstrap **10 000** resamples to obtain a **95 % confidence interval** for RMSE.  
  5. Perform a **paired two‑sided t‑test** (α = 0.05) between predictions and DFT values.  
  *Outputs:* `data/processed/performance.json` (full schema) and `figures/pred_vs_actual.png` (scatter plot with 1:1 line).  
  *Verification:*  
  1. `performance.json` validates against the **entire** `model_performance.schema.yaml`.  
  2. The scatter plot contains axis labels, a 1:1 reference line, and is saved as a PNG.  

- [ ] **T011** [US‑3] Implement `src/models/feature_importance.py` to extract `feature_importances_` from the selected model, normalize them (sum = 1), write a ranked bar chart `figures/feature_importance.png`, and update the `feature_importances` array in `performance.json`.  
  *Verification:*  
  1. PNG file exists and displays descriptors in descending order.  
  2. The `feature_importances` field in `performance.json` matches the bar chart and sums to 1 (within tolerance 1e‑6).  

- [ ] **T012** [FR‑012] **Fallback augmentation** – If the decision rule after T010 fails (RMSE > 0.5 eV **or** R² < 0.70 **or** p‑value ≤ 0.05), automatically:  
  1. Run `src/data/augment_structural.py` to compute additional structural descriptors (coordination numbers, average bond lengths, crystal symmetry class) and **append** them to `features.csv`.  
  2. Overwrite `data/processed/features.csv` and recompute its checksum (T006).  
  3. Re‑run T009, T010, and T011 on the augmented matrix.  
  *Outputs:* Updated `features.csv`, new checksum, refreshed `cv_metrics.json`, `performance.json`, and figures.  
  *Verification:*  
  - A log `data/processed/augmentation.log` records that augmentation was triggered, lists the new descriptor names, and shows the post‑augmentation performance metrics.  
  - After augmentation, the performance must satisfy **RMSE ≤ 0.5 eV** **and** **R² ≥ 0.70** **and** **p‑value > 0.05**; otherwise the log notes that the fallback still did not meet thresholds (the project would then be reported as a negative result, which is acceptable).
