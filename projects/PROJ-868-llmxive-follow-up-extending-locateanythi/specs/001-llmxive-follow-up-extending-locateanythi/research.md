# Research: llmXive follow‑up – extending “LocateAnything: Fast and High‑Quality Vision‑Language Grounding with P”

**Feature**: llmXive follow‑up – attention sparsity impact study  
**Prepared on**: 2026‑10‑24  

## Overview
We will empirically measure how Restricting the attention window of a LocateAnything‑style vision‑language grounding model degrades bounding‑box geometric coherence (mean Intersection‑over‑Union, mIoU) on dense scenes; locate the sparsity “tipping point” for a high‑performance mIoU threshold., and explain failure modes via gradient‑based attribution. All work runs on the free‑tier GitHub Actions CPU runner (2 cores, ≤ 7 GB RAM, ≤ 6 h wall‑clock).

## Compute Decision & Rationale
- **CPU‑first**: All required operations (sparsity mask generation, inference, statistical tests, Grad‑CAM) have faithful CPU implementations. The **LocateAnything‑mini** checkpoint (≈1 GB) fits comfortably on CPU with `torch.set_num_threads(2)`. No GPU‑only kernels are needed.  
- **GPU escape hatch**: Not required for this study. If future work demands a larger transformer, the plan would switch to a quantized 8‑bit model on Kaggle’s free GPU, but the current pipeline stays entirely on CPU.

## Methodology

### 1. Pre‑processing & Subset Construction
1. Load VRSBench and COCO (validation) with memory‑mapped loading (`mmap=True`).  
2. For each image, compute pairwise IoU among all ground‑truth boxes.  
   - **Dense‑scene**: > 5 boxes where each pair’s IoU > 0.10 (FR‑003).  
   - **Low‑density**: ≤ 5 overlapping pairs – still processed for mIoU but the ambiguity‑resolution failure metric is recorded as “N/A” (FR‑008/SC‑007).  
   - **Non‑dense**: all remaining images (including low‑density).  
3. Flag **ambiguous** boxes (zero‑area or IoU > 0.95 with another box) and exclude them from any mIoU computation (FR‑007). Record the proportion of excluded samples (must be ≤ 5 % → SC‑006).  
4. **Sampling for feasibility**: Randomly sample **up to 2 000 dense images** (fixed seed = 42) to respect the CPU memory budget; if the dense pool is smaller, use all available images. This sample size yields > 80 % power for a medium effect size (see Phase 4).  
5. Persist dense and non‑dense subsets as Parquet files (Phase 1 output).  

### 2. Model & Sparsity Configuration
- Load the **LocateAnything‑mini** checkpoint (FP32) on CPU.  
- Implement `SparsityConfig(num_patches, window_size=None)` that masks all tokens outside a sliding window of `num_patches` patches in each transformer layer. Supported values: `0` (global), `64`, `32`, `16`, optional `1`. The mask is generated by `get_mask()` (no arguments) and returns a binary tensor of shape `[num_tokens]`. For `num_patches` larger than the token grid the mask is all‑ones (global). This satisfies the test expectations (FR‑013).  

### 3. Inference & Metric Computation
For each sparsity configuration (global, 64, 32, 16, optional 1):  
- **Randomize configuration order** using a fixed seed (`np.random.RandomState(42)`) to avoid systematic warm‑up or caching effects.  
- **Within each configuration**, shuffle the image list (same seed) before batching (batch = 4) to eliminate batch‑order confounds (addresses methodology‑90d73a53).  
- Reset model state to avoid carry‑over effects.  
- Apply the mask via `LocateAnythingSparsityWrapper(sparsity_config)`.  
- Run inference on **both** dense and non‑dense subsets.  
- Save per‑image predictions as JSON under `data/predictions/<image_id>_<window>.json`.  
- Compute per‑image **mIoU**, record inference **latency** (ms), and set `excluded` flag if the image was ambiguous.  
- Append a row to `inference_<window>.parquet` containing all fields required by the contract schema (FR‑002, FR‑009).  

### 4. Statistical Analysis
- **Mixed two‑way ANOVA**: Within‑subject factor = sparsity level; between‑subject factor = scene density.  
  - Test normality per cell with Shapiro‑Wilk; if any p < 0.05, fall back to **Friedman aligned‑rank test** (FR‑004).  
  - Report the interaction p‑value (SC‑002).  
- **Power analysis**: Assuming a medium effect size f = 0.25, α = 0.05, within‑subject correlation r = 0.5, `statsmodels.stats.power.FTestPower` yields a required dense‑scene N ≈ 180. Our sampled dense set (≤ 2 000) comfortably exceeds this; the script records the calculated N and notes any shortfall (methodology‑4394f758).  
- **Beta‑GLMM fallback**: If ANOVA/Friedman residuals remain non‑normal or heteroscedastic, fit a beta mixed‑effects regression (`statsmodels` GLM with `family=Beta()`) treating sparsity as an ordered factor. This respects the bounded nature of mIoU (methodology‑69c1d2df).  
- **Trend analysis**: Perform a **Jonckheere‑Terpstra** test for ordered sparsity levels against mIoU (primary SC‑003). Additionally compute **Kendall’s τ** and report its p‑value.  

### 5. Tipping‑Point Detection & ±8‑Patch Sweep
- Identify the **statistical tipping point** as the smallest window where the **upper bound of the 95 % confidence interval** of dense‑scene mean mIoU is **< 0.80** (FR‑010). If no window satisfies this CI criterion, report “no tipping point reached”.  
- When a tipping point is found and the window > 1, run a **±8‑patch sweep** (clamped to 1‑64) around it, re‑run inference, and record the extra mIoU values (FR‑011). The sweep is **exploratory**; apply a **Bonferroni correction** for the multiple comparisons and report corrected p‑values (methodology‑19bf7b83).  
- Optional 1‑patch run is executed only when `--run-one-patch` is set (FR‑009).  

### 6. Attribution on Failure / Success Cases
- **Pre‑registered hold‑out**: Randomly select 200 dense images (seed = 0) **before** any tipping‑point computation and split them into two independent groups (Group A, Group B) without looking at mIoU. This avoids post‑hoc selection bias (methodology‑a7d2ed79).  
- After the tipping point is known, label Group A as “failure” if its mIoU under the tipping‑point window < 0.80, otherwise “success”; similarly label Group B.  
- Apply Captum‑based Grad‑CAM to the **full, unmasked model** for all hold‑out images; generate heatmaps.  
- Compute **global‑context activation proportion** for each image and store in the inference parquet (`global_context_activation_proportion`).  
- Summarize the **absolute difference** between the failure and success groups; **verify** that the difference ≥ 0.30 as required by SC‑004. If the threshold is not met, flag the result as “SC‑004 not satisfied” (addresses scientific_soundness‑c8133d0a).  

### 7. Consolidation & Reporting
- **7‑a. Consolidation**: Concatenate all `inference_*.parquet` files into a single `master_inference.parquet` and compute a SHA‑256 checksum (addresses plan_consistency‑fb7470e4).  
- **7‑b.** Assemble: <br>  - Degradation curve (Figure 1). <br>  - ANOVA/Friedman table (Table 1). <br>  - Trend test results (Table 2). <br>  - Tipping‑point table (Table 3). <br>  - Attribution collage (Figure 2). <br>  - Latency bar chart (Figure 3). <br>All tables/figures draw directly from `data/results/master_inference.parquet`, satisfying Constitution Principle IV. Write `docs/results.md` for downstream paper pipeline.  

### 8. Contract Validation
Run `pytest -q tests/contract/` against `contracts/inference_results.schema.yaml`. CI fails if any result file violates the schema.  

All phases respect the data dependency order (download → preprocess → model → inference → analysis → reporting) and stay within the CPU‑only compute budget; no GPU escape hatch is required.

## Success Criteria
| SC | Requirement | How it is satisfied |
|----|-------------|---------------------|
| **SC‑001** | Degradation curve of dense‑scene mIoU across the sparsity grid (including optional 1‑patch) must be measured; tipping point defined as first window where the **upper 95 % CI** of mean mIoU < 0.80. | Phase 5 computes the curve, CI, and applies the CI‑based tipping‑point rule. |
| **SC‑002** | Report p‑value from the two‑way mixed ANOVA (or Friedman fallback). | Phase 4 outputs `anova_results.json`. |
| **SC‑003** | Report an ordinal‑compatible correlation between attention window size and mIoU for both dense and non‑dense subsets. | Phase 4 computes Kendall’s τ and Jonckheere‑Terpstra test (trend_test.json). |
| **SC‑004** | For attribution analysis, compute the global‑context activation proportion for failure and success groups and report the absolute difference **≥ 30 %**; if not met, flag. | Phase 6 computes the proportion, checks the ≥ 0.30 threshold, and records the outcome in `attribution_summary.json`. |
| **SC‑005** | Total inference latency per image must be measured and the overall batch run must complete within **6 hours** on the specified 2‑core CPU. | Phase 3 logs `latency_ms`; overall runtime is monitored by the CI runner (expected ≤ 4 h). |
| **SC‑006** | Number of images excluded due to ambiguous ground‑truth must be ≤ 5 % of total. | Phase 1 logs exclusion proportion; enforced in `exclusion_log.json`. |
| **SC‑007** | For low‑density images, the ambiguity‑resolution failure metric must be reported as “N/A”. | Phase 1 flags low‑density images; reporting step writes “N/A” for that metric. |
| **SC‑008** | The randomization seed used for ordering sparsity runs must be logged, and a checksum confirming that the master inference table includes data from all sparsity levels must be provided. | Phase 3 uses seed = 42 and logs it; Phase 7 writes SHA‑256 checksum of `master_inference.parquet`. |
