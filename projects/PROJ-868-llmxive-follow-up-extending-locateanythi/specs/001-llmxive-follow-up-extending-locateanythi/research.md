# Research: llmXive follow‑up – extending “LocateAnything: Fast and High‑Quality Vision‑Language Grounding with P”

**Feature**: llmXive follow‑up – attention sparsity impact study  
**Prepared on**: 2026‑10‑24  

## Overview
We will empirically measure how restricting the attention window of a LocateAnything‑style vision‑language grounding model degrades bounding‑box geometric coherence (mean Intersection‑over‑Union, mIoU) on dense scenes, locate the sparsity “tipping point” for an 80 % mIoU threshold, and explain failure modes via gradient‑based attribution. All work runs on the free‑tier GitHub Actions CPU runner (2 cores, ≤ 7 GB RAM, ≤ 6 h wall‑clock).

All datasets are directly downloadable via the Hugging Face `datasets` library or `urllib`. No authentication is required. Checksums are recorded in `data/` as part of the pipeline.

## Compute Decision & Rationale
- **CPU‑first**: All required operations (sparsity mask generation, inference, statistical tests, Grad‑CAM) have faithful CPU implementations. The LocateAnything checkpoint fits in < 3 GB when loaded on CPU and runs comfortably with `torch.set_num_threads(2)`. No GPU‑only kernels are needed.  
- **GPU escape hatch**: Not required for this study. If future work demands a larger transformer, the plan would switch to a quantized 8‑bit model on Kaggle’s free GPU, but the current pipeline stays entirely on CPU.

## Methodology

### 1. Pre‑processing & Subset Construction
1. Load VRSBench and COCO (validation) with memory‑mapped loading (`mmap=True`).  
2. For each image, compute pairwise IoU among all ground‑truth boxes.  
   - **Dense‑scene**: > 5 boxes where each pair’s IoU > 0.10 (FR‑003).  
   - **Low‑density**: ≤ 5 overlapping pairs – still processed for mIoU but the ambiguity‑resolution failure metric is recorded as “N/A” (FR‑008/SC‑007).  
   - **Non‑dense**: all remaining images (including low‑density).  
3. Flag **ambiguous** boxes (zero‑area or IoU > 0.95 with another box) and exclude them from any mIoU computation (FR‑007). Record the proportion of excluded samples (must be ≤ 5 % → SC‑006).  
4. Persist dense and non‑dense subsets as Parquet files (Phase 1 output).  

### 2. Model & Sparsity Configuration
- Load the LocateAnything checkpoint (FP32) on CPU.  
- Implement `SparsityConfig(num_patches)` that masks all tokens outside a sliding window of `num_patches` patches in each transformer layer. Supported values: `0` (global), `64`, `32`, `16`, optional `1`.  
- The mask is generated by `get_mask()` (no arguments) and returns a binary tensor of shape `[num_tokens]`. For `num_patches` larger than the grid the mask is all‑ones (global). This satisfies the test expectations (FR‑003).  

### 3. Inference & Metric Computation
For each sparsity configuration (global, 64, 32, 16, optional 1):  
- **Randomize** the order of configurations using a fixed seed (`np.random.RandomState(42)`) to avoid systematic warm‑up or caching effects.  
- Reset model state to avoid carry‑over effects.  
- Apply the mask via `LocateAnythingSparsityWrapper(sparsity_config)`.  
- Run inference on **both** dense and non‑dense subsets (batch = 8).  
- Save per‑image predictions as JSON under `data/predictions/<image_id>_<window>.json`.  
- Compute per‑image **mIoU** against ground truth, record inference **latency** (ms), and set `excluded` flag if the image was ambiguous.  
- Append a row to `inference_<window>.parquet` containing all fields required by the contract schema (FR‑002, FR‑009).  

### 4. Statistical Analysis
- **Mixed two‑way ANOVA**: Within‑subject factor = sparsity level; between‑subject factor = scene density.  
  - Test normality per cell with Shapiro‑Wilk; if any p < 0.05, fall back to **Friedman aligned‑rank test** (FR‑004).  
  - Report the interaction p‑value (SC‑002).  
- **Power analysis**: Assuming a medium effect size f = 0.25, α = 0.05, within‑subject correlation r = 0.5, and 4 sparsity levels, `statsmodels.stats.power.FTestPower` indicates > 80 % power with the expected dense‑scene N (on the order of thousands). The script `src/analysis/power_analysis.py` records the calculation (SC‑002).  
- **Trend analysis**: Perform a **Jonckheere‑Terpstra** test for ordered sparsity levels against mIoU (primary SC‑003). Additionally compute **Kendall’s τ** as an ordinal‑compatible correlation coefficient and report its value. This respects the categorical nature of the sparsity predictor while still providing a correlation‑type metric (SC‑003).  

### 5. Tipping‑Point Detection & Sensitivity Sweep
- Identify the smallest window where dense‑scene **mean** mIoU < 0.80 (FR‑010).  
- If such a window exists and is > 1, run a **±8‑patch sweep** (clamped to 1‑64) around it, re‑run inference, and record the extra mIoU values (FR‑011).  
- If no tipping point is found, record “no tipping point reached”.  
- Optional 1‑patch run is executed only when `--run-one-patch` is set (FR‑009).  

### 6. Attribution Analysis (Hold‑out Procedure)
- **Hold‑out set**: Before any tipping‑point computation, randomly sample 200 dense images (seed = 0) – A comparable number of participants are designated as “failure candidates” and as “success candidates.”. This set is **not** used for determining the tipping point (FR‑003).  
- After the tipping point is known, select from the hold‑out set:  
  - **Failure images**: those where the tipping‑point window yields mIoU < 0.80.  
  - **Success images**: those where global attention yields mIoU ≥ 0.80.  
- Apply Captum‑based Grad‑CAM to the final convolutional layer, generate heatmaps, and compute **global‑context activation proportion** (mass on tokens labelled “global‑context”).  
- Store the proportion in the inference results parquet (`global_context_activation_proportion`).  
- Summarize the absolute difference between failure and success groups (SC‑004).  

### 7. Consolidation & Reporting
- **7‑a. Consolidation**: Concatenate all `inference_*.parquet` files into a single `master_inference.parquet`. This concrete merge step satisfies the Single Source of Truth principle.  
- **7‑b.** Assemble: <br>  - Degradation curve (Figure 1). <br>  - ANOVA/Friedman table (Table 1). <br>  - Trend test results (Table 2). <br>  - Tipping‑point table (Table 3). <br>  - Attribution collage (Figure 2). <br>  - Latency bar chart (Figure 3). <br>All tables/figures draw directly from `data/results/master_inference.parquet`, satisfying Constitution Principle IV. Write `docs/results.md` for downstream paper pipeline.  

### 8. Contract Validation
Run `pytest -q tests/contract/` against `contracts/inference_results.schema.yaml`. CI fails if any result file violates the schema.  

All phases respect the data dependency order (download → preprocess → model → inference → analysis → reporting) and stay within the CPU‑only compute budget; no GPU escape hatch is required.

## Success Criteria
| SC | Requirement | How it is satisfied |
|----|-------------|---------------------|
| **SC‑001** | Degradation curve of dense‑scene mIoU across the sparsity grid (including optional 1‑patch) must be measured; tipping point defined as first window where mIoU < 0.80. | Phase 5 computes the curve and records the tipping point (or “no tipping point”). |
| **SC‑002** | Report p‑value from the two‑way mixed ANOVA (or Friedman fallback). | Phase 4 outputs `anova_results.json`. |
| **SC‑003** | Report an ordinal‑compatible correlation between attention window size and mIoU for both dense and non‑dense subsets. | Phase 4 computes Kendall’s τ and Jonckheere‑Terpstra test (trend test) and records them in `trend_test.json`. |
| **SC‑004** | For attribution analysis, compute the global‑context activation proportion for failure and success groups and report the absolute difference. | Phase 6 produces `attribution_summary.json`. |
| **SC‑005** | Total inference latency per image must be measured and the overall batch run must complete within **6 hours** on the specified 2‑core CPU. | Phase 3 logs `latency_ms`; overall runtime is monitored by the CI runner (expected ≤ 4 h). |
| **SC‑006** | Number of images excluded due to ambiguous ground‑truth must be ≤ 5 % of total. | Phase 1 logs exclusion proportion; enforced in `exclusion_log.json`. |
| **SC‑007** | For low‑density images, the ambiguity‑resolution failure metric must be reported as “N/A”. | Phase 1 flags low‑density images; reporting step writes “N/A” for that metric. |
