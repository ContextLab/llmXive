## Unresolved concerns

- The plan relies on a fully synthetic dataset to quantify the incremental predictive value of SNPs and MGE context for real bacterial antibiotic resistance. Synthetic genomes, SNP rates, and MGE distances are simulated rather than derived from empirical data, which threatens construct validity: the measured effect may not reflect true biological relationships, limiting the ability to answer the research question about real-world predictive value.
- In the Summary the nested CV is described as “nested 5‑fold outer / inner CV”, but Phase‑3 states an “inner 3‑fold CV”. This inconsistency leaves the cross‑validation protocol ambiguous, risking data leakage or insufficient hyper‑parameter tuning.
- The plan implements a paired McNemar test for model comparison, yet the specification (FR‑012) explicitly requires a two‑sided Wilcoxon signed‑rank test on paired predicted probabilities. This mismatch means the statistical test does not align with the documented requirement and may not measure the intended performance difference.
- The power analysis computes required N ≈ 1 400 for effect size = 0.1, yet the synthetic dataset contains only 200 isolates per species‑antibiotic pair, yielding ≈ 0.30 power. The plan proceeds with modeling despite this severe under‑power, only logging a warning. Running under‑powered analyses without a clear decision rule (e.g., abort or adjust effect size) risks producing unreliable effect estimates.
- Confounder assessment is described as “including them as covariates in the mixed‑effects model or performing stratified analyses”, but the implementation details (e.g., how geography, date, platform are encoded, whether they are entered into the permutation‑importance step) are missing. Without explicit modeling, confounding may remain uncontrolled.
- Functional Requirement FR‑018 (computational feasibility against GitHub Actions free‑tier constraints) is not explicitly linked to any phase in the mapping table. Although the summary mentions compute feasibility, the spec‑to‑plan traceability matrix does not list FR‑018, leaving reviewers without a concrete task to verify this requirement.
- Functional Requirement FR‑019 (report the sensitivity of the decision threshold by providing false‑positive and false‑negative rates for each threshold {0.3, 0.5, 0.7}) is absent from the mapping. The plan only references FR‑007 (threshold sweep) but does not map FR‑019, which is a distinct requirement.
- Success Criterion SC‑003 (computational feasibility measured against free‑tier limits) is not mapped to any phase. The plan’s “Compute Feasibility” paragraph mentions the limits, but the traceability table does not list SC‑003, so there is no explicit verification step.
- Phase 9 (Contract Validation) has no corresponding FR or SC in the specification. While contract validation is useful, it is not required by the spec and should be either anchored to an existing requirement (e.g., FR‑014 or a new FR) or removed to avoid over‑reach.
- The plan states that *no verified public dataset provides the required variable set* and therefore uses a fully synthetic dataset (see “Data Availability & Scope Adjustment” section). This directly conflicts with functional requirement FR‑001, which mandates downloading and preprocessing a subset of real *E. coli* and *S. aureus* genomes with associated phenotypic AST data from NCBI and CARD. Using a synthetic dataset does not satisfy the requirement to evaluate predictive value on real public genomic data, making the chosen data resource inappropriate for the research question.
- The plan states that `stats_validation.py --mcnemar` performs a **McNemar test** on paired classification outcomes, explicitly *replacing* the originally required Wilcoxon signed‑rank test (FR‑012). This contradicts the functional requirement FR‑012 in the spec, which mandates a two‑sided Wilcoxon signed‑rank test on paired predicted probabilities.
- The plan generates SNP counts and MGE distance features *synthetically* (“SNPs are simulated to reflect realistic mutation rates; MGE distances are generated analytically”) rather than using the mandated `snp-sites` pipeline, CARD API, and explicit genomic distance calculations required by Constitution Principle VI (Genomic Variant Rigor). This violates the required variant‑calling methodology.
- The core research question asks whether SNP counts and MGE proximity provide *incremental predictive value* for real bacterial antibiotic resistance. The plan evaluates this claim using a fully synthetic dataset that is generated deterministically to “mimic the structure of real NCBI Pathogen Browser and CARD data”. Because the synthetic phenotype‑genotype relationships are defined by the data‑generation script, any observed improvement of the integrated model over the baseline is guaranteed (or pre‑determined) by the simulation design rather than reflecting an independent biological signal. This makes the validation target (model performance on the synthetic data) *not independent* of the predictors, resulting in a circular/tautological validation of the hypothesis.
