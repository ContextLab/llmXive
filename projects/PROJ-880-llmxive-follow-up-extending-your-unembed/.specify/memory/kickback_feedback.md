## Unresolved concerns

- The plan falls back to RedPajama language‑filtered splits as a proxy for French/Chinese corpora because verified Common Crawl URLs are missing. This proxy may not reflect true language‑specific token frequency distributions, threatening construct validity of the ‘mean embedding’ and token‑frequency centroid measurements.
- Subspace similarity is compared across three models (Llama‑3, Mistral, BLOOM) that differ in architecture, training data, and token vocabularies. Without controlling for these model‑level confounds, any observed cross‑lingual shift could be driven by model differences rather than linguistic typology.
- Correlation with WALS features and SentEval performance is performed on only three languages (English, French, Chinese). This yields at most three data points for each correlation, providing insufficient statistical power to draw reliable inferential conclusions.
- The permutation test uses a fixed 1 000 iterations and a within‑language null distribution. Given the small effect sizes expected and the limited number of language/model pairs, 1 000 draws may not yield a stable p‑value, and the null does not account for model‑specific variability, limiting the test’s ability to substantiate the claimed shift.
- The plan lists WALS and Multilingual SentEval as external validation datasets but marks their URLs as **not verified** (e.g., “Download WALS CSV (public URL – **not verified**, flagged).”). This violates the constitution’s Verified Accuracy principle and leaves the validation step dependent on unverified data, risking an incomplete or invalid answer to the research question.
- Phase 2 states the JSON report is saved to `results/subspace_similarity.json`, but `data-model.md` defines this artifact as `data/derived/subspace_similarity.json`. The path mismatch breaks the single source of truth between design documents.
- Phase 3 writes `results/token_attribution_{model}.json`, whereas the data model lists `data/derived/token_attribution_{model}.json`. Paths are inconsistent.
- Phase 4 stores `results/validation.json`, but the data model records this artifact as `data/derived/validation.json`. This divergence violates the data‑model ↔ plan alignment.
- Phase 5 outputs `results/permutation_test.json`; the data model expects `data/derived/permutation_test.json`. Paths do not match.
- The plan flags missing verified URLs for Common Crawl subsets, WALS, and SentEval, yet Principle II of the constitution requires every external citation to be verified. Including unverified data sources violates the constitution.
- The plan only references `contracts/similarity_report.schema.yaml` (final report). Several other contracts (e.g., `edge_spectrum.schema.yaml`, `feasibility_report.schema.yaml`, `frequency_list.schema.yaml`, `similarity_matrix.schema.yaml`, `similarity_metric.schema.yaml`) are defined but never exercised by any plan phase, leaving them orphaned.
- The contract `edge_spectrum.schema.yaml` expects a JSON object with `model_pairs` and `similarity_matrix`. The plan’s Phase 2 description only mentions a simple list of cosine similarities without specifying the required structure, so the contract may not be satisfied.
- The validation step correlates the subspace shift vector with WALS typological differences and Multilingual SentEval performance drops using Pearson correlation, but only three language points (English, French, Chinese) are available. Pearson correlation with n=3 provides no meaningful statistical power, making the claimed validation non‑robust and effectively circular because the shift is derived from language‑specific data.
- Cosine similarity between edge‑spectrum bases is reported as a single scalar per model pair without reporting confidence intervals or accounting for variability due to the stochastic SVD initialization; this may overstate precision of the metric.
- The table notes “WALS CSV (public URL – **not verified**, flagged)” and “Multilingual SentEval STS results (public repo – **not verified**, flagged)”. The plan proceeds with validation despite these datasets being unverified, which could lead to missing or inconsistent external references.
