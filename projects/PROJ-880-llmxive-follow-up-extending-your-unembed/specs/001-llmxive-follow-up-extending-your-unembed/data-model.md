# Data Model: llmXive follow-up: extending "Your UnEmbedding Matrix is Secretly a Feature Lens for Text Embeddings"

## Overview

This document defines the data structures, schemas, and flow for the project. All data is stored in `data/` with strict separation between raw and processed artifacts.

## Data Flow Diagram

1. **Raw Ingestion**:
   - `data/raw/redpajama_freqs.json` (Derived from streaming RedPajama)
   - `data/raw/oscar_fr_freqs.json` (Derived from streaming OSCAR)
   - `data/raw/oscar_zh_freqs.json` (Derived from streaming OSCAR)
   - `data/raw/wals_features.csv` (External typological data)
   - `data/raw/model_weights/` (Cached Hugging Face models)

2. **Processing**:
   - **Frequency Counting**: Raw text $\to$ Token ID counts $\to$ Normalized vector.
   - **Alignment**: Shared vocab $\to$ Procrustes Matrix $R$.
   - **SVD**: $W_U$ $\to$ Top-$k$ singular vectors ($U_{top}$).
   - **Projection**: Frequency vector + $W_E$ $\to$ Mean embedding $\hat{\vh}$.
   - **Similarity**: Aligned $U_{top}^{(A)}$ vs $U_{top}^{(B)}$ $\to$ Cosine matrix.
   - **Bootstrap**: Permute labels $\to$ Null distribution $\to$ p-value.

3. **Output Artifacts**:
   - `data/processed/similarity_report.json` (Geometric metrics)
   - `data/processed/token_attribution.json` (Top tokens per language)
   - `data/processed/permutation_result.json` (Bootstrap p-values)
   - `data/processed/wals_validation.json` (Correlation metrics)
   - `data/processed/spectrum_output.json` (SVD details)

## Entity Definitions

### Edge Spectrum Matrix
- **Type**: `numpy.ndarray` (float32)
- **Shape**: `(vocabulary_size, k)` where $k=100$.
- **Description**: The matrix of top-$k$ left singular vectors from the SVD of $W_U$.

### Mean Embedding Vector
- **Type**: `numpy.ndarray` (float32)
- **Shape**: `(embedding_dimension,)`
- **Description**: The centroid of the vocabulary weighted by frequency, projected onto $W_E$.

### Subspace Similarity Metric
- **Type**: `float`
- **Description**: The average cosine similarity between aligned singular vectors of two models.

### Permutation Null Distribution
- **Type**: `list[float]`
- **Description**: A list of similarity scores generated by permuting language labels.

### WALS Feature Vector
- **Type**: `numpy.ndarray` (float32 or int)
- **Shape**: `(num_features,)`
- **Description**: Binary or categorical vector representing typological properties.

### Procrustes Alignment Matrix
- **Type**: `numpy.ndarray` (float32)
- **Shape**: `(k, k)`
- **Description**: Orthogonal matrix $R$ aligning the target subspace to the reference subspace.

## Schema Definitions

The following JSON schemas define the structure of the output artifacts. These are validated by `tests/contract/test_schemas.py`.

### 1. Frequency List (`frequency_list.schema.yaml`)
Defines the raw frequency counts derived from OSCAR/RedPajama.

### 2. SVD Output (`svd_output.schema.yaml`)
Defines the output of the SVD extraction step.

### 3. Similarity Report (`similarity_report.schema.yaml`)
Defines the geometric comparison between model subspaces.

### 4. Token Attribution (`token_attribution.schema.yaml`)
Defines the ranked list of tokens and their weights within the edge spectrum.

### 5. Permutation Result (`permutation_result.schema.yaml`)
Defines the output of the label permutation statistical test.

### 6. WALS Validation (`wals_validation.schema.yaml`)
Defines the correlation results between the subspace rotation angle and typological features.

## Data Hygiene & Versioning

- **Checksums**: Every file in `data/raw` and `data/processed` is checksummed (SHA-256) and recorded in `data/checksums.txt`.
- **Immutability**: Raw data files are never modified. Derivations are written to new files (e.g., `freqs_en.json`, `freqs_fr.json`).
- **PII**: No personally identifying information is stored. Token IDs are anonymous.
- **Versioning**: Artifact hashes are recorded in `state/projects/PROJ-880-llmxive-follow-up-extending-your-unembed.yaml` by the pipeline (Phase 6).
