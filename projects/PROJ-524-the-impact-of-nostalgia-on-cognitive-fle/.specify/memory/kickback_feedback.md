## Unresolved concerns

- The plan assigns `stimulus_type` uniformly at random (seed 42) to archival WCST data. A randomly assigned predictor is, by construction, independent of the outcomes, so the planned Welch's tests have zero power to detect any nostalgia effect and cannot answer the spec's primary goal ('Determine if nostalgia induction improves cognitive flexibility'). The spec (§7 Data Feasibility Justification) explicitly mandates primary data collection under controlled nostalgia/neutral conditions; the plan abandons this without a spec change. A 'simulation' flag does not repair the design — it concedes the research question is unanswerable by this pipeline.
- SC-002 requires 'Bonferroni-corrected p ≤ 0.05 for at least one primary outcome when the effect is present.' With random stimulus assignment the true effect is exactly zero, so SC-002 is unsatisfiable by design; the plan's mapping claims it is 'Handled in analysis.run_welch_test()' but no mechanism (e.g., a validated synthetic effect injection for a positive-control arm) is specified that could ever demonstrate SC-002.
- The two 'verified' MMSE URLs (a `_timestamps.txt` from a Chlorophyll directory and an action-recognition JSONL) are unrelated to the Mini-Mental State Examination; they cannot 'illustrate MMSE distribution' and provide no construct validity for the MMSE covariate. Citing them as MMSE references is a construct-validity failure.
- Power analysis (d=0.5, 80% power → ~128/group) is presented as dictating subsampling of the real WCST pool, but no evidence is given that any open WCST dataset contains ≥256 participants aged ≥65 with the required columns (perseverative_errors, categories_completed, age, optional MMSE, plus education_years and gender for the adjusted OLS). If the pool is smaller or lacks covariates, the adjusted model silently degrades to 'covariates_missing' — the plan should state the actual dataset identity and its N/age range before committing to this design.
- 'Cohen's d computed from Welch's pooled variance' is internally contradictory: Welch's test deliberately does NOT assume equal variances, so a pooled-variance d is inconsistent with the test. The plan should specify a Welch-consistent effect size (e.g., Hedges' g with unpooled SD, or deltat) and its CI method.
- The plan includes a deterministic power analysis step (`ingestion.generate_sample_size()`) that is not required by any Functional Requirement (FR) or Success Criterion (SC) in the specification.
- The plan adds an OLS covariate‑adjustment step (`analysis.run_adjusted_model()`) which is not referenced by any FR or SC in the spec, representing an over‑reach beyond the documented requirements.
- "No open dataset contains the required stimulus manipulation; therefore the pipeline will: 1. Download a publicly available WCST outcome dataset (no stimulus label). 2. Assign a synthetic `stimulus_type` (“nostalgia” or “control”) uniformly at random (seed = 42) for demonstration only."
- The data model (data-model.md) defines required fields `education_years` and `gender` for the `Participant` entity, but the plan’s ingestion step does not describe how these covariates are populated. Either the source WCST dataset must contain them, or the ingestion script must synthesize them – this needs to be added to the plan.
- The `Stimulus` entity in the data model includes a `stimulus_id` that links a participant to a specific audio file. The plan only mentions verifying placeholder audio files via `manifest.json` but never creates or records a `stimulus_id` nor ties it to the `Participant` records. Add a step that generates/assigns `stimulus_id` and ensures the one‑to‑one relationship required by the model.
- Principle V (Versioning Discipline) requires that every artifact’s content hash be recorded in the project‑state YAML (`state/projects/...yaml`). The plan states that `utils` updates artifact hashes, but it does not explicitly say that the state file is written/updated. Clarify that the hash is persisted to the state YAML after each write.
- The plan states it will compute “Cohen’s d with 95 % CI (bias‑corrected, consistent with Welch’s test)”. Cohen’s d traditionally uses a pooled standard deviation, which assumes equal variances—contradicting the Welch’s t‑test that explicitly allows unequal variances. For methodological consistency the effect‑size should be calculated using a variance‑unbiased estimator (e.g., Hedges’ g or Welch‑compatible d) or the pooled SD should be justified. This mismatch may bias the reported effect size and its confidence interval.
