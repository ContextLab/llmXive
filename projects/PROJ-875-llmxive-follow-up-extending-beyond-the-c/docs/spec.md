# Project Specification: llmXive Follow-up - Extending Beyond the Current Observation

## Project Overview
This project evaluates the ability of Multimodal Large Language Models (MLLMs) to maintain a coherent internal state ("mental map") of a dynamic environment beyond the current observation frame. We compare a text-only agent (processing ASCII representations) against a vision-capable baseline (processing raw visual frames) to quantify the "Memory Gap."

## User Stories
- **US1**: Renderer generates consistent ASCII grids and visual frames with event logs.
- **US2**: Text Agent and Baseline Agent process inputs and generate structured mental maps.
- **US3**: Scorer calculates the Memory Gap metric using structured comparison and semantic similarity.

## Functional Requirements

### FR-001: Event Logging
The renderer must generate a JSON event log for every time step, capturing state transitions.

### FR-002: Text Agent Constraints
The text agent must use a quantized LLM (≤3B params) optimized for CPU execution.

### FR-006: Metric Definition (UPDATED)
**Original Requirement**: Calculate a scalar score representing the difference between the agent's mental map and the ground truth.
**Plan Override**: The metric is now defined as a **Structured JSON Comparison + Semantic Similarity** score, explicitly designed to measure state retention while penalizing missing critical items.

**New Metric Definition**:
The "Memory Gap" score ($S$) is calculated as:
$$ S = (1 - \text{SemanticSimilarity}(\text{AgentMap}, \text{GroundTruth})) + (\text{Penalty} \times \text{MissingCriticalItems}) $$

Where:
1. **SemanticSimilarity**: Computed using `sentence-transformers/all-MiniLM-L6-v2` on the string representation of the mental maps.
2. **MissingCriticalItems**: The count of critical items (keys, doors) present in the `masked_ground_truth` but absent in the `agent_mental_map`.
3. **Penalty**: A fixed scalar of `1.0` per missing critical item.

*Note: This deviation from a raw Levenshtein distance approach is ratified as a Plan Override to better capture semantic understanding of the environment state.*

### FR-007: Hidden State Masking
The system must mask critical items in the ground truth provided to the agent, ensuring the agent must infer their existence from context or memory.

### FR-008: Baseline Input Modality (UPDATED)
**Original Requirement**: Baseline agent processes text descriptions.
**Plan Override**: The Baseline agent shall process **Visual Inputs** (raw frames) to establish a vision-capable performance ceiling.

**New Baseline Strategy**:
- The baseline agent (`code/baseline_runner.py`) utilizes a Vision-Language Model (e.g., Qwen-VL-Chat-Int4).
- Input: Raw image frames (PNG) generated by the renderer.
- Output: Structured JSON mental map matching the schema of the Text Agent.
- Comparison: The baseline's output is compared against the *same masked ground truth* used for the Text Agent to ensure a fair, modality-isolated comparison.

## Data Contracts
- **State Snapshot**: Defined in `specs/contracts/state_snapshot.schema.yaml` (fields: `ascii_grid`, `event_log`, `ground_truth_state`, `masked_ground_truth`).
- **Metric Result**: Defined in `specs/contracts/metric_result.schema.yaml` (fields: `memory_gap_score`, `p_value`, `confidence_interval`, `run_id`).

## Execution Workflow
1. **Data Generation**: Run `code/renderer.py` to produce ASCII grids, event logs, and visual frames.
2. **Validation**: Run `utils/renderer_validator.py` to ensure ASCII/Visual consistency (Levenshtein distance = 0).
3. **Agent Execution**:
 - Text Agent: `code/agent_loop.py` processes ASCII/Logs.
 - Baseline Agent: `code/baseline_runner.py` processes Visual Frames.
4. **Scoring**: `code/scorer.py` computes Memory Gap using the Structured Metric (FR-006 Override).
5. **Analysis**: `code/stats.py` performs Mann-Whitney U tests on the scores.
