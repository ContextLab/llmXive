# Implementation Plan: Predicting the Impact of Residual Stress on Fatigue Life Using Public Datasets

**Branch**: `001-predict-residual-stress-fatigue` | **Date**: 2026-10-18 | **Spec**: [spec.md](../specs/001-predict-residual-stress-fatigue/spec.md)
**Input**: Feature specification from `/specs/001-predict-residual-stress-fatigue/spec.md`

## Summary
The pipeline will (1) verify the CI environment, (2) load the repo-bundled pipeline-verification CSV and the deterministic synthetic validation dataset, (3) harmonize them into a unified schema, (4) compute a residual-stress proxy for **all** rows (independently of whether a measured value exists), (5) construct Feature Sets A and B on an **identical balanced subset** of measured-stress rows and Feature Set C on the full dataset, (6) train Random Forest, Gradient Boosting, and a shallow neural network with 5-fold CV and a held-out test set, (7) compare predictive gains using a **Wilcoxon signed-rank test** and a **≥10 % MAPE improvement** threshold, (8) evaluate cross-material transfer performance with permutation testing, (9) conditionally run bootstrap mediation analysis **only when ≥50 measured-stress rows** are available (per FR-013) with an explicit under-power warning band, (10) report proxy–measured agreement descriptively with an explicit circularity caveat, (11) generate reproducible reports. All steps run on CPU within GitHub Actions free-tier limits.

**Scope limitation (flagged for spec kickback)**: No verified open dataset provides measured residual stress together with fatigue life, process parameters, and material class, and the previously considered NIST/UCI sources were verified as unrelated to materials engineering. FR-001's requirement to "ingest data from NIST, UCI, and OpenML repositories" is therefore **partially unmet**: the plan implements FR-001's schema-unification, CSV/JSON parsing, unit-standardization, and imputation requirements against the repo-bundled verification CSV and the synthetic dataset, but repository ingestion from NIST/UCI/OpenML cannot be performed against verified suitable sources. The spec (FR-001 and US-1) should be revised to reflect this verified unavailability. All conclusions depending on measured residual stress are based on synthetic data and are labeled "synthetic validation — pipeline validation only, not an external scientific claim".

## Detailed Phases & FR/SC Coverage

| Phase | Description | FR(s) addressed | SC(s) addressed |
|-------|-------------|-----------------|-----------------|
| **0. Preliminary Environment Check** | Run `scripts/env_check.sh` to verify Python version, required packages, and available disk/RAM. Fails fast if the CI runner cannot meet the resource budget. | — | SC-005 |
| **1. Data Ingestion & Preprocessing** | • Load the repo-bundled `data/raw/pipeline_verification.csv` (known unit inconsistencies and missing values) and the deterministic synthetic validation dataset (`data/raw/synthetic_fatigue.csv`, generated from seed 42; see research.md). **Note (spec gap)**: FR-001's NIST/UCI/OpenML repository ingestion is NOT performed — no verified suitable source exists in those repositories; this gap is flagged for spec kickback (see Summary).<br>• Compute SHA-256 checksum for every raw file; store under `data/raw/` and embed a `checksum` column.<br>• Convert all stress values to MPa (`1 psi = 0.00689476 MPa`).<br>• Median-impute missing numeric values (FR-002).<br>• **Proxy Computation**: Compute `σ_res = k·heat_input·cooling_rate` for **all rows** (`k=0.8` for steel, `k=0.6` for aluminum), independently of whether a measured value exists. Set `is_proxy=True` for rows where the proxy is used **instead of** a measured value; otherwise `is_proxy=False`. Clamp negative proxy values to 0.01 MPa and log adjustments. Because the proxy is computed for all rows, rows with both measured and proxy values exist, making the FR-014 agreement computation feasible.<br>• **Proxy–Measured Agreement (FR-014)**: Compute Pearson's r and R² between proxy and measured stress on rows where both exist. **This is a descriptive agreement check only, NOT an independent validation**: the proxy is a deterministic function of the same process parameters used as predictors, so the comparison is inherently circular. Report the metrics with this caveat and a bias/limitations discussion, per FR-014.<br>• Validate the unified CSV against `contracts/dataset_schema.yaml`; abort on failure.<br>• Fixed random seed `SEED=42`. | FR-001 (partial: schema/parsing/unification only — repository ingestion unmet, spec gap flagged), FR-002, FR-003, FR-010, FR-012, FR-014 | SC-005 |
| **2. Feature-Set Construction (Balanced Subsets)** | • **Feature Sets A and B** are built on the **identical balanced subset** of rows with measured residual stress (`is_proxy=False`), so paired A-vs-B comparisons isolate the stress feature's contribution with equal sample sizes:<br>  – **Feature Set A – Process-only** (process parameters).<br>  – **Feature Set B – Process + Measured Stress** (A + `residual_stress_measured`).<br>• **Feature Set C** uses the **full dataset** (including proxy rows) because the proxy is required (FR-003, FR-012). **C is never compared head-to-head with A or B via paired tests** — C is reported descriptively with explicit sample-size disclosure; any A-vs-C contrast is unpaired and annotated with the differing row sets. | FR-003, FR-012 (schema continuity with FR-001) | — |
| **3. Model Training & Hyper-parameter Search** | For each algorithm (Random Forest, Gradient Boosting, shallow NN):<br>• Define a grid of 10 hyper-parameter combos.<br>• Perform 5-fold CV stratified by `material_class` on the **balanced subset** (A and B) and on the full dataset (C).<br>• Record MAPE and R² per fold.<br>• Select combo with lowest mean CV-MAPE.<br>• Retrain on the full training split and persist the best model per feature set. | FR-004, FR-005, FR-010 | SC-002, SC-005 |
| **4. Held-out Test Evaluation** | Split the **balanced subset** into a held-out test set (stratified by material) using seed 42; compute MAPE & R² for each saved model on the test set. | FR-005, FR-010 | SC-002, SC-005 |
| **5. Wilcoxon Signed-Rank Tests & Improvement Threshold** | • Compute absolute errors for Model A vs. Model B **only on the measured-stress subset** (`is_proxy=False`) — identical rows for both models.<br>• Run the **Wilcoxon signed-rank test** (non-parametric, per FR-008) per algorithm family; no paired t-test is used.<br>• Apply **Bonferroni correction** across the three families (α = 0.05/3).<br>• **Improvement Criterion (Principle VII)**: Report a model as meaningfully improved only if its MAPE is **≥10 % lower** than the baseline, demonstrated on the held-out test set together with the paired Wilcoxon result. | FR-008, FR-010 | SC-003, SC-005 |
| **6. Cross-Material Transfer Evaluation** | Train each model on steel-only data, test on aluminum-only data, and vice-versa; compute ΔMAPE relative to the within-material baseline.<br>• Assess significance using a **permutation test** (10 000 permutations, α = 0.05, Holm-Bonferroni across material pairs). | FR-009, FR-011, FR-010 | SC-004, SC-005 |
| **7. Mediation Analysis (Conditional, Associational Framing)** | • **Eligibility**: Proceed only if rows with `is_proxy=False` **≥ 50** (the operational threshold mandated by FR-013). If the count falls in the **50–63 under-power band**, the report flags the mediation estimate as potentially under-powered (elevated Type II error risk, unstable indirect-effect estimates) and widens the interpretation caveat; if < 50, log a warning and skip.<br>• **Model Specification**: Linear models for the **a-path** (process → residual stress) and **b-path** (residual stress → fatigue life) controlling for `heat_input`, `cooling_rate`, `elastic_modulus`, `yield_strength`, `material_class`, and other numeric process parameters.<br>• Compute VIF for each predictor; flag any > 5.<br>• Run **bootstrap mediation** with 10 000 resamples.<br>• Apply **Holm-Bonferroni** correction across material classes.<br>• **Causal Framing (mandatory)**: The data are observational/synthetic with **no causal identification strategy** (no randomization, no instruments). Mediation inherently assumes a causal pathway that these data cannot license; therefore all indirect-effect results are reported strictly as **associational** and labeled "associational — no causal identification" in `mediation_summary.csv`, the figures, and the final report. No causal interpretation is offered.<br>• **Synthetic-data caveat**: When mediation runs on the synthetic validation dataset, outputs are additionally labeled "pipeline validation only — synthetic data, not an external scientific claim". The research question cannot be answered with real measured residual stress from open data; this scope limitation is stated in the final report.<br>• Save `mediation_summary.csv` and generate PNG effect-size plots. | FR-006, FR-007, FR-010, FR-012, FR-013 | SC-001, SC-003, SC-005 |
| **8. Reporting & Artifact Generation** | • Consolidate metrics into `results/reports/model_performance.csv`.<br>• Export Wilcoxon test results, cross-material ΔMAPE (with permutation p-values), proxy–measured agreement metrics (with circularity caveat), and mediation summary (if executed, with associational and synthetic-data labels).<br>• Generate PNG figures for performance curves, Wilcoxon distributions, and mediation effects.<br>• Produce `runtime_summary.csv` with wall-clock & memory usage per phase. | FR-001–FR-014 (traceability, with FR-001 partial-coverage annotation) | SC-001–SC-005 |
| **9. Edge-Case Logic** | • If no measured residual stress exists, set `proxy_dependent=True` in the final report and omit mediation.<br>• If any proxy calculation yields negative values, clamp to 0.01 MPa and log the adjustment.<br>• If total measured-stress rows < 50, raise a warning and skip mediation; if 50–63, proceed with the under-power warning (Phase 7). | FR-003, FR-006, FR-012, FR-013 | — |
