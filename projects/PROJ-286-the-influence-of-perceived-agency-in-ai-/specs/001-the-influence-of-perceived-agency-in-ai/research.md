# Research: The Influence of Perceived Agency in AI Interactions on Trust

## Executive Summary

This research plan validates the feasibility of testing the hypothesis: "Does increasing a user's perception of agency in their interactions with an AI assistant—even when illusory—increase trust in the AI's recommendations?" The study utilizes a between-subjects experimental design with three conditions (High Agency, Low Agency, Control). Data will be generated via a simulated participant interface (for pipeline validation) and analyzed using planned contrasts and robust sensitivity checks. All statistical methods are CPU-tractable and fit within the GitHub Actions free-tier constraints.

**Critical Distinction**: Simulated data validates the *pipeline*. Real human data is required to test the *causal hypothesis*.

## Theoretical Background

### Perceived Agency and Trust
The "illusion of control" is a well-documented psychological phenomenon where individuals overestimate their influence over outcomes. In Human-AI interaction, providing users with adjustable parameters (even if they do not alter the AI's output) may increase the perception of agency, thereby increasing trust (Lee & See, 2004). However, if the agency is perceived as "fake" or manipulative, it could backfire. This study isolates the *perception* of agency by manipulating the interface (sliders vs. static) while holding the AI's actual recommendation constant.

### Trust in Automation
Trust is operationalized using the **Trust in Automation Scale** (Lee & See, 2004). This scale measures the degree to which an operator trusts an automated system. The scale consists of multiple items rated on a Likert scale.

## Statistical Methodology

### Hypotheses
- **H1**: Trust scores in the High Agency condition will be significantly higher than in the Low Agency condition.
- **H2**: Trust scores in the (High + Low) conditions will be significantly higher than in the Control condition (testing the presence of an AI agent).

### Analysis Plan (Hierarchical Strategy)

1.  **Manipulation Check (Prerequisite)**:
    *   **Test**: One-way ANOVA on `Perceived_Agency_Score` by condition.
    *   **Decision**: If p > 0.05, halt analysis and report "Manipulation Failed". No Trust results are interpreted.
    *   **Rationale**: Ensures the independent variable was successfully manipulated.

2.  **Cognitive Load Control**:
    *   **Test**: One-way ANOVA on `Cognitive_Load_Score` by condition.
    *   **Action**: If significant, include `Cognitive_Load_Score` as a covariate in the main Trust analysis (ANCOVA).

3.  **Omnibus Test**:
    *   **Test**: One-way ANOVA (F-test) on `Trust_Score` by condition.
    *   **Decision**: If p > 0.05, report null result. Do not proceed to post-hoc tests.

4.  **Planned Contrasts (Conditional on Omnibus)**:
    *   **Method**: ANOVA with custom contrast coding (GLM) using `statsmodels`.
    *   **Contrast 1**: High vs. Low (Vector: [1, -1, 0]).
    *   **Contrast 2**: (High + Low) vs. Control (Vector: [0.5, 0.5, -1]).
    *   **Correction**: Holm-Bonferroni correction applied to the combined set of 5 tests (2 contrasts + 3 pairwise) to control family-wise error rate.

5.  **Pairwise Comparisons (Conditional on Omnibus)**:
    *   **Method**: Tukey HSD for pairwise comparisons.
    *   **Decision**: Performed if Omnibus is significant.
    *   **Correction**: Holm-Bonferroni correction applied to the combined set of 5 tests (2 contrasts + 3 pairwise).

6.  **Effect Size**:
    *   Cohen's d calculated for all significant pairwise comparisons.

7.  **Power Analysis**:
    *   Target: Power ≥ 0.80, α = 0.05, f = 0.25 (medium effect).
    *   Required N: Calculated pre-study (expected N estimated for 3 groups).

8.  **Sensitivity Analysis**:
    *   **Metric**: `Attention_Score` (continuous, 0-100, derived from 5 attention questions).
    *   **Thresholds**: Sweep, 80, 90, 95.
    *   **Justification**: Based on standard practice in online panel studies to balance data quality and sample size. The valid range is determined by the score derived from 5 items (0, 20, 40, 60, 80, 100).
    *   **Action**: Re-run primary analysis at each threshold and report variation in the primary outcome (High vs. Low difference).

## Compute Feasibility

-   **CPU-First**: All statistical operations (ANOVA, Tukey HSD, power calculation) are performed using `scipy.stats` and `statsmodels`. These are lightweight CPU operations.
-   **Memory**: The maximum dataset size (N=10,000) fits easily within 7 GB RAM.
-   **GPU**: Not required. No deep learning models are used.
-   **Time**: Full pipeline execution < 15 minutes.

## Decision/Rationale

| Decision | Rationale |
| :--- | :--- |
| **Simulated Data** | Ensures reproducibility and CI reliability. Real data collection is external to the code execution. |
| **Planned Contrasts via ANOVA** | Directly tests the specific hypotheses defined in the spec (FR-003) with proper error control using custom contrast vectors. |
| **Unified Holm-Bonferroni Correction** | Controls Type I error for the entire family of inferences (2 contrasts + 3 pairwise) without inflating error rates. |
| **Hierarchical Testing** | Prevents Type I error inflation by conditioning post-hoc tests on significant omnibus results. |
| **Sensitivity Sweep** | Addresses the robustness requirement (FR-006) by verifying results are not driven by arbitrary exclusion thresholds. |
| **CPU Execution** | Aligns with the GitHub Actions free-tier constraints. No GPU is needed for classical statistics. |
