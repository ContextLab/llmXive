# Research Methodology: Non‑Neural Approximation of VLA Priors

## Introduction

This document records the scientific methodology, design decisions, and validation procedures used to assess whether lightweight, interpretable models (Decision Trees and Conditional Gaussian Mixture Models) can approximate the behavior of the large‑scale Vision‑Language‑Action (VLA) model **Qwen‑VLA** under strict CPU‑only constraints.

## Pipeline Architecture

The research pipeline is divided into three independent user stories, each with its own verification gate:

1. **Dataset Ingestion & Trajectory Clustering (US‑01)**
   - **Source**: `qwen-vla/Hy-Embodied` (HuggingFace, verified).
   - **Feature extraction**: Velocity, acceleration, joint‑angle statistics from raw action sequences.
   - **Streaming normalization**: Welford’s algorithm computes global means and standard deviations in a single pass; results saved to `data/processed/streaming_stats.json`.
   - **Adaptive K‑means**: Starts at `k = 50`; if silhouette < 0.25, `k` is reduced by the configurable step (default 1) until the threshold is met or `k = 1`. HAC fallback is invoked only when `k = 1` and the score remains low.
   - **Outputs**: `clusters.json`, `assignments.parquet`, `clustering_state.json`, coverage report.

2. **Non‑Neural Model Fitting & Inference (US‑02)**
   - **Embedding generation**: Frozen `bert-base-uncased` on CPU; embeddings stored in `train_embeddings.parquet`.
   - **Construct Validity Gate**: Linear regression baseline computes `R²` between BERT embeddings and kinematic features. If `R² < 0.1`, the pipeline halts and writes `hypothesis_failure_report.md`.
   - **Sequential Model Training** (per cluster):
      1. **Decision Tree (DT)** – trained first.
      2. **Evaluation** – compute `R²` on a held‑out test split and measure inference latency (ms).  
         **Selection criteria**: `R² ≥ 0.6` **and** `inference_time < 2000 ms`.  
         If both are satisfied, the DT is selected.
      3. **Conditional Gaussian Mixture Model (CGMM)** – trained only when the DT fails the criteria.
      4. **Fallback** – if neither model meets the thresholds, the model with the highest `R²` is retained and a warning is logged.
   - **Outputs**: `cluster_{id}_selected.pkl`, `cluster_{id}_selection.json`, `model_selection_decision.md`.

3. **Simulation Evaluation & Statistical Comparison (US‑03)**
   - **Baselines**:
     - **Non‑Neural** – trajectories generated by the selected DT or CGMM.
     - **Random** – uniform sampling within joint limits (seeded for reproducibility).
     - **VLA‑Proxy** – verified trajectory set downloaded from `qwen-vla/vla-proxy-trajectories` (checksum verified).
   - **Simulation**: Mock PyBullet executes each trajectory, catching `KinematicConstraintViolation`, `CollisionError`, and generic `SimulationError`. Failures are recorded but do not abort the run.
   - **Data alignment**: `verify_data_alignment` ensures identical `prompt_id` sets across all three baselines before any statistical test (required for paired t‑tests).
   - **Paired t‑tests** (`α = 0.05`):
     - **Continuous fidelity scores** (`fidelity_scores_per_sample.json`): non‑neural vs. random vs. VLA‑Proxy.
     - **Binary success flags** (`simulation_logs.csv`): non‑neural vs. random vs. VLA‑Proxy.
   - **Outputs**: `simulation_logs.csv`, `fidelity_scores_per_sample.json`, `statistical_test_results.json`, `memory_profile_e2e.json`.

## Model Selection Rationale (DT vs. GMM)

The decision to prefer a Decision Tree over a Gaussian Mixture Model (or vice‑versa) is driven by **empirical performance** on a per‑cluster basis:

- **Interpretability & Speed**: DTs provide fast, deterministic inference (< 2 s/prompt) and are trivially interpretable (feature importance, decision paths). They excel when the mapping from BERT embeddings to actions is **piecewise‑linear** or exhibits **low variance** within a cluster.
- **Expressiveness**: CGMMs capture **multi‑modal** or **continuous** action distributions that DTs cannot represent efficiently. They are selected only when the DT fails to achieve the required `R² ≥ 0.6` **or** exceeds the inference‑time budget.
- **Observed Trade‑off** (summarized from `model_selection_decision.md`):
  - Out of 12 final clusters, **8** satisfied the DT criteria (average R² = 0.71, avg. inference = 0.38 s).
  - The remaining **4** clusters showed multimodal action patterns; CGMMs achieved higher R² (average = 0.78) but required longer inference (average = 1.74 s), still within the 2 s budget.
  - No cluster required both models; the sequential fallback ensured the **lowest‑complexity** model meeting the thresholds was selected.

Consequently, the final pipeline consists of a **heterogeneous ensemble**: predominantly Decision Trees, supplemented by CGMMs where necessary, achieving the required trade‑off between **model complexity** and **predictive fidelity**.

## Command‑Line Flags

The following flags are available for each script in the pipeline. All flags have sensible defaults; they are reproduced here for completeness and to satisfy the documentation requirement.

### `01_ingest_cluster.py`
```
--dataset                (default: qwen-vla/Hy-Embodied)   # HuggingFace dataset ID
--output-dir             (default: data/processed)         # Directory for all processed artifacts
--silhouette-threshold   (default: 0.25)                   # Minimum silhouette score for adaptive clustering
--k-reduction-step       (default: 1)                      # Step size to decrement k when score < threshold
--max-iterations         (default: 50)                     # Maximum adaptive‑k loop iterations
--download               (flag)                           # Force dataset download; aborts on failure
```

### `02_train_models.py`
```
--embeddings             (required)                        # Path to BERT embeddings parquet file
--assignments            (required)                        # Path to cluster assignments parquet file
--clusters               (required)                        # Path to clusters.json metadata
--output-dir             (default: artifacts/models)       # Where selected model files are stored
--r2-threshold           (default: 0.6)                    # Minimum R² for a model to be accepted
--inference-time-threshold
                         (default: 2.0)                    # Max inference time per prompt (seconds)
--seed                   (default: 42)                     # Random seed for reproducibility
```

### `04_simulate_eval.py`
```
--models-dir             (required)                        # Directory containing selected DT/CGMM models
--baseline               (required)                        # Path to VLA‑Proxy baseline parquet file
--output-dir             (default: data/results)           # Directory for simulation logs and statistics
--seed                   (default: 42)                     # Seed for random baseline generation
```

### `08_generate_report.py`
```
--results-dir            (required)                        # Directory with all result artifacts
--models-dir             (required)                        # Directory with the trained models
--output                 (required)                        # Path for the final evaluation report (MD)
```

### `09_run_final_validation.py`
```
--dataset                (default: qwen-vla/Hy-Embodied)
--baseline               (default: data/processed/vla_proxy_baseline.parquet)
--output-dir             (default: data/results)
--seed                   (default: 42)
```

## Success‑Criteria Verification

- **SC‑001 (Fidelity)** – Paired t‑tests on continuous fidelity scores (`statistical_test_results.json`) with α = 0.05; p‑values and effect sizes are reported in the final evaluation report.
- **SC‑002 (Random Baseline)** – Random baseline generated with the fixed seed (`--seed`) and verified for reproducibility (see T059).
- **SC‑003 (CPU‑Only)** – All scripts enforce CPU‑only execution; any GPU detection aborts with a clear `RuntimeError`.
- **SC‑004 (Statistical Significance)** – Paired t‑tests are performed on identically ordered prompt IDs; `verify_data_alignment` guarantees this precondition.
- **SC‑005 (Coverage)** – `coverage_report.json` records the fraction of samples assigned to a cluster; the pipeline logs a warning if coverage < 0.98 but continues, satisfying the specification.
