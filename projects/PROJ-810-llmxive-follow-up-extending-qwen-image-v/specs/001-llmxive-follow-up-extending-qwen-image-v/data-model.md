# Data Model: llmXive follow-up: extending "Qwen-Image-VAE-2.0 Technical Report"

## Overview
All persistent artifacts exchanged between pipeline stages are defined as JSON‑serializable objects stored under `data/`. Validation is performed against the JSON‑Schema contracts in `contracts/`. The entities directly correspond to the phases in the implementation plan.

## Entity Definitions

### 1. RawImageCrop
- **Description**: Cropped region extracted from a source document using ground‑truth bounding boxes.
- **Fields**:
  - `image_id` (string): Identifier of the source document image.
  - `crop_id` (string): Unique identifier for the crop.
  - `modality` (string, enum: `"text"`, `"image"`): Ground‑truth label.
  - `bbox` (array of 4 numbers): `[x1, y1, x2, y2]`.
  - `pixels` (object): Reference to a NumPy file (`format: "numpy"`; includes `shape` array).
  - `confounders` (object, optional):  
    - `overlap_ratio` (number, 0‑1) – proportion of mixed‑modality area.  
    - `ocr_confidence` (number, 0‑1) – mean OCR confidence for the crop.  
    - `size_category` (string, enum: `"small"`, `"medium"`, `"large"`).

### 2. LatentVector
- **Description**: High‑dimensional encoding produced by the **tiny‑vae** encoder (CPU‑compatible fallback for Qwen‑Image‑VAE‑2.0).
- **Fields**:
  - `latent_id` (string): Unique identifier.
  - `crop_id` (string): Links back to `RawImageCrop`.
  - `vector` (array of numbers): Float32 latent representation.
  - `modality` (string, enum: `"text"`, `"image"`).
  - `encoder_version` (string): Model version tag (e.g., `"tiny-vae"` or `"Qwen-Image-VAE-2.0"` if the original model becomes available).

### 3. Centroid
- **Description**: Mean vector of a modality‑specific cluster.
- **Fields**:
  - `centroid_id` (string, enum: `"text_centroid"`, `"image_centroid"`).
  - `vector` (array of numbers).
  - `n_samples` (integer): Number of vectors aggregated.

### 4. EditedImage
- **Description**: Image generated by decoding a modified latent vector to swap text content.
- **Fields**:
  - `image_id` (string).
  - `source_crop_id` (string).
  - `pixels` (object, same structure as in `RawImageCrop`).
  - `operation` (string, enum: `"text_swap"`).
  - `baseline_image_id` (string): Identifier of the **original raw crop** used for layout comparison.

### 5. MetricResult
- **Description**: Single metric computation for a given test.
- **Fields**:
  - `metric_name` (string).
  - `value` (number).
  - `p_value` (number, nullable).
  - `is_significant` (boolean).
  - `metadata` (object, optional): e.g., `threshold`, `sample_size`, `confounder_info`.

## Data Flow
1. **Ingestion** → `RawImageCrop` (Phase 3).  
2. **Encoding** → `LatentVector` (Phase 4) using the **tiny‑vae** model.  
3. **Clustering / Centroid computation** → `Centroid` (Phase 8).  
4. **Editing** → `EditedImage` (Phase 9).  
5. **Evaluation** → `MetricResult` (Phases 5, 6, 9, 10).  

All intermediate files are stored as compressed NumPy (`.npz`) or JSON (`.json`) under `data/interim/` and `data/results/`. The final experiment output conforms to `contracts/output.schema.yaml`.
