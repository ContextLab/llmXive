# Data Model: llmXive follow-up: extending "Qwen-Image-VAE-2.0 Technical Report"

## Overview
This document defines the data structures used for the latent space analysis and editing pipeline. All data is derived from the OmniDoc-TokenBench dataset.

## Entity Definitions

### 1. Raw Image Crop
- **Description**: A cropped region from a document image, extracted using ground-truth bounding boxes.
- **Fields**:
  - `image_id`: Unique identifier for the source document.
  - `crop_id`: Unique identifier for the crop.
  - `modality`: "text" or "image" (ground-truth label).
  - `bbox`: `[x1, y1, x2, y2]` coordinates.
  - `pixels`: Numpy array (H, W, C).

### 2. LatentVector
- **Description**: The high-dimensional encoding of a `Raw Image Crop` produced by the Qwen-Image-VAE encoder.
- **Fields**:
  - `latent_id`: Unique identifier.
  - `crop_id`: Reference to the source crop.
  - `vector`: Float32 array of dimension D (model-specific).
  - `modality`: "text" or "image" (label used for training).

### 3. Centroid
- **Description**: The mean vector of a cluster of latent vectors.
- **Fields**:
  - `centroid_id`: "text_centroid" or "image_centroid".
  - `vector`: Float32 array of dimension D.
  - `n_samples`: Number of vectors used to compute the mean.

### 4. EditedImage
- **Description**: An image generated by decoding a modified latent vector.
- **Fields**:
  - `image_id`: Unique identifier.
  - `source_crop_id`: Reference to the original crop.
  - `pixels`: Numpy array (H, W, C).
  - `operation`: "text_swap".
  - `baseline_reconstruction_id`: Reference to the baseline image.

### 5. MetricResult
- **Description**: A record of a computed metric for a specific image or test.
- **Fields**:
  - `metric_name`: "accuracy", "f1", "ssim", "keypoint_score".
  - `value`: Float.
  - `p_value`: Float (if applicable).
  - `is_significant`: Boolean (after Bonferroni correction).
  - `metadata`: JSON object with test details.

## Data Flow

1. **Ingestion**: `Raw Image Crop` is created from `OmniDoc-TokenBench` parquet.
2. **Encoding**: `Raw Image Crop` -> `LatentVector`.
3. **Clustering**: `LatentVector` -> `Centroid`.
4. **Editing**: `LatentVector` + `Centroid` -> `EditedImage`.
5. **Evaluation**: `EditedImage` + `OriginalImage` -> `MetricResult`.

## Storage Strategy
- **Raw Data**: Stored in `data/raw/` (parquet).
- **Interim Data**: `LatentVector` and `EditedImage` stored in `data/interim/` as `.npy` or `.pt` files.
- **Results**: `MetricResult` stored in `data/results/metrics.json`.
- **Checksums**: All files in `data/` are checksummed (SHA-256) and recorded in `state/...yaml`.
