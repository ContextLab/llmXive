## Statistical Rigor

### Power Analysis (FR‑025)
A two‑sided binomial test detecting an inconsistency proportion of 0.10 with α = 0.05 and power ≥ 0.80 requires **N ≥ 300**. The pipeline computes the exact required N (Task T044) and aborts if the supplied corpus is smaller.

### Multiple‑Comparison Correction (FR‑032)
Subgroup analyses (by source domain and publication year) employ **Bonferroni correction**: adjusted α = 0.05 / `num_subgroups`. This controls family‑wise error rate across all Fisher exact tests.

### Baseline Handling (FR‑012)
When a baseline conversion rate is missing, the heuristic “average of the two variant rates” is used to reconstruct absolute effect size. The audit notes flag this heuristic and quantify the added uncertainty.

### Statistical Validation (FR‑026)
For each statistical routine (two‑proportion z/Fisher, Welch t, binomial), a Monte Carlo simulation with **10 000 replicates** is run (Task T062). **Independence Note:** The synthetic validation dataset used for this Monte Carlo validation is generated by `src/validation/synthetic_generator.py` using direct random draws (`numpy.random`) and closed‑form calculations (`scipy.stats`) **without** calling the reconstruction code from FR‑003, ensuring true independence of the ground truth. The absolute difference between the library result and the Monte Carlo estimate must be **≤ 0.005** (SC‑003, SC‑026).

### Consistency Threshold (Constitution VI)
The pipeline flags a summary as *inconsistent* if **|reported p – reconstructed p| > 0.05** (absolute floor). Relative or log‑scale thresholds are forbidden. Effect‑size inconsistency uses the [deferred] relative rule (FR‑004).

### Bias Adjustment (FR‑027)
Domain proportions are computed; any domain > 30 % triggers subsampling (Task T044). The bias‑adjusted prevalence is a domain‑weighted average, preventing dominance by any single source.

### Construct Validity Limitation
The audit assesses **internal statistical consistency** only; it cannot verify whether the reported numbers reflect the true underlying data. This limitation is explicit in the final report.

## Compute Feasibility

- **Libraries**: `scipy`, `statsmodels`, `pandas`, `numpy` – all CPU‑optimized.  
- **Memory**: Synthetic set (a sizable number of rows) + audit corpus (≥ 300 rows) < 200 MB.  
- **Runtime**: Estimated total < 3 CPU‑hours; comfortably within the 6‑hour CI wall‑clock limit.  
- **GPU**: Not required; the plan contains no GPU‑only steps.

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| Dead or non‑HTML URLs | Logged with `ERR‑###` (FR‑007); excluded from aggregates; parsing‑error rate monitored (SC‑005). |
| Domain dominance | Subsampling when > 30 % (FR‑027); bias‑adjusted rate reported. |
| Extraction failures | Real‑world validation set ensures ≥ 85 % precision (SC‑031b). |
| Statistical implementation bugs | Monte Carlo validation (FR‑026) + independent synthetic generator (FR‑030). |
| Resource overrun | CI workflow aborts if memory > 2 GB or runtime > 6 h (SC‑008). |
| Baseline missing | Heuristic documented in notes; flagged for downstream reviewers (FR‑012). |
