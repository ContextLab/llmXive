# Specification: llmXive ALE Extension - Agents' Last Exam

## 1. Overview

This specification defines the extension of the llmXive project to analyze "Agents' Last Exam" (ALE) logs. The goal is to classify failure modes into "State Persistence Errors" and "Reasoning Deficits" and evaluate the efficacy of a context-checkpointing intervention.

## 2. Functional Requirements

### FR-001: Normalization Protocol
The system MUST normalize execution traces before comparison. This includes:
- Comparing floating-point values with a tolerance of 1e-6.
- Stripping timestamps and random IDs.
- Canonicalizing object references to a stable hash of their content.

### FR-002: Local LLM Classification
The system MUST use a local LLM (e.g., Llama-3-8B Q4_K_M) to classify failure modes. Classification MUST be deterministic (temperature=0).

### FR-003: Context Checkpointing
The system MUST implement a wrapper that forces state summary regeneration at a configurable interval N.

### FR-004: CPU-Only Execution
The system MUST run on CPU with a memory limit of 7GB and a timeout of 6 hours per task.

### FR-005: Statistical Significance
The system MUST use McNemar's test (not Mixed-Effects Logistic Regression) to assess statistical significance of the intervention.

### FR-006: Sensitivity Analysis
The system MUST report pass rates for N=1, N=3, and N=5 and calculate delta pass rates.

### FR-007: Deterministic Constraint Validation
The system MUST use a deterministic template matcher (regex-based) for validating task constraints, NOT an LLM.

### FR-008: Seed Pinning
Every random operation MUST use `seeds.get_seed(task_id)` to ensure reproducibility.

### FR-009: Ground Truth Proxy
The system MUST validate classification accuracy against a "human-annotated subset" or a ratified research proxy.

**Implementation Note for FR-009**:
Due to the unavailability of a real human-annotated dataset for this specific research prototype, the file `data/raw/golden_fixture.json` (generated by task T015c) serves as the ratified research proxy for the "human-annotated subset". This file contains 10 synthetic traces with hardcoded, deterministic ground truth labels (`ground_truth_label`) corresponding to the 5 "State Persistence Error" and 5 "Reasoning Deficit" scenarios defined in `code/data/generator_logic.py`. All downstream validation tasks (e.g., T013c) MUST compare their outputs against this specific file.

## 3. Assumptions

### Assumption 1: Synthetic Data Validity
The research assumes that the synthetic traces generated in `data/raw/golden_fixture.json` accurately model the failure modes of interest (State Persistence and Reasoning Deficits) sufficiently for the purpose of validating the classification pipeline and the checkpointing intervention. The ground truth labels in this file are treated as the "oracle" for the duration of this study.

### Assumption 2: Model Availability
The system assumes the availability of a quantized Llama-3-8B model (Q4_K_M) at the path specified in the configuration.

### Assumption 3: Resource Constraints
The system assumes a maximum RAM of 7GB and a per-task timeout of 6 hours.

## 4. Data Models

### ExecutionTrace
- `trace_id`: string
- `task_description`: string
- `steps`: list of StepState
- `final_state`: dict
- `ground_truth_label`: enum (StatePersistenceError, ReasoningDeficit, None)

### StepState
- `step_id`: integer
- `action`: string
- `state_snapshot`: dict
- `timestamp`: string (stripped during normalization)

## 5. Contracts

### Input/Output Paths
- Input: `data/raw/golden_fixture.json`
- Output: `data/processed/classification_report.json`, `data/processed/sensitivity_analysis.json`, `docs/report.md`
