# Specification: llmXive ALE Extension - Automated Failure Mode Classification

## 1. Overview
This document defines the requirements for extending the llmXive project to automatically classify failure modes in Agent Learning Environment (ALE) execution traces. The system aims to distinguish between "State Persistence Errors" (context loss) and "Reasoning Deficits" (logical errors) to guide targeted interventions.

## 2. Functional Requirements

### FR-001: Trace Parsing and Normalization
The system MUST parse raw ALE logs into structured execution traces.
It MUST normalize floating-point comparisons using a tolerance of 1e-6.
It MUST strip timestamps and random IDs to ensure deterministic comparison.
It MUST canonicalize object references using content-based hashing (SHA-256).

### FR-002: Failure Mode Classification
The system MUST classify each failure in a trace as either:
- "State Persistence Error"
- "Reasoning Deficit"
- "Pass" (if no failure detected)
Classification MUST be driven by a local LLM (e.g., Llama-3-8B) using semantic analysis.

### FR-003: Context Checkpointing
The system MUST implement a wrapper that forces state summary regeneration at a configurable interval N.

### FR-004: Resource Constraints
All interventions MUST run on CPU-only environments with a memory limit of 7GB RAM.
Quantization (Q4_K_M) MUST be used for model loading.

### FR-005: Statistical Validation
The system MUST use McNemar's test (not Mixed-Effects Logistic Regression) to validate the significance of intervention improvements over baseline.

### FR-006: Sensitivity Analysis
The system MUST report pass rates for checkpoint intervals N=1, N=3, and N=5.

### FR-007: Deterministic Goal Validation
The system MUST validate task goals using a deterministic regex-based template matcher, NOT an LLM.

### FR-008: Reproducibility
All random operations MUST use `seeds.get_seed(task_id)` to ensure deterministic replay.

### FR-009: Ground Truth Proxy
The system MUST utilize a static, ratifiable dataset for validation where human annotation is unavailable.
**Implementation Note**: The file `data/raw/golden_fixture.json` (generated by task T015c) serves as the ratified research proxy for the "human-annotated subset" required by this requirement. This fixture contains 10 synthetic traces with deterministic ground truth labels ("State Persistence Error", "Reasoning Deficit", "Pass") generated by the `generator_logic` module. The validation pipeline (T013c) compares classifier output against this specific file to compute accuracy, precision, recall, and F1 scores.

## 3. Assumptions

### Assumption 1: Synthetic Ground Truth
Due to the lack of a large, publicly available dataset of human-annotated ALE failure traces with specific "State Persistence" vs. "Reasoning Deficit" labels, the system relies on a synthetic "Golden Fixture" for validation.
**Ratification**: This assumption is ratified by the explicit generation of `data/raw/golden_fixture.json` via `code/data/generator.py` (Task T015b/T015c). The fixture is constructed using hardcoded scenario definitions (SP_01-SP_05, RD_01-RD_05) to ensure the ground truth is known and deterministic. This file is treated as the "Human-Annotated Subset" equivalent for the purpose of FR-009 validation.

### Assumption 2: Local LLM Availability
The execution environment has access to a quantized Llama-3-8B model (Q4_K_M) via `llama-cpp-python`.
