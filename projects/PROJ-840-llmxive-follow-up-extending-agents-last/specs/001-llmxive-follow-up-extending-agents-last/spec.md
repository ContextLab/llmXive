# Specification: llmXive ALE Extension (Agents' Last Exam)

## Overview
This document defines the requirements for extending the llmXive pipeline to analyze
"Agents' Last Exam" (ALE) execution traces, classify failure modes, and evaluate
context-checkpointing interventions.

## Functional Requirements

### FR-001: State Reconstruction Validation
The system must validate the agent's reconstructed state against a ground truth
reference.

### FR-002: Failure Mode Classification
The system must classify failures into "State Persistence Error" or "Reasoning Deficit"
using a local LLM with deterministic seed pinning.

### FR-003: Context Checkpointing
The system must implement a wrapper that regenerates state summaries at configurable
intervals.

### FR-004: Resource Constraints
All execution must remain within 7GB RAM and 6-hour time limits, using CPU-only
inference with quantized models.

### FR-005: Statistical Significance
The system must use McNemar's test for paired binary outcomes to evaluate
intervention efficacy.

### FR-006: Sensitivity Analysis
The system must report pass-rate deltas for different checkpoint intervals (N=1, 3, 5).

### FR-007: Deterministic Validation
Task goal validation must use deterministic regex-based template matching, not LLMs.

### FR-008: Seed Pinning
All random operations must use `seeds.get_seed(task_id)` for reproducibility.

### FR-009: Ground Truth Proxy
**Implementation Note**: Due to the unavailability of a human-annotated dataset for
the specific "Agents' Last Exam" scenarios in the current automated pipeline context,
the system utilizes a synthetic "golden fixture" as a ratified research proxy.
Specifically, the file `data/raw/golden_fixture.json` (generated by task T015c via
`code/data/generator.py`) serves as the ground truth reference for validation and
classification accuracy metrics. This file contains 10 strictly defined scenarios
(5 State Persistence Errors, 5 Reasoning Deficits) with deterministic labels.
The generation logic is hardcoded in `code/data/generator_logic.py` to ensure
reproducibility and eliminate the need for external human annotation in the
initial research phase. This approach is explicitly ratified for the purpose of
testing the classification and validation pipeline (US1) and statistical analysis (US3).

## Assumptions

1. **Data Availability**: The system assumes access to `data/raw/golden_fixture.json`
 as the ratified research proxy for the "human-annotated subset" required by FR-009.
 This file is generated deterministically by the project's own generator script
 (`code/data/generator.py`) and contains the exact 10 scenarios defined in the
 implementation plan. No external human-annotated dataset is required or used.

2. **Model Availability**: The system assumes a quantized LLM (e.g., `llama-3-8b-instruct.Q4_K_M.gguf`)
 is available at the configured model path.

3. **Environment**: Execution occurs in a CPU-constrained environment (7GB RAM limit).

## Non-Functional Requirements

- **Reproducibility**: All experiments must be reproducible via seed pinning.
- **Performance**: Inference must complete within the 6-hour limit per task batch.
- **Memory**: Peak memory usage must not exceed 7GB.

## Data Model

### ExecutionTrace
- `trace_id`: string
- `task_description`: string
- `steps`: list of StepState
- `final_state`: dict
- `ground_truth_label`: string (one of: "State Persistence Error", "Reasoning Deficit", "Pass")

### StepState
- `step_id`: integer
- `action`: string
- `state_snapshot`: dict
- `timestamp`: string (normalized)

## Evaluation Metrics

- **State Reconstruction Accuracy**: Percentage of steps where reconstructed state matches ground truth.
- **Classification Accuracy**: Percentage of failure modes correctly identified.
- **Pass Rate**: Percentage of tasks completed successfully.
- **Sensitivity Delta**: Difference in pass rates between baseline and intervention conditions.

## Implementation Notes

- **T015d**: This spec update explicitly ratifies `data/raw/golden_fixture.json` as the ground truth source,
 resolving the dependency on human annotation for the initial pipeline validation.
- **T012**: Uses deterministic regex matching for constraint validation (FR-007).
- **T026a**: Uses McNemar's test, overriding the initial Plan.md suggestion of Mixed-Effects Logistic Regression.
- **T011**: Normalization uses 1e-6 tolerance for floats and canonicalizes object references.
