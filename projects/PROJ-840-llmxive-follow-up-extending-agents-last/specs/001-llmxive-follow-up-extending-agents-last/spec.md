# Specification: llmXive ALE Extension - Agents' Last Exam
# Project ID: PROJ-840-llmxive-follow-up-extending-agents-last

## 1. Introduction

This document specifies the requirements for extending the llmXive pipeline to analyze the "Agents' Last Exam" (ALE) dataset. The goal is to classify failure modes in agent execution traces and evaluate the efficacy of context-checkpointing interventions.

## 2. Functional Requirements

### FR-001: Trace Parsing
The system MUST parse ALE execution logs to reconstruct environment states and agent actions.

### FR-002: Failure Classification
The system MUST classify failures into "State Persistence Error" or "Reasoning Deficit" using a local LLM with deterministic seeding.

### FR-003: Context Checkpointing
The system MUST implement a wrapper to regenerate state summaries at configurable intervals (N steps).

### FR-004: CPU-Only Execution
The system MUST run all inference tasks on CPU using quantized models (Q4_K_M) to ensure reproducibility in standard environments.

### FR-005: Statistical Significance
The system MUST use **McNemar's test** (not Mixed-Effects Logistic Regression) to determine the statistical significance of the intervention's effect on pass rates.

### FR-006: Sensitivity Analysis
The system MUST analyze pass rate sensitivity across different checkpoint intervals (N=1, N=3, N=5).

### FR-007: Deterministic Validation
The system MUST use a **deterministic template matcher** (regex-based) for extracting static constraints from task descriptions, NOT an LLM.

### FR-008: Seed Pinning
The system MUST pin random seeds for all stochastic operations to ensure reproducibility.

### FR-009: Ground Truth Proxy
The system MUST utilize a verified, static dataset as the ground truth for validation.

**Implementation Note**: Due to the unavailability of a pre-existing human-annotated subset of the ALE dataset, this project ratifies `data/raw/golden_fixture.json` (generated by task T015c) as the research proxy for the "human-annotated subset" required by this requirement. This file contains 10 synthetic traces with deterministic, rule-based `ground_truth_label` values (either "State Persistence Error" or "Reasoning Deficit") derived from the 5 "State Persistence Error" and 5 "Reasoning Deficit" scenarios defined in T015a. All downstream validation (T013c, T026a) compares system outputs against this ratified fixture.

## 3. Non-Functional Requirements

### NFR-001: Reproducibility
All experiments must be reproducible given the same seed and input data.

### NFR-002: Performance
Execution must complete within 6 hours on a standard CPU environment.

### NFR-003: Memory Constraints
Peak memory usage must not exceed 7GB.

## 4. Assumptions

1. **Data Availability**: The project assumes that `data/raw/golden_fixture.json` (generated by T015c) serves as the ratified research proxy for the "human-annotated subset" required by FR-009. This assumption replaces the original requirement for a human-labeled dataset, as the generated fixture provides a deterministic, verifiable ground truth for the specific failure modes under investigation.
2. **Model Availability**: The system assumes access to a quantized LLM (e.g., Llama-3-8b-instruct.Q4_K_M.gguf) or a compatible local inference engine.
3. **Environment**: The system assumes a standard Linux environment with Python 3.10+ and necessary dependencies installed.

## 5. Data Model

### ExecutionTrace
- `trace_id`: string (UUID)
- `task_description`: string
- `steps`: list of `StepState`
- `final_state`: `StateSnapshot`
- `ground_truth_label`: enum ("State Persistence Error", "Reasoning Deficit", "Pass")

### StepState
- `step_index`: integer
- `action`: string
- `state_before`: `StateSnapshot`
- `state_after`: `StateSnapshot`

### StateSnapshot
- `file_tree`: dictionary (path -> content_hash)
- `variables`: dictionary (name -> value_hash)

## 6. Acceptance Criteria

1. The system successfully parses a set of ALE logs and outputs parsed traces.
2. The system classifies failures with >90% accuracy against the `golden_fixture.json` ground truth.
3. The intervention wrapper reduces "State Persistence Error" rate by a statistically significant margin (p < 0.05) using McNemar's test.
4. The final report includes sensitivity analysis and memory footprint verification.
