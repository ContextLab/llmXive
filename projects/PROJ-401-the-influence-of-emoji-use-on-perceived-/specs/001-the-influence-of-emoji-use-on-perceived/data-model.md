# Data Model: The Influence of Emoji Use on Perceived Emotional Intensity in Text

## Entities & Attributes

### 1. Message
Represents a single text record from the source corpus.

| Attribute | Type | Description | Source |
|-----------|------|-------------|--------|
| `message_id` | int | Unique identifier for the message. | `ml_datasets` |
| `text` | string | The raw text content of the message. | `ml_datasets` |
| `emoji_present` | boolean | True if at least one emoji is present. | Derived |
| `emoji_count` | int | Total number of emojis in the message. | Derived |
| `emoji_types` | list[string] | List of Unicode code points (e.g., "U+1F60D"). | Derived |
| `text_length` | int | Number of characters in the text. | Derived |
| `punctuation_count` | int | Count of punctuation marks. | Derived |
| `intensity_score` | int | Perceived emotional intensity (1-7). | **Human-Rated** OR **Synthetic Proxy** |
| `is_proxy` | boolean | True if the score was generated by the synthetic proxy module. | Flag (FR-002) |

### 2. AnalysisResult
Represents the output of the statistical tests.

| Attribute | Type | Description | Source |
|-----------|------|-------------|--------|
| `test_type` | string | e.g., "Pearson", "Regression" | Code |
| `variable` | string | e.g., "emoji_count", "heart_emoji" | Code |
| `coefficient` | float | Correlation (r) or Regression Beta. | Code |
| `p_value` | float | Raw p-value. | Code |
| `adjusted_p_value` | float | Bonferroni-corrected p-value. | Code |
| `effect_size_label` | string | "Small", "Medium", "Large" (based on Beta). | Code |
| `sample_size` | int | N used for the test. | Code |

### 3. ProxyValidityReport
Represents the result of the proxy validation step (FR-002b).

| Attribute | Type | Description | Source |
|-----------|------|-------------|--------|
| `validation_sample_size` | int | N=20 (held-out human subset). | Code |
| `correlation_with_human` | float | Pearson r between proxy and human scores. | Code |
| `status` | string | "PASS" (r ≥ 0.6) or "FAIL" (r < 0.6). | Code |
| `warning_message` | string | If FAIL, explains the limitation. | Code |

## Data Flow

1.  **Raw Input**: `ml_datasets.cmu()` -> `data/raw/cmu_messages.csv` (Checksummed).
2.  **Validation**: Check for `intensity_score` in raw data.
    *   **If Missing**: Execute **Proxy Generation** module.
        *   **Input**: Text, Emoji features.
        *   **Logic**: Stochastic assignment based on emoji features **excluding** text_length/punctuation.
        *   **Output**: `intensity_score` (1-7), `is_proxy=True`.
    *   **If Present**: Use human scores, `is_proxy=False`.
3.  **Proxy Validation**: If proxy generated, compare against human subset (N=20). Generate `ProxyValidityReport`.
4.  **Feature Extraction**: `text` -> `emoji_count`, `emoji_types`, `text_length` -> `data/processed/features.csv`.
5.  **Analysis**: `features.csv` (with scores) -> `AnalysisResult` -> `data/processed/results.csv`.
6.  **Visualization**: `results.csv` -> `output/` plots.

## Constraints

- **Emoji Types**: Normalized to base Unicode points (e.g., skin tone modifiers removed) to ensure consistent counting.
- **Intensity Scale**: Strictly integers 1-7.
- **Missing Data**: Messages with encoding errors are logged and excluded; no imputation for missing text.
- **Proxy Logic**: The synthetic proxy **MUST NOT** use `text_length` or `punctuation` as predictors to ensure these remain valid control variables in the final regression model (addressing methodology-f32e3adc).
- **Proxy Prohibition**: The `is_proxy` field is `false` only if human data exists. Otherwise, it is `true` and the validity check is mandatory.
