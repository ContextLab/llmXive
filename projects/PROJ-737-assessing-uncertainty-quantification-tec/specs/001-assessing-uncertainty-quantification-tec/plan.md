# Implementation Plan: Assessing Uncertainty Quantification Techniques for Materials Property Predictions

**Branch**: `001-assessing-uq-techniques` | **Date**: 2026-10-11 | **Spec**: `specs/001-assessing-uncertainty-quantification-tec/spec.md`  
**Input**: Feature specification from `specs/001-assessing-uncertainty-quantification-tec/spec.md`

## Summary

Implement a reproducible, CPU‑only pipeline that (1) downloads three open‑access materials datasets, (2) featurizes compositions/structures with `matminer`, (3) trains four UQ‑enabled models (GPR, MC‑Dropout MLP, Deep Ensemble MLP, Split‑Conformal XGBoost), (4) computes Calibration Error and Prediction‑Interval Sharpness, (5) runs paired Wilcoxon signed‑rank tests on per‑sample errors, (6) performs a sweep of conformal coverage levels (0.80‑0.99), and (7) stores all outputs as CSVs validated against the contracts in `contracts/`.

## Technical Context

- **Language/Version**: Python 3.11  
- **Primary Dependencies**: `numpy`, `pandas`, `scikit-learn`, `xgboost`, `torch`, `matminer`, `datasets`, `scipy`.  
- **Storage**: Local filesystem under `data/` and `results/`.  
- **Testing**: `pytest` for unit & integration tests.  
- **Target Platform**: Linux GitHub Actions runner (A modest number of CPU cores., ≤2 GB RAM).  
- **Performance Goals**: Full end‑to‑end run ≤ 1 h, peak RAM ≤ 2 GB.  
- **Constraints**: No GPU, no 8‑bit quantization, max ensemble size = 3, MC‑Dropout passes ≤ 200.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Proxy for Elastic Modulus | No open Elastic Modulus dataset; Formation Energy is the closest open material property. | Dropping to two datasets would breach SC‑005. |
| Dataset Sampling | RAM limit forces capping dataset size for GPR & ensembles. | Full dataset would exceed 2 GB RAM and >1 h runtime. |
| Paired Wilcoxon Tests | Constitution mandates paired tests; ensures valid comparison on the same test set. | Independent tests would violate both constitution and statistical rigor. |
| Multiple‑Comparison Correction | Multiple pairwise tests. inflate family‑wise error; Bonferroni correction controls Type I error. | Ignoring correction would breach Statistical‑Rigor Standard. |

## Statistical Analysis Plan (Revised)

- **Wilcoxon Signed‑Rank Test** is applied to **per‑sample absolute errors** (for Sharpness) **and to per‑sample calibration residuals** (difference between predicted CDF and empirical outcome) for Calibration Error. This respects the paired nature of the data.
- **α = 0.05** significance threshold.
- **Bonferroni correction** is applied across the 18 pairwise tests (adjusted α = 0.05/18).
- **Sensitivity Analysis**: Sweep nominal coverage α from 0.80 to 0.99 (step = 0.01) for the split‑conformal method; record empirical coverage and interval width.

## Compute Feasibility & Constraints

- **RAM**: ≤ 2 GB by capping dataset size (≤ 5 k samples per property) and limiting model footprints.  
- **Time**: ≤ 1 h by training models sequentially, using small MLPs, and limiting GPR to ≤ 2000 points.  
- **Fallbacks**: If `matminer` fails, simple composition fractions are generated with pure `pandas`.  

## Power Analysis (Acknowledged)

With a minimum test set of **100 samples per dataset**, the Wilcoxon signed‑rank test has [deferred] power to detect a medium effect size (Cohen’s d ≈ 0.5) at α = 0.05. Smaller effects may go undetected; this limitation will be reported in the results section.

## Assumptions & Risks

- `matminer` installs without GPU dependencies.  
- Verified URLs remain reachable; if a URL becomes unavailable, the pipeline logs the failure and continues with remaining datasets.  
- Using Formation Energy as a proxy may affect direct comparability to Elastic Modulus; results will be interpreted with this caveat.
