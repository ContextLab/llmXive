# Reproducibility and Checksum Verification Guide

## Overview

This document describes the procedures for ensuring reproducibility of all artifacts
generated by the llmXive automated science pipeline.

## Artifact Checksumming

All critical artifacts are checksummed to ensure:
- Data integrity
- Reproducibility of results
- Detection of unauthorized modifications

## Checksum Registry

The file `data/processed/checksum_registry.json` contains SHA-256 checksums for all
key artifacts in the project.

## Verification Procedure

To verify all artifacts:

```bash
python code/utils/checksum_validator.py
```

This script will:
1. Load the checksum registry
2. Calculate actual checksums for all listed files
3. Compare actual vs expected checksums
4. Generate a validation report

## Generating New Checksums

After modifying any artifacts, regenerate checksums:

```bash
python code/scheduler/update_checksums.py
```

## Required Artifacts

The following artifacts must be checksummed:

- `data/processed/scheduler_trace.json` - Scheduler execution trace
- `data/processed/coverage_vectors.json` - State coverage vectors
- `data/processed/sensitivity_report.md` - Sensitivity analysis report
- `data/processed/convergence_results.json` - Convergence analysis results
- `data/processed/transfer_results.json` - Transfer learning results
- `data/processed/success_rate_vs_steps.png` - Convergence visualization
- `data/raw/.checksums.txt` - Raw data checksums
- `data/processed/held_out_test_set.json` - Held-out test set for transfer evaluation

## Failure Handling

If checksum verification fails:
1. Identify the mismatched files
2. Determine if the change was intentional
3. If intentional, regenerate the checksum registry
4. If unintentional, restore from version control

## CI Integration

Checksum verification should be part of the CI pipeline to ensure
reproducibility on every build.
