# Research: Function-Aware FIM for Non-Code Domains

## Research Question

Does the function-call inductive bias learned via Function-Aware Fill-in-the-Middle (FIM) transfer to non-code domains (e.g., logical deduction chains or math proofs) when the mid-training corpus consists of structured, function-like reasoning traces, or is the performance gain strictly dependent on syntactic code patterns?

## Hypothesis

**H1**: Models trained with Function-Aware FIM on pseudo-code logical traces will demonstrate statistically significantly higher accuracy on the LogiQA benchmark compared to:
1.  A Natural Language Control (same data, *same graph structure* serialized as plain text, no `def` syntax).
2.  A Baseline model (no mid-training).

**Rationale**: The FIM objective forces the model to predict missing logical steps based on signatures and context. If this mechanism learns a *structural* dependency resolution strategy (predicting "step N" based on "step N-1" and "step N-2"), it should generalize to logical reasoning regardless of the syntactic wrapper (pseudo-code vs. natural language).

## Dataset Strategy

The experiment relies on two primary datasets with strict domain separation.

| Dataset | Role | Source (Verified) | Format | Notes |
|---------|------|-------------------|--------|-------|
| **GSM8K** | Training Source | `openai/gsm8k` (HuggingFace) | Math word problems | Converted to pseudo-code `def step_N(): return fact`. Used for mid-training only. |
| **LogiQA** | Evaluation Benchmark | `logiqa` (HuggingFace) | Logical reasoning (multiple choice) | Independent test set. No overlap with GSM8K. |

**Dataset Strategy Details**:
- **GSM8K**: The raw math problems will be parsed to extract intermediate reasoning steps.
    - **Step 1: Linear Conversion**: Transform `Step 1: ... Step 2: ...` → `def step_1(): return ...`.
    - **Step 2: Graph Complexity Injection**: Synthesize non-linear dependencies. The pipeline will combine reasoning chains or artificially create dependencies where `step_N` relies on multiple previous steps (e.g., `step_3` depends on `step_1` AND `step_2`). This ensures the graph is not trivially linear, testing true structural resolution.
    - **Validation**: Run topological sort. If cycle detected, exclude example.
- **LogiQA**: Served as the out-of-domain test. The model will be evaluated on its ability to answer multiple-choice logic questions without any fine-tuning on LogiQA data.
- **Data Hygiene**:
    - **Overlap Check 1**: Verify zero overlap between raw GSM8K and LogiQA.
    - **Overlap Check 2**: Verify zero overlap between the *derived synthetic dataset* (problem IDs) and LogiQA.
    - **Leakage Check**: Verify that the "logical function" format does not inadvertently encode LogiQA answers.

**Verified Sources**:
- GSM8K: https://huggingface.co/datasets/openai/gsm8k
- LogiQA: (Standard HuggingFace dataset `logiqa` - verified as accessible via `datasets.load_dataset`)

*Note: The "SyntheticLogicalDataset" is a derived artifact generated from GSM8K. It does not have a pre-existing URL; it is generated by `code/data/convert_to_pseudo_code.py` and `code/data/inject_graph_complexity.py`.*

## Methodology

### Phase 1: Synthetic Dataset Construction
1.  **Download**: Fetch GSM8K (train split) and LogiQA (test split).
2.  **Conversion**: Parse GSM8K reasoning chains.
    -   Transform: `Step 1: ... Step 2: ...` → `def step_1(): return ... \n def step_2(): return ...`
    -   **Dependency Extraction**: Build a directed graph where edges represent data dependencies between steps.
    -   **Graph Complexity Injection**: Intentionally create non-linear structures (branching/merging) where steps depend on multiple predecessors. Exclude examples that cannot be reasonably converted to non-linear graphs.
    -   **Validation**: Run topological sort. If cycle detected, exclude example.
3.  **Control Generation**: Create a parallel version for the **NL Control** where the *same* dependency graph is serialized as plain text (e.g., "Step 1 depends on Step 2; Step 3 depends on Step 1 and 2") but without the `def` syntax. This ensures the NL Control has access to the *same structural information*, isolating syntax as the only variable.

### Phase 2: CPU-Tractable Mid-Training
1.  **Model Selection**: TinyLlama-110M (or similar ≤150M param model).
2.  **Environment**: GitHub Actions CPU runner (multiple vCPU, sufficient RAM).
3.  **Training Configuration**:
    -   **FIM Group**: Standard Causal LM with custom FIM masking. **Masking Strategy**: Target *entire missing steps* (signature + body) or intermediate steps in a chain. The model must infer the missing step's content from the context (previous steps) and the function signature, explicitly testing dependency resolution.
    -   **NL Control Group**: Standard Causal LM (no FIM) on the plain-text version of the same data (with explicit dependency markers).
    -   **Baseline**: Pre-trained weights (no further training).
    -   **Convergence Check**: Monitor training loss. If the model fails to reach a predefined loss threshold (indicating underfitting) after the single epoch, the run is flagged, and a secondary "mini-epoch" or extended training is triggered if within time limits. If underfitting persists, the result is reported as a null due to insufficient training, not a failure of the hypothesis.
4.  **Constraints**:
    -   Single epoch (or until convergence).
    -   Batch size ≤ 32 (tuned for RAM).
    -   Sequence length ≤ 2048.
    -   **No CUDA**: Explicitly force `device="cpu"`.
    -   **Output**: Save `masking_map.json` for verification.

### Phase 3: Statistical Evaluation
1.  **Inference**: Run all three model variants (FIM, NL-Control, Baseline) on the LogiQA test set.
2.  **Metrics**: Accuracy (%).
3.  **Statistical Test**:
    -   Perform multiple runs (seeds) to generate a distribution of scores.
    -   **Test**: **Bootstrap Confidence Interval** on the difference in means (FIM vs NL-Control) and a **Permutation Test** to assess significance. Standard paired t-tests are avoided as they assume independence that may not hold for fixed test sets with seed-dependent variability.
    -   **Hypothesis**: Compare FIM vs. NL-Control.
    -   **Significance Threshold**: p < 0.05 (or 95% CI excludes 0).

## Statistical Rigor & Feasibility

-   **Multiple Comparison Correction**: Since the primary comparison is FIM vs. NL-Control, a single hypothesis test is performed. If multiple benchmarks are added later, Bonferroni correction will be applied.
-   **Power Analysis**: The plan assumes a sample size of [deferred] (determined during data exploration) and ≥3 random seeds. This is designed to detect a medium effect size (Cohen's d) with α = 0.05. If power is insufficient, the limitation will be explicitly stated in the results.
-   **Causal Inference**: This is an observational study on model performance. Claims of "transfer" are associational unless the experimental design (strict domain separation, control groups) isolates the structural bias variable.
-   **Collinearity**: The "function" syntax and the "logical structure" are conflated in the training data. The NL Control group (same structure, no syntax) is the specific design choice to disentangle this.
-   **Compute Feasibility**:
    -   **CPU-First**: TinyLlamaM fits in ~GB RAM with float32 weights + overhead.
    -   **Time Limit**: Single epoch on a subset ensures the time limit is met. If full dataset exceeds limits, a random sample is used, and power limitations are noted.
    -   **No GPU Fabrication**: The plan does not simulate GPU performance; it runs the real training on CPU. If the model size were larger, a scaled-down version would be used, not a fake CPU approximation.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| **Dataset Variable Mismatch**: GSM8K reasoning steps may not map cleanly to function calls. | High (Invalid training signal) | Implement robust parser; exclude ambiguous examples; validate with topological sort; ensure non-linear graph injection. |
| **OOM on CPU**: Training exceeds 7GB RAM. | High (Job failure) | Dynamically reduce batch size; use gradient accumulation; monitor memory usage. |
| **Data Leakage**: GSM8K examples appear in LogiQA. | Critical (Invalid results) | Run strict string-hash overlap check before training (both raw and synthetic). |
| **No Transfer**: FIM performs same as NL Control. | Medium (Null result) | Null result is valid; report p-value, effect size, and CI. |
| **Underfitting**: Model fails to learn training signal. | High (Invalid null result) | Implement convergence check; extend training if needed; report as "insufficient training" if threshold not met. |
