## Unresolved concerns

- The validation step records a single binary outcome per test clip (`auto_success` and `baseline_success`). Because each clip’s success is evaluated on only one episode, the measurement is highly noisy, which can reduce statistical power and inflate Type I/II error rates for the McNemar and Wilcoxon tests. The plan should aggregate success over multiple episodes per clip (e.g., compute a success rate) or otherwise increase replication to obtain a more reliable estimate of performance differences.
- The plan proposes a grid search over 12 (τ, k) combos for each of the 500 training clips, running 10 episodes per combo (≈ 60 000 simulation episodes). On a free‑tier GitHub Actions runner (2‑core CPU, 7 GB RAM) this workload is highly likely to exceed the 6‑hour runtime budget, violating FR‑006 and the Resource‑Constrained Execution principle. The plan must reduce the labeling workload (e.g., fewer clips, fewer episodes per combo, or a smarter hyper‑parameter search) or provide a concrete runtime estimate demonstrating feasibility.
- The 'Phase Mapping to Functional Requirements & Success Criteria' table incorrectly links FR‑007 (task‑complexity metric) and SC‑001 (variance‑complexity correlation) to Phase 1, which only performs clip generation and descriptor extraction. FR‑007 and the correlation analysis belong to Phase 5. This mis‑alignment may cause traceability confusion and violates the traceability expectations of the constitution.
- The plan computes a *partial correlation* between latent variance and the *predicted* hyperparameters (τ, k) while controlling for task‑complexity. Since the predicted hyperparameters are generated by a regressor whose inputs include variance, this test is tautological: it measures the relationship between a variable and a function of that same variable, violating independence of predictor and validation target.
- The statistical evaluation includes a *Wilcoxon signed‑rank test* on the paired binary outcomes (auto_success vs baseline_success). The Wilcoxon signed‑rank test assumes ordinal or continuous paired differences; applying it to binary data is inappropriate. McNemar’s exact test already addresses paired binary outcomes, so the Wilcoxon test should be removed or replaced with a suitable method for binary paired data.
