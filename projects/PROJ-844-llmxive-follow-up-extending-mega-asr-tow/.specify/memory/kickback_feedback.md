## Unresolved concerns

- The deterministic collapse algorithm (FR‑021) defines collapse intensity using thresholds on the same Semantic Similarity Score (SSS) and WER that later serve as the target for regression modeling. This creates a circular dependency that can artificially inflate R² and may cause the regression to simply learn the rule rather than genuine acoustic interaction effects.
- The regression model predicts collapse intensity from acoustic parameters only, without accounting for clip‑level confounds such as baseline SSS/WER or transcript difficulty. Variation in content difficulty could bias the estimated interaction coefficients, threatening construct validity of the ‘critical interaction vector’.
- The plan cites a power analysis (≥ 80 % power for effect size f² ≥ 0.02) but defers the concrete sample‑size calculation ([deferred]). Without an explicit justification linking the 50 000‑clip sample to the ability to detect the targeted non‑linear interaction effects in a hierarchical model, the adequacy of the sample remains unverified.
- The plan references the **Voices‑in‑the‑Wild‑2M** corpus but does not provide a verified dataset citation (e.g., a URL or a ‘Verified datasets’ block). Add a citation block with the canonical source URL to satisfy the data‑resource requirement.
- FR‑018 requires validation against real‑world noisy clips from the DNS‑Challenge dataset. The plan instead proposes using bundled demo noise files from `pyroomacoustics`, which are not the DNS‑Challenge data and lack a verified source. This does not meet the functional requirement and may invalidate the realism validation step.
- The plan references a “Verified datasets” block for Principle II compliance, but no such block listing the actual dataset URLs is present in the document, violating the constitution’s Verified Accuracy requirement.
- Contract file `contracts/collapse_point.schema.yaml` defines a schema that is never exercised by any pipeline step described in the plan (e.g., no script outputs a file matching this schema).
- Contract file `contracts/critical_vector.schema.yaml` defines a critical interaction vector schema, yet the plan does not specify generating or validating an artifact that conforms to this schema.
- The collapse intensity target is defined deterministically from the same SSS and WER metrics that are later used as predictors in the regression model (via acoustic parameters). This creates a circular validation: the regression is essentially learning a rule that was already applied to generate the target, making the R² ≥ 0.6 claim trivially achievable and not evidence of a genuine, underlying acoustic interaction.
- The universal “critical interaction vector” is assessed by comparing regression coefficients (or SHAP interaction strengths) across ASR models. Since each model’s target collapse intensity was derived using model‑specific baseline SSS/WER thresholds, the resulting coefficients are mathematically constrained to be similar, leading to a tautological confirmation of universality.
- The deterministic rule mixes two thresholds (SSS < 0.5 × baseline and WER > 2 × baseline) and an inflection‑point fallback. Because the rule is hard‑coded, any downstream regression will inherit this piecewise definition, violating the assumption of a smooth, learnable relationship required for linear mixed‑effects modeling.
- FR‑018 validates synthetic distortions against DNS‑Challenge clips but cites no verified URL for the DNS data, contravening the project's Verified Accuracy principle and potentially compromising the scientific validity of the realism check.
