# LlmXive Mode Guide: CI vs Research

This document explains the operational modes of the LlmXive pipeline, specifically
distinguishing between **CI Mode** (Continuous Integration/Simulation) and **Research Mode**
(Real Human Data Analysis).

## Overview

The pipeline supports two distinct execution modes to facilitate both automated testing
and rigorous scientific research. The mode is controlled via the `MODE` environment variable
or the `config.py` interface.

### Configuration

```bash
# Set to CI Mode (Simulation)
export MODE=CI

# Set to Research Mode (Real Data)
export MODE=RESEARCH
```

Alternatively, in Python:
```python
from config import set_mode
set_mode('CI') # or 'RESEARCH'
```

---

## CI Mode (Continuous Integration / Simulation)

**Purpose**: Automated testing, pipeline validation, and performance benchmarking without
requiring external human data or expensive model training.

**Characteristics**:
- **Ground Truth**: Uses `decoupled_scores.csv` generated via `np.random` with a fixed seed.
 Scores are explicitly **decoupled** from synthetic mask metrics to prevent circularity.
- **Inter-Rater Reliability (IR)**: Skipped. The pipeline logs a simulation notice.
- **Proxy Validation**: Expected to show low correlation. The gate logic marks this as
 `EXPECTED_LOW_CORRELATION` and **continues execution** rather than blocking.
- **Data Source**: Synthetic masks generated by `code/data/mask_generator.py` on a subset
 of Places365.
- **Model**: Typically runs `Moebius-Tiny` (CPU optimized) for latency benchmarks.

**Key Artifacts**:
- `data/annotations/decoupled_scores.csv`: Contains a `mode` column set to `CI_MODE`.
- `data/results/proxy_validation.json`: Contains `gate_status: EXPECTED_LOW_CORRELATION`.
- `data/results/validation_log.txt`: Logs `[CI_MODE] Single-Rater Simulation`.

**Usage**:
```bash
# Run full pipeline in CI mode
python code/data/validate_and_log.py --mode CI
python code/eval/metrics.py --mode CI
```

## Research Mode (Real Human Data)

**Purpose**: Scientific validation of the "Moebius-Dynamic" hypothesis using real human
complexity annotations.

**Characteristics**:
- **Ground Truth**: Requires `data/annotations/human_scores.csv` with columns
 `[image_id, score, rater_id]`.
- **Validation**:
 - **Existence Check**: Fails loudly (`SystemExit`) if the human scores file is missing.
 - **Inter-Rater Reliability**: Calculates Krippendorff's alpha. If `alpha < 0.5`, logs
 warnings to `data/results/validation_log.txt`.
- **Proxy Validation**: Requires Pearson correlation `r >= 0.7` between synthetic metrics
 and human scores. If `r < 0.7`, the gate **blocks** execution (`gate_status: BLOCKED`).
- **Data Source**: Real human annotations + synthetic masks.
- **Model**: Can attempt `Moebius 0.2B` if memory permits; otherwise falls back to Tiny.

**Key Artifacts**:
- `data/annotations/human_scores.csv`: Input file (external).
- `data/results/inter_rater_reliability.json`: Contains Krippendorff's alpha value.
- `data/results/proxy_validation.json`: Contains `gate_status: PASSED` or `BLOCKED`.

**Usage**:
```bash
# Ensure human_scores.csv exists in data/annotations/
python code/data/validate_and_log.py --mode RESEARCH
```

## Mode Decision Logic

The pipeline determines the mode at the start of `code/data/annotator.py` and `code/eval/stats.py`.

| Feature | CI Mode | Research Mode |
|:--- |:--- |:--- |
| **Ground Truth Source** | Synthetic (Decoupled) | Real Human Scores |
| **File Required** | None (Generated) | `human_scores.csv` |
| **Krippendorff's Alpha** | Skipped | Calculated |
| **Proxy Correlation Gate** | Expected Low (Pass) | Required >= 0.7 (Fail if low) |
| **Model Target** | Moebius-Tiny | Moebius-Tiny / 0.2B |
| **Primary Goal** | Pipeline Integrity | Scientific Validity |

## Troubleshooting

### "Missing human_scores.csv" Error
If running in `RESEARCH` mode, ensure `data/annotations/human_scores.csv` exists.
If you intend to run a simulation, set `MODE=CI`.

### "Proxy Validation Blocked"
In `RESEARCH` mode, if the correlation between synthetic metrics and human scores is
below 0.7, the pipeline stops. This is a safety feature to prevent training on
unvalidated data. Review `data/results/proxy_validation.json` for details.

### "CI Mode: Low Correlation Expected"
In `CI` mode, low correlation is normal because scores are intentionally decoupled
from metrics. This log entry confirms the simulation is running correctly.
