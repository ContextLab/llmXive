## Unresolved concerns

- The plan allows a synthetic surrogate dataset to replace missing experimental CCR data (see Phase 0 description). Using synthetic data as the primary source undermines construct validity of the target variable and threatens external validity of any predictive claims about real alloys.
- The power analysis claims 90 % power to detect an RMSE reduction of 0.05 K/s with ≥ 500 samples, but provides no justification for the effect size (0.05 K/s) relative to the typical CCR range (10–500 K/s). This makes the sample‑size justification unsound.
- The sensitivity analysis simultaneously reports continuous RMSE and binary F1‑score across thresholds without a pre‑registered hypothesis or correction for multiple comparisons, introducing researcher degrees of freedom and inflating Type I error risk.
- FR‑008 requires mitigation of composition‑distribution bias via stratified sampling or weighting, yet the plan does not specify how the stratification by element families will be implemented, leaving a potential confound uncontrolled.
- The collinearity handling drops the ‘lower‑variance’ descriptor when |r| > 0.8, a data‑driven decision that can introduce post‑hoc model tuning and bias the importance results; the rule lacks a pre‑specified criterion and thus threatens methodological rigor.
- FR-007 (acknowledgement of limitation due to using only three thermodynamic descriptors) is absent from the plan. A dedicated step (perhaps in Phase 5 or Phase 6) should be added to document this limitation in the final report and discuss potential bias.
- The plan states that no open experimental dataset with `critical_cooling_rate` exists and will therefore generate a synthetic surrogate dataset (see the 'Experimental alloy CCR' entry in the Dataset Strategy table). This violates FR‑001, which requires a *curated experimental* dataset (target N ≥ 1000, minimum N ≥ 500). Using synthetic data does not satisfy the functional requirement and provides an inappropriate data source for answering the research question.
- Principle II (Verified Accuracy) requires a ‘Verified datasets’ block listing the exact OQMD URLs used. The plan’s Constitution Check table claims compliance but no such block is present, violating the constitution.
- The plan writes `cv_metrics.json` but does not reference the `contracts/model_metrics.schema.yaml` contract that defines the required fields (fold_scores, mean_rmse, etc.). This leaves the model‑metrics artifact unchecked against its schema.
- Feature importance is saved as `feature_importance.csv` but there is no contract file (e.g., `contracts/feature_importance.schema.yaml`) referenced. The data‑model defines a `FeatureImportance` entity, yet no schema contract exists, creating a data‑model ↔ contracts mismatch.
- The plan produces `sensitivity_report.json` but never mentions the `contracts/sensitivity.schema.yaml` contract, so the sensitivity report is not validated against its schema.
- Phase 5 only validates against `contracts/features.schema.yaml`. It should also run validation for all other contracts (model_metrics, sensitivity, processed_alloys, etc.) to satisfy the constitution’s contract‑execution requirement (SC‑006).
- The data model defines a `FeatureImportance` entity, but no corresponding contract file is provided in the `contracts/` directory. This breaks the Plan ↔ Data‑Model ↔ Contracts consistency rule.
- The `row_count` field uses a placeholder description “minimum a sufficiently large sample size” instead of a concrete numeric minimum (e.g., 500). This makes the schema non‑deterministic and conflicts with FR‑001 which requires ≥ 500 rows.
- Phase 0 references SC‑006 (contract execution) but does not actually execute any contract validation steps, leaving the requirement unfulfilled.
- The plan states that artifacts are “hash‑named in the `state/` YAML (handled by the CI)”, but no explicit step in the plan creates or updates these hashes, nor is there a script shown that writes them. This may violate Principle V’s version‑discipline requirement.
- The plan generates a synthetic `critical_cooling_rate` as a linear combination of the same thermodynamic descriptors that are later used as predictors (mixing_enthalpy, atomic_size_mismatch, electronegativity_variance). This makes the validation target definitionally dependent on the predictors, creating a circular/tautological evaluation: the model is guaranteed to perform well because the target was constructed from the features, not because the descriptors genuinely predict glass‑forming ability.
