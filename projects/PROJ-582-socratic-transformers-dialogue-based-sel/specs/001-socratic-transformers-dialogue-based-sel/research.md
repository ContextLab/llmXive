# Research: Socratic Transformers (Negative Selection on Belief)

## Problem Framing

The core hypothesis is that **negative selection on belief**—a process where a model learns to reject reasoning paths that fail an adversarial critique—improves reasoning accuracy more effectively than static training or neutral context. This reframes "self-teaching" as an evolutionary selection process, aligning with the thymic selection of T-cells: the system does not "learn the answer" but learns to avoid the "belief space" of erroneous reasoning.

## Methodology & Statistical Rigor

### 1. Data Generation (US1)
- **Static**: `(Question, Answer)`
- **Dialogue (Selection)**: `(Question, Initial Answer, Critique, Revised Answer)`
 - *Critique*: Generated by a **frozen** 4-bit model (e.g., Llama-3-8B) to identify logical errors.
 - *Revised Answer*: Generated by the same model, conditioned on the critique.
- **Ablation**: `(Question, Initial Answer, [Fixed Neutral Placeholder], Revised Answer)`
 - Placeholder is a **fixed, human-curated** neutral string (e.g., "The model considers this answer.") padded/truncated to match the critique's token count.

**Regeneration Loop**: To satisfy Constitution Principle VII, if a generated dialogue fails the quality gate (e.g., lacks logical keywords, too short), the system re-prompts the critic up to 3 times. If all attempts fail, the sample is logged as "failed" and skipped, ensuring the curriculum contains only valid signal.

### 2. Training (US2)
- **Model**: Base LLM (e.g., `mistralai/Mistral-7B-v0.1` or `Phi-3-mini` as fallback).
- **Method**: LoRA (Low-Rank Adaptation) fine-tuning.
- **Conditions**:
 - **Condition A (Selection)**: Train on Dialogue Tuples.
 - **Condition B (Ablation)**: Train on Ablation Tuples.
 - **Condition C (Static)**: Train on Static Tuples.
- **Compute**: 4-bit quantization (`bitsandbytes`). If CUDA is detected (via Kaggle offload), use GPU; otherwise, CPU.

### 3. Evaluation & Analysis (US3)
- **Metrics**: Accuracy on held-out GSM8K and MMLU STEM subsets.
- **Statistical Test**: **Independent Samples t-tests** (Welch's t-test) comparing Condition A vs. B and A vs. C.
 - *Note*: The source spec's mention of "paired t-tests" is corrected here to "independent" as the groups are independent.
- **Correction**: **Bonferroni correction** applied for multiple comparisons (family-wise error rate control).
- **Power Limitation**: Acknowledged that sample size (N ~ 500-1000) may limit power for small effect sizes (d=0.3).
 - *Mitigation*: Pool data across GSM8K and MATH to increase N where feasible.
 - *Justification*: Target effect size d=0.5, alpha=0.05 (Bonferroni), Power=80% requires N~128 per group. Current N is sufficient for medium effects.
- **Causal Claims**: Claims are strictly **associational** unless randomization of the critique content is proven. The design isolates the *effect of the critique content* via the Ablation condition (fixed placeholder), but does not claim causal generalization beyond the specific model/dataset context.

## Compute Feasibility & Escape Hatch

- **CPU-First**: The plan uses 4-bit quantization and streaming to fit within 7GB RAM.
- **GPU Escape Hatch**: If the fine-tuning step fails due to memory constraints on CPU, the execution stage automatically offloads to a Kaggle GPU. The plan is scaled down (e.g., fewer epochs, smaller batch size) to fit the ~16GB VRAM of a free-tier Kaggle GPU.
- **No Fabrication**: We do not plan a synthetic stand-in for the GPU computation. If the real computation is required, we plan the real scaled GPU run.

## Decision/Rationale

| Method | Platform | Rationale |
|--------|----------|-----------|
| 4-bit Quantization | CPU | Essential for 7GB RAM constraint. |
| Streaming Data | CPU | Prevents OOM on large datasets. |
| LoRA Fine-tuning | CPU/GPU | Efficient parameter update; feasible on CPU for small models. |
| Bonferroni Correction | CPU | Standard statistical rigor for multiple comparisons. |
| Regeneration Loop | CPU | Ensures data quality per Constitution Principle VII. |
| Fixed Neutral Placeholder | CPU | Isolates logical content effect from stylistic artifacts. |
| Independent t-test | CPU | Corrects spec error; matches independent group design. |
