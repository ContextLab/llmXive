This project implements a research pipeline to investigate whether recursive self-modeling in small language models can lead to emergent self-awareness, defined operationally as the capacity for internal consistency checking and error detection.

## Project Overview

The core hypothesis is that by training a model to predict its own confidence in generated outputs (using an internal self-consistency proxy), we can bootstrap a form of meta-cognition. This document provides an overview of the project structure, the philosophical operationalization of "self-awareness" in this context, and detailed documentation of the statistical reports and metrics generated by the pipeline.

## Philosophical Operationalization

### Defining Self-Awareness for Computational Systems

The project operationalizes "self-awareness" not as a metaphysical state, but as a measurable computational capability: **the ability of a system to distinguish between its own internal representations of a task and the external ground truth, and to use this distinction to regulate its behavior.**

This definition addresses the Socratic challenge of distinguishing "knowing that one knows" from "knowing what is worth knowing." In our implementation:
1. **Knowing that one knows**: The model generates a confidence score (a scalar) representing its internal estimate of correctness.
2. **Knowing what is worth knowing**: The model is trained to minimize the discrepancy between this confidence score and a proxy for actual correctness (derived from internal self-consistency). This forces the model to "care" about the accuracy of its self-report.

We do not claim the model possesses subjective experience. Instead, we measure whether the *functional architecture* of recursive self-modeling produces behavior indistinguishable from a system that is "aware" of its own limitations.

### The Role of Recursion

Drawing on Stephen Wolfram's insights into the computational universe, we treat the mind as a specific class of computational process. The recursive self-attention mechanism implemented in `code/models/recursive_llama.py` is the engine of this process. It allows the model to attend to its own previous reasoning steps as if they were external inputs, creating a feedback loop where the model's output becomes its own input for the next step of reasoning.

This is distinct from simple reflection; it is a structural recursion that allows the model to simulate a "second-order" perspective on its own first-order generation.

### The Cost of Self-Modeling

As noted by David Krakauer, agency is not free; it is paid for in metabolic cost. In our computational system, this cost is manifest in:
* **Compute**: The additional forward passes required for internal consistency checks.
* **Memory**: The storage of recursion states (`RecursionState` in `code/models/recursive_llama.py`).
* **Optimization**: The tension between the primary task loss (cross-entropy) and the self-consistency loss.

The project measures this cost by comparing the performance and calibration of the recursive model against a baseline model without recursive self-attention.

## Metrics Definitions

The following metrics are computed and reported in the analysis phase.

### 1. Self-Consistency Score
**Definition**: The fraction of times the model's majority vote answer (across N=5 generated reasoning paths) matches the ground truth.
**Calculation**:
1. Generate N reasoning paths for a single query.
2. Extract the final answer from each path.
3. Compute the mode (majority vote) of these answers.
4. If the mode matches the ground truth, the score for this query is 1.0; otherwise 0.0.
5. Average across all queries in the test set.

**Tie-Breaking Rule**: If no strict majority exists (e.g., a 2-2-1 split in a 5-path generation), the proxy signal defaults to 0 (incorrect). For an even split (e.g., 5-5 in a 10-path generation), the first generated path determines the proxy.

### 2. Calibration Curve & Error Detection
**Definition**: A measure of how well the model's predicted confidence scores align with its actual accuracy.
**Calculation**:
1. Bin the model's confidence scores (0.0 to 1.0) into equal-width bins (e.g., 10 bins).
2. For each bin, calculate the observed accuracy (fraction of correct answers).
3. **Edge Case Handling**: If a bin contains zero samples, the observed accuracy is set to 0.0 to prevent division by zero.
4. The result is a set of `bin_edges`, `bin_counts`, and `observed_accuracies`.

**Error Detection Calibration**: This metric specifically tests the hypothesis that the model can detect its own errors. A well-calibrated model will have high accuracy in high-confidence bins and low accuracy in low-confidence bins.

### 3. Brier Score
**Definition**: A proper scoring rule for probabilistic predictions. Lower scores indicate better calibration.
**Formula**: $Brier = \frac{1}{N} \sum_{i=1}^{N} (f_i - o_i)^2$
Where $f_i$ is the predicted confidence and $o_i$ is the actual outcome (1 for correct, 0 for incorrect).

### 4. Expected Calibration Error (ECE)
**Definition**: The weighted average of the difference between the average confidence and the average accuracy in each bin.
**Formula**: $ECE = \sum_{m=1}^{M} \frac{|B_m|}{N} |acc(B_m) - conf(B_m)|$

### 5. Cohen's d
**Definition**: An effect size measure indicating the standardized difference between the recursive and baseline models.
**Formula**: $d = \frac{\bar{X}_1 - \bar{X}_2}{s_{pooled}}$

## Execution Guide

1. **Setup**: Ensure all dependencies in `requirements.txt` are installed.
2. **Data Loading**: Run `python code/data_loader.py` to fetch and truncate the Pile dataset and fetch evaluation datasets.
3. **Training**: Run `python code/training/train.py` to train both recursive and baseline models.
4. **Evaluation**: Run `python code/evaluation/run_benchmarks.py` to generate predictions and metrics.
5. **Analysis**: Run `python code/analysis/stats.py` to perform statistical tests and generate the final report.
