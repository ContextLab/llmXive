# Data Model: Investigating the Relationship Between Brain Network Dynamics and Individual Differences in Musical Improvisation Skill

## Overview
Schemas describe every artifact produced by the pipeline. Contract tests in `tests/contract/` validate outputs against the files in `contracts/`. All behavioral/covariate fields are **optional** because their presence is determined at runtime; mandatory fields are only those generated by the pipeline itself.

## Core Entities

| Entity | Key Fields | Description |
|--------|------------|-------------|
| **Subject** | `subject_id`, `age`, `fd`, `years_of_training`, `task_condition`, `instrument_type`, `musical_genre`, `practice_intensity`, `education_level`, `expert_rating`, `excluded`, `exclusion_reason` | One row per participant; covariates are present only if the column exists in the raw parquet. |
| **QCRecord** (`qc_<subject>.json`) | `fraction_bad_volumes`, `excluded`, `exclusion_reason` | Summary of motion/QC metrics for a subject. |
| **ColumnInventory** (`data/raw/column_inventory.json`) | `available_columns`, `available_subject_count` | Lists which of the expected behavioral/covariate columns are actually present in each dataset. |
| **ROITimeseries** | `subject_id`, `timepoint`, `roi_id` (`roi_1` … `roi_100`), `value` | Band‑pass filtered mean BOLD per ROI (Schaefer atlas, standard parcellation). |
| **NetworkMetric** | `subject_id`, `window_id`, `window_seconds`, `step_seconds`, `global_efficiency`, `modularity`, `participation_coefficient` | ROI‑based connectivity descriptors per sliding window. |
| **PCAScores** | `subject_id`, `n_components_retained`, `variance_explained_total`, `pc_scores` (mapping `pc_i` → score) | PCA output per subject. |
| **RegressionResult** | `pc`, `skill_proxy_used`, `coefficient`, `raw_p`, `fdr_p`, `significance`, `null_result_flag`, `permutation_scheme`, `covariates_included` | One row per retained PC (present only when a skill proxy exists). |
| **ManifestRow** (`results/manifest.csv`) | See `contracts/manifest.schema.yaml` | Single Source of Truth row for each subject, aggregating all derived values, covariates, QC flags, power status, and (if computed) regression outcomes. |

## File Layout

```text
data/
├── raw/ds001600.parquet            # verified download for association
├── raw/ds000246.parquet            # verified download for descriptive work
├── raw/column_inventory.json       # discovered columns per dataset
├── checksums.json                  # SHA‑256 of raw files
└── derived/
    ├── roi_timeseries_<subject>.csv
    ├── qc_<subject>.json
    ├── metrics_<subject>.csv
    └── pca_scores.csv

results/
├── manifest.csv
├── regression_results.csv        # only if a skill proxy exists
├── sensitivity_summary.csv
├── power_analysis.json
└── fig_network_topology.png
```

## Schema Notes (refer to `contracts/manifest.schema.yaml`)

- `roi_id` values correspond to the full set of region identifiers defined in the Schaefer atlas.  
- `window_seconds` ∈ {30, 45, 60}; `step_seconds` ∈ {5, 10}.  
- `skill_proxy_used` records the actual column name used as the skill proxy, or `"none"` (expected halt path).  
- Excluded subjects appear with `excluded = true` and an explanatory `exclusion_reason`; metric fields may be null.  
- The manifest includes a `power_status` field (`"adequate"`, `"underpowered_association_skipped"`, or `"not_applicable_descriptive_only"`).  

All optional fields are allowed to be missing; the manifest schema permits additional properties to accommodate future extensions.
