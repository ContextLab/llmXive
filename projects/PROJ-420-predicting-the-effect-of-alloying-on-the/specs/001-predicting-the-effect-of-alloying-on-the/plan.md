# Implementation Plan: Predicting the Effect of Alloying on the Poisson's Ratio of Aluminum Alloys

**Branch**: `001-predict-poissons-ratio` | **Date**: 2026-07-04 | **Spec**: `specs/001-predict-poissons-ratio/spec.md`
**Input**: Feature specification from `specs/001-predict-poissons-ratio/spec.md`

## Summary

This project implements a machine learning pipeline to predict the Poisson's ratio of monolithic aluminum alloys based on the atomic fractions of key alloying elements (Cu, Mg, Si, Zn, Mn). The approach strictly adheres to the project constitution's principles of reproducibility and data hygiene. The technical strategy involves downloading real, verified data from OpenML., filtering for monolithic alloys with complete compositional and property data, applying Isometric Log-Ratio (ILR) transformations to handle the compositional nature of the data, and training a Random Forest regressor. All findings will be framed as associational, with rigorous diagnostic checks for collinearity, data independence, and model robustness. The plan explicitly avoids unimplementable physical derivations (e.g., VRH bounds) due to missing elemental constants, focusing instead on a data-driven approach validated against known physical limits.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| ILR Transformation | Required to handle the unit-sum constraint of compositional data (atomic fractions). | Standard linear regression on raw fractions violates the simplex geometry, leading to spurious correlations and invalid statistical inference. |
| VIF Diagnostics | Required to detect collinearity in raw predictors (Cu, Mg, etc. often co-occur). | Ignoring collinearity would obscure the true contribution of individual elements and violate the "Compositional Attribution" principle. |
| Perturbation Analysis | Required for valid feature importance ranking in compositional space. | Direct interpretation of ILR feature importance is ambiguous due to basis dependence; Perturbation Analysis provides a basis-invariant ranking. |
| Physical Sanity Check | Required to ensure predictions are physically plausible (0.0 <= nu <= 0.5). | Raw model outputs may occasionally drift due to noise; a post-hoc check ensures results respect fundamental material physics without requiring missing elemental constants for VRH derivation. |

## Execution Phases

### Phase 0: Data Acquisition & Validation
1. **Download**: Fetch OpenML dataset ID 42347 using `openml.datasets.get_dataset(42347)`.
   - **Retry Logic**: Implement exponential backoff for network failures (no authentication required).
2. **Validate**: Check schema against `contracts/dataset.schema.yaml`.
3. **Filter**:
   - Keep only monolithic alloys.
   - Keep only records with non-missing Poisson's ratio, Young's modulus, and composition for Cu, Mg, Si, Zn, Mn.
   - **Independence Check**: Filter records where `measurement_method` is NOT 'Ultrasonic' or 'Derived' (keep only independent measurements).
   - **Completeness Check**: Exclude records where sum of major elements < 0.95.
4. **Log**: Record the count of filtered entries (SC-001).

### Phase 1: Feature Engineering & Diagnostics
1. **Normalize**: Convert all elastic constants to GPa.
2. **ILR**: Apply Isometric Log-Ratio transformation to atomic fractions.
3. **VIF**: Calculate Variance Inflation Factors on raw composition. Flag if VIF > 5 (expected, but logged).
4. **Power Analysis**: Check sample size. If < 100, log a warning and limit model complexity (max_depth=5).
5. **Physical Sanity Check**: Validate that the distribution of Poisson's ratio in the dataset falls within known physical bounds (0.0 <= nu <= 0.5) and typical Aluminum alloy ranges (lower bound to 0.36).

### Phase 2: Model Training & Evaluation
1. **Split**: / train/test split.
2. **Train**: Random Forest Regressor with k-fold cross-validation.
3. **Evaluate**: Compute CV MAE and Test MAE.
4. **Interpret**:
   - Compute Permutation Importance on ILR features.
   - Perform Perturbation Analysis to rank elements in original space.
   - Compute Null Model Threshold (high percentile of random importance).
   - Compute Basis Sensitivity Flag (check if ranking changes with alternative ILR basis).

### Phase 3: Reporting & Validation
1. **Memory Check**: Log peak memory usage during training (Tc).
   - **Artifact**: Generate `results/memory_profile.log` with peak usage < 4 GB.
2. **Quickstart Validation**: Run `quickstart.md` commands in a clean env and log output (T045).
   - **Artifact**: Generate `results/quickstart_validation.log` confirming successful execution.
3. **Output**: Save `results/metrics.json` and `results/feature_importance.json` conforming to `contracts/model_output.schema.yaml`.
4. **Framing**: Ensure all results are framed as associational.

## Risk Assessment

- **Medium Risk**: Sample size may be small (<100). Mitigation: Limit model complexity and report power limitation.
- **Low Risk**: Data independence verification. Mitigation: Explicit filtering based on `measurement_method` field.
- **Low Risk**: Collinearity. Mitigation: ILR transformation and VIF diagnostics.
- **Low Risk**: Physical Plausibility. Mitigation: Post-hoc sanity checks against known bounds.
