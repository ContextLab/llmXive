## Unresolved concerns

- The Monte‑Carlo power simulation estimates 0.68 power for a medium effect (Cohen’s d≈0.5), which is below the conventional 0.80 threshold. Because the primary tests (KS and block‑permutation) are already low‑power for subtle distribution shifts, the study is at risk of a false‑negative conclusion. The plan should either increase the effective sample size (e.g., extend the temporal window, include lower‑magnitude events with appropriate weighting) or adopt a more powerful test (e.g., mixed‑effects modeling) to meet a reasonable power target.
- Control windows are matched on calendar month, ENSO/PDO phase, and broad geographic region, but other potential confounders (e.g., local temperature trends, humidity, seasonal pressure cycles beyond month) are not accounted for. Residual climate variability could bias the comparison, especially given the coarse 30‑day baseline. The plan should incorporate additional covariates or a more granular matching scheme (e.g., propensity‑score matching on multiple meteorological variables).
- The Kolmogorov–Smirnov test assumes independent observations. Even with the 30‑day event‑thinning, spatial and temporal autocorrelation may remain, violating the independence assumption and inflating Type I error. Consider using a test that explicitly models dependence (e.g., permutation of whole event clusters, or a hierarchical bootstrap) or verify independence empirically before applying KS.
- A 30‑day left‑censored moving average is justified for seasonal removal, yet the 12‑day gap before the event may still allow leakage of pre‑event pressure trends into the baseline, especially if precursory signals have longer lead times. The plan should either test alternative baseline lengths or conduct a sensitivity analysis on the gap size to ensure no contamination.
- Multiple‑comparison correction (Benjamini‑Hochberg) is applied across all strata, which will further reduce power. Given the already modest power, the plan should pre‑specify a limited set of primary hypotheses or use hierarchical testing to balance false‑discovery control with sensitivity.
- Success Criterion SC‑003 (stability of anomaly detection across σ thresholds) is not explicitly addressed in the plan. The plan mentions a sensitivity sweep over {0.5σ, 1.0σ, 1.5σ} (FR‑007) but does not state that the variation in significance rates or inconsistency rates will be measured and reported as required by SC‑003.
- The Data Acquisition table includes a “Pressure Test Subset (fallback)” entry with no verified source and notes it is “not used in the primary pipeline”. This artifact is not required by any FR or SC and adds unnecessary scope; it should be removed or clearly marked as out‑of‑scope to avoid over‑reach.
- The NOAA NCEP/NCAR Global Sea‑Level Pressure dataset is accessed via the OPeNDAP endpoint but is **not listed in the Verified Datasets block**. This violates Constitution Principle II (Verified Accuracy) which requires all external data sources to be verified. Use a pressure dataset that has an explicit verified URL (e.g., a curated subset hosted on HuggingFace) or add the NOAA endpoint to the verified list after appropriate validation.
- The plan stores the raw NOAA pressure reanalysis file under `data/raw/ncep_global_pressure.nc`. The full NCEP/NCAR reanalysis archive exceeds the allocated disk quota (< 14 GB) for the free‑tier GitHub Actions runner, risking storage overflow and CI failure. Either stream the data without persisting the full file, or switch to a smaller, verified pressure subset that fits within the disk limit.
- The plan marks Principle II (Verified Accuracy) as PASS, yet the NOAA NCEP/NCAR pressure dataset is listed as having *no verified public URL* and is accessed via OPeNDAP at runtime. Constitution Principle II requires every external citation to be verified; using an unverified source while claiming PASS violates this non‑negotiable principle.
- The success criterion SC‑001 defines project success as detecting an effect (Cohen’s d ≥ 0.3 with p < 0.05 in ≥ 80 % of bootstrap resamples). This makes the hypothesis test itself a prerequisite for project success, violating the Constitution’s Null Result Rigor principle and introducing a circular bias: a null result would be treated as project failure rather than a valid scientific outcome.
- Similarly, SC‑002 requires all strata to have p < 0.05 and a coefficient‑of‑variation < 0.1. This again ties project success to achieving statistical significance across all tests, which biases the study toward confirming the hypothesis and undermines the ability to report a robust null finding.
