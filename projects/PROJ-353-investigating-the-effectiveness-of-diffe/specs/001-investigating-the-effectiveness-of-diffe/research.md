# Research: Investigating the Effectiveness of Loss Functions on Small-World Graphs

## Overview

This research validates the feasibility of the implementation plan, focusing on the synthetic data generation strategy, the computational viability of the training loop on CPU, and the statistical methodology for handling censored convergence data and fixed-epoch comparisons.

## Dataset Strategy

Since this project relies on **synthetic** data generated via the Watts-Strogatz model, no external dataset download is required. The "dataset" is the set of 110 graphs generated by `code/generate_graphs.py`.

| Dataset Name | Source Type | Access Method | Verification |
|--------------|-------------|---------------|--------------|
| Watts-Strogatz Synthetic Graphs | Algorithmic Generation | `networkx.watts_strogatz_graph(n, k, beta, seed)` | Verified: `networkx` is a standard Python library. The algorithm is deterministic given a seed. |

**Variable Fit Check**:
- **Required**: Graph topology (adjacency), node features (community labels), connectivity parameter ($\beta$).
- **Generated**: `networkx` generates the graph structure. Community labels are assigned via `community.greedy_modularity_communities`. $\beta$ is the input parameter.
- **Conclusion**: The generation script provides all necessary variables. No external dataset is needed or used.

## Computational Feasibility (CPU vs. GPU)

**Method**: Training a small GCN (2 layers) on graphs of size $N=100$ nodes.
**Hardware Constraint**: GitHub Actions Free Tier (2 CPU, 7GB RAM).

1.  **Model Size**: A GCN with 2 layers, hidden dimension 16, and 100 nodes is negligible in memory (< 100MB).
2.  **Training Time**: 1000 epochs on a 100-node graph with CPU-only PyTorch is estimated at < 30 seconds per run.
3.  **Total Budget**: 220 runs $\times$ 30s = 110 minutes. Well within the 6-hour limit.
4.  **GPU Necessity**: **None**. The problem size is small enough for CPU. No CUDA offload is required.

**Decision**: All computations will run on CPU. No `device="cuda"` code will be used, ensuring maximum compatibility with the CI runner.

## Statistical Methodology

### 1. Downstream Task Protocol (Addressing InfoNCE Accuracy)
- **Problem**: InfoNCE is a self-supervised loss and does not directly optimize for community labels. Measuring "accuracy" requires a downstream task.
- **Solution**: After the GCN encoder is trained with InfoNCE or Cross-Entropy, a **frozen linear probe** (single linear layer) is trained on the node embeddings to predict community labels.
- **Metric**: Accuracy is measured on the validation set of this linear probe. Convergence is defined as the first epoch where the probe accuracy reaches a predefined high-performance threshold.

### 2. Censoring Handling (Tobit Regression)
- **Problem**: Some runs may not reach the target accuracy threshold within `MAX_EPOCHS`. These are "right-censored" observations.
- **Solution**: Tobit Regression (Type I) models the latent variable (epochs to convergence) while accounting for the censoring threshold.
- **Implementation**: `statsmodels` `Tobit` class.
- **Note on Structural Solvability**: We do **not** exclude graphs that fail to converge. Non-convergence is treated as a valid outcome (censored data) to avoid selection bias against high-beta graphs where community structure is weak. The interaction effect may manifest as "InfoNCE fails to converge more often at high beta."

### 3. Survival Analysis (Cox PH)
- **Problem**: Model time-to-event (convergence) with censored data.
- **Solution**: Cox Proportional Hazards model.
- **Implementation**: `lifelines.CoxPHFitter`.
- **Diagnostic**: **Mandatory** Schoenfeld residual test to verify the Proportional Hazards assumption. If $p < 0.05$ for the global test, the Cox model is considered invalid for this dataset, and results will rely on Tobit and fixed-epoch metrics.
- **Variables**: `loss_type` (categorical), `beta` (continuous), `interaction` (product term).

### 4. Accuracy at Fixed Epochs (Addressing Category Error)
- **Problem**: Survival analysis on a deterministic threshold is a category error; it does not capture optimization efficiency if the threshold is never reached.
- **Solution**: Extract accuracy values at fixed epochs (e.g., 100, 500, 1000) for all runs.
- **Analysis**: Compare mean accuracy at these fixed points using linear regression with `loss_type`, `beta`, and `interaction` terms. This provides a direct measure of optimization speed independent of the 0.90 threshold.

### 5. Interaction Focus & Significance
- **Primary Hypothesis**: The effect of `loss_type` on convergence speed/accuracy depends on `beta`.
- **Metric**: Interaction term p-value from Tobit, Cox (if valid), and Fixed-Epoch regression.
- **Significance Definition**: `is_significant` is `true` if **either** the Tobit OR the Cox interaction p-value is < 0.05. **No Bonferroni correction** is applied, as these are alternative estimators for the same hypothesis, not independent tests.

## Power Analysis & Sample Size

- **Target**: Detect moderate interaction effect ($f^2 = 0.15$).
- **Sample**: N=110 (10 per $\beta$ level).
- **Power**: **Low**. With 11 groups and N=110, the power to detect a specific interaction slope change is limited.
- **Limitation**: The study is underpowered. A non-significant result will be interpreted as "inconclusive due to low power" rather than a definitive negative. The analysis will prioritize reporting observed effect sizes and confidence intervals.
