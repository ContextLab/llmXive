## Unresolved concerns

- Task T016 (Linkage Gate) depends on T018a (Metric Calculation). T018a writes `ingest_metrics.json`. T016 reads `ingest_metrics.json`. This is correct. However, T018a also writes `LINKAGE_THRESHOLD` to `config/analysis_params.json`. T016 reads `LINKAGE_THRESHOLD` from `config/analysis_params.json`. This creates a dependency chain: T018a -> T016. But T018a's description says 'Must run after T013/T014'. T016's description says 'Must run after T018a'. This is consistent. The issue is T018b (Define Threshold) is listed as a dependency for T018a, which is circular as noted in the first concern.
- Task T023 (Confounding Check) depends on T022d (Finalize Ambiguity Status). T023 checks if 'prime' is confounded with trial order. It needs the `linked_trials.csv` (from T017) and the `stimulus_metadata.csv` (from T022e). T022d is a status reporting task. T023 should depend on T022e (Merge Metadata), not T022d. T022d does not produce the data T023 needs.
- Task T024 (Aggregate Data) depends on T023 (Confounding Check). T024 aggregates `linked_trials.csv` to `aggregated_trials.csv`. T023 checks for confounding. T024 does not need the result of T023 to run. T023 is a diagnostic that might *halt* the pipeline, but T024 (aggregation) can run in parallel or before T023. Making T024 depend on T023 is an unnecessary serialization of independent data transformations.
- Task T025 (LMM Fitting) depends on T024 (Aggregation). T025 uses `aggregated_trials.csv`. This is correct. However, T025 also depends on T023 (Confounding Check) implicitly (via T024's dependency). If T023 halts, T024 and T025 are blocked. This is correct behavior. The issue is T023's dependency on T022d (status) instead of T022e (data).
- Task T027a (VIF Calculation) depends on T025 (Modeling). T027a calculates VIF for predictors. VIF is a property of the *design matrix* (predictors), not the *model fit*. It can (and should) be calculated *before* fitting the model to decide if the model is safe to run. Calculating it after fitting (T025) is too late to prevent a collinear model fit. T027a should be before T025, or T025 should be conditional on T027a's result.
- Task T027b (Model Convergence Success Rate) depends on T025 (Modeling). This is correct, as it measures the outcome of T025. However, T027b is listed as a dependency for T028 (FDR Correction)? No, T028 is independent. T027b is a post-modeling metric. This is fine.
- Task T028 (FDR Correction) depends on T025 (Modeling). FDR correction is applied to p-values *from* the model. This is correct. T028 should be after T025.
- Task T029 (Associational Framing) depends on T025 (Modeling). T029 modifies the output of T025 to add caution notes. This is correct. T029 should be after T025.
- Task T047 (Convergence Fallback) is integrated into T025. This is correct. T047 is not a separate task but a logic branch within T025. The dependency list correctly shows T047 as integrated.
- Task T013 (Ingest) and T014 (Metadata Extraction) are both in US1. T014 depends on T013. T014 extracts metadata from the data downloaded by T013. This is correct. T013 must run before T014.
- Task T013 requires downloading from 'verified OSF/HF URLs' but does not specify WHICH URL to use or how to retrieve the 'verified list' referenced in the spec. The implementer cannot execute this deterministically without a hardcoded URL or a specific path to a verified_sources.json file.

It assumes the existence of `data/processed/metadata_mapping.csv` (from T014) but does not explicitly state the dependency or the file path format, risking a runtime error if the file is missing or named differently.
