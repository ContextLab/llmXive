## Unresolved concerns

- The plan states ‘fit an OLS (or thin‑plate‑spline GAM) regression’.  Allowing a post‑hoc choice between a linear model and a flexible GAM introduces model‑selection flexibility that is not pre‑registered, opening the analysis to data‑driven fishing and inflating Type I error.
- Density predictors (π(n), 1/ln n, ∑_{p≤n}1/p) are highly collinear.  The plan only mentions computing VIF and reporting any VIF > 5, but does not specify a strategy for handling multicollinearity (e.g., dropping variables, regularisation).  Using collinear predictors can render coefficient tests unreliable.
- No explicit power analysis is provided.  Although the sample size (n up to 50 000) is large, autocorrelation in the ordered data reduces the effective sample size, and the plan does not quantify the detectable effect size for the density predictors under the chosen HAC‑adjusted SE framework.
- Potential confounding factors such as prime‑gap structure, higher‑order terms from the generating function, or non‑density‑related systematic deviations are not modelled or controlled for.  Without accounting for these, any observed association between R(n) and the density features may be spurious.
- The plan references a `reference_data.csv` file for verifying DP counts for n≤100 (e.g., "Matches reference values for n≤100 (see `reference_data.csv`)."), but this file is not listed in the project structure nor provided in the repository. Without this dataset, the verification step cannot be performed, undermining the claim of exactness and violating the data‑hygiene principle.
- The plan’s Quickstart and task description refer to a task identifier **T016b** (e.g., “Feature engineering … created by T016b”) but no such task is defined in the Task List (which only includes T001–T013). This breaks traceability between the plan and its task definitions.
- The `dataset.schema.yaml` contract requires the field `R_n` to be a non‑null number, yet the plan (and data‑model) state that `R_n` may be omitted or set to null for rows where `p_P_n` = 0 or `Q_as_n` ≤ 0. This creates a contradiction between the contract and the intended data output.
- The plan claims that the calibrated Meinardus asymptotic “does **not** directly employ the individual density metrics π(n), 1/ln n, or ∑_{p≤n}1/p” (see line “The baseline computation uses the full prime‑zeta saddle‑point method and does not directly employ the individual density metrics …”). However the asymptotic formula
\[
  Q_{as}(n)=C\,n^{-3/4}\exp\!\Bigl(2\sqrt{\tfrac{n}{2}\cdot\tfrac{1}{\ln n}}\Bigr)
\]
contains the factor \(1/\ln n\) inside the exponent. This is exactly one of the three density predictors later regressed against the log‑residual \(R(n)\). Consequently the validation target (the residual) is **not independent** of the predictor \(1/\ln n\); the predictor is already baked into the baseline. This creates a circular/tautological validation where the analysis is guaranteed to find a relationship (or at least a non‑zero coefficient) because the predictor contributed to the quantity being explained. The claim of “eliminating circularity (Principle VII)” is therefore false.
- The predictor set includes both π(n) (the prime‑counting function) and \(1/\ln n\). By the Prime Number Theorem, π(n) ≈ n/ln n, so these two variables are highly collinear (VIF ≫ 5). The plan acknowledges possible high VIF but still retains the model “for exploratory purposes”. Such multicollinearity violates the assumption of independent regressors, inflates standard errors, and makes the significance tests (HAC‑adjusted p‑values) unreliable. A more sound approach would either orthogonalise the predictors (e.g., regress π(n) on \(1/\ln n\) and use residuals) or drop one of the redundant variables.
