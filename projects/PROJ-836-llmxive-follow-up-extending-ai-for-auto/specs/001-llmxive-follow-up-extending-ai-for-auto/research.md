# Research: llmXive follow-up: extending "AI for Auto-Research: Roadmap & User Guide"

## 1. Problem Definition

The project investigates whether structural anomalies in AI-generated literature review graphs (specifically cycle density, isolation ratio, and semantic distance) can predict experimental failure or novelty degradation. The hypothesis is that AI-generated research ideas with "hallucinated" or ungrounded logic will exhibit distinct topological signatures compared to valid, well-grounded research.

## 2. Dataset Strategy

### 2.1 Primary Dataset: "AI for Auto-Research" Benchmark (Hypothetical)
The project targets the "AI for Auto-Research" benchmark, which is hypothesized to contain:
- **Creation Phase Logs**: Literature review text generated by AI agents.
- **Validation Phase Results**: Ground-truth binary labels indicating "experimental failure" or "novelty degradation" vs. "valid".

**Verified Datasets**:
- **Status**: The "AI for Auto-Research" benchmark is **not** a verified, publicly available dataset with a programmatic download URL (e.g., Hugging Face ID, direct URL) as of the current planning stage.
- **Fallback Strategy**: If the dataset cannot be programmatically downloaded, the pipeline will switch to a **Synthetic Data Generation** mode. This mode will generate synthetic literature review texts and assign labels based on a simulated topological process to ensure the pipeline can be tested and validated. The synthetic data will be explicitly labeled as such in all reports.
- **Access**: The dataset must be programmatically downloadable (e.g., `datasets.load_dataset`, direct URL) to run on CI. If a real dataset is found, it will be used; otherwise, the synthetic generator will be invoked.
- **Constraint**: If the dataset requires registration or credentials (e.g., ADNI, HCP), it is **NOT** usable. An open substitute must be identified, or the project must be reframed.
- **Feasibility Check**: The dataset size must be manageable on a 7 GB RAM CPU runner. If the full dataset is too large, a well-defined random sample (e.g., first 1000 rows) will be used, with power limitations explicitly noted.

**Action**: The implementation will first attempt to load the dataset from the canonical source. If the dataset is missing or inaccessible, the pipeline will fail gracefully with a clear error message, then automatically switch to the synthetic data generator.

### 2.2 Data Preprocessing & Integrity
- **Missing Labels**: Entries without ground-truth labels will be excluded from training (FR-007).
- **Empty Text**: Literature reviews that are too short to form a graph will be assigned default metric values (0.0) and logged (FR-008).
- **Duplicate Entities**: Nodes with identical labels will be merged before metric calculation to ensure graph integrity.

## 3. Methodology

### 3.1 Graph Construction (FR-001, FR-002)
1. **Parsing**: Use `spaCy` (or a small transformer) to parse literature review text and extract entity-relation triplets (Concept, Method, Claim).
2. **Triplet Validation**: To ensure **Topological Metric Integrity** (Constitution Principle VI), extracted triplets will be validated against the source text using a fuzzy matching threshold to confirm that the relationships exist in the text, preventing parsing artifacts from skewing metrics.
3. **Graph Building**: Construct a directed graph using `networkx`. Nodes represent concepts/methods; edges represent claims.
4. **Validation**: Ensure the graph construction pipeline strictly adheres to the methodology sketch to avoid parsing artifacts.

### 3.2 Metric Extraction
- **Cycle Density**: Ratio of actual cycles to maximum possible cycles (0.0 to 1.0).
- **Isolation Ratio**: **Corrected Definition**: The fraction of nodes in the graph that have an in-degree of zero (i.e., no incoming edges from other nodes within the extracted subgraph). This metric serves as a hypothesized proxy for "lack of grounding" or "hallucination" (FR-010).
- **Semantic Distance**: **Corrected Definition**: The mean pairwise cosine distance between concept embeddings (using `all-MiniLM-L6-v2`) **within each connected component** of the graph. Components with a single node are excluded from this calculation to avoid undefined distances. The final metric is the average of the distances calculated for each component with size > 1.

### 3.3 Predictive Modeling (FR-004, FR-005)
- **Model**: Logistic Regression (interpretable coefficients) as primary model.
- **Fallback**: Random Forest (with SHAP values) if LR fails to converge.
- **Validation**: 5-fold cross-validation to estimate AUC.
- **Performance Metric**: AUC compared against random guessing (AUC = 0.5) (SC-001).

### 3.4 Statistical Significance (FR-006, SC-002)
- **Permutation Test**: Shuffle labels **[deferred] times** (minimum) to generate a null distribution of AUC scores.
- **Power Analysis**: A minimum of 1,000 permutations is required to achieve a standard error of ~0.007 for a p-value threshold of 0.05.
- **Runtime Guard**: If the 6-hour runtime limit is approached, the number of permutations may be reduced, but **never below [deferred]** to maintain statistical validity. If the dataset is small (n < 30), a **bootstrap confidence interval** for the AUC will be calculated to supplement the permutation test, addressing the discrete nature of the null distribution in small samples.
- **Significance**: Calculate p-value to determine if the observed correlation is statistically significant (p < 0.05).
- **Causal Framing**: Since this is observational data, claims will be framed as associational, not causal.

## 4. Compute Feasibility

- **CPU-First**: All models (LR, RF) and graph operations are CPU-tractable. `sentence-transformers` will be run in CPU mode.
- **Memory**: Streaming the dataset and processing graphs one-by-one will ensure memory usage remains within acceptable operational limits.
- **Runtime**: The pipeline is designed to complete within 6 hours. Permutation tests will be capped at [deferred] (minimum) to ensure feasibility.
- **GPU Escape Hatch**: Not required for this project. If the NLP step proves too slow on CPU, a small model (e.g., `all-MiniLM-L6-v2`) is still CPU-optimized. No transformer fine-tuning is planned.

## 5. Limitations & Risks

- **Dataset Availability**: The "AI for Auto-Research" benchmark is currently hypothetical. The project relies on a synthetic data generation fallback if a real dataset is not found.
- **Metric Validity**: "Isolation Ratio" is a hypothesized proxy for hallucination. If no ground-truth hallucination data exists, this will be reported as a limitation (FR-010).
- **Collinearity**: Topological metrics may be definitionally related. The analysis will report descriptive relationships and acknowledge collinearity, avoiding claims of independent effects where inappropriate.
- **Power**: If the dataset is small (n < 30), statistical power will be limited. This will be explicitly stated in the results, and a bootstrap confidence interval will be used.

## 6. Decision Rationale

- **Why Logistic Regression?** It provides interpretable coefficients, allowing us to see the direction and magnitude of each metric's effect on failure prediction.
- **Why Permutation Test?** It provides a robust, non-parametric way to verify significance without assuming a specific distribution of the test statistic.
- **Why CPU-only?** The project goals (reproducibility, low cost) align with CPU execution. The methods chosen (LR, RF, NetworkX) are all efficient on CPU.
- **Why Synthetic Fallback?** Ensures the pipeline can be tested and validated even if the primary dataset is unavailable, preventing project stagnation.
