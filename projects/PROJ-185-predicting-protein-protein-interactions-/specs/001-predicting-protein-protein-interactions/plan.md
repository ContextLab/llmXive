# Implementation Plan: Predict Protein‑Protein Interactions from Co‑expression Networks in Public Plant Databases

**Branch**: `PROJ-185-predict-ppi-coexpression` | **Date**: 2026‑07‑25 | **Spec**: [spec.md](../spec.md)  
**Input**: Feature specification from `specs/PROJ-185-predict-ppi-coexpression/spec.md`

## Summary
The pipeline will (1) download public Arabidopsis thaliana RNA‑seq count matrices from NCBI GEO, (2) normalize (VST or TPM) and filter genes, (3) correct batch effects, (4) compute pairwise gene‑gene correlations, (5) map genes to STRING protein identifiers, (6) retain edges with correlation ≥ 0.80 (never below 0.75) and FDR ≤ 0.05, (7) optionally filter edges by orthogonal subcellular colocalization evidence, (8) output per‑species edge‑list files, (9) evaluate against STRING high‑confidence interactions (combined ≥ 700, excluding co‑expression channel) producing AUROC/AUPRC and a degree‑preserving random‑graph baseline, (10) perform GO enrichment on the predicted interactome, and (11) generate per‑species and final summary reports. All steps are orchestrated via a Makefile and fully reproducible via a pinned random seed.

## Technical Context
- **Language/Version**: Python 3.11, R 4.2  
- **Primary Dependencies**: `pandas`, `numpy`, `scipy`, `statsmodels`, `networkx`, `goatools`, `torch` (CPU only), `rpy2` (to call DESeq2/limma), `biopython`, `GEOparse`, `pybiomart`, `stringdb` (simple wrapper).  
- **Storage**: Files under `data/` (raw GEO series, STRING reference), `results/` (edges, scores, reports).  
- **Testing**: `pytest` for unit tests, `ruff` + `black` for linting, `schema` validation via `jsonschema`.  
- **Target Platform**: Linux GitHub Actions runner (multiple CPUs, 7 GB RAM).  
- **Constraints**: Full pipeline wall‑clock ≤ 6 h; correlation threshold ≥ 0.75, default 0.80; edge‑list ≥ 10 000 edges for non‑empty species (SC‑001).  
- **Scale/Scope**: Default Arabidopsis dataset expected to contain a moderate number of samples.; after CPM ≥ 1 filtering and variance‑based sub‑selection ≤ 5 000 genes → ≤ 12.5 M pairwise tests.

## Constitution Check
| Principle | Compliance Statement |
|-----------|----------------------|
| I. Reproducibility | All random processes use `--seed`; software versions are pinned in `requirements.txt` and `renv.lock`. External datasets are fetched from canonical GEO/STRING URLs on every run. |
| II. Verified Accuracy | All citations (e.g., Zhang 2020, Lee 2021, arXiv 2107.01173, arXiv 2402.03547) are verified against the provided sources; no unverified claims are introduced. |
| III. Data Hygiene | Raw GEO count matrices are stored unchanged under `data/raw/` with SHA‑256 checksums recorded in `state/artifact_hashes.yaml`. All transformations write new files with provenance metadata. |
| IV. Single Source of Truth | Every statistic in the final report is traced to a specific row in a TSV/JSON output file generated by the pipeline. |
| V. Versioning Discipline | All artifacts (code, data, schemas) are content‑hashed; changes update `state/projects/PROJ-185-...yaml`. |
| VI. Biological Data Provenance | GEO accession identifiers are preserved in file names and logs; normalization method and parameters are logged. |
| VII. Evaluation Benchmarking | STRING high‑confidence set (combined ≥ 700, excluding co‑expression channel) is downloaded from the official STRING release; AUROC/AUPRC thresholds (≥ 0.70) and random‑graph baseline are computed as required. |

## Complexity Tracking
All FR and SC items are mapped to concrete plan phases below. No principle violations remain; the plan is intentionally linear to respect the 6‑hour runtime budget.

## Phase‑by‑Phase Plan (FR/SC Mapping)

| Phase | Tasks | FR IDs | SC IDs |
|-------|-------|--------|--------|
| **Phase 1 – Data Acquisition** | Download GEO series listed in `config/species.yaml`; compute SHA‑256; abort on failure. | FR‑001 | – |
| **Phase 2 – Normalization & Filtering** | VST (DESeq2) or TPM; CPM ≥ 1 in >80 % samples; retain top‑variance genes (≤5 000). **Power analysis**: simulation with a representative set of samples shows [deferred] power to detect true Pearson r ≥ 0.80 at Bonferroni‑adjusted α≈×10⁻⁹ (see Spec assumptions). After batch correction, regress out gene‑length and GC‑content covariates; verify reduction in variance explained by these factors. | FR‑002, FR‑003, FR‑014, FR‑045 | – |
| **Phase 3 – Correlation Computation** | Block‑wise Pearson (or Spearman for TPM); compute p‑values; apply Benjamini–Hochberg FDR ≤ 0.05; store raw scores in `raw_correlations_*.tsv.gz`. | FR‑004, FR‑020, FR‑025, FR‑045 | – |
| **Phase 4 – Identifier Mapping** | Map TAIR IDs via `org.At.tair.db`; fallback to Ensembl BioMart; record **mapping rate** (percent of genes successfully mapped) and log it; unmapped genes are omitted but their proportion is reported in the per‑species summary (bias assessment). | FR‑005 | – |
| **Phase 5 – Edge Selection & Thresholding** | Apply correlation ≥ 0.80 (enforced minimum 0.75). Optional orthogonal filter: retain only edges where both proteins share a subcellular compartment according to UniProt (adds construct validity). Validate `predicted_ppi_*.tsv` against `contracts/predicted_edges.schema.yaml`. Run **threshold sensitivity analysis** (0.75 → 0.90) and select the threshold that maximizes F1 while keeping FDR ≤ 0.05; report both the default (0.80) and the selected optimal threshold. Write `threshold_sensitivity_*.tsv` and validate against `contracts/threshold_sensitivity.schema.yaml`. | FR‑004, FR‑011, FR‑013, FR‑030, FR‑023, FR‑045 | SC‑001, SC‑003, SC‑004, SC‑005, SC‑006 |
| **Phase 6 – Evaluation** | Score all raw correlations against STRING high‑confidence (≥ 700, excl. co‑expression channel); generate balanced negative set; compute **AUPRC as primary metric** (precision‑recall curve) and AUROC for completeness; generate degree‑preserving random‑graph baseline; compute baseline p‑value; write `evaluation_metrics.json` and validate against `contracts/evaluation.schema.yaml`. | FR‑006, FR‑007, FR‑016, FR‑018, FR‑019, FR‑032, FR‑012 | SC‑001 (AUPRC ≥ 0.70, AUROC ≥ 0.70), SC‑004, SC‑005, SC‑006 |
| **Phase 7 – Functional Enrichment** | GOATOOLS Fisher test on genes in predicted PPIs; Benjamini–Hochberg correction; write `go_enrichment_*.tsv`; if no term passes, write “No significant enrichment”. Validate output against `contracts/go_enrichment.schema.yaml`. | FR‑008, FR‑022, FR‑024 | SC‑002, SC‑004, SC‑005, SC‑006 |
| **Phase 8 – Reporting, Logging & Verification** | Assemble `summary_*.txt` (edge count, evaluation metrics, top GO terms, mapping rate, construct‑validity justification per FR‑026, selected correlation threshold). Aggregate into `final_report.txt`. JSON‑Line logging (`pipeline_log.schema.yaml`) records command‑line, software versions, seed, and all major actions. After each Make target, run verification script (FR‑017) that checks presence, parsability, and schema compliance of all required outputs. | FR‑010, FR‑017, FR‑021, FR‑028, FR‑034, FR‑035, FR‑026 | SC‑003, SC‑004, SC‑005, SC‑006 |

All success criteria are addressed explicitly in the corresponding phases.
