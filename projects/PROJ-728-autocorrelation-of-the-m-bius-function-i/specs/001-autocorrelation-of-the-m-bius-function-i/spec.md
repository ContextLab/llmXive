# Feature Specification: Autocorrelation of the Möbius Function in Short Intervals

**Feature Branch**: `001-autocorrelation-mobius`  
**Created**: 2026-06-17  
**Status**: Draft  
**Input**: User description: "Autocorrelation of the Möbius Function in Short Intervals"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Generate Möbius Sequence and Compute Short-Interval Autocorrelation (Priority: P1)

A researcher needs to compute the normalized autocorrelation of the Möbius function $\mu(n)$ across short intervals of lengths $L \in \{10^3, 10^4, 10^5\}$ to verify if the empirical values align with the zero-correlation prediction of Chowla's conjecture.

**Why this priority**: This is the core scientific engine of the project. Without the ability to generate the sequence and compute the specific statistic (autocorrelation) for defined lags and intervals, no hypothesis testing or visualization can occur. It directly addresses the primary research question.

**Independent Test**: The system can generate a binary array of $\mu(n)$ for $N=10^7$ and output a CSV file containing the normalized autocorrelation values for a single interval of length $L=10^3$ and a single lag $h=1$. The output can be verified mathematically against a manual calculation for that specific window.

**Acceptance Scenarios**:

1. **Given** a maximum integer $N=10^7$, **When** the sieve algorithm runs, **Then** the system produces an array of $\mu(n)$ values where $\mu(n) \in \{-1, 0, 1\}$ for all $1 \le n \le N$.
2. **Given** a window of length $L=10^3$ starting at index $k$, **When** the autocorrelation is computed for lag $h=1$, **Then** the system outputs the normalized sum $\frac{1}{L-h}\sum_{i=1}^{L-h}\mu(k+i)\mu(k+i+h)$ with a precision of at least 6 decimal places.
3. **Given** the requirement to test multiple interval lengths, **When** the process is executed for $L \in \{10^3, 10^4, 10^5\}$, **Then** the system successfully computes statistics for all specified lengths without memory overflow or execution timeout.

### User Story 2 - Perform Permutation-Based Statistical Significance Testing (Priority: P2)

A researcher needs to determine if the observed autocorrelation is statistically significant by comparing it against a null distribution generated by randomizing the sign patterns within the same interval, preserving the density of zeros.

**Why this priority**: Computing the raw autocorrelation is insufficient to validate Chowla's conjecture; one must establish that the observed value is indistinguishable from random noise. This step transforms raw data into a statistical claim (p-value), which is essential for the "Expected Results" section of the idea.

**Independent Test**: The system can take a single interval of $\mu(n)$ values, generate 1,000 shuffled permutations of those values (preserving the count of zeros), compute the autocorrelation for each permutation at a specific lag, and output the resulting p-value for the original observation.

**Acceptance Scenarios**:

1. **Given** an interval of $\mu(n)$ values with a specific proportion of zeros, **When** the permutation engine runs, **Then** it generates [deferred] distinct sequences where the set of values (including zero count) is identical to the original, but the order is randomized.
2. **Given** an observed autocorrelation value $r_{obs}$ and a null distribution of [deferred] permuted values, **When** the p-value is calculated, **Then** it is reported as the two-sided proportion of permuted values with absolute magnitude greater than or equal to $|r_{obs}|$.
3. **Given** a lag $h$ where the null hypothesis holds, **When** the test is repeated over 100 independent intervals, **Then** the resulting p-values are uniformly distributed (approximate Kolmogorov-Smirnov test $p > 0.05$).

### User Story 3 - Visualize Autocorrelation Heatmaps and Confidence Bands (Priority: P3)

A researcher needs to visualize the autocorrelation landscape across different lags and interval lengths to identify systematic deviations or patterns that might be missed in tabular data, specifically overlaying the theoretical zero line and permutation-based confidence intervals.

**Why this priority**: While the numerical results are the primary output, the visualization is the mechanism for "qualitative evidence" mentioned in the motivation. It allows the researcher to quickly assess if deviations are localized or systematic, supporting the "Expected Results" claim of "systematic positive or negative bias" if it exists.

**Independent Test**: The system can generate a heatmap image where the X-axis represents lags $h \in \{1, \dots, L/2\}$, the Y-axis represents interval start positions, and the color represents the autocorrelation value, with a distinct overlay for the 95% confidence envelope derived from the permutation test.

**Acceptance Scenarios**:

1. **Given** a dataset of autocorrelation values for all lags $h \le L/2$ across multiple intervals, **When** the heatmap is generated, **Then** the plot includes a horizontal line at $y=0$ and shaded regions representing the 2.5th and 97.5th percentiles of the null distribution.
2. **Given** a specific interval length $L=10^5$, **When** the visualization is rendered, **Then** the image resolution is sufficient to distinguish individual lags without pixelation artifacts (minimum 1000x1000 pixels).
3. **Given** a lag where the empirical autocorrelation exceeds the 95% confidence band, **When** the heatmap is inspected, **Then** that specific cell is highlighted or annotated to indicate statistical significance.

---

### Edge Cases

- **What happens when the interval contains no non-zero values?** The system must detect intervals where all $\mu(n) = 0$ (highly unlikely for $L \ge 10^3$ but possible in theory for specific $N$) and either skip the permutation test for that interval or return a null result with a warning flag, preventing division by zero in normalization.
- **How does the system handle boundary lags?** For lags $h$ close to $L/2$, the summation window shrinks. The system must correctly normalize by $L-h$ rather than $L$ to avoid bias, and ensure the permutation logic respects the shrinking effective sample size if the lag is dynamic.
- **What if the permutation test yields a p-value of exactly 0 or 1?** The system must handle edge cases where the observed statistic is more extreme than all 1,000 permutations by reporting $p < 0.001$ or $p > 0.999$ rather than exact 0/1, to avoid false absolute certainty.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST implement a linear-time sieve to compute $\mu(n)$ for $1 \le n \le 10^7$ and store the result as a binary array (See US-1).
- **FR-002**: System MUST compute the normalized autocorrelation $\frac{1}{L-h}\sum \mu(k)\mu(k+h)$ for all lags $h \in \{1, \dots, \lfloor L/2 \rfloor\}$ within sliding windows of length $L \in \{10^3, 10^4, 10^5\}$ (See US-1).
- **FR-003**: System MUST generate 1,000 random sign permutations of the $\mu$-values within each window, strictly preserving the proportion of zeros, to construct a null distribution (See US-2).
- **FR-004**: System MUST calculate two-sided p-values and 95% confidence intervals for each lag by comparing empirical values against the permutation null distribution (See US-2).
- **FR-005**: System MUST produce a heatmap visualization for each interval length $L$, overlaying the empirical autocorrelation values, the theoretical zero line, and the permutation-derived confidence bands (See US-3).
- **FR-006**: System MUST output all raw statistical data (autocorrelation values, p-values, confidence bounds) to a structured CSV file for reproducibility (See US-1).

### Key Entities

- **Möbius Sequence**: A contiguous array of integers $\{-1, 0, 1\}$ representing the values of $\mu(n)$ for $n \in [1, N]$.
- **Autocorrelation Metric**: A floating-point value representing the normalized sum of products $\mu(k)\mu(k+h)$ for a specific window and lag.
- **Null Distribution**: A set of [deferred] autocorrelation values generated from permuted sequences, used to derive p-values and confidence intervals.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: The normalized autocorrelation values for lags $h \le L/2$ are measured against the theoretical prediction of zero (Chowla's conjecture) to determine statistical indistinguishability (See US-1).
- **SC-002**: The p-values derived from permutation tests are measured against the standard $\alpha=0.05$ threshold to identify lags with statistically significant deviations from randomness (See US-2).
- **SC-003**: The execution time for the full pipeline (sieve, correlation, 1,000 permutations, visualization) for $N=10^7$ and all specified $L$ is measured against the 6-hour GitHub Actions free-tier limit to ensure feasibility (See US-1).
- **SC-004**: The memory footprint of the sieve array and intermediate data structures is measured against the 7 GB RAM limit of the free-tier runner to ensure no out-of-memory crashes (See US-1).
- **SC-005**: The consistency of the permutation test is measured by verifying that the empirical distribution of p-values under the null hypothesis (simulated on random data) follows a uniform distribution (See US-2).

## Assumptions

- **Assumption about data availability**: The Möbius function $\mu(n)$ is deterministic and can be computed exactly for $N=10^7$ using a linear sieve without external data sources or probabilistic approximations.
- **Assumption about computational constraints**: The linear-time sieve and the subsequent autocorrelation calculations for $N=10^7$ will fit within the ~7 GB RAM and ~14 GB disk limits of the GitHub Actions free-tier runner, provided the data is stored as compact integer arrays (1 byte per value) and processed in streaming windows where possible.
- **Assumption about statistical validity**: The null hypothesis of "random sign pattern" is sufficiently approximated by the permutation test that preserves the zero-density, and the sample size of 1,000 permutations provides sufficient resolution for p-value estimation at the $\alpha=0.05$ level.
- **Assumption about methodological framing**: Since the study is observational (computing a property of a deterministic sequence rather than a randomized experiment), all findings regarding "deviations" will be framed as associational evidence against the random-sign heuristic, not as causal proofs of non-randomness, consistent with the methodology panel's requirements for observational designs.
- **Assumption about threshold justification**: The choice of interval lengths $L \in \{10^3, 10^4, 10^5\}$ and lag range $h \le L/2$ is based on the "short interval" definition in the research question and existing literature (Matomäki & Teräväinen 2019); a sensitivity analysis sweeping $L$ by factors of 10 is deferred to future work as the current scope is fixed by the research question.
- **Assumption about library dependencies**: The analysis relies solely on Python's standard library and `numpy` (CPU-only, default precision), avoiding any GPU-specific libraries (CUDA, bitsandbytes) or large-model training frameworks that would exceed the free-tier compute capabilities.
