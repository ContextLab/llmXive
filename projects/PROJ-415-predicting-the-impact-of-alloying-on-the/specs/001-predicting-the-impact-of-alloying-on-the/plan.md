# Implementation Plan: Predicting the Impact of Alloying on the Diffusion Activation Energy in FCC Metals

**Branch**: `001-predict-alloy-diffusion` | **Date**: 2026-06-26 | **Spec**: `specs/001-predict-alloy-diffusion/spec.md`
**Input**: Feature specification from `/specs/001-predict-alloy-diffusion/spec.md`

## Summary

This project implements a data-driven pipeline to predict how alloying elements affect diffusion activation energy in metals. The approach ingests experimental/simulation data from verified public repositories. The primary target is **FCC self-diffusion**. 

**Critical Constraint**: The pipeline executes a mandatory **Data Availability Check** at the very start. If no verified real dataset for FCC self-diffusion is found in the provided `Verified datasets` block, the pipeline **halts immediately** with a specific error. It does **not** proceed to modeling, nor does it substitute synthetic data or pivot to unrelated datasets (e.g., HCP or text data). This ensures scientific validity and compliance with the project's core requirement to analyze *real* diffusion activation energy.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| **Nested Cross-Validation** | Required by FR-004 to prevent data leakage during hyperparameter tuning. | A simple train/test split would risk overfitting to the validation set, violating scientific rigor. |
| **Multiple Models (RF, GB, Linear)** | RF/GB for prediction accuracy; Linear for statistical inference (p-values) of `size_mismatch`. | A single model type cannot satisfy both high-accuracy prediction and statistical significance testing of a specific coefficient. |
| **Bootstrap CI (sufficient resamples)** | Required by FR-005 to establish robust confidence intervals for the Linear coefficient. | Standard error estimation assumes normality which may not hold for small datasets (n < 200); bootstrap is more robust. |
| **Data Availability Check** | Required to ensure the research question is answerable with real data. | Proceeding with synthetic or irrelevant data would render the scientific results invalid and violate the core research premise. |

## Statistical Rigor & Validation

-   **Multiple Comparisons**: Not applicable for the primary regression (single hypothesis: size mismatch effect). However, if multiple descriptors are tested, Bonferroni correction will be applied.
-   **Power Analysis**: Acknowledged limitation. If dataset size < 50, the study is underpowered. Results will be framed as "exploratory" with wide confidence intervals.
-   **Causal Inference**: **Observational Data Only**. No randomization of solutes. All claims will be framed as "associational" (e.g., "Size mismatch is associated with..."). No causal claims will be made.
-   **Collinearity**: If `size_mismatch` and `electronegativity` are correlated, VIF (Variance Inflation Factor) will be checked. If VIF > 5, collinearity will be reported, and independent effects will not be claimed.
-   **Sensitivity Analysis (FR-005)**:
    -   **Condition**: Executed only if a valid dataset (FCC) is loaded.
    -   **Method**: Sweep classification threshold for "significant shift" from 0.45 eV to 0.55 eV in 0.01 eV increments.
    -   **Metric**: Stability measured as `std(classification_rates) / (max_threshold - min_threshold)` (unit: 1/eV).
    -   **Output**: `reports/sensitivity_plot.png` and `validation_report.json`.

## Compute Feasibility

-   **CPU-First**: All models (RF, GB, Linear) are lightweight and run efficiently on 2 CPU cores.
-   **Memory**: Dataset < 10 MB (if data exists). Feature engineering and model training will use < 2 GB RAM.
-   **Time**: Grid search on small datasets (< 200 rows) will take < 30 minutes.

## Data Availability Failure Protocol (FR-001 Compliance)

Per FR-001, if the "Data Availability Check" fails (no verified FCC dataset found):
1.  The pipeline **halts immediately**.
2.  The script generates `data/curated/data_provenance.json` with the following content:
    ```json
    {
      "status": "HALTED",
      "reason": "NO_VERIFIED_DATASET",
      "message": "ERROR: No verified real dataset found for FCC self-diffusion. Synthetic data is not permitted.",
      "timestamp": "<ISO8601>",
      "attempted_sources": ["list of attempted URLs"]
    }
    ```
3.  No modeling, feature engineering, or validation steps are executed.
4.  The process exits with a non-zero exit code to signal failure to the CI runner.

## Assumptions (Updated)

-   **Assumption about data availability**: Public repositories contain sufficient data points (≥50) for **FCC** self-diffusion. **If no verified dataset is found in the provided block, the project terminates.**
-   **Assumption about atomic properties**: Standard periodic table values for atomic radius and electronegativity are sufficient proxies for the electronic environment effects in FCC alloys, and no quantum-mechanical calculations are required for feature generation.
-   **Assumption about linearity**: The relationship between size mismatch and activation energy shift can be adequately captured by a Random Forest regressor without requiring deep neural networks or GPU acceleration. The Linear Regression model is used solely for statistical inference of the geometric descriptor's significance.
-   **Assumption about threshold justification**: A threshold is used as an arbitrary exploratory baseline for sensitivity analysis. The sweep (–0.55 eV) validates robustness.
-   **Assumption about inference framing**: Since the dataset is observational, all conclusions will be framed as associational.
-   **Assumption about ground truth**: The "ground truth" for the baseline calculation is defined by external physical standards (e.g., NIST, handbook values) for the pure host metal.
