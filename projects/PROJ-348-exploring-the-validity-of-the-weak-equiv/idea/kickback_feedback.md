## Unresolved concerns

- FR-006 mandates 'exactly 10,000 iterations' for the Monte Carlo simulation, while the Edge Cases section states: 'The system must retry with a reduced iteration count ([deferred])... if convergence is not achieved'. These are contradictory: one requires a fixed count, the other allows dynamic reduction. FR-006 must be updated to allow variable iterations or the Edge Case logic must be removed.
- FR-009 and the Assumptions section both mandate the pipeline must complete within '6 hours on a CPU-only environment with ≤7 GB RAM'. However, the spec simultaneously requires downloading multi-decadal high-precision ephemeris data for 4 planets, computing time-series differences, performing OLS regression, and running a Monte Carlo simulation with up to 10,000 iterations. The spec does not define how these computationally intensive tasks (especially the MC simulation) fit within the 6-hour/7GB constraint, creating a potential internal contradiction between functional requirements and performance constraints.
- Terminology inconsistency: User Story 1 refers to 'INPOP19a' as a data source, while FR-002 refers to 'INPOP19a ephemeris data'. While likely referring to the same thing, the spec should consistently use either 'INPOP19a' or 'INPOP19a ephemeris' throughout to avoid ambiguity. Additionally, FR-001 mentions 'astroquery' but FR-002 mentions 'astroquery.imcce' or 'direct file download' without clarifying if these are mutually exclusive or fallback options.
- FR-004 and User Story 2 require retrieving gravitational binding energy fractions ($\Omega$) from 'peer-reviewed interior structure models (e.g., Seager et al., Nimmo et al.)'. However, the spec does not define a mechanism to handle cases where these specific models are unavailable or conflicting. The Edge Cases mention 'retry fetching from alternative sources', but FR-004 does not explicitly allow for alternative sources, creating a potential conflict between the strict requirement and the error handling logic.
- FR-007 states the system must 'derive an upper bound on the Nordtvedt parameter $ta$... if the p-value... is > 0.05'. However, User Story 3 states the system must 'determine if the correlation is statistically significant (p < 0.05) and derive an upper bound... if the null hypothesis cannot be rejected'. These are logically equivalent but use different phrasing ('p-value > 0.05' vs 'null hypothesis cannot be rejected'). While not a direct contradiction, the spec should use consistent terminology for statistical decision-making to avoid confusion.
- The 'Key Entities' section defines 'GravitationalBindingEnergy' as '$\Omega pprox -GM/Rc^2$', but User Story 2 and FR-004 explicitly state that $\Omega$ must be derived from 'peer-reviewed interior structure models' and NOT from 'bulk NASA Fact Sheets' (which use the simple GM/R approximation). The definition in Key Entities contradicts the requirement to use complex interior models, as the formula provided is the simplified bulk approximation that the spec explicitly forbids.
- FR-006 mandates 'exactly 10,000 iterations' OR 'until standard error < 0.01'. These are mutually exclusive stopping criteria that cannot be simultaneously satisfied in a deterministic test. A test cannot verify 'exactly 10,000' if the loop terminates early at 5,000 due to convergence. The requirement must specify a single, deterministic stopping condition (e.g., 'run 10,000 iterations' OR 'run until SE < 0.01, capped at 10,000').
- FR-009 requires execution within '6 hours on a CPU-only environment with ≤7 GB RAM'. This is not verifiable without defining the specific hardware architecture (e.g., 'Intel Xeon E5-2680 v4' or 'AWS t3.medium') and the specific input dataset size (e.g., '1950-2025, daily sampling'). 'CPU-only' is ambiguous across different CPU generations; a test on a modern 16-core CPU will pass while an older 2-core CPU fails, making the requirement non-deterministic without a defined reference environment.
- SC-001 states the RMS must fall within '[100m, 1500m]'. This range is derived from 'documented INPOP/JPL agreement' but does not specify the *source* document or the *specific time interval* for this agreement. Without a fixed reference value or a specific citation to the 'documented agreement', a tester cannot verify if the result is correct, as the 'agreement' varies by planet and epoch.
- SC-002 requires $\Omega$ values to match 'published values... within ±0.5%'. It does not specify *which* published values (e.g., 'Nimmo et al. 2004 Table 2' vs 'Seager et al. 2015'). Different papers provide different values for planetary binding energy. Without a specific target value or a single authoritative source cited in the spec, the success criterion is unverifiable.
- The edge case 'retry with a reduced iteration count ([deferred])' is not a verifiable procedure. '[deferred]' is a placeholder for a value that does not exist in the spec. A test cannot verify 'retry with reduced count' if the reduced count is undefined. The spec must define the fallback iteration count (e.g., 'retry with 1,000 iterations') or the logic for calculating it.
- FR-004 mandates retrieving $\Omega$ from 'peer-reviewed interior structure models (e.g., Seager et al., Nimmo et al.)'. It does not specify *which* model to use if multiple exist or if they conflict. A test cannot verify 'correctness' if the spec allows multiple valid sources with potentially different values. The requirement must specify a single canonical source or a deterministic selection rule (e.g., 'use the most recent peer-reviewed value').
- The spec redefines the research question from the Idea's 'differential acceleration... derived from high-precision ranging residuals after subtracting a GR-only ephemeris' to a 'differential analysis' comparing two independent ephemerides (JPL vs. INPOP). The Idea explicitly requires generating a 'GR-only' simulation baseline to subtract from observations. The spec drops the 'GR-only simulation' and 'subtracting' steps entirely, replacing them with a direct comparison of two observational models. This is a fundamental drift in the research methodology that changes the nature of the signal being measured (model disagreement vs. observation-model residual).
- The spec's regression target (RMS of ephemeris difference vectors) does not match the Idea's target ('differential acceleration... derived from... residuals'). The Idea requires calculating residuals from a GR-only baseline to isolate the Nordtvedt effect. The spec calculates the RMS of the difference between JPL and INPOP. These are physically distinct quantities; the spec's approach measures inter-ephemeris agreement, not the specific WEP violation signal defined in the Idea's research question.
- The spec assumes 'The linear relationship between the RMS of the ephemeris difference vector and the gravitational binding energy fraction ($\Omega$) is a valid proxy for testing the Nordtvedt effect'. The Idea's methodology relies on 'subtracting a GR-only ephemeris' to find residuals. The spec's assumption validates a different physical hypothesis (that model disagreement scales with $\Omega$) rather than the Idea's hypothesis (that observation-model residuals scale with $\Omega$). This is a redefinition of the scientific claim.
- FR-003 mandates computing the 'time-series difference vector... between the JPL Horizons and INPOP19a ephemerides'. The Idea's methodology explicitly requires 'Generate a GR-only trajectory... Compute the difference between the JPL Horizons observational data and the GR-only simulation'. The spec drops the 'GR-only simulation' generation and the 'observation minus simulation' subtraction, replacing it with 'model minus model'. This is an under-reach of the Idea's required methodology steps.
- FR-005 requires regression of 'RMS of the ephemeris difference vectors' (JPL vs INPOP). The Idea requires regression of 'orbital residuals' (Observation vs GR-only). The dependent variable in the spec is not the dependent variable in the Idea. This is a scope drift that invalidates the ability to answer the Idea's research question.
- The core validation strategy is circular/tautological. The spec proposes to validate the Nordtvedt effect (a WEP violation) by computing the difference between two independent ephemerides (JPL Horizons and INPOP19a) and regressing this difference against planetary binding energy ($\Omega$). However, both JPL and INPOP ephemerides are constructed by fitting observational data to a dynamical model that *already assumes* General Relativity (where the Nordtvedt parameter $ta = 0$). The difference between two GR-based models reflects modeling uncertainties (e.g., asteroid masses, solar $J_2$, initial conditions), not a physical WEP violation signal. Regressing these 'model residuals' against $\Omega$ tests for correlations in modeling errors, not the physical effect. The 'validation target' (ephemeris difference) is definitionally determined by the same GR assumptions used to generate the 'predictor' context, rendering the test incapable of detecting the claimed phenomenon.
- The proposed statistical relationship is non-trivial in the wrong direction. The spec assumes a linear relationship between RMS ephemeris differences and $\Omega$ to detect the Nordtvedt effect. However, the Nordtvedt effect manifests as a specific time-dependent polarization of orbits (a periodic perturbation), not a static RMS shift or a secular precession rate difference. The RMS of the difference vector between two GR-based ephemerides is dominated by unmodeled non-gravitational forces and parameter estimation noise, which do not scale linearly with $\Omega$. The claim that 'the differential signal scales with $\Omega$' is true for the *physical* effect, but false for the *residuals of GR-based models*. The methodology conflates the physical signal with the noise floor of the models, making the regression slope an invalid proxy for $ta$.
- The independent variable ($\Omega$) is treated as a static, known quantity, but the spec fails to account for the fact that the 'signal' (ephemeris difference) is not a direct measurement of acceleration but a derived residual. The spec assumes that if a WEP violation exists, it would manifest as a systematic offset in the JPL-INPOP difference. This is incorrect; a WEP violation would cause the *actual* orbits to deviate from the GR-predicted orbits. Since both JPL and INPOP *force* the orbits to fit the data using GR, the residuals (JPL - INPOP) will not contain the WEP signal unless one of the ephemerides was explicitly generated with a non-zero $ta$ (which neither is). The validation target is effectively 'zero' by construction for the signal of interest.
- The Monte Carlo simulation design is methodologically unsound for the research question. The spec proposes resampling 'ephemeris difference vector uncertainties' to generate a null distribution for the regression slope. However, the uncertainties in the JPL-INPOP difference are dominated by systematic modeling errors (e.g., asteroid belt mass distribution, solar oblateness), not random Gaussian noise. Resampling these systematic errors does not generate a valid null distribution for a physical parameter like $ta$. The simulation tests the stability of the *modeling noise*, not the statistical significance of a physical correlation. A valid test would require injecting a synthetic WEP signal into the raw observational data and re-fitting the ephemerides, which is computationally infeasible with public data and outside the scope of the proposed pipeline.
- The assumption that 'the inter-ephemeris differences (JPL vs. INPOP) are dominated by modeling differences and potential SEP violations' is scientifically flawed. The differences are dominated by *modeling differences* (different force models, different data weighting, different initial conditions) which are uncorrelated with $\Omega$ in a way that mimics a WEP signal. The assumption that these differences can be cleanly separated into 'modeling noise' and 'SEP violation' without a full re-fit of the ephemerides with a variable $ta$ is invalid. The spec treats the residuals as a proxy for the physical effect, which is a category error.
