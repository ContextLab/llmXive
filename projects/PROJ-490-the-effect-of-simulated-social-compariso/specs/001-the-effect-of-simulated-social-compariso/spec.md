# Project Specification: The Effect of Simulated Social Comparison on Self-Esteem in Virtual Reality

## 1. Overview
This project investigates the impact of simulated social comparison in Virtual Reality (VR) on self-esteem.
The study utilizes an experimental design where participants are exposed to either an "idealized" avatar condition
(high social comparison) or a "neutral" avatar condition (control).

## 2. Functional Requirements

### FR-001: Sample Size
The study must include a minimum of N ≥ 100 participants to ensure statistical power.

### FR-002: Missing Data Handling
Missing data must be handled using Multiple Imputation by Chained Equations (MICE) if missingness is < 20%.
Rows with > 20% missingness across key variables must be excluded.

### FR-003: Statistical Model (ANCOVA Specification)
**AMENDED SPECIFICATION (Per T017a):**
The primary statistical model is an Analysis of Covariance (ANCOVA).
- **Outcome Variable (Dependent Variable):** `post_self_esteem` (Post-test self-esteem score).
- **Covariate:** `pre_self_esteem` (Pre-test self-esteem score).
- **Predictors:** `avatar_condition` (0=Neutral, 1=Idealized), `comparison_tendency`, and the interaction term `avatar_condition * comparison_tendency`.

**REASON FOR AMENDMENT:** The original requirement to use `self-esteem_change` (post - pre) as the outcome is deprecated.
Using change scores as the outcome when the pre-score is a predictor (or implicitly correlated) introduces mathematical coupling,
leading to biased estimates. The ANCOVA approach (modeling `post_self_esteem` directly while controlling for `pre_self_esteem`)
is the statistically robust alternative mandated by the research plan.

### FR-004: Assumption Validation
The model must validate the following assumptions:
- Normality of residuals (Shapiro-Wilk test).
- Homoscedasticity (Breusch-Pagan test).
- Multicollinearity (Variance Inflation Factor, VIF < 5).

### FR-005: Robustness
Bootstrap resampling (≥ 1,000 iterations) must be performed to estimate confidence intervals and assess stability.
Stability is confirmed if the variance of CI widths across bootstrap samples is < 0.01.

### FR-006: Error Correction
Family-wise error correction (Bonferroni or Holm) must be applied to the set of hypothesis tests generated by sensitivity sweeps.

### FR-007: Sensitivity Analysis
The pipeline must perform a threshold sensitivity sweep over imputation limits and p-value thresholds.

### FR-008: Output
Regression coefficients must be exported to `data/processed/regression_coefficients.csv` and diagnostics to `data/processed/model_diagnostics.json`.

### FR-009: Data Integrity
The system must verify the presence of all required variables (`avatar_condition`, `pre_self_esteem`, `post_self_esteem`, `comparison_tendency`) before processing.
If real data lacks IRB/Consent documentation, the system must fallback to synthetic data generation with explicit logging.

### FR-010: Interpretation
The final report must distinguish between "Empirical Association" (real data) and "Simulated Causal Effect" (synthetic data).

### FR-011: Synthetic Fallback
If no valid real dataset is found or consent is missing, a synthetic dataset must be generated using ground-truth parameters:
- intercept = 0
- main_effect_avatar = 0.1
- main_effect_comparison = 0.1
- interaction_beta = 0.2
- noise_sigma = 1.0
This data must be labeled as "Pipeline Validation Only".

### FR-012: Final Report
A comprehensive JSON report must be generated containing data source type, model results, bootstrap stability, and sensitivity findings.

### FR-013: Imputation Fallback
If `miceforest` is unavailable, the system must fallback to `sklearn.impute.IterativeImputer`.

### FR-014: Logging
All data path decisions (Real vs. Synthetic) must be logged to `logs/data_path_decision.log`.

## 3. Data Model

### Input Variables
- `participant_id`: String (Unique identifier)
- `pre_self_esteem`: Float (RSES score, pre-intervention)
- `post_self_esteem`: Float (RSES score, post-intervention)
- `avatar_condition`: Int (0 = Neutral, 1 = Idealized)
- `comparison_tendency`: Float (INCOM scale score)

### Output Variables
- `coefficients`: Array of model parameters (name, estimate, std_err, p_value)
- `assumptions`: Object containing diagnostic p-values and VIF scores.

## 4. Execution Flow
1. **Data Discovery:** Query HuggingFace, OpenML, OSF for valid datasets.
2. **IRB Verification:** Check for consent documentation.
3. **Data Loading:** Load real data or generate synthetic data (if fallback triggered).
4. **Preprocessing:** Handle missing values (MICE), normalize variables.
5. **Modeling:** Fit ANCOVA (Outcome: `post_self_esteem`, Covariate: `pre_self_esteem`).
6. **Validation:** Check assumptions (Normality, Homoscedasticity, Collinearity).
7. **Robustness:** Run bootstrap resampling and sensitivity analysis.
8. **Reporting:** Generate final JSON report and CSV exports.

## 5. Constraints
- **Compute:** Must complete within 6 hours on CPU-only hardware.
- **Memory:** Must handle large datasets via streaming or chunking if necessary.
- **Reproducibility:** All random operations must use a fixed seed defined in `code/data/config.py`.
