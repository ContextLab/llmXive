## Unresolved concerns

- The plan states Phase 4 (Baseline & Validation) is 'Gated: Wait for human annotation ingestion' and Phase 5 halts if human data is missing. However, the 'Unresolved Concerns' section admits that tasks T025a/T026b allow US-01 validation against a 'Gold-Standard Proxy' for MVP/CI. This creates a causal validity gap: the plan claims to reject simulation-only fallbacks for final reporting, yet the task structure permits validating the core statistical claim (US-01) against a proxy. If the proxy is not a verified human-annotated gold standard, the statistical separation (p < 0.05) does not prove the system detects *novel* threats, only that it separates data based on the proxy's arbitrary labels.
- The methodology proposes using 'Logistic regression of drift score vs. human label' to compute Cohen's Kappa. This is a statistical error. Cohen's Kappa measures inter-rater agreement between two categorical classifications (e.,g., System Flag vs. Human Label). Logistic regression estimates the probability of a binary outcome given a continuous predictor; it does not compute agreement metrics. The plan conflates correlation (logistic regression) with agreement (Kappa), invalidating the proposed validation method for US-02.
- The plan proposes comparing the Drift AUC to the Flan-T5 AUC with a threshold of 'Drift AUC >= (Flan-T5 AUC - 0.10)'. This assumes the Flan-T5 baseline is a 'ground truth' or 'oracle' for novel threat detection. However, Flan-T5 is a zero-shot classifier trained on general web data, not a verified expert on AgentDoG novel threats. If Flan-T5 has low accuracy on the specific novel patterns, the drift method could be 'within 0.10' of a poor baseline and still be ineffective. The methodology lacks a mechanism to validate the baseline's own accuracy against the human gold standard before using it as a reference.
- The plan separates 'US-01 (Drift Separation)' from 'US-02 (Human Agreement)'. It suggests US-01 can be validated against a proxy. However, US-01's acceptance criteria explicitly require 'significant separation between benign and novel logs'. If the 'proxy' used for US-01 validation is not the human-annotated gold standard (as required by Constitution Principle VI), then the 'novel' and 'benign' labels in the test set are unverified. Validating separation against unverified labels does not satisfy the causal claim that the system detects *novel* patterns.
- The feasibility analysis claims 'Total: < 1 hour' for 10k logs including Flan-T5 inference. `google/flan-t5-small` on CPU for 10k samples (even with batching) is likely to exceed this significantly given the 2-core constraint and the overhead of tokenization and generation. If the runtime exceeds the 6-hour limit or causes OOM, the 'CPU OOM' logic described in 'Unresolved Concerns' (which contradicts itself by mentioning CUDA OOM) is insufficient. The plan lacks a robust fallback strategy for CPU performance degradation that doesn't rely on the disallowed GPU escape hatch.

- US-02 validation plan is circular/tautological. The plan computes 'Drift Score' as the minimum cosine distance to category centroids derived from labeled data. It then proposes to validate this score against 'Human Annotations' of the same logs. However, the 'Human Annotations' (is_novel) are likely derived from the same underlying safety taxonomy or are the ground truth used to define the categories. If the human label is 'Safety' and the centroid is the mean of 'Safety' logs, the distance is trivially minimized. Validating a distance-to-category metric against the category label itself is not an empirical test of 'novelty' or 'drift'; it is a verification of the embedding space's clustering, not the detection of *new* patterns. The 'novelty' ground truth must be independent of the category definitions used to build the centroids.
- The Mann-Whitney U test in US-01 compares 'high-drift' vs 'low-drift' bins. These bins are constructed *by sorting* the data on the drift score itself. Testing whether the distribution of a variable differs between its own high and low quantiles is a tautology; the test will always return p < 0.05 and a large effect size because the bins are defined by the variable's magnitude. This analysis cannot validate the *utility* of the drift score; it only confirms that the score has variance. A valid validation requires an independent outcome variable (e.g., human 'novelty' label) to compare against the drift score distribution.
- The baseline comparison (US-03) compares the Drift Method's AUC-ROC against Flan-T5's AUC-ROC. However, the 'Drift Method' is a zero-shot distance metric, while Flan-T5 is a zero-shot classifier. If the 'ground truth' for AUC-ROC is the same safety taxonomy labels used to build the centroids, the Drift Method is effectively a 'nearest centroid' classifier. Comparing two zero-shot methods against the same training-derived labels does not prove the Drift Method detects *novel* patterns; it only proves it aligns with the existing taxonomy. The 'novelty' claim requires a ground truth of *unseen* or *unlabeled* patterns, which the current plan does not define as the target for AUC calculation.
- The plan defines 'Drift Score' as the minimum distance to *any* centroid. If a log belongs to the 'Safety' category, its distance to the 'Safety' centroid will be low. If it is 'novel', it should be far from *all* centroids. The plan's validation logic (US-02) compares 'is_novel' (1/0) against 'review_flag' (high drift). However, if 'is_novel' is defined as 'not in the 4 categories', then a log labeled 'Safety' (0) should have a low drift score. The plan fails to explicitly define the 'novel' ground truth as 'far from all centroids'. Without this explicit definition, the statistical test (Mann-Whitney) might simply be measuring 'distance to the correct category' vs 'distance to the wrong category', which is a standard classification task, not a drift detection task.
- The plan states 'top 10% and bottom 10% quantiles' for stratification. While this resolves the placeholder issue, the scientific rationale for these specific thresholds is missing. Why 10%? A sensitivity analysis or justification based on the expected distribution of drift scores (e.g., to capture the tail of the distribution where novelty is expected) is required to ensure the validation is not biased by arbitrary binning.
