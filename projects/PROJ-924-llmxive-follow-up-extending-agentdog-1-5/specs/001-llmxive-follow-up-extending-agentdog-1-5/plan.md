# Implementation Plan: Zero-Shot Drift Detection for AgentDoG 1.5

**Branch**: `PROJ-924-zero-shot-drift` | **Date**: 2026-07-17 | **Spec**: `spec.md`
**Input**: Feature specification from `specs/PROJ-924/spec.md`

## Summary

This project extends the AgentDoG 1.5 safety taxonomy by implementing a zero-shot drift detection mechanism. The system computes cosine distances between log embeddings (derived from `all-MiniLM-L6-v2`) and pre-defined safety category centroids to flag novel harmful patterns. The implementation strictly adheres to the GitHub Actions free-tier constraints (7GB RAM, CPU cores) and mandates a human-annotated gold standard for validation.

## Technical Context

**Language/Version**: Python 3.11
**Primary Dependencies**: `torch` (CPU-only), `sentence-transformers`, `scikit-learn`, `pandas`, `numpy`, `datasets`
**Storage**: Local file system (`data/`), JSON/Parquet for intermediate artifacts
**Testing**: `pytest` with `ruff` for linting
**Target Platform**: Linux (GitHub Actions free-tier runner)
**Project Type**: Research pipeline / CLI tool
**Performance Goals**: Process ~10k logs in < 6 hours (conservative estimate); Embedding generation < 30s per batch of 64
**Constraints**: Max RAM GB (GitHub Actions free-tier), No local GPU, Batch size = 64 (fixed per verified fact), No synthetic data substitution for human validation.
**Scale/Scope**: Proxy dataset (bigcode/the-stack subset + openai/humaneval), a substantial volume of logs, safety categories.

> **Note on GPU**: No GPU escape hatch is planned. Constitution Principle VII mandates CPU-only execution. If the baseline `google/flan-t5-small` cannot run within 7GB RAM on CPU, the plan will utilize a smaller, quantized variant or a distilled alternative that fits the memory budget, rather than assuming external GPU resources.

## Phase Plan

### Phase 0: Research & Data Strategy
- **Goal**: Identify open, downloadable datasets matching the AgentDoG taxonomy.
- **Action**: Verify dataset availability (Safety-Proxy: bigcode/the-stack + openai/humaneval). Confirm `all-MiniLM-L6-v2` and `google/flan-t5-small` fit in 7GB RAM on CPU.
- **Output**: `research.md`.

### Phase 1: Data Model & Contracts
- **Goal**: Define schemas for logs, embeddings, and drift scores.
- **Action**: Create `contracts/drift_output.schema.yaml`, `contracts/agent_log.schema.yaml`, `contracts/human_annotation.schema.yaml`, `contracts/taxonomy_centroid.schema.yaml`, `contracts/drift_result.schema.yaml`, `contracts/log.schema.yaml`, `contracts/taxonomy.schema.yaml`. Define `data-model.md`.
- **Output**: `data-model.md`, `contracts/*.yaml`.

### Phase 2: Implementation Setup
- **Goal**: Setup `config.py`, `requirements.txt`, and CI tests.
- **Action**: Implement `config.py` with `RANDOM_SEED=42`, `MAX_RAM_GB=7`, `BATCH_SIZE=64`. Write `pytest` tests for config and ruff.
- **Output**: `code/config.py`, `tests/unit/`.

### Phase 3: Core Pipeline (US-01)
- **Goal**: Implement centroid generation and drift scoring.
- **Action**: Load data (streaming), generate centroids, compute cosine distances **referencing the Drift Score entity defined in data-model.md**, and write results to `drift_output.schema.yaml`.
- **Output**: `code/embeddings.py`, `data/processed/scores.parquet`.

### Phase 4: Baseline & Validation (US-02, US-03)
- **Goal**: Run Flan-T5 baseline and statistical validation.
- **Action**: Stratify data (**top [deferred] and bottom [deferred]** quantiles), run baseline (CPU), compute AUC-ROC.
- **Output**: `code/baseline_llm.py`, `code/validation.py`.

### Phase 5: Final Reporting
- **Goal**: Generate report with verified metrics.
- **Action**: Compute Kappa (if human data present), Mann-Whitney U, Cohen's d.
- **Constraint**: **HARD GATE**: If human data is missing, the pipeline halts; no simulation-based report is generated. Project status set to 'Incomplete'.
- **Output**: Final report.

## Unresolved Concerns Resolution

1.  **Human Validation Gating**: The plan explicitly removes the "simulation fallback" for the final report. `T035-real-human-verify` is a hard dependency for the final validation step. If human data is missing, the project is marked as "Incomplete" rather than proceeding with a proxy.
2.  **CPU OOM Logic**: The plan removes the GPU escape hatch entirely.
3. **Task Dependency Order**: The plan maintains the separation between US-01 and US-02, but ensures the dependency on human data is explicit for the final validation.
4. **Statistical Validation**:  The plan clarifies that the Mann-Whitney U test compares Human-Labeled Novel vs. Human-Labeled Benign.
5.  **Resource Constraints**: The plan ensures CPU-only execution and adheres to the 7GB RAM limit.
6.  **Data Availability**: The plan acknowledges the limitations of the current dataset and prioritizes human-annotated data for final validation.
