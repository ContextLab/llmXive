## Unresolved concerns

- The plan states that, because no verified dataset with a clearly defined dependent variable is available, the numeric column with the greatest variance will be treated as the outcome ("treat the numeric column with the greatest variance as the outcome"). This arbitrary surrogate compromises construct validity – the measured ‘outcome’ may not represent the construct the research question intends to study, making effect‑size and p‑value changes difficult to interpret.
- The scope is limited to only 2–3 public datasets ("Scale/Scope: 2–3 public datasets"). Such a small sample of datasets provides very low statistical power to detect modest impacts of cleaning procedures, even with 1 000 bootstrap iterations, and limits the generalizability of any conclusions.
- No diagnostic checks for the assumptions underlying t‑tests and OLS regressions (normality, homoscedasticity, linearity) are described. Cleaning operations (especially outlier removal) can alter these assumptions, potentially invalidating the statistical tests. The plan should include explicit assumption‑checking steps and fallback robust methods if violations are detected.
- Multiple‑comparison correction is mentioned only for predictors within a single dataset (Bonferroni across predictors). The plan does not address the family‑wise error rate across the many cleaning variants, outlier‑threshold sweeps, and permutation runs, which could inflate Type I error when interpreting delta metrics.
- The research hypotheses are phrased as expectations (e.g., "Outlier removal is expected to reduce p‑values"). While the authors note that statements will be associational, the wording still suggests a causal interpretation of cleaning actions on statistical significance. Clarify that the study assesses *associative* changes and avoid causal language.
- The plan references a “Dataset Strategy” that includes primary statistical datasets (UCI Wine Quality and UCI Adult Income) which are marked as *not available* and lack a clearly defined numeric outcome variable. Using such unverified or ill‑specified datasets undermines the core research question of quantifying how data cleaning impacts statistical inference, because the statistical tests require a well‑defined dependent variable. Replace these with verified public datasets that have an explicit outcome column and provide reachable URLs.
- The statement “Scale/Scope: 2–3 public datasets (see Dataset Strategy)” is insufficient; the plan must explicitly name the concrete, verified datasets that will be used (including their HuggingFace repo IDs or URLs) and justify their suitability for t‑tests and regressions.
- The acquisition phase mentions downloading raw datasets and verifying checksums, but does not reference the `dataset.schema.yaml` contract defined in `contracts/dataset.schema.yaml`. To ensure data‑hygiene and contract compliance, the plan should explicitly state that each downloaded dataset will be validated against this schema before further processing.
- Baseline analysis stores results in JSON files, yet the plan does not cite the `analysis_result.schema.yaml` contract (or the `baseline_metrics.schema.yaml` which extends it). Adding a step that validates each analysis result against the appropriate schema will close the gap between the plan and the contract suite.
- Cleaning pipelines are described, but the plan does not indicate that cleaning‑metadata fields (e.g., `rows_removed`, `missing_before`, `missing_after`, `variance_reduction`) required by the `cleaned_metrics.schema.yaml` will be captured and written. The plan should be updated to state that these fields will be populated and later validated against the cleaned‑metrics contract.
