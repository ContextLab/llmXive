# Data Model Documentation

**Project**: Exploring the Relationship Between Brain Network Dynamics and Fluid Intelligence
**Version**: 1.0.0
**Date**: 2026-06-24

This document defines the core data entities used throughout the pipeline, aligning with the requirements specified in `specs/amendment-001-fluid-intelligence-n10.md` and the project plan.

## Entities

### 1. Subject

Represents a single participant in the study. This entity aggregates demographic information and links to behavioral and neuroimaging data.

**Attributes**:

| Attribute | Type | Description | Source |
|:--- |:--- |:--- |:--- |
| `id` | `str` | Unique subject identifier (e.g., "sub-001", "sub-002"). Matches BIDS naming convention. | OpenNeuro `participants.tsv` |
| `age` | `int` | Age of the subject in years. | OpenNeuro `participants.tsv` |
| `gender` | `str` | Biological sex/gender of the subject (e.g., "M", "F", "Other"). | OpenNeuro `participants.tsv` |
| `fluid_intelligence_score` | `float` | Normalized Fluid Intelligence score (0.0 to 1.0 or z-score). **Critical**: Used for correlation analysis. | OpenNeuro `participants.tsv` or sidecar JSON |
| `fmr_path` | `Path` | Path to the preprocessed NIfTI file (`data/processed/sub-XX_preproc.nii.gz`). | Generated by `preprocess.py` |
| `excluded` | `bool` | Flag indicating if the subject was excluded due to motion artifacts or missing metadata. | `motion_exclusion_log.csv` |

**Constraints**:
- `id` must be unique across the dataset.
- `fluid_intelligence_score` must be present; subjects missing this score are excluded per `specs/amendment-001-fluid-intelligence-n10.md` (FR-001).
- `age` and `gender` are required for covariate control in regression models.

### 2. GraphMetric

Represents a derived graph theoretical metric calculated from the functional connectivity matrix of a subject.

**Attributes**:

| Attribute | Type | Description | Source |
|:--- |:--- |:--- |:--- |
| `subject_id` | `str` | Reference to the `Subject.id`. | `Subject` entity |
| `metric_name` | `str` | Name of the graph metric (e.g., "global_efficiency", "clustering_coefficient", "modularity"). | `graph_metrics.py` |
| `value` | `float` | The calculated numerical value of the metric. | `graph_metrics.py` |
| `atlas_id` | `str` | Identifier of the parcellation atlas used (e.g., "Schaefer-200"). | Configuration (`config.yaml`) |
| `resolution` | `float` | Resolution parameter used for modularity (if applicable). | `graph_metrics.py` |

**Constraints**:
- `metric_name` must be one of the predefined metrics (Global Efficiency, Clustering Coefficient, Modularity).
- `value` must be within valid theoretical bounds (e.g., Efficiency ∈ [0, 1]).
- Aggregated in `data/processed/graph_metrics.csv`.

### 3. BehavioralScore

Represents the behavioral outcome variable used for correlation analysis. While often merged into the `Subject` entity for simplicity in the CSV output, this entity definition clarifies the specific data point used for statistical testing.

**Attributes**:

| Attribute | Type | Description | Source |
|:--- |:--- |:--- |:--- |
| `subject_id` | `str` | Reference to the `Subject.id`. | `Subject` entity |
| `score_type` | `str` | Type of behavioral score (e.g., "Fluid_Intelligence", "Creativity"). | Amended to "Fluid_Intelligence" only |
| `raw_score` | `float` | The raw score from the assessment. | OpenNeuro `participants.tsv` |
| `normalized_score` | `float` | The score normalized for analysis (z-score or 0-1 scaling). | `download.py` / `stats.py` |

**Constraints**:
- Only `Fluid_Intelligence` is valid per `specs/amendment-001-fluid-intelligence-n10.md`.
- Used as the dependent variable (Y) in correlation and regression analyses (US3).

## Data Flow Summary

1. **Ingestion**: `Subject` data is downloaded from OpenNeuro (`data/raw`).
2. **Preprocessing**: `Subject.fmr_path` is generated by `preprocess.py`.
3. **Graph Analysis**: `GraphMetric` entries are generated for each `Subject` and aggregated into `data/processed/graph_metrics.csv`.
4. **Statistics**: `BehavioralScore` (embedded in `Subject`) is correlated with `GraphMetric` values in `data/processed/correlation_results.csv`.
