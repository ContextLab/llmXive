# Constitution FR-030: Statistical Methods for Code Complexity and Bug Prediction

## Version
2.0 (Amended 2023-10-27)

## Scope
This constitution defines the mandatory statistical methods and validation procedures
for the llmXive automated science pipeline, specifically for projects analyzing
the relationship between code complexity metrics and bug prediction accuracy.

## Principle I: Data Integrity
All data ingestion processes must use real, external sources. Synthetic or fabricated
data is strictly prohibited unless explicitly authorized for unit testing with
clear isolation from production results.

## Principle II: Reproducibility
All experiments must be reproducible. Random seeds must be fixed (default: 42)
and documented. All dependencies must be pinned.

## Principle III: Resource Limits
Execution must adhere to strict memory and time limits to ensure CI compatibility.
Processes exceeding these limits must fail loudly.

## Principle IV: Validation
All generated artifacts (datasets, models, reports) must pass schema validation
and integrity checks before being considered complete.

## Principle V: Transparency
All exclusions, errors, and warnings during data processing must be logged
and reported in the final analysis.

## Principle VI: Statistical Methods
**Mandatory Methods:**
- **Correlation Analysis:** Use **Point-Biserial correlation** for binary target variables
 (buggy vs. non-buggy) and continuous metrics.
- **Significance Testing:** Use **Permutation Tests** (non-parametric) to validate
 differences between model performance distributions (e.g., ROC-AUC).
- **Prohibited Methods:** Pearson correlation and McNemar's test are explicitly
 deprecated for this project scope due to their assumptions about data distribution
 and paired nominal data which do not align with the continuous metric vs. binary
 label structure.

**Rationale:**
The Point-Biserial correlation is the mathematically correct extension of Pearson's
r for a binary variable, providing a more accurate measure of association in this
specific context. Permutation tests offer a robust, assumption-free method for
significance testing, avoiding the parametric assumptions required by t-tests
or McNemar's test in this scenario.

## Principle VII: Error Handling
Failures in external toolchains (e.g., PMD, JavaParser) must be logged and
handled gracefully without silently substituting results.

## Amendment History
- v1.0: Initial draft (Pearson/McNemar).
- v2.0: Amended to replace Pearson/McNemar with Point-Biserial/Permutation
 following human ratification of the constitutional amendment process.
