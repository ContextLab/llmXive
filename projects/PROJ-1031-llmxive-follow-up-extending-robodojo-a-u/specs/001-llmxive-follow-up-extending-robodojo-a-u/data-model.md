# Data Model: llmXive Follow-up: Extending RoboDojo with Symbolic Abstractions

## Overview

This document defines the data structures used in the symbolic abstraction pipeline. All data is persisted to `data/` in Parquet format for efficiency and type safety.

## Key Entities

### 1. SemanticEmbedding
High-level vector representation of visual observations.
- **Source**: `code/models/semantic_encoder.py`
- **Storage**: `data/interim/semantic_embeddings.parquet`
- **Schema**:
    - `task_id`: string (UUID)
    - `frame_id`: integer
    - `embedding_vector`: list[float] (fixed size, e.g., 512)
    - `timestamp`: datetime
    - `mapping_accuracy`: float (optional, for validation)

### 2. SymbolicState
Discrete state in PDDL-like format representing object affordances and connectivity.
- **Source**: `code/models/symbolic_state.py`
- **Storage**: `data/interim/symbolic_states.parquet`
- **Schema**:
    - `state_id`: string (UUID)
    - `task_id`: string
    - `predicates`: list[string] (e.g., ["Graspable(A)", "On(A, B)"])
    - `affordances`: list[string] (e.g., ["Move", "Grasp"])
    - `connectivity_graph`: json (adjacency list representation)
    - `graph_type`: string (e.g., "Full Affordance", "Simplified Connectivity" for ablation)

### 3. ActionSequence
Ordered list of discrete sub-goals generated by the symbolic planner.
- **Source**: `code/services/planner.py`
- **Storage**: `data/interim/action_sequences.parquet`
- **Schema**:
    - `sequence_id`: string (UUID)
    - `task_id`: string
    - `steps`: list[json] (each step: {action, target_state_id})
    - `planner_type`: string ("A*" or "MCTS")
    - `planning_time_ms`: float
    - `graph_type`: string (for ablation tracking)

### 4. ExecutionOutcome
Binary record of a task execution in the real-world environment.
- **Source**: `code/services/failure_detector.py`
- **Storage**: `data/interim/execution_logs.parquet` (T024, T026)
- **Schema**:
    - `log_id`: string (UUID)
    - `task_id`: string
    - `step_index`: integer
    - `outcome`: string ("Success", "Failure")
    - `failure_mode`: string ("Planner Infeasibility", "Controller Execution Failure", "Encoder Ambiguity", "None")
    - `timestamp`: datetime
    - `error_details`: string (optional)
    - `graph_type`: string (for ablation tracking)

### 5. ComputeMetric
Record of CPU cycles, memory usage, and wall-clock time.
- **Source**: `code/utils/logging.py`
- **Storage**: `data/interim/compute_metrics.parquet`
- **Schema**:
    - `metric_id`: string (UUID)
    - `task_id`: string
    - `phase`: string ("Planning", "Execution", "Total")
    - `cpu_usage_pct`: float
    - `memory_mb`: float
    - `wall_clock_seconds`: float
    - `graph_type`: string (for ablation tracking)

### 6. AblationResult
Result of the ablation study comparing different state representation levels.
- **Source**: `code/analysis/stats.py`
- **Storage**: `data/interim/ablation_results.parquet`
- **Schema**:
    - `ablation_id`: string (UUID)
    - `graph_type`: string
    - `success_rate`: float
    - `compute_overhead`: float
    - `catastrophic_failure_rate`: float

## Data Flow

1.  **Raw Data**: `RoboDojo` Parquet (Video, Tasks) -> `data/raw/` (Checksummed).
2.  **Embeddings**: `Raw Data` -> `SemanticEmbedding` -> `data/interim/semantic_embeddings.parquet`.
3.  **States**: `Embeddings` -> `SymbolicState` -> `data/interim/symbolic_states.parquet`.
4.  **Planning**: `States` -> `ActionSequence` -> `data/interim/action_sequences.parquet`.
5.  **Execution**: `ActionSequence` -> `ExecutionOutcome` -> `data/interim/execution_logs.parquet`.
6.  **Metrics**: `All Phases` -> `ComputeMetric` -> `data/interim/compute_metrics.parquet`.
7.  **Ablation**: `ExecutionOutcome` + `ComputeMetric` -> `AblationResult` -> `data/interim/ablation_results.parquet`.

## Validation Rules

- **Uniqueness**: `task_id` must be unique per run.
- **Completeness**: `failure_mode` must be "None" if `outcome` is "Success".
- **Type Safety**: All vectors must match the expected dimension (512).
- **Referential Integrity**: `state_id` in `ActionSequence` must exist in `SymbolicState`.
- **Graph Type Consistency**: `graph_type` must be consistent across related records (State, Sequence, Outcome, Metric).
