## Unresolved concerns

- The 'Perfect Low-Level Executor' (Oracle) is defined as a 'simulated ground-truth physics' model. This creates a causal validity flaw: if the Oracle is a physics simulation, it inherently possesses the 'high-fidelity physics' the hypothesis claims is unnecessary. Using a physics-based Oracle to measure the 'Physics Fidelity Gap' conflates the symbolic planner's logical validity with the physics engine's fidelity. To isolate the hypothesis (that topology suffices), the Oracle must be a deterministic, non-physics rule-based verifier (e.,g., checking if the symbolic sequence matches the ground-truth task graph), not a physics simulation.
- The Wilcoxon signed-rank test is proposed to compare 'Symbolic vs. Baseline' success rates. However, the Baseline (RoboDojo Neural Policy) and the Symbolic approach operate on fundamentally different input spaces (continuous video vs. discrete graphs). A paired test assumes the same underlying distribution or paired observations; comparing a neural policy's success rate against a symbolic planner's success rate on the same tasks without controlling for the 'sim-to-real' adapter's performance (FR-009) introduces a confound. The analysis plan fails to isolate the 'symbolic abstraction' variable from the 'low-level controller adaptation' variable.
- Phase 0 lists 'Confirm MobileViT CPU inference speed' but lacks a power analysis or sample size justification for the 18 tasks. With only 18 data points, the Wilcoxon test has low statistical power to detect anything but massive effect sizes. The plan does not address how the study will handle the high variance expected in real-world robot execution with such a small N, risking a Type II error (failing to detect a real difference).
- FR-008 (Ablation Study Mode) is not explicitly backed by a plan element. The plan mentions 'Ablation study' in the 'Complexity Tracking' table as a reason for structure, but Phase 2 (Core Implementation) and Phase 3 (Analysis) do not list specific tasks to implement the 'ablation study mode' or the 'ablation_result' schema logic. The 'contracts/ablation_result.schema.yaml' exists, but the plan does not describe how the system will vary state representation levels (e.g., 'Full Affordance Graph' vs 'Simplified Connectivity Graph') to generate the data required for this FR.
- FR-009 (Sim-to-Real Adapter/Fine-tuning Protocol) is not backed by a plan element. The plan's Phase 2 lists 'executor_real.py' and 'executor_oracle.py', but does not explicitly include a task or module for the 'Sim-to-Real Adapter' or 'Fine-tuning Protocol' using real-world videos. The 'research.md' mentions 'adapted RoboDojo weights' but the implementation plan lacks a specific phase or task to define or implement the adaptation protocol required by FR-009.
- SC-005 (Catastrophic Failure Rate ≤ 5%) is not backed by a plan element. - The plan defines 'Planner Infeasibility' as a failure mode occurring when the 'Oracle Executor' fails. However, the Oracle is defined as a 'Perfect Low-Level Executor' that assumes the symbolic plan is physically feasible. If the Oracle fails, it implies the symbolic plan itself is invalid (e.,g., unreachable state). This creates a circular definition: the Oracle is supposed to validate the *planner's* logic, but if the Oracle fails, the plan labels it as 'Planner Infeasibility' based on the Oracle's failure. The Oracle's success/failure is the *dependent variable* used to validate the *independent variable* (planner logic), but the Oracle's definition ('Perfect... assumes feasible') contradicts the outcome (failure). The validation target (Oracle outcome) is not independent of the predictor (planner output) because the Oracle's 'perfection' is defined by the planner's output validity. This is a tautological validation loop.
- The plan proposes a Wilcoxon signed-rank test to compare 'Symbolic vs. Baseline' success rates. However, the 'Baseline' is the 'original RoboDojo Neural Policy'. The 'Symbolic' approach uses a 'Perfect Low-Level Executor' (Oracle) for its control condition (US-4) but a 'Real-World Executor' for the main test (US-2). The comparison is between (Symbolic+Real) and (Neural+Real). The 'Physics Fidelity Gap' is calculated as (Oracle - Real). The plan claims to test if 'topological symbolic abstractions alone suffice'. If the Oracle (Symbolic+Perfect) succeeds but Real (Symbolic+Real) fails, the gap is attributed to the controller. If the Neural+Real fails, the comparison is valid. However, the plan does not define a 'Neural+Oracle' baseline. Without a 'Neural+Oracle' control, one cannot isolate whether the Neural policy's failure is due to poor planning (like the Symbolic planner) or poor execution. The statistical test compares two mixed systems (Symbolic+Real vs Neural+Real) without controlling for the 'Planning' variable, making the conclusion about 'symbolic abstractions' scientifically unsound.
- The plan uses a 'frozen MobileViT' to generate embeddings and then maps them to 'SymbolicState' nodes. The mapping from continuous high-dimensional embeddings to discrete topological predicates (e.g., 'Graspable', 'On') is a non-trivial, non-deterministic process (often requiring a learned classifier or heuristic threshold). The plan treats this mapping as a deterministic 'process' without specifying the validation of the mapping accuracy. If the mapping is noisy, the 'SymbolicState' graph is corrupted, and the planner's failure is due to the encoder, not the planner. The plan fails to account for the error propagation from the encoder to the planner, making the 'Planner Infeasibility' metric confounded by 'Encoder Ambiguity'.
