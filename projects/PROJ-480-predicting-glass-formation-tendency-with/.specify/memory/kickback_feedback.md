## Unresolved concerns

- The plan relies on 'dynamic runtime discovery' of datasets (OpenML/Zenodo) to find ≥30 samples. This introduces a non-deterministic failure mode where the research question cannot be answered if no suitable public dataset exists at runtime. A methodology must guarantee data availability *before* committing to the analysis design. The plan lacks a fallback research question or a confirmed data source, risking a 'null result' due to data absence rather than model performance.
- The plan proposes a binary fallback (Glass vs. Crystal) if continuous $D_c$ data is missing. However, the scientific validity of predicting 'Glass vs. Crystal' (a binary label) using the same thermodynamic descriptors as $D_c$ (a continuous physical property) is not established. The plan does not address whether the feature space is sufficient to distinguish these classes or if the 'glass formation tendency' construct is valid for a binary classification task without specific domain validation.
- The plan mentions 'Power Analysis' but defers the actual calculation to the research phase ('With a target of ≥ 500 samples, power is likely sufficient'). For a regression task predicting a continuous variable ($D_c$) with multiple correlated predictors (VIF > 5 expected), a sample size of 30-500 is often underpowered to detect moderate effect sizes or to reliably estimate feature importance. The plan lacks a concrete power calculation or a minimum detectable effect size (MDES) to justify the sample size target.
- The plan assumes 'mixing enthalpy' and 'atomic size mismatch' can be computed from composition alone. In materials science, glass formation is highly sensitive to cooling rate and processing history, which are often missing from public composition-only datasets. If the target variable ($D_c$) in the dataset was measured under varying cooling rates, the model will learn noise (confounding by processing conditions) rather than the intrinsic glass-forming ability, invalidating the causal/associational link to composition descriptors.
- FR-005 requires a sensitivity analysis on the classification threshold (sweeping cutoff values 0.4, 0.5, 0.6) and reporting false-positive/negative rates. The plan.md 'Phase Execution Order' and 'Compute Feasibility Strategy' sections describe training, evaluation, and diagnostics (VIF), but contain no explicit task, phase, or step to perform this specific threshold sensitivity sweep. SC-005 also relies on this being measured. This is an unbacked functional requirement.
- FR-007 mandates that the final report MUST frame all findings as associational, not causal. While the plan mentions 'framing all findings as associational' in the Summary, there is no specific phase, contract, or deliverable step in the 'Phase Execution Order' or 'Project Structure' that explicitly generates or validates this framing in the final report artifact. The plan lacks a concrete task to ensure this constraint is met in the output.
- FR-006 requires the system to halt and raise a specific `DataValidationError` if required variables are missing, and to log the count of missing records. The plan mentions 'Data Validation' in Phase 3 and 'validate.py' in the structure, but does not explicitly define the task to implement the specific error message format ('Missing required variable: {variable_name} in {dataset_name}') or the logging of missing record counts as a distinct, testable step. The specific error handling behavior is not clearly backed by a plan element.
- The plan cites 'Materials Project' and 'Zenodo' as primary sources for metallic glass critical casting thickness ($D_c$) but provides no specific dataset IDs, DOIs, or URLs. The 'Verified Datasets' block explicitly states 'NO verified source found' and relies on 'runtime discovery' via OpenML/UCI. This is a methodology failure: the plan assumes the existence of a specific, high-quality dataset (continuous $D_c$) without confirming its availability. If the runtime discovery fails to find a dataset with $D_c$ (which is rare in open repositories compared to binary labels), the primary research goal (regression) becomes infeasible, forcing a fallback to binary classification which may not answer the specific research question about 'tendency' magnitude.
- Assumption: 'The public repositories (Materials Project, Zenodo) will provide access to at least 500 metallic glass compositions with either critical casting thickness ($D_c$) or a binary glass/crystal label.' This is an unverified empirical claim. Materials Project primarily focuses on crystal structures and formation energies, not necessarily metallic glass $D_c$ values. Relying on it for this specific target variable without a confirmed dataset citation risks the entire pipeline failing at the ingestion phase. The plan must cite a specific, existing dataset (e.g., a specific Zenodo DOI or a known repository like the 'Glass Data Repository' with a direct link) that actually contains the target variable $D_c$ or binary labels before proceeding.
- Constitution Principle II (Verified Accuracy) is marked 'Compliant' in the plan, but the plan text in 'Research' and 'Data Ingestion' explicitly states the system must 'dynamically discover' or 'fallback' if no verified source is found. This contradicts Principle II which mandates that citations MUST be verified by the Reference-Validator Agent before contributing points. The plan currently allows a path where the project proceeds with unverified or dynamically discovered data sources, violating the 'Verified Accuracy' gate.
- Phase 1 'Descriptor Computation' and Phase 3 'Data Validation' reference handling 'Unknown Element' exclusions and logging dropped records, but the plan does not explicitly mandate that the `data/` directory checksums (required by Constitution Principle III) are updated or recorded in `state/` for these derived/filtered datasets. The plan mentions checksumming 'raw data' but is silent on the checksumming of the 'processed' dataset which is the actual SSoT for the model, risking a violation of Principle III (Data Hygiene) and Principle IV (SSoT).
- The 'Scale/Scope' section states 'Target dataset size ≥ 500 samples (minimum 30 for training)'. While this aligns with the spec, the plan does not explicitly reference the specific Success Criteria (SC-001) or Functional Requirement (FR-001) IDs that define this threshold, making the traceability between the plan's scope and the spec's requirements implicit rather than explicit.
- Phase 6 'Diagnostics' mentions 'VIF calculation' but does not explicitly state that the VIF scores must be written to the `ModelArtifact` (as defined in `data-model.md` and `contracts/model_output.schema.yaml`) or that they must be included in the final report as a mandatory field. The plan says 'check stability' but the contract requires specific output fields. This creates a potential gap between the plan's intent and the contract's output requirements.
- The plan proposes validating the model's predictive power using the same thermodynamic descriptors (atomic size mismatch, mixing enthalpy) that are physically defined to determine the glass formation tendency. In materials science, these descriptors are not independent predictors but are the *definition* of the glass-forming ability (GFA) criteria (e.g., Inoue's rules). Validating a model trained on these against the target (GFA) is tautological if the target is derived from the same physical principles. The plan must explicitly define an *independent* ground truth (e.g., experimentally measured critical casting thickness $D_c$ from literature, distinct from the calculated descriptors) to avoid circular validation where the model merely recovers the input definitions.
- The plan assumes that 'Mixing Enthalpy' and 'Atomic Size Mismatch' are independent predictors. However, in thermodynamic theory, these quantities are often highly correlated (collinear) and physically coupled. The plan mentions VIF diagnostics but does not address the fundamental scientific issue: if the target variable (glass formation) is *defined* by thresholds of these exact descriptors, the machine learning task becomes a trivial regression/classification of a known physical rule rather than a discovery of new predictive relationships. The validation strategy must ensure the target is an empirical observation, not a calculated restatement of the features.
- The plan relies on 5-fold Cross-Validation (CV) to assess model stability. In materials informatics, datasets often suffer from 'chemical bias' where similar compositions cluster together. Standard random CV splits can lead to data leakage where the test set contains compositions chemically similar to the training set, inflating performance metrics. The plan should specify a 'leave-one-cluster-out' or 'composition-scaffold' split strategy to ensure the model generalizes to *novel* chemical spaces, not just interpolates within known families.
