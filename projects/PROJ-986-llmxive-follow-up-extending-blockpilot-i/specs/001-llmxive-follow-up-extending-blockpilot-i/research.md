# Research: llmXive follow-up: extending "BlockPilot: Instance-Adaptive Policy Learning for Diffusion-based Spec"

## 1. Research Question

Can static prefilling features (prompt length, mean attention entropy, hidden state norms) serve as robust, architecture-agnostic proxies for model uncertainty to predict the optimal block size ($B^*$) in diffusion-based speculative decoding, without requiring a neural policy network?

**Methodological Clarification**: The target $B^*$ is derived from an exhaustive sweep maximizing acceptance length. The hypothesis is validated **exclusively** by the **generalization** of the learned mapping to unseen architectures and domains. An independent correlation with perplexity (FR-006) serves as secondary validation. All results are framed as **exploratory** due to sample size constraints. The task is explicitly treated as **Classification** (predicting discrete classes), not regression.

- **Risk**: If acceptance length calculation fails due to model incompatibility, the sweep will be invalid. Mitigation: Test on a small number of samples first.

## 4. Statistical Rigor

### Multiple Comparison Correction
- **Context**: Testing models (XGBoost, RF, DT) across 2 architectures × 3 domains.
- **Method**: Apply Benjamini-Hochberg procedure to control false discovery rate (FDR) at α=0.05.

### Sample Size & Power
- **Plan**: A moderate sample size for Qwen and a smaller sample size for Llama.
- **Justification**: For a 6-class classification problem, a minimum number of samples per class is required for stable tree-based models. Given the computational constraints and exploratory nature, A reasonable baseline sample size is established for Qwen., while A preliminary test is accepted for Llama..
- **Acknowledgement**: Power limitation noted; results framed as **exploratory** and **preliminary**. No claims of statistical significance for the Llama subset. A formal power analysis is not feasible due to the unknown effect size of the proxy relationship, but the sample sizes are chosen to maximize data within the 6-hour CI limit.

### Causal Inference Framing
- **Observational Study**: Block sizes are assigned exhaustively, not randomly.
- **Framing**: All claims are associational ("correlation", "prediction"). No causal claims made.
- **Null Hypothesis**: Static features are not sufficient to capture model uncertainty.

### Measurement Validity
- **Attention Entropy**: Calculated per diffusion architecture definition (mean over layers, per token).
- **Hidden State Norms**: L2 norm of final token hidden states.
- **Independent Uncertainty Measure (FR-006)**: **Perplexity** calculated via a **separate greedy forward pass** (distinct from the sweep) on the same samples. This ensures independence from the acceptance-length metric.

### Predictor Collinearity
- **Risk**: Prompt length may correlate with hidden state norms.
- **Handling**:
 1. Calculate Variance Inflation Factor (VIF) for all features.
 2. If VIF > 5, apply **residualization** or **PCA** to decorrelate features before training.
 3. Report feature importance on the decorrelated set.
 4. This step is critical to ensure that feature importance scores reflect true predictive power and not just correlation with prompt length.

## 5. Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Sweep exceeds 6h limit | Low | High | Sample size reduced to 100 for Llama; GPU escape hatch enabled. |
| NaN in attention entropy | Medium | Medium | Detect, log, impute with median or exclude sample. |
| Model OOM on CPU | Low | High | Use smaller model (Qwen3-4B); stream data; reduce batch size. |
| Dataset URL unreachable | Low | High | Fallback to alternate verified URL; retry with exponential backoff. |
| Perplexity calculation too slow | Low | Medium | Limit to a manageable sample size for Llama; optimize with batched inference. |

## 6. Decision Rationale

- **CPU-First**: Chosen because the method (sweep + classification) is computationally light and fits within free-tier constraints.
- **No GPU (Primary)**: No need for 8-bit inference or fine-tuning; CPU is sufficient for the reduced sample size.
- **Streaming**: Ensures memory safety; avoids disk I/O bottlenecks.
- **Classical ML**: XGBoost/RF/DT chosen for speed, interpretability, and CPU efficiency.
- **Classification vs Regression**: Target $B^*$ is discrete (multiple classes); classification metrics (Accuracy, F1) are methodologically sounder than regression metrics.
