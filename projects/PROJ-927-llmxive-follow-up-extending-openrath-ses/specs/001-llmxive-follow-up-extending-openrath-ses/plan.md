## Summary

This project implements a synthetic benchmark to evaluate the resilience of a "Session-First" agent architecture against a traditional "Event-Log" architecture under data corruption. The system generates deterministic multi-agent debugging workflows, captures ground-truth states, executes them under two architectures while injecting stochastic network delays and random log corruption, and reconstructs the final state to measure "Total Resilience" (Primary) and "Recoverable State Fidelity" (Secondary). The implementation strictly adheres to the project constitution, ensuring reproducibility, data hygiene, and statistical rigor (including Cochran's Q test with Holm-Bonferroni post-hoc correction).

**Scale/Scope**: synthetic workflows; Multiple corruption levels (concrete set: {0.05, 0.10, 0.20}); architectural models.

## Unresolved Panel Concerns Resolution

The following concerns from the previous iteration have been explicitly addressed in this plan:

1.  **Statistical Test Ambiguity (McNemar vs. Cochran's Q)**: The primary test is now **Cochran's Q** applied to a 2x2x3 design (Architecture x Outcome x Corruption Rate) to test for differences in success rates across the 3 rates. The binary outcome is defined as **Total Resilience** (Success vs. Failure/Unrecoverable). Post-hoc pairwise comparisons for specific rate differences will use **McNemar's test** with **Holm-Bonferroni** correction.
2.  **Metric Definition (Total Resilience vs. Recoverable Fidelity)**: The **Primary Metric** is now **Total Resilience** (Success / Total), treating 'Unrecoverable' as a failure. This eliminates selection bias. **Recoverable State Fidelity** (Success / Recoverable) is retained as a **Secondary, descriptive metric** only.
3.  **Jitter Injection Point (FR-004)**: The `corruption_injector.py` and architecture implementations will inject jitter *specifically* during the simulation of tool calls (inside the `tool_call` method), not as a global network delay.
4.  **Data Hygiene Checksumming (Principle III)**: A dedicated task step is now explicitly defined in the Task Coverage Matrix to checksum *every* file under `data/` (including corrupted logs and results) and register hashes in `state/` immediately after generation.
5. **Sensitivity Sweep Concrete Set (SC-004)**: The sweep logic will explicitly iterate over the fixed set: `{0.05, 0.10, 0.20}` ([deferred], [deferred], [deferred]).
6.  **Task Deliverables & File Names**: The Task Coverage Matrix below explicitly defines the implementation details (file paths, logic) for all FR/SC requirements, ensuring the plan itself contains the verified coverage.
7.  **Unrecoverable Detection Logic**: The `metrics.py` module will implement a graph-traversal algorithm to check if any node in the decision tree references a `deleted` log entry, marking the workflow as "Unrecoverable" if so.

## Risk Mitigation

- **Risk**: Corruption deletes critical data.
  - *Mitigation*: 'Unrecoverable' flag logic (T007) excludes these from fidelity but counts them as failures in Total Resilience.
- **Risk**: Non-deterministic execution.
  - *Mitigation*: Fixed seeds, checkpointing, and isolation of RNG state.
- **Risk**: Statistical invalidity (small N).
  - *Mitigation*: Exact McNemar and Monte Carlo Cochran's Q (T016).
