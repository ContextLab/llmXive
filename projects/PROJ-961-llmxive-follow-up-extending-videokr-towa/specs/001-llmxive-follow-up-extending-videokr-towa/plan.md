# Implementation Plan: Video Reasoning Threshold Analysis

**Branch**: `001-video-reasoning-threshold` | **Date**: 2026-10-14 | **Spec**: `specs/001-llmxive-follow-up-extending-videokr-towa/spec.md`  
**Input**: Feature specification from `/specs/001-llmxive-follow-up-extending-videokr-towa/spec.md`

## Summary
The project will (1) ingest the **TVQA** open‑source dataset (verified Hugging Face URL) and its knowledge graph, (2) deterministically map question entities to graph nodes using exact‑match and Levenshtein fuzzy matching (no embeddings), (3) compute shortest‑path hop counts (`chain_length`) and derive binned categories (`chain_bin`), (4) calculate per‑bin accuracy, (5) detect a “reasoning cliff” via a **permutation‑based change‑point test using binomial logistic GLMs** with Bonferroni correction, (6) perform a sensitivity sweep over candidate thresholds **and** include additional covariates (question difficulty, video length, answer type) to guard against omitted‑variable bias, (7) log runtime and memory usage, and (8) conduct a formal **power analysis** to justify the ≥ 50‑sample minimum per bin. All steps produce verifiable output files that conform to JSON/YAML schemas.

## Computational Feasibility
- **CPU‑first**: All algorithms (BFS, permutation GLM, fuzzy matching) run on CPU.  
- **Memory**: Graph stored as adjacency list; dataset streamed or sampled to stay ≤ 5 GB.  
- **Runtime**: Permutation test limited to **5 000** permutations (adjustable) → ≤ 4 h on 2 cores.  
- **GPU**: Not required.

## Power Analysis (addresses methodology‑bfa5f1f8)
We will estimate the detectable odds‑ratio for a binary outcome using `statsmodels.stats.power.NormalIndPower`. Assuming a two‑sided α = 0.05 (Bonferroni‑adjusted to 0.0167) and a target power of 0.80, the required sample per bin is computed; the ≥ 50‑sample rule is the ceiling of that calculation for modest effect sizes (OR ≈ 1.5). The plan logs the computed detectable effect size in `runtime_log.json`. The two‑stage sampling (pilot → oversampling) is driven by this calculation, guaranteeing that each bin meets the power requirement or is flagged as under‑powered and the corresponding knot is deferred.

## Covariate Modeling (addresses methodology‑e7e0125f)
Additional columns extracted from the raw TVQA metadata:
- `question_difficulty` (e.g., token count or pre‑computed difficulty score)
- `video_duration` (seconds)
- `answer_type` (categorical: “yes/no”, “multiple‑choice”, etc.)

These are included as fixed effects in the GLM for both null and alternative models, reducing omitted‑variable bias and ensuring that any observed cliff is not confounded by these factors.

## Statistical Rigor (addresses methodology‑4fe1a45d & scientific_soundness‑ac7050e0)
- **Null Model**: **Binomial logistic GLM** of `correctness` on hop count **and** covariates.  
- **Alternative Model**: Piecewise logistic GLM with a knot at candidate `k`.  
- **Test Statistic**: Likelihood‑ratio (Δ log‑likelihood).  
- **Permutation**: Shuffle `correctness` labels 5 000 times, recompute max Δ log‑likelihood across knots, yielding an empirical null distribution.  
- **Multiple Comparisons**: Bonferroni correction applied to raw p‑values (3 knots) or equivalently using the max‑statistic null distribution.  
- **Significance**: Cliff declared if corrected p < 0.05.

## Sensitivity & Bias Checks (addresses methodology‑e7e0125f)
- **Threshold Sweep**: Run the permutation GLM test separately for knots 2, 3, 4, recording p‑values, effect sizes, and cliff magnitudes.  
- **Disconnection Bias**: Compute the proportion of `status = "disconnected"` or `"mapping_failure"` per bin. Re‑compute accuracy assuming all such records are incorrect; if the cliff disappears, flag `bias_flag = true`.  
- **Robustness**: Passes if ≥ 2 of the 3 knots yield significant cliffs (SC‑003).  
- **Outputs**: Updated `threshold_results.json` (includes `robustness_status`) and `accuracy_vs_hop_raw.png` (scatter + LOESS).

## Risk Management
| Risk | Mitigation |
|------|------------|
| Missing verified TVQA source | Data‑availability gate aborts with clear error; user must place open substitute in `data/raw/`. |
| Embedding‑based linking (T102) | Deterministic exact + Levenshtein matching only; embedding path removed from code and documentation. |
| Insufficient high‑hop samples | Power analysis and oversampling guarantee ≥ 50; if still insufficient, test for that knot is deferred and logged. |
| Out‑of‑memory on full graph | Load only the subgraph induced by sampled nodes; fallback to streaming mode. |
