# Implementation Plan: llmXive follow-up: extending "ABot-AgentOS" with Symbolic Memory

**Branch**: `001-symbolic-memory-edge-robotics` | **Date**: 2026-09-04 | **Spec**: [link]
**Input**: Feature specification from `/specs/001-symbolic-memory-edge-robotics/spec.md`

## Summary

This feature implements a purely symbolic, CPU-tractable memory system for robotic navigation to replace the neural embedding-based memory of ABot-AgentOS. The system ingests 500 task traces from the **ALFWorld** benchmark (verified source), converts them into a deterministic Directed Acyclic Graph (DAG) of semantic tokens and logical predicates using a frozen VLM for offline discretization, and executes queries via depth-first traversal. The plan includes a parametric study sweeping tokenization granularity and predicate expressiveness, comparing the symbolic system against the neural baseline (ABot-AgentOS) on success rate, latency, and memory footprint. The implementation adheres to strict reproducibility and determinism constraints, ensuring all results are reproducible on a CPU-only GitHub Actions runner. The neural baseline is re-executed dynamically on the same traces to ensure valid paired comparisons.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: `networkx` (graph structure), `pandas` (data handling), `scikit-learn` (data processing), `statsmodels` (Logistic Mixed Effects Model), `datasets` (Hugging Face data loading), `transformers` (frozen VLM inference in offline mode), `pytest` (testing).  
**Storage**: In-memory graph structures (RAM), CSV/JSON logs for traces and metrics. No persistent database required for the prototype.  
**Testing**: `pytest` with unit tests for graph construction logic, integration tests for query execution, and contract tests against schema definitions.  
**Target Platform**: Linux (GitHub Actions free-tier runner: 2 CPU, ~7 GB RAM).  
**Project Type**: Research simulation / comparative analysis engine.  
**Performance Goals**: Query latency ≤ 100 ms on CPU; Peak RAM ≤ 2 GB for 500 traces; Success rate difference ≤ 5% vs. baseline.  
**Constraints**: Zero GPU dependency for symbolic path; strict determinism in graph construction; no synthetic data generation (must use real or sampled real traces from ALFWorld).  
**Scale/Scope**: 500 task traces; Two independent variables (granularity, predicate expressiveness); dependent variable (success rate) + efficiency metrics.

> **Dataset Availability Note**: The original spec referenced "EmbodiedWorldBench," which has no verified public source. This plan switches to **ALFWorld** (`alfworld/alfworld` on Hugging Face), a verified, programmatically accessible benchmark containing the required spatial, dialogue, and temporal traces. If the ALFWorld download fails, the system will attempt to load a versioned, checksummed artifact from `data/raw/` (generated during a prior successful run), ensuring reproducibility without relying on ad-hoc user input.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
| :--- | :--- | :--- |
| **Symbolic Graph Construction** | Required to replace neural memory with a deterministic, CPU-tractable substrate. | A simple list of logs would not support logical inference or spatial queries (predicates like `near`, `on_top_of`). |
| **Parametric Sweeping** | Required to study the trade-off between granularity/predicates and performance. | A single configuration would not answer the research question regarding the "optimal" trade-off. |
| **Dual-Baseline Comparison** | Required to measure the specific "symbolic vs. neural" trade-off. | Comparing only to a random baseline would not validate the "ABot-AgentOS" extension hypothesis. |
| **Dynamic Design Pruning** | Required to handle missing variables (e.g., spatial coords) without failing the study. | A hard stop would render the study infeasible if the dataset lacks specific fields; pruning allows valid sub-studies. |

## Run Configuration & Seeds

-   **Canonical Seeds**: `config.py` contains the default pinned seeds (e.g., `RANDOM_SEED = 42`).
-   **CLI Overrides**: If CLI arguments override seeds, the actual values used are logged to `data/results/run_config.json`.
-   **Reproducibility**: The `run_config.json` file serves as the "Single Source of Truth" for the specific run configuration, ensuring that results can be reproduced by re-running with the exact same parameters.
