## Unresolved concerns

- FR-013 (verify instrument validity via DOI/citations) lacks an implementing task. T012 mentions 'verify instrument validity' but provides no logic to fetch DOI metadata or check citation counts. Without this, the gate to exclude invalid datasets (FR-009) cannot be executed.
- FR-012 (derive lead time only if trigger is distinct) is not fully implemented. T014 describes extracting motion features but fails to specify the logic for deriving `lead_time` from `latency` and `user_response_trigger` or validating the trigger's independence to prevent tautological coupling.
- SC-001 (dataset completeness ≥100) and SC-004 (VIF <5) lack explicit verification tasks producing evidence. T016 checks N but aborts instead of reporting a pass/fail status for SC-001. T015 computes VIF, but T017 (final output) does not explicitly log the final VIF status against the SC-004 threshold.
- FR-014 (perform power analysis) is mapped to T016, but T016 only calculates N and sets a `max_depth` flag. It does not perform the actual power analysis (e.,g., calculating detectable effect size) required by the spec, nor does it produce the documented power analysis artifact.
- FR-005 (multiple-comparison correction) is assigned to T022, but the task description only says 'Apply correction' without specifying which method (Bonferroni vs. Benjamini-Hochberg) to use based on the number of tests, creating ambiguity on how to satisfy the conditional logic in the spec.
- SC-002 (Model generalizability via 5-fold CV) is assigned to T024, but the task description is generic and does not explicitly mandate 5-fold cross-validation or verify that `model_metrics.json` contains the specific R²/RMSE breakdown required to prove the success criterion.
- SC-005 (Visualization interpretability ≥80% reviewer rating) is assigned to T033b, but T033b is marked 'Completed' with no actual execution evidence. The task describes a manual process that cannot be verified by an automated agent or CI pipeline, leaving the success criterion unmeasurable.
- T000 claims to 'Disable Real data path,' which contradicts FR-001 (System MUST download real datasets) and FR-011 (generate synthetic IF no real dataset exists). The task permanently disables the real data path rather than implementing the conditional logic required by the spec.
- T023 (Sensitivity Analysis) is listed as 'FAILED: unspecified' yet remains in the task list with a '- [ ]' status. The task description relies on '1000 bootstrap samples' which may violate the 'CPU-only' constraint in the plan, and lacks a clear timeout or resource limit definition.
- T013 (Synthetic Generator) is marked as depending on T012 (Data Downloader) sequentially. However, T012's logic is to check for real data availability. If real data is unavailable (the expected state per plan), T012 produces a status file but no data. T013 then reads this status and generates synthetic data. This is a valid dependency, BUT T014 (Preprocessing) is described as accepting input from 'T012 (real) or T013 (synthetic)'. The task list does not explicitly enforce that T014 waits for the *completion* of the conditional branch (either T012 success or T013 generation). The current ordering implies T014 might run before T013 if T012 fails, leading to missing input data.
- T016b (Enforce N>=80 Gate) is listed as a separate task after T016 (Power Analysis). T016 outputs `modeling_config.json` with an `abort_flag`. T016b reads this flag. However, T017 (Output cleaned CSV) is listed *before* T016b in the text flow (T014->T015->T017->T016->T016b). If T017 runs before T016b checks the abort flag, the pipeline may produce a `raw_cleaned.csv` even when N < 80, violating the gate logic. The order must be T016 -> T016b -> (if pass) T017.
- T015 (VIF diagnostic) outputs `vif_report.json` and a boolean `vif_pass`. T017 (Output cleaned CSV) depends on this report to 'Apply final VIF-based feature exclusion'. The current text flow lists T017 after T015, which is correct, but T017 is marked as [X] (Completed) while T015 is [ ] (Pending). This creates a semantic contradiction: a 'completed' task (T017) depends on a 'pending' task (T015) that produces its critical input artifact. The ordering implies T017 cannot be completed until T015 is executed.
