# Data Model: Statistical Discrepancies in Publicly Available Election Data

## Overview

This document defines the data structures used for ingestion, processing, and analysis in the election discrepancy pipeline. The model ensures type safety, handles missing data explicitly, and supports the statistical tests required by the spec.

## Entity Definitions

### 1. Raw Jurisdiction Record
Represents a single row from the source election CSV/Parquet.

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `source_file` | str | Name of the original file | Not null |
| `state` | str | State FIPS or name | Not null |
| `county` | str | County name | Not null |
| `precinct_id` | str | Unique precinct identifier | Not null, unique within county |
| `candidate_name` | str | Candidate name | Not null |
| `vote_count` | int | Votes for candidate | >= 0 |

### 2. Aggregated Jurisdiction Record
Derived from Raw records, aggregated to the precinct level, then compared to county totals.

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `county_fips` | str | County FIPS code | Not null |
| `county_name` | str | County name | Not null |
| `precinct_id` | str | Precinct ID | Not null |
| `precinct_sum_votes` | int | Sum of all candidate votes in precinct | >= 0 |
| `county_reported_total` | int | Total votes reported by county for the election | >= 0 |
| `discrepancy_abs` | float | `|precinct_sum_votes - county_reported_total|` | >= 0 |
| `discrepancy_pct` | float | `discrepancy_abs / county_reported_total` | >= 0, NaN if denominator is 0 |
| `data_quality_flag` | str | `OK`, `MISSING_PRECINCT`, `ZERO_DENOM`, `DIRECTIONAL_ANOMALY` | Enum |

### 3. Null Model Simulation Output
Generated by `simulation.py` for each iteration.

| Field | Type | Description |
|-------|------|-------------|
| `iteration_id` | int | 1 to [deferred] |
| `simulated_discrepancy` | float | Value drawn from NB or Parametric Bootstrap null |
| `model_type` | str | `negative_binomial` or `parametric_bootstrap` |

### 4. Analysis Result
Final output of the statistical tests.

| Field | Type | Description |
|-------|------|-------------|
| `test_type` | str | `anderson_darling` or `kolmogorov_smirnov` |
| `statistic` | float | Test statistic value |
| `p_value` | float | P-value |
| `conclusion` | str | `REJECT_NULL` or `FAIL_TO_REJECT` |
| `anomaly_count` | int | Number of jurisdictions flagged at primary threshold |

## Data Flow

1.  **Ingestion**: `Raw Jurisdiction Record` -> `Aggregated Jurisdiction Record` (with flags).
2.  **Simulation**: `Aggregated Jurisdiction Record` (observed discrepancies) -> Robust Fit -> Generate `Null Model Simulation Output`.
3.  **Analysis**: Compare Observed vs. Simulated -> `Analysis Result`.

## Handling Missing Data

-   **Missing Precinct Votes**: If `vote_count` is missing for a precinct, the row is flagged `MISSING_PRECINCT` and **excluded** from `precinct_sum_votes` calculation (no imputation to avoid bias).
-   **Zero Denominator**: If `county_reported_total` is 0, `discrepancy_pct` is set to `NaN` and the row is flagged `ZERO_DENOM`. These rows are excluded from relative discrepancy analysis.
-   **Directional Anomalies**: If `precinct_sum_votes > county_reported_total`, the discrepancy is flagged `DIRECTIONAL_ANOMALY` and excluded from the NB fit (which assumes non-negative error) but included in sensitivity analysis.
