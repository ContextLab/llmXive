# Data Model: Quantifying Hallucination in LLM-Generated API Documentation

## Overview

This document defines the data structures, schemas, and relationships for the hallucination quantification pipeline. All data flows from the raw CodeSearchNet dataset through a series of transformations to the final analysis results.

## Entity Definitions

### FunctionRecord
Represents a single unit of analysis (a Python function).
- `id`: Unique identifier (hash of source code + function name).
- `source_code`: Raw Python source code string.
- `reference_docstring`: Original docstring from the dataset (if available).
- `function_name`: Name of the function.
- `token_count_source`: Number of tokens in the source code (estimated).
- `naming_style`: Categorical (`snake_case`, `camelCase`, `other`).
- `cyclomatic_complexity`: Integer (from `radon`).
- `generated_description_codegen`: One-sentence description generated by `codegen-350M`.
- `generated_description_starcoder`: One-sentence description generated by `starcoderbase-1b`.
- `token_count_gen`: Number of tokens in the generated description.

### HallucinationMetrics
Derived metrics for a `FunctionRecord`.
- `entity_f1_codegen`: Entity-overlap F1 score (0.0 to 1.0) comparing `generated_description_codegen` vs. source code AST entities.
- `entity_f1_starcoder`: Entity-overlap F1 score (0.0 to 1.0) comparing `generated_description_starcoder` vs. source code AST entities.
- `composite_index_codegen`: Alias for `entity_f1_codegen` (sole component of the index).
- `composite_index_starcoder`: Alias for `entity_f1_starcoder`.
- `is_high_hallucination_codegen`: Boolean (True if `composite_index_codegen >= 0.05`).
- `is_high_hallucination_starcoder`: Boolean (True if `composite_index_starcoder >= 0.05`).

### AnalysisResult
Aggregated statistical output.
- `correlation_token_length`: Spearman $\rho$ between token count and hallucination index.
- `correlation_naming`: Spearman $\rho$ between naming style and hallucination index.
- `correlation_complexity`: Spearman $\rho$ between cyclomatic complexity and hallucination index.
- `p_value_raw`: List of raw p-values for the above correlations.
- `p_value_adjusted`: List of Bonferroni-adjusted p-values.
- `regression_coefficients`: Dictionary of coefficients from the MLR model.
- `vif_scores`: Dictionary of Variance Inflation Factors for predictors.
- `sensitivity_data`: List of objects `{threshold, rate}`.
- `manual_validation_correlation`: Correlation between automated index and manual score.

## Data Flow

1.  **Ingestion**: `download.py` fetches `CodeSearchNet` (streaming).
    - Output: `data/raw/processed.parquet` (streamed chunks merged or processed on-the-fly).
2.  **Preprocessing**: `preprocess.py` parses AST, extracts entities, calculates complexity.
    - Output: `data/processed/features.csv` (contains `FunctionRecord` attributes).
3.  **Generation**: `generate.py` runs LLMs.
    - Output: `data/processed/generations.csv` (appends `generated_description_*` to `features.csv`).
4.  **Metrics**: `metrics.py` calculates F1 scores.
    - Output: `data/processed/metrics.csv` (appends `HallucinationMetrics`).
5.  **Analysis**: `analysis.py` runs statistics (including VIF, encoding).
    - Output: `data/results/analysis_report.json` (contains `AnalysisResult`).
6.  **Validation**: `validate.py` (manual subset).
    - Output: `data/results/validation_report.json`.

## Constraints

- **Immutability**: Raw data (`data/raw/`) is never modified. All derived files are written to new paths.
- **Checksums**: Every file in `data/` is checksummed (SHA-256) and recorded in the state file.
- **Schema Validation**: All CSV/JSON outputs must conform to the schemas defined in `contracts/`.
