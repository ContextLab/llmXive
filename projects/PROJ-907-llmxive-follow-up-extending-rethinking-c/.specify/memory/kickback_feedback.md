## Unresolved concerns

- FR-001 and FR-002 require recording and clustering routing weight matrices for *every block* at every timestep to derive a per-block static map. Task T011 records data but T012 explicitly aggregates these into a 'mean routing vector across all images/blocks' before clustering. This aggregation destroys the per-block dimension required to satisfy FR-002 and generate the 'Canonical Routing Map' (static weight vector *per block*). No task exists to cluster per-block vectors or derive per-block static weights.
- FR-006 mandates a non-parametric bootstrap with '1000 resamples'. Task T026 instructs the implementer to use 'a sufficient number of resamples' without specifying the count. This creates an untestable gap where the specific numerical requirement in the spec is not enforced by the task, violating the requirement for a specific statistical method.
- Task T018 (implementing static_model.py) depends on the artifact `data/routing_cache/canonical_map.json` from T013. The Analyze Report indicates T013 has 'FAILED: unspecified' verification. T018 is listed as a 'Re-do' task but lacks a dependency fix or a prerequisite task to ensure T013 succeeds first. This creates a circular failure where the dependent task cannot run until the blocker is fixed, yet the blocker is not prioritized.
- SC-005 requires measuring memory usage against the GitHub Actions free-tier limit (7GB) to ensure no OOM errors. Tasks T011 and T019 implement generic logging and a `memory_guard` function, but no task exists to parse these logs and explicitly report the comparison against the 7GB limit to verify SC-005. The success criterion is not covered by a verification task.
- FR-007 and US-3 require a sensitivity analysis sweeping the 'clustering distance threshold' used to define the dominant cluster. Task T027 sweeps a parameter but conflates it with general clustering parameters and re-runs the derivation logic (T012/T013) which may not isolate the specific 'distance threshold' edge case (k<2 or silhouette<0.25) defined in the spec. The task description does not explicitly map to the specific threshold sweep required by FR-007.
- The plan lists `torchmetrics` as a primary dependency for FID calculation, but Task T006 explicitly implements FID using `torchvision.models.inception_v3` manually. While the implementation approach is valid, the task does not address the unused `torchmetrics` dependency listed in the plan, creating a minor inconsistency in the dependency list vs. implementation plan.
- Task T012 (clustering) aggregates routing tensors across ALL blocks into a single mean vector before clustering. This destroys the per-block data required by the spec (FR-002) to generate a 'Canonical Routing Map' (static weight vector PER BLOCK). T013 (canonical_map) cannot produce the required artifact because its input (T012) has already collapsed the necessary dimension. T012 must be reordered/rewritten to cluster per-block vectors or preserve block dimensionality before aggregation.
- Task T027 (sensitivity analysis) depends on T013 (canonical_map) and T019 (benchmark). However, T027's description requires re-running the derivation logic (T012/T013) for each threshold. This creates a circular dependency or a missing intermediate artifact: T027 needs to generate *new* canonical maps for each threshold, but T013 is a single task producing a single file. The task order implies T013 runs once, but the logic requires it to run N times. T027 must explicitly define the generation of temporary canonical maps or T013 must be split into a reusable function/task.
