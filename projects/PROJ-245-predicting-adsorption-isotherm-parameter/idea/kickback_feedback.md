## Unresolved concerns

- FR-006 and FR-007 (Cluster-aware permutation testing) are anchored to US-2 and US-3, but the User Stories do not describe the *methodology* for statistical validation or the specific handling of multicollinearity. US-2 focuses on model training/metrics, and US-3 on SHAP interpretation. The FRs introduce a complex statistical testing protocol (cluster-aware shuffling) that is not reflected in the user journey or acceptance scenarios of the stories they claim to serve, creating a 'silent scope creep' where the implementation logic is defined without a corresponding user goal or testable scenario in the story.
- SC-003 requires measuring R² of a model trained *only* on the top 3 descriptors against a null model. While anchored to US-3, US-3's 'Acceptance Scenarios' only cover SHAP plots (SC-001 equivalent) and comparison to the LiteratureConsensusList (SC-002 equivalent). There is no acceptance scenario in US-3 that describes the training of a reduced-feature model or the specific comparison to a null model required by SC-003. The success criterion exists without a corresponding user story acceptance scenario to validate it.
- The 'Edge Cases' section describes system behaviors (flagging outliers, imputing missing pore volume, diagnostic reports for poor R²) that are not explicitly covered by any Functional Requirement or Success Criterion. For instance, the requirement to 'flag these as potential outliers' or 'output a diagnostic report' is a functional behavior that lacks a corresponding FR-NNN or SC-NNN, representing silent under-specification for these specific edge-case handling mechanisms.
- FR-006 requires permutation-based p-values and FDR correction. FR-007 requires 'cluster-aware permutation testing' where features are shuffled *within* material clusters. These are mutually exclusive or contradictory methodologies for a single feature importance test. Shuffling within clusters (FR-007) destroys the adsorbate-adsorbent pairing necessary to predict isotherm parameters if the target varies by adsorbate, while standard permutation (FR-006) breaks the global correlation. The spec does not define how to reconcile these two distinct statistical tests or which one takes precedence for the final p-value reported in SC-005.
- FR-002 mandates filtering for 'Type I' isotherms. User Story 1 and Edge Cases acknowledge the source data may lack a reliable 'isotherm_type' column, proposing a heuristic or exclusion. This creates a logical contradiction: if the heuristic fails (as admitted in Edge Cases), the system excludes ALL entries, making it impossible to satisfy FR-002's requirement to 'include only Type I' (since the set of included entries becomes empty). The spec lacks a fallback mechanism to ensure the dataset is non-empty, violating the internal consistency of the data pipeline requirements.
- FR-007 and SC-005 require reporting adjusted p-values from 'cluster-aware permutation testing'. However, the spec does not define the 'cluster' key (e.g., `adsorbent_id` vs `adsorbent_material`) or the specific algorithm for shuffling within these clusters in a way that preserves the physical pairing of adsorbate-adsorbent. Without a defined clustering key and shuffling logic that respects the paired nature of the data (adsorbate properties + adsorbent properties -> target), the requirement is internally inconsistent with the data model described in 'Key Entities' (which lists Adsorbate and Adsorbent as separate entities).
- The 'Key Entities' section defines 'Adsorbate' and 'Adsorbent' as separate entities. However, FR-007 and the Edge Cases refer to 'material clusters' and 'adsorbent_id' without explicitly linking these terms to the defined 'Adsorbent' entity. The terminology 'material' is used interchangeably with 'Adsorbent' in the Edge Cases, while 'Adsorbent' is the formal entity name. This inconsistency risks ambiguity in implementation regarding which ID field to use for clustering.
- FR-008 and SC-002 require comparing results against a `LiteratureConsensusList`. The 'Key Entities' section defines this list as 'configurable' and 'NOT for validation'. However, FR-008 requires the system to 'explicitly discuss the alignment or divergence' and 'highlight any novel descriptors'. This creates a tension: if the list is not for validation, how can 'alignment' be a success criterion? The spec does not clarify whether the 'alignment' is a pass/fail metric or purely a discussion point, making the requirement's intent ambiguous and potentially contradictory to the 'NOT for validation' clause.
- FR-006 mandates 'permutation-based p-values' and 'FDR correction' but does not specify the permutation count (e.g., 1000 iterations) or the significance threshold (e.g., alpha=0.05). Without these parameters, the test for 'significance' is not reproducible or verifiable.
- FR-007 requires 'cluster-aware permutation testing' but fails to define the cluster key (e.g., 'adsorbent_id' vs 'material_id') or the shuffling mechanism (e.g., 'shuffle adsorbate labels within cluster'). The spec references 'adsorbent_id' in the Key Entities but the permutation logic is ambiguous, making the requirement untestable.
- SC-001 states the R² improvement over the null model must be '≥ 0.2'. This is a quantitative threshold, but the SC does not specify the statistical test used to validate this improvement (e.g., 'paired t-test on 5-fold CV scores, p < 0.05'). Without a statistical test, the 'improvement' claim is not scientifically verifiable.
- SC-002 requires the report to 'explicitly identify at least one point of convergence or divergence'. This is a binary pass/fail condition that is verifiable, but the SC does not define the metric for 'alignment' (e.g., 'top 3 SHAP features must match top 3 in LiteratureConsensusList'). The current phrasing allows for subjective interpretation of 'alignment'.
- SC-003 requires measuring R² of a model trained *only* on the top 3 descriptors against a null model. The SC does not specify how the 'top 3' are selected (e.g., 'mean absolute SHAP value from the best-performing model in SC-001'). If the selection method is not fixed, the SC is not reproducible.
- SC-004 sets a runtime threshold of '≤ 4 hours'. This is measurable, but the SC does not define the hardware environment (e.g., 'GitHub Actions 2-core runner, 7GB RAM'). Runtime is hardware-dependent; without a defined environment, the criterion is not verifiable across different runners.
- FR-008 requires the report to 'highlight any novel descriptors... and any consensus descriptors that the model failed to identify'. This is verifiable, but the FR does not define the 'LiteratureConsensusList' source or update mechanism. If the list is static and outdated, the 'novel' claim is not scientifically valid. The FR must specify the list is a configurable input file.
- Acceptance Scenario 2 states the partial dependence plot must be 'monotonically non-decreasing... and bounded by the Langmuir capacity'. This is a physical constraint that may not hold for all adsorbates (e.g., steric hindrance). Enforcing this as a 'Then' condition makes the test fail for valid physical phenomena, rendering the requirement scientifically invalid and untestable for real-world data.
- The Edge Case 'What happens when the test set performance is poor (R² < 0.5)?' requires a 'diagnostic report'. The spec does not define the content or format of this report, nor the specific causes to check. Without a defined checklist, the 'diagnostic' is not verifiable.
- FR-002 requires filtering for 'Type I' isotherms. The spec does not define the algorithm or column mapping to identify 'Type I' (e., 'regex match on isotherm_type column' or 'IUPAC classification code'). If the source data schema varies, the filter is not reproducible. The FR must specify the exact column name or mapping logic.
- FR-007 mandates 'cluster-aware permutation testing' where features are shuffled *within* material clusters. The upstream idea and Constitution Principle VII require validating that the model captures *generalizable physics* across materials. Shuffling within a cluster (where the adsorbent is constant) tests intra-cluster variance, not the predictive power of the descriptor *across* different materials. This methodology fails to answer the research question 'Which descriptors... determine... parameters' in a generalizable way and risks producing invalid p-values for the stated hypothesis.
- FR-002 and US-1 require filtering for 'Type I' isotherms. The spec assumes a reliable 'isotherm_type' column exists in raw NIST/MOF data. The upstream idea notes a 'lack of data-driven models' and the plan (referenced in kickback) admits source data often lacks this column. The spec provides no fallback strategy (e.g., heuristic shape-fitting, alternative dataset) if the column is missing, creating a 'zero-data' failure mode that prevents answering the research question.
- FR-008 requires comparing results against a 'LiteratureConsensusList'. The spec does not define the source of this list. If the list is derived from the same theoretical principles used to select RDKit descriptors (e.g., polarizability), the comparison is circular/tautological. Constitution Principle VII requires validation against 'independent literature datasets' or 'established physicochemical principles'. The spec must explicitly mandate an *external*, independent source for this list to avoid confirming the hypothesis by definition.
- FR-003 requires splitting data to prevent leakage. The spec does not explicitly address the 'sparse dataset' scenario (one adsorbate per material) mentioned in the kickback. If the dataset is sparse, a material-level split leaves no data for training or testing on that material. The spec needs a defined fallback (e.g., leave-one-adsorbate-out, or a different clustering strategy) to ensure the research question can be answered even with sparse data.
- SC-003 requires measuring R² of a model trained *only* on the top 3 descriptors against a null model. The spec defines the models to train (US-2) and the SHAP analysis (US-3) but does not explicitly include a functional requirement or user story step to *train this specific reduced model* and perform the comparison. The success criterion exists without a corresponding implementation requirement.
- FR-001 lists specific descriptors (polarizability, etc.) but does not explicitly mandate the calculation of 'kinetic diameter' or 'Lennard-Jones energy parameter' which are listed in the 'LiteratureConsensusList' (Key Entities) and the Idea's 'Expected Results'. If these are critical for the 'dominant drivers' analysis, they must be explicitly included in the descriptor calculation requirement.
- FR-007 mandates 'cluster-aware permutation testing' where feature values are shuffled *within* material clusters (adsorbent_id). This is scientifically invalid for this paired dataset. Adsorbent properties (surface area, pore volume) are constant within a cluster; shuffling adsorbate descriptors within a fixed adsorbent does not break the physical pairing (adsorbate-adsorbent interaction) required to predict the isotherm parameter. If the target varies by adsorbate, this shuffle creates a meaningless null distribution. If the target is constant, the p-value is trivially 1.0. A valid approach requires permuting the *pairing* (shuffling adsorbate IDs across adsorbents) or using leave-one-cluster-out CV.
- FR-006 and FR-007 propose permutation-based p-values for feature importance in a high-dimensional descriptor space. However, the spec does not define the null hypothesis clearly for a regression task with correlated features. Standard permutation tests assume feature independence or require specific blocking. The proposed 'cluster-aware' method (FR-007) fails to address the multicollinearity of molecular descriptors (e.g., polarizability and van der Waals volume are often correlated). Without a method to handle correlated predictors (e.g., conditional permutation or group permutation), the resulting p-values will be biased and the FDR correction (FR-006) will be invalid.
- SC-002 and US-3 require comparing model findings against a 'LiteratureConsensusList'. There is a high risk of circular validation if this list is derived from the same physical principles used to select the RDKit descriptors (e.g., polarizability is in the list *because* it is known to correlate with adsorption). If the model selects polarizability, the 'convergence' is a tautology of the feature selection process, not an independent validation. The spec must explicitly define the 'LiteratureConsensusList' as an external benchmark derived from independent experimental studies or a distinct theoretical framework, not just a list of descriptors that are physically plausible by construction.
- SC-001 and SC-003 require measuring R² improvement over a 'null model'. The spec defines the null model as 'predicting the mean'. However, in adsorption isotherm prediction, a simple mean model is often a poor baseline because the target distribution is highly skewed (e.g., Henry's constants span orders of magnitude). A more scientifically sound baseline would be a model based on the geometric mean or a simple physicochemical rule (e.g., Langmuir capacity proportional to surface area). Using a trivial mean baseline may inflate the perceived performance of the ML model without demonstrating genuine predictive power.
- FR-002 requires filtering for 'Type I' isotherms. The spec relies on a heuristic to filter based on a 'Type I' column or string. If the source data lacks a reliable 'isotherm_type' column (common in raw NIST exports), the plan defaults to 'exclude all rows'. This creates a 'zero-data' failure mode. The methodology is brittle to schema variations and does not guarantee the FR is satisfied. A robust scientific pipeline must include a fallback strategy (e.g., automated shape classification or manual review) to ensure Type I data is actually retained, rather than risking the exclusion of all data.
- FR-003 mandates splitting the dataset such that 'no single adsorbent material appears in both sets'. While this prevents data leakage for adsorbent properties, it does not account for the possibility that the same adsorbate appears in multiple materials. If the model learns a strong adsorbate-specific signal (e.g., 'CO2 always has high capacity'), it may overfit to the adsorbate distribution in the test set if the adsorbate distribution is not balanced across the train/test split. The spec should require stratification by adsorbate type or a check for adsorbate distribution balance to ensure the test set is representative.
- FR-005 requires generating SHAP summary plots and partial dependence plots. SHAP values for tree-based models (RF, GB) can be computationally expensive and may not be well-defined for highly correlated features. The spec does not address the potential for SHAP values to be unstable or misleading in the presence of strong multicollinearity (common in molecular descriptors). A more robust approach might involve using SHAP with a background dataset that is representative of the training distribution or using alternative interpretability methods (e.,g., permutation importance with confidence intervals) to validate the SHAP findings.
