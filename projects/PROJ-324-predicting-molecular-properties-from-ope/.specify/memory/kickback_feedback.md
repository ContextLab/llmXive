## Unresolved concerns

- Top‑K MACCS bit selection (T014) uses mean absolute SHAP values, which capture main‑effect importance. Selecting bits this way may bias the subsequent LNAI analysis toward bits with strong individual effects, potentially missing true interaction‑specific signals where bits have low marginal importance but high joint effect.
- LNAI computation (T015) correlates the error difference (RF − Baseline) with the joint‑presence indicator but does not adjust for the individual main effects of each bit. This can confound interaction detection because a significant rank‑biserial correlation may arise from additive contributions of the two bits rather than a genuine non‑additive interaction.
- The prevalence filters (≥ 5 % marginal and joint) ensure enough samples, yet with ~5 000 molecules the minimum joint count (~250) may still be under‑powered to detect modest interaction effect sizes after correcting for ~4 950 tests, even with 10 000 permutation samples. Power analysis for the LNAI step is not provided.
- The paired Wilcoxon signed‑rank test (T010) compares absolute errors across properties but does not account for potential heteroscedasticity or differing error distributions among logP, solubility, and boiling point, which could affect the validity of the combined significance claim.
- The plan proposes a 10 000‑permutation test for the Local Non‑Additivity Index on up to 4 950 bit‑pairs (≈ 49 M correlation calculations). On the GitHub Actions free tier (2 CPU cores, 7 GB RAM) this is unlikely to complete within the stated ≤ 4 h runtime budget, making the compute requirement infeasible.
- The fingerprint length constraint is stated as ≤ 2 200 bits, yet the plan generates three fingerprints (MACCS 166 bits, ECFP4 1024 bits, FP2 1024 bits) totaling 2 214 bits, exceeding the limit.
- The Data Model defines a field `local_non_additivity_index` per molecule (Output Data table), but the Implementation Plan (Task T015) only computes LNAI per fingerprint bit‑pair and outputs `data/derived/lna_index.csv`. No per‑molecule LNAI artifact is produced, violating the data‑model specification.
- The `prediction.schema.yaml` contract is never exercised by any task in the plan; there is no plan element that generates records conforming to this schema.
- The `molecule.schema.yaml` contract is not referenced by any task in the plan, leaving the contract unvalidated.
- The plan validates SHAP interaction values using a permutation test that shuffles target values ("Permutation test (1 000 shuffles) to assess stability"). Permuting the response while keeping the trained model fixed does not generate a proper null distribution for SHAP interactions, because SHAP values are a deterministic function of the model, not of the target vector. A more appropriate approach would be to bootstrap the model (re‑train on resampled data) or to compare against a null model trained on permuted targets.
- Top‑K MACCS bits are selected based on mean absolute SHAP values computed on the full dataset, and the same dataset is then used to compute the Local Non‑Additivity Index (LNAI) for all bit‑pair combinations. This introduces selection bias: the bits are chosen because they appear important on the data, and the subsequent LNAI test evaluates those same bits on the same data, inflating the chance of finding significant interactions. An independent hold‑out set or nested cross‑validation for bit selection versus LNAI testing should be employed to avoid circular validation.
