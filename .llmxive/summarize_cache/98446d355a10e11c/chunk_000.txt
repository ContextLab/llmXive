## Unresolved concerns

- FR-003.2 mandates 'L1 regularization or Recursive Feature Elimination' (RFE) for feature selection. Tasks T029a (PCA) and T029b (Residualization) introduce unrequested dimensionality reduction and decorrelation steps that alter the feature space before the required selection step. There is no task explicitly implementing the mandated L1/RFE selection on the final feature set as required by FR-003.2, creating a gap in satisfying the spec.
- FR-005 explicitly requires '5-fold Cross-Validation'. Tasks T034_impl and T034_test mandate 'Nested Cross-Validation' and 'Repeated Stratified K-Fold' without specifying the fold count (5 vs 10). The plan's Complexity Tracking explicitly rejects 'Repeated 10-Fold CV' in favor of 'Repeated 5-Fold', but the tasks do not explicitly enforce the 5-fold count required by FR-005, creating ambiguity and potential non-compliance.
- SC-003 defines feature importance stability as a 'measurable outcome' to be reported. Task T041_gate enforces this as a hard pipeline halting condition ('HALT PIPELINE... if value >= 2.0'). There is no task that simply calculates and reports the metric without enforcing a hard gate, which contradicts the spec's definition of SC-003 as a success criterion rather than a blocking failure condition.
- SC-002 sets an MAE threshold of ≤ 50 MPa as a 'practical utility' metric. Task T054 treats this as a hard failure gate ('HALT PIPELINE'). There is no task that calculates and reports the MAE against the threshold without enforcing a hard halt, which contradicts the spec's intent for SC-002 as a success criterion for the paper, not a blocking condition for the code.
- SC-004 states runtime is measured against the 'standard GitHub Actions free-tier limit' (a vague policy). Task T056 hardcodes a specific '6 hours' threshold. There is no task that explicitly references the 'free-tier limit' policy or calculates the runtime against a defined policy value, creating a gap in satisfying the spec's reference source.
- Task T029a specifies a 'Target variance threshold: 0.95'. This specific empirical value is not present in the spec or plan. While the plan mentions PCA, it does not define the variance threshold. This is a planning artifact that should defer the value or cite a source, rather than hardcoding an unverified number.
- Task T053 adds a 'post-hoc power analysis' with an acceptance criterion 'Assert power > 0.8'. This requirement is not present in the spec (FRs or SCs) or the plan. This is a scope addition not covered by the upstream artifacts.
- Logical flow violation: T033_impl (stratified split) and T049 (bin validation) are scheduled to run BEFORE the hard data-scarity gate (T017). FR-004 mandates a halt if N < 80. If N < 80, T033/T049 will fail on empty or insufficient data, creating a race condition where the pipeline attempts to split data that should have been rejected earlier. T017 must strictly precede T033_impl.
- Producer/Consumer dependency violation: T029b (Residualization) is marked as dependent on T029a (PCA). However, the spec (FR-003.1) requires ILR and scalar descriptors to be used in 'COMPLEMENT'. PCA (T029a) reduces the dimensionality of the *combined* matrix, potentially destroying the distinct physical mechanisms of the scalar descriptors before Residualization (T029b) can operate on them. The order T029a -> T029b implies PCA is a prerequisite for Residualization, but Residualization typically requires the full feature set to regress scalars against ILRs. This ordering may break the intended scientific method.
- Artifact flow violation: T038a (Permutation Importance) is described as running on 'EACH of the bootstrap resampled datasets (from T036b)'. However, T036b outputs 'confidence intervals' (a distribution of R² scores), not the 'bootstrap resampled datasets' (prediction arrays) required for permutation testing. T036b must explicitly generate and save the resampled feature/target arrays (e.g., to `data/processed/bootstrap_resamples.pkl`) before T038a can consume them. The current task description implies a missing artifact generation step.
- Dependency ordering violation: T056 (Runtime gate) depends on `data/logs/pipeline_runtime.log` generated by T052. However, T052 is defined as a wrapper in `code/main.py` capturing time 'from start of T013 to end of T051'. If T056 runs *after* T051 (as implied by the gate logic), it must also run *after* T052. The current list places T056 before T052 in the visual flow (T056 is listed before T052 in the implementation block), creating a 'read before write' dependency error.
