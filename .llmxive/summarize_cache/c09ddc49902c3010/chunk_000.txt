## Unresolved concerns

- FR-006 requires sensitivity analysis sweeping values '∈ {0.70, 0.75, 0.80}'. Task T029 describes sweeping 'across a range of values' without explicitly defining the discrete set {0.70, 0.75, 0.80}, risking deviation from the required experimental design.
- The plan indicates T008b and T009 failed verification due to missing `config.yaml`, yet `tasks.md` lists them as incomplete (`- [ ]`) without a re-planned task guaranteeing the creation of `config.yaml` at the exact path with the required schema.
- Consumer before Producer: Task T027a (Evaluation Protocol) and T027c (ValidationService) are in Phase 5. However, the Independent Test for US3 (Phase 5) requires generating scenarios with perturbed counterfactual details. The generation logic (T027b) is in Phase 5, but the *execution* of the human evaluation (implied by SC-004 and US3 test) requires the protocol to be ready. More critically, T027c (ValidationService) calculates inter-rater reliability, which requires the *data* from the human evaluation. The tasks do not include a step to actually *run* the human evaluation or collect the data; they only create the protocol and the analysis script. The analysis script (T027c) is a consumer of data that is never produced by a preceding task in the list. The 'human evaluation' is a missing producer task.
- Missing Producer for Consumer: Task T019b (Phase 2) calls `run_power_analysis()`. Task T023 (Phase 4) implements `run_mixed_effects_test()` and mentions `run_power_analysis` in its description? No, T019b description says 'Implement ... function `run_power_analysis()`'. But T019b is in Phase 2. T023 is in Phase 4. If T019b is the implementation, why is T023 needed? T023 description says 'Implement `run_mixed_effects_test()` ... using statsmodels'. It does not mention power analysis. T019b claims to implement the power analysis function. If T019b is the implementation, it must be in Phase 2. But T019b depends on T023? No, T019b is in Phase 2, T023 in Phase 4. The dependency is reversed. T019b (Phase 2) cannot call a function that is implemented in T023 (Phase 4). The implementation of `run_power_analysis` must be moved to Phase 2 (or T019b must be split), OR T019b must be moved to Phase 4. Since power analysis is a prerequisite for data collection (Phase 3/4), the implementation MUST be in Phase 2. The current placement of T023 (Phase 4) as the only stats task suggests T019b is a placeholder or the implementation is missing.
- Dependency Ambiguity: Task T011b depends on T004a (Data Download) and T012 (EpisodicMemory). T004a is in Phase 2, T012 in Phase 3. T011b is in Phase 3. This is correct. However, T011b loads 'real entries from `data/processed/trajectories.parquet` (generated by T004a)'. T004a is a script to 'fetch ALFWorld/TextWorld datasets'. It does not explicitly state it generates `trajectories.parquet`. T012 (EpisodicMemory) might generate this, or a missing preprocessing task. The dependency chain is unclear: T004a (fetch) -> [Missing Preprocessing] -> T011b (load). If T004a does not generate the parquet, T011b has a missing producer.
- Task T019b mandates generating a power analysis report with fixed values (n=10, power=0.80, d=0.8). However, the spec (Assumptions) and plan state that empirical specifics are deferred to the research phase. The task lacks a concrete deliverable for *how* to handle the 'deferred' nature of these values in a deterministic script without hardcoding assumptions that may be invalidated by actual data collection. It needs to either output a template with placeholders or explicitly calculate based on a pre-registered formula, not just 'generate a report' with assumed numbers.
- Task T027a creates a 'protocol document' for human raters. The spec (SC-004) requires measuring coherence via 'human evaluation ratings'. A document describing *how* to recruit raters is not the deliverable that satisfies the success criterion. The task must include the execution of the evaluation (e.g., 'Run evaluation script X to collect Y ratings') or a simulation of the data collection process if human raters are not available in the CI environment. Currently, the task stops at documentation, leaving the actual data generation unaddressed.
