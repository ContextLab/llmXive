## Unresolved concerns

- Task T007b-1 hardcodes a specific HuggingFace repository (stabilityai/collection-lora) and file name (adapter_fp.safetensors) which do not exist as public artifacts. The Spec Assumption 011 states 'specific CollectionLoRA adapter... are publicly available' but the Plan explicitly notes 'If no public CollectionLoRA exists, we construct a synthetic adapter'. There is NO task to implement the synthetic adapter construction logic (merging verified single-effect LoRAs) required to satisfy the spec if the primary source fails. This leaves FR-001 (load adapter) and FR-010 (SVD) unimplementable if the hardcoded repo is missing.
- Task T016 implements zero-shot quantization but lacks the 'Model Integrity Check' logic mandated by Plan Section 5 (Point 2) and Spec Edge Cases. The plan requires: 'If LPIPS > 0.8 or similarity < 0.1... log "Quantization Failure: Catastrophic Collapse" and skip the level'. T016 only mentions skipping if the backend is unavailable. Without this check, the pipeline cannot satisfy FR-002 (isolate noise) or FR-008 (graceful skip) for catastrophic failures, potentially producing invalid data.
- Task T018 implements CESR but misses the 'Negative Control' logic required by Plan Section 2 (Point 2) and Plan Phase 5. The plan mandates generating/loading a 'Distractor Reference' set and computing CESR against these to validate metric specificity. T018 only compares against FP16 ReferenceImages. Without the negative control task, the system cannot satisfy the plan's requirement to 'validate that the metric is not detecting random semantic distance'.
- Tasks T026 and T027 implement the 'Underpowered' flag logic but miss the 'Unstable Posterior' check mandated by Plan Section 4 (Power Analysis). The plan requires calculating Effective Sample Size (ESS) for the correlation coefficient; if ESS < 200, flag as 'Unstable Posterior'. T026 only checks posterior width. T027's JSON schema lacks the 'unstable_posterior' field. This leaves the FR-014 power analysis incomplete.
