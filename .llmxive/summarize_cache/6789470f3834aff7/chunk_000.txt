## Unresolved concerns

- Task T007b-1 attempts to download 'stabilityai/stable-diffusion-1-5-lora-collection' from HuggingFace. However, the Spec (Assumption about model availability) and Plan (Section 2) reference 'CollectionLoRA' generally, and the specific repository 'stabilityai/stable-diffusion-1-5-lora-collection' does not exist in the public HuggingFace model hub (the actual repo is typically 'stabilityai/collection-lora' or similar). This task is unimplementable as written because the source artifact is missing, blocking FR-001, FR-010, and all downstream generation tasks.
- Tasks T007b-1 and T007c mandate a 'Fail Loudly' policy (raising ValueError) if the primary download fails, with NO fallback mechanism. The Spec (Assumption about model availability) and Plan (Section 5) acknowledge the risk of model availability but do not provide a mirror or alternative source. If the primary HuggingFace repo is temporarily down or the specific path is incorrect (see T007b-1 concern), the entire pipeline halts immediately, violating the robustness required for a research pipeline on a free-tier runner.
- Task T016 implements quantization using `torch.ao.quantization` with `backend='x86'` and `qconfig` for static quantization. However, `torch.ao.quantization` static quantization on CPU for Stable Diffusion (UNet) is notoriously unstable and often requires specific QAT (Quantization Aware Training) or dynamic quantization patterns not covered by the default 'x86' config. The task description does not address the specific handling of the UNet's dynamic graph or the LoRA adapter's specific weight structure, risking a failure to produce valid INT8/INT4 weights (FR-002) or a crash during the 'Verification' step.
- Task T009a computes SVD on 'per-effect LoRA weight matrices' by splitting keys via regex. However, the CollectionLoRA adapter structure often merges LoRA weights into a single state dict without explicit per-effect separation in the keys (e.g., 'lora_unet_down_blocks...'). The regex `r"lora_unet_.*_(.+)_lora"` assumes a specific naming convention that may not exist in the actual adapter file. If the keys do not match this pattern, the task will fail to extract matrices, blocking FR-010 (Subspace Rank) and FR-007 (Correlation Analysis).
- Task T011c generates 'FP16 ReferenceImages' using `seed=43` for CESR calculation. However, the Spec (US-1) and Plan (Section 3.1) define the experimental design as '10 effects * 3 levels * 5 seeds'. The task only generates references for a single seed (43). The CESR metric (FR-011) requires comparing quantized outputs (which will be generated for 5 seeds) against these references. If the references are only for one seed, the statistical power of the CESR calculation is severely compromised, and the comparison may be invalid due to seed-specific variance.
- Task T031a defines a CI workflow to verify job duration ≤ 6 hours (SC-005). However, the task description states it 'adds a timing wrapper in code/main.py'. The timing logic is actually implemented in T031b. T031a should focus on the workflow definition, while T031b handles the code. The current phrasing blurs the responsibility and creates a dependency loop where T031a depends on T031b's output (the timing logic) to verify the duration, but T031b depends on T031a to exist. This is a minor structural ambiguity.
- Task T014 (US1 Main Loop) depends on T013 and T012, but T013 (LPIPS self-consistency) depends on T011c (Reference Images). T011c is marked [X] (complete) but logically requires T011 (Generation) to exist first. T011 depends on T010b (Model Loading). The dependency chain T010b -> T011 -> T011c -> T013 -> T014 is implied but T014's explicit dependencies list T013, T012. However, T014 also needs the *output* of T011 (generated images) to compute metrics. The current dependency list for T014 is incomplete; it must explicitly depend on T011 to ensure images exist before metrics are computed.
- Task T020 (US2 Main Loop) depends on T018 and T019. T018 (CESR) depends on T011d (Reference Lookup) and T017 (Quantized Generation). T017 depends on T016 (Quantization). T016 depends on T009a (SVD). The chain is valid, BUT T020 also requires the *output* of T011 (FP16 baseline images) to compute LPIPS (T019) and CESR (T018).
