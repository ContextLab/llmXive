It neither checked placeholder contents nor preserved arbitrary research bytes. Its test asserted new directory creation rather than reproducing the original downstream exception. This is not an accepted repair. Publication separately rejected the stale target hash at 05:21:39 UTC, so no PR was created or patch deployed.

The repair runner now runs a fixed existing preservation suite in a separate isolated container after the generated regression/related tests and before model review. A repair cannot modify existing tests. Eight cases require both actual placeholder bytes and arbitrary binary content at four scaffold paths to remain recoverable in place or in a project-local backup. Refusing a collision safely is allowed; deleting contents is not. Publication additionally requires this gate's successful result. The model reviewer is also told to reject disconnected helpers and tests that do not reproduce the observed caller's defect.
