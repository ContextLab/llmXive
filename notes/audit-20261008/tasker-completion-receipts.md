# Task planning cannot certify implementation completion

The 04:32 UTC canary task-panel kickback listed 24 unresolved concerns. Many
concerned tasks marked completed while their CSV/JSON/PNG artifacts, validation
tests or full-study outputs did not exist. Replanning had introduced unchecked
claims of completion, so the task review rejected implementation state before
implementation could resume.

Research task generation and task revision now keep a checked task only when
the independent verifier's receipt matches its new definition, specification and
current artifact evidence. Unverified checks are reopened before task analysis.
Existing verified work stays checked; changed requirements or source bytes
invalidate that reuse. No task is automatically accepted and receipts are not
rewritten by planning. Fenced examples remain outside executable task parsing.

61 focused verifier, task-analysis, task-document and reviser tests pass. Two
regressions fail against the prior platform: new tasks remain falsely checked
at initial task analysis and after task revision. The fixed behavior preserves
one actual saved review while reopening unverified output tasks. Backend verdicts
in these regressions are controlled collaborators; this is persistence/routing
proof, not live scientific acceptance.
