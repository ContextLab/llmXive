### REVIEW CONCERNS (2026-07-16, comprehensive review) — ADDRESS BEFORE PHASE 1
- **[C1 — confirmed, reservations.py `reconcile_settled`] Attribution over-release under
  out-of-order charging.** The prefix rule orders the settling batch by `created_at`
  and uses `covered = observed_spend - min(settlement_baseline)`. A **failed-but-reached**
  reservation (settling, never charges) is WRONGLY reconciled once LATER reservations'
  charges inflate `covered` — reproduced: r0,r1 reserved@100; r0 charges→110 (r0
  reconciled); r2 reserved@110 charges→120; sweep then reconciles BOTH r1 (never
  charged!) and r2, releasing r1's hold early (counting 10→0). Bounded headroom leak,
  but violates the strong no-overspend guarantee. Root cause: created_at-order ≠
  charge-order, and reconciled charges aren't discounted from `covered`. **Options:**
  (a) accept as a known bound (maintainer chose the prefix rule in spec review);
  (b) all-or-nothing per batch (safe, converges slower — a stuck failed reservation
  blocks the batch until the daily reset discards it); (c) per-reservation charge
  tracking. Needs a maintainer decision. **Severity nuance:** NOT a permanent leak —
  reconciling against lagged AGGREGATE spend is inherently approximate (two
  same-baseline reservations are indistinguishable by (baseline, worst_case)); a
  wrongly-released hold only briefly re-opens THAT reservation's settlement-lag
  window, and the FRESH-spend re-check at the next `reserve` is the real backstop.
  Recommendation: lean (a) + document the bound, unless the maintainer wants strict (b).
- **[C2 — tokens.py] char/÷4 is not a strict upper bound.** Reused per Constitution I +
  the plan ("deliberately over-estimating"), but token-dense/CJK text can exceed
  chars/4; the +8/msg +16/req overhead only partly cushions it. Low real-world risk
  (llmXive inputs are prose/code; Dartmouth context is 128–256K so the fail-fast
  budget check rarely binds). Flag only.
- **[C3 — ledger_transport.py, low] same-clone + remote + concurrent-threads edge:** after a

## Spec 026 — the design (what to review + build)

Three-layer separation (the core principle — keep it clean):
```
snap     = runtime_snapshot(...)      # acquisition: composite over ALL backends +
                                      #   CreditGuardSnapshot; networked, fallible
decision = select(requirement, snap)  # decision: PURE, deterministic, no net/env
response = execute(chain, options, backend_factory)  # execution: retries/breakers/
                                      #   + cross-runner credit RESERVATION ledger
```
Key contracts (in `src/llmxive/model_selection/types.py`, slice 1 DONE):
`ModelRef(backend, serving_endpoint, model_id, model_family, vendor)` (vendor ≠
endpoint); `ModelRequirement(capability, call_budget:CallBudget,
independence_against:IndependenceBaseline, required/preferred_independence,
exclude_*, allow_paid, max_credits, max_catalog_age_s, max_candidates)`;
`ModelChain(candidates, call_budget, snapshot_digest, snapshot_provenance,
selection_policy_version, explanation)`; `RuntimeSnapshot`; `CreditGuardSnapshot`;
`ExecutionOptions`; `Candidate`; `ModelUnavailable`.

Locked design points (survived 6 review rounds — don't regress):
- Eligibility = **versioned CapabilityPolicy ∩ live snapshot**; catalog proves
  presence/price, NOT competence. **Unknown price ≠ free.**
- Cost: `worst_case_credits = 1000 × (in_tok×input_usd_per_token +
  out_tok×output_usd_per_token)` (USD→credits; **1 credit=$0.001**). Compare vs
  `available_headroom = max(0, budget_fraction×max_budget − spend)` (fraction
  default **0.75**, from `credits.py`). NOT raw balance−spend.
- **Full cross-runner credit RESERVATION ledger** (maintainer chose strong over
  best-effort): authoritative ref **`refs/llmxive/credit-ledger`**, events at
  `reservations/<schema_revision>/<event-id>.json`. **Dedicated strict per-record
  CAS** (fetch→rebuild→verify→append-only→fast-forward→recompute-on-reject) —
  **NOT `commit-and-push.sh`** (its `-X theirs` whole-tree rebase is NOT CAS).
  States `open→settling→reconciled` (open+settling both count against headroom;
  never release at call-return — leaks headroom during Dartmouth settlement lag).
  Lease relative to `ExecutionOptions.deadline_s` + heartbeats + separate
  settlement timeout; crashed in-flight → conservative settlement (retain), not
  reclaim. Each reservation records `budget_epoch (budget_reset_at)` +
  `settlement_baseline (spend at reservation)` for deterministic reconciliation
  across the daily reset. ALL ledger mutations use the same strict CAS.
- Paid checked **twice**: at selection (vs snapshot headroom) AND immediately
  pre-call — extend the canonical guard `credits.py:paid_call_allowed` to accept
  `estimated_cost_credits` (do NOT duplicate the formula, Constitution I).
- `execute()` preserves ALL router safeguards (transient/permanent, per-model
  breakers, retries/deadlines, peer+backend fallback); `ModelChain` replaces
  `MODEL_FALLBACKS` chain only. Three per-candidate outcomes: skip-candidate
  (paid-guard denial) / retry-advance (transient) / abort-chain (permanent
  refusal). Fail-fast if input > `call_budget.max_input_tokens` or
  `options.max_tokens` > `max_output_tokens`; **canonical conservative token
  estimator** shared by selection + execution.
- Independence: `independence_against` baseline + `required` (fail closed
  `ModelUnavailable`) vs `preferred` (degrade + record in `explanation`);
  `exclude_*` = unconditional prohibitions. Panel (025): family required,
  endpoint preferred.
- Deterministic tie-breaks (order): required capabilities → required independence
  → free-before-paid → preferred quality tier → **preferred independence** →
  health → cost → stable model id. NO model-generated ranking in `select()`.
